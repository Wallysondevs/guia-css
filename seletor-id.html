CSS Seletor de ID (#)

A classe é uma etiqueta que você cola em quantos elementos quiser. O ID é outra coisa: é o nome próprio de um único elemento da página, como o CPF de uma pessoa. No CSS, ele é chamado com uma cerquilha (#) na frente. Nesta aula você vai ver como usar o seletor de ID, para que o ID serve de verdade e por que, para dar estilo, quase sempre a classe é a melhor escolha.

Você vai aprender
  • O atributo id no HTML e o seletor #nome no CSS.
  • A regra de ouro: um ID aparece uma vez só em cada página.
  • Para que o ID serve: âncoras (href="#bolo"), formulários e JavaScript.
  • Por que preferir a classe para o estilo: o ID é "forte demais".
  • Os erros comuns: esquecer o #, ID repetido, espaço no ID, número no começo.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: o nome próprio e o uniforme

Numa escola, vários alunos usam o mesmo uniforme do time de vôlei: isso é uma classe. Mas cada aluno tem um número de matrícula só dele: isso é um ID. Se a diretora chama "matrícula 1234", só uma pessoa se levanta.

1. O primeiro seletor de ID

Experimente: o cabeçalho com id="topo" ficou com fundo azul-marinho e letras brancas. Mude o navy para darkgreen no CSS.

<link rel="stylesheet" href="style.css">
<header id="topo">
  <h1>Padaria da Ana</h1>
</header>
<p>Pão quentinho às 7 da manhã.</p>

#topo {
  background-color: navy;
  color: white;
  padding: 8px;
}
id="topo"
No HTML: o atributo id (de identifier, "identificador") dá ao elemento o nome topo, sem #.
#
No CSS: a cerquilha quer dizer "o elemento com este ID". É o mesmo # das âncoras do HTML (href="#topo"), e não é coincidência: os dois apontam para o elemento com aquele id.
topo
O nome, igual ao do HTML, maiúsculas incluídas.
{ … }
As declarações, que valem só para esse elemento.

Repare que o <h1> também ficou branco, embora a regra fale do <header>: a cor das letras passa de pai para filho. Isso é a herança, assunto de outra aula.

2. Um ID, um elemento

A regra do HTML é clara: o valor de um id não pode se repetir na mesma página. E se repetir? O CSS não liga: pinta os dois. Mas o resto do navegador se confunde:

<style>
  #aviso {
    background-color: lightyellow;
    color: darkred;
  }
</style>
<p id="aviso">Loja fechada no feriado.</p>
<p id="aviso">Encomendas até sexta.</p>
<p><a href="#aviso">Ir para o aviso</a></p>

Os dois parágrafos ficaram amarelos: o seletor #aviso pegou os dois. Parece que funcionou, mas:

  • o link href="#aviso" só leva ao primeiro;
  • no JavaScript, document.getElementById("aviso") devolve só o primeiro;
  • num formulário, <label for="aviso"> só se liga ao primeiro;
  • o validador acusa erro.
$ vnu repetido.html
"file:/home/ana/site/repetido.html":10.1-10.14: error: Duplicate ID “aviso”.
"file:/home/ana/site/repetido.html":9.1-9.14: info warning: The first occurrence of ID “aviso” was here.

"ID aviso duplicado" na linha 10, e a nota "a primeira ocorrência do ID aviso foi aqui", na linha 9. Se o estilo é para vários elementos, ele pede uma classe.

3. Para que o ID serve, então

O ID é ótimo para o que precisa apontar para um elemento só:

UsoExemplo
Âncora: um link para um ponto da página<a href="#ingredientes"> leva ao <h2 id="ingredientes"> (Guia HTML: Âncoras)
Formulário: ligar o rótulo ao campo<label for="email"> e <input id="email">
JavaScript: achar um elementodocument.getElementById("carrinho")
Acessibilidade: ligar um texto a outroaria-describedby="dica-senha"

Nenhum desses usos é estilo. Para o estilo, a recomendação do guia é: use classe. Um elemento pode ter as duas coisas, cada uma no seu papel:

<h2 id="ingredientes" class="titulo-secao">Ingredientes</h2>

O id serve para o link #ingredientes; a class serve para o CSS.

4. Por que preferir a classe: o ID é forte demais

Quando duas regras falam da mesma propriedade, o navegador tem de escolher uma. Um dos critérios é a força do seletor, a especificidade. E o ID é muito forte: um único ID vence qualquer quantidade de classes.

Experimente: a Ana deu cor ao prato do dia pelo ID (#prato, azul-marinho). Depois criou a classe destaque, em vermelho, e pôs no mesmo parágrafo. A cor não mudou: o #prato ganha, mesmo vindo antes. Troque o ID por classe: no HTML, class="prato destaque" (e apague o id); no CSS, .prato no lugar de #prato. E agora?

<link rel="stylesheet" href="style.css">
<p>Pão francês</p>
<p id="prato" class="destaque">Prato do dia: sopa de legumes</p>

#prato {
  color: navy;
}

.destaque {
  color: crimson;
  font-weight: bold;
}

Com o ID, o prato do dia fica azul-marinho e em negrito: o font-weight da .destaque pegou (ninguém disputava com ele), mas a cor perdeu para #prato. Depois da troca, as duas regras têm a mesma força (uma classe contra uma classe), e quem vem depois no CSS vence: o prato fica vermelho, como a Ana queria. Com IDs no estilo, a página vira uma briga em que só outro ID (ou o !important) consegue ganhar.

5. Combinando com elemento e classe

Como na classe, você pode colar o ID a um nome de elemento ou a uma classe, sem espaço:

SeletorQuer dizerVale a pena?
#topoO elemento com id="topo"Sim, quando for usar ID
header#topoO <header> com id="topo"Raramente: o ID já é único
#topo.fixoO #topo, quando ele também tiver a classe fixoÀs vezes (o JavaScript liga e desliga a classe)
#topo aOs links dentro do #topo (com espaço: combinador)Melhor com classe: .topo a

Quando dá errado

Esqueceu a cerquilha 
<style>
  topo {
    background-color: navy;
    color: white;
  }
</style>
<header id="topo">
  <h1>Padaria da Ana</h1>
</header>

O que você vê: o cabeçalho continua sem fundo, com o título preto.

Por quê: sem o #, topo é um seletor de elemento: "os <topo> da página". Não há nenhum. O validador de CSS não reclama, porque o seletor é válido.

Como consertar: #topo. Do mesmo jeito, id="#topo" no HTML não funciona: a cerquilha é só do CSS (e do href).

Espaço no ID: An ID must not contain whitespace 
$ vnu espaco.html
"file:/home/ana/site/espaco.html":9.1-9.22: error: Bad value “bolo de fuba” for attribute “id” on element “h2”: An ID must not contain whitespace.

O que significa: "valor inválido bolo de fuba para o atributo id: um ID não pode ter espaço". Diferente do class, em que o espaço separa várias classes, o id é um nome só. E não há como escrever esse nome no CSS sem escapes: #bolo de fuba quer dizer outra coisa (um elemento <fuba> dentro de um <de> dentro do #bolo).

Como consertar: hífen no lugar do espaço: id="bolo-de-fuba" e #bolo-de-fuba.

ID começando com número: Invalid ID selector 
<style>
  #1ano {
    background-color: lightyellow;
  }
</style>
<p id="1ano">A padaria faz 1 ano!</p>

O que você vê: nada muda. No HTML, id="1ano" é permitido; no CSS, o nome depois do # não pode começar com algarismo, e a regra inteira é ignorada.

$ vnu --css numero.css
"file:/home/ana/site/numero.css":1.1-1.5: error: CSS: Invalid ID selector.

O que significa: "seletor de ID inválido".

Como consertar: comece com letra: id="aniversario-1ano".

Espaço depois da cerquilha: Parse Error 
$ cat espaco.css
# topo {
  color: red;
}
$ vnu --css espaco.css
"file:/home/ana/site/espaco.css":0.0-0.0: error: CSS: Parse Error.

O que significa: "erro de leitura". Desta vez o validador nem consegue dizer a linha (0.0). O # e o nome têm de vir colados; com o espaço, a regra é ignorada.

Resumo

  • O ID é o nome único de um elemento: id="topo" no HTML, #topo no CSS.
  • Um ID, um elemento. Repetido, o CSS ainda pinta todos, mas links, label e JavaScript só acham o primeiro, e o validador acusa Duplicate ID.
  • O ID serve para âncoras, formulários, JavaScript e acessibilidade. Para estilo, use classe.
  • Um seletor com ID vence qualquer quantidade de classes: no estilo, isso vira briga (aula Especificidade).
  • Sem #, o seletor procura um elemento que não existe. ID com espaço é inválido no HTML; começando com número, o CSS não aceita.
