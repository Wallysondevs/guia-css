CSS Links

Todo link nasce azul e sublinhado, e fica roxo depois de visitado: é o estilo que o navegador dá a todo <a href> (aula de HTML Links). Com CSS, a Ana pode pintar os links com as cores do site, mudar o sublinhado, reagir quando o mouse passa por cima e até transformar um link num botão. Nesta aula você vai conhecer os quatro estados de um link e a ordem em que eles precisam aparecer no CSS, a famosa ordem LVHA.

Você vai aprender
  • O estilo padrão dos links e como trocá-lo: cor e sublinhado.
  • Os quatro estados: :link, :visited, :hover e :active.
  • Por que a ordem Link, Visited, Hover, Active importa, e o que acontece fora dela.
  • O foco do teclado nos links (:focus-visible).
  • O link com cara de botão e o menu de navegação.
  • O que o :visited não deixa mudar, por privacidade.
  • Os erros reais do validador e os que ele não pega.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código: passe o mouse e clique nos links para ver os estados. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a placa que muda de cor

Imagine uma placa de loja que acende de um jeito antes de você entrar, de outro depois que você já entrou, brilha quando você chega perto e pisca no instante em que você empurra a porta. É o mesmo link, em momentos diferentes.

No CSS, cada momento é uma pseudo-classe: uma palavra depois de dois-pontos que escolhe o elemento num certo estado. a:hover quer dizer "o link, quando o mouse está em cima".

1. O estilo padrão e o seletor a

Sem nenhum CSS seu, o navegador desenha os links assim:

<p style="color: darkgreen">Este parágrafo é verde, mas <a href="#receitas">este link</a> não.</p>
  • Cor: azul (no Chromium do guia, rgb(0, 0, 238)); roxo depois de visitado; e, no Chrome, vermelho (rgb(255, 0, 0)) no instante do clique.
  • Sublinhado: text-decoration-line: underline.
  • Cursor: a mãozinha (cursor: pointer, aula Cursor).

Repare: o parágrafo é verde, e o link continua azul. O link não herda a cor do pai, porque o navegador dá uma cor própria a ele (aula Herança). Para mudar a cor de um link, a regra tem de mirar no próprio a.

Cor e sublinhado

<style>
  .site a {
    color: darkred;
  }
  .sem-traco {
    text-decoration: none;
  }
  .traco-bonito {
    text-decoration-thickness: 2px;
    text-underline-offset: 4px;
  }
</style>
<div class="site">
  <p><a href="#bolo">Bolo de cenoura</a>: vermelho-escuro, sublinhado normal.</p>
  <p><a class="sem-traco" href="#pao">Pão de queijo</a>: sem sublinhado.</p>
  <p><a class="traco-bonito" href="#pudim">Pudim</a>: sublinhado mais grosso e mais afastado.</p>
</div>
.site a { color: darkred; }
Todos os links dentro de .site ficam vermelho-escuros, em todos os estados: visitados também (já que nada diz o contrário).
text-decoration: none;
Tira o sublinhado (aula Sublinhado e Riscado).
text-decoration-thickness: 2px;
A espessura do traço.
text-underline-offset: 4px;
A distância entre o texto e o traço. Afastado, o traço não corta as "perninhas" do g, p e q.
Cuidado ao tirar o sublinhado

No meio de um parágrafo, o sublinhado é o que diz "isto é clicável", também para quem não enxerga bem as cores ou não distingue vermelho de verde. Num link dentro do texto, mantenha o sublinhado (pode deixá-lo bonito, com espessura e afastamento). Tirar faz sentido em menus e botões, onde a forma já mostra que é clicável.

2. Os quatro estados

Pseudo-classeTraduçãoVale quando…
a:linklinko link ainda não foi visitado (e tem href)
a:visitedvisitadoo endereço do link já está no histórico do navegador
a:hoverpairaro mouse está em cima do link
a:activeativoo link está sendo clicado: entre apertar e soltar o botão do mouse

Um link pode estar em vários estados ao mesmo tempo: um link visitado com o mouse em cima é :visited e :hover. É aí que entra a ordem.

<style>
  a:link {
    color: navy;
  }
  a:visited {
    color: purple;
  }
  a:hover {
    color: crimson;
    text-decoration-thickness: 3px;
  }
  a:active {
    color: darkorange;
  }
</style>
<p>Passe o mouse e clique (segure o botão): <a href="#receitas">receitas da Ana</a>.</p>

O link começa azul-marinho. Com o mouse em cima, fica vermelho com o traço mais grosso. Segurando o botão do mouse, fica laranja. Depois do primeiro clique, o endereço #receitas entra no histórico, e o link pode passar a aparecer roxo.

3. A ordem LVHA

As quatro regras têm a mesma especificidade (um elemento e uma pseudo-classe). Quando duas valem ao mesmo tempo, vence a que vem por último no CSS (aula A Cascata). Por isso a ordem tem de ser:

OrdemRegraPor quê
1ºa:linkOs dois estados "de repouso". Um link é um ou outro, nunca os dois, então a ordem entre eles não importa; mas os dois têm de vir antes dos estados de ação.
2ºa:visited
3ºa:hoverVem depois, para vencer o repouso quando o mouse chega.
4ºa:activePor último: no clique, o mouse também está em cima (:hover), e o clique precisa vencer.
Para decorar: LoVe HAte

"Amor e ódio", em inglês: LoVe HAte = Link, Visited, Hover, Active.

O que acontece fora da ordem

<style>
  a:hover {
    color: crimson;
  }
  a:link {
    color: navy;
  }
</style>
<p>Passe o mouse: <a href="#nunca-visitado">este link não fica vermelho</a>.</p>

O a:hover veio antes. Com o mouse em cima de um link não visitado, valem as duas regras, e a de baixo (a:link, azul-marinho) vence: o vermelho nunca aparece. No F12, no painel de estilos do link, você veria o color: crimson riscado, vencido pelo outro. O validador não diz nada: as duas regras são CSS válido.

Missão: o link deveria ficar vermelho (crimson) com o mouse em cima, mas não fica. Ponha as regras na ordem LVHA, sem mudar as cores. Depois, passe o mouse sobre o link para conferir.

<link rel="stylesheet" href="style.css">
<p>Veja a <a class="receita" href="#bolo">receita do bolo de cenoura</a>.</p>

.receita:active {
  color: darkorange;
}

.receita:hover {
  color: crimson;
}

.receita:link {
  color: navy;
}

.receita:visited {
  color: navy;
}

.receita:link {
  color: navy;
}

.receita:visited {
  color: navy;
}

.receita:hover {
  color: crimson;
}

.receita:active {
  color: darkorange;
}

Repare que a missão usa .receita:hover em vez de a:hover. A ordem LVHA vale do mesmo jeito: as quatro regras continuam com especificidades iguais entre si.

4. Os limites do :visited

Se um site pudesse ver quais links você já visitou, ele descobriria o seu histórico: em que banco você entra, que sites de saúde você leu. Para impedir isso, os navegadores limitam o :visited:

  • Só as cores podem mudar: color, background-color, border-color, outline-color e outras cores. Tamanho de letra, fundo com imagem, display… são ignorados no :visited, sem aviso.
  • O JavaScript (e as ferramentas do F12 em parte) recebe o estilo como se o link não tivesse sido visitado. No Chromium do guia, mesmo forçando o estado :visited, o getComputedStyle devolveu o azul de link novo.
  • Por isso, as missões do guia não conferem o :visited: confira olhando.
<style>
  a:visited {
    color: purple;
    font-size: 2rem;
  }
</style>
<p>Clique: <a href="#visitado">link de teste</a>. Ele pode ficar roxo, mas nunca grande.</p>

5. O foco do teclado

Quem navega com Tab não tem mouse para o :hover. Para essa pessoa, o estado que importa é o foco. O navegador já desenha um anel em volta do link focado; se você quiser outro, use :focus-visible e nunca apague o anel sem pôr um no lugar (aula outline).

<style>
  a:hover,
  a:focus-visible {
    color: crimson;
  }
  a:focus-visible {
    outline: 3px solid #b35900;
    outline-offset: 2px;
  }
</style>
<p>Clique aqui no branco e aperte Tab: <a href="#um">primeiro</a> e <a href="#dois">segundo</a>.</p>

Escrever a:hover, a:focus-visible juntos é um costume bom: quem usa o teclado ganha o mesmo destaque de quem usa o mouse. Na ordem, o foco anda junto do :hover: L, V, H + foco, A.

6. O link com cara de botão

Quando um link leva a uma página importante ("Encomendar", "Ver cardápio"), ele pode ganhar cara de botão: padding, fundo, cantos arredondados. Continua sendo um link (leva a outro lugar); só muda a aparência.

<style>
  .botao {
    display: inline-block;
    padding: 10px 20px;
    background-color: darkgreen;
    color: white;
    text-decoration: none;
    border-radius: 8px;
  }
  .botao:hover,
  .botao:focus-visible {
    background-color: forestgreen;
  }
  .botao:active {
    background-color: green;
  }
</style>
<a class="botao" href="#encomendar">Encomendar bolo</a>
display: inline-block;
O link é em linha; com inline-block, o padding de cima e de baixo passa a ocupar espaço (aula padding).
color: white;
Na própria classe, vale para todos os estados: visitado ou não, o texto fica branco.
text-decoration: none;
Aqui pode: a forma de botão já mostra que é clicável.
:hover, :focus-visible / :active
O fundo clareia com o mouse (ou o foco) e escurece no clique, dando a sensação de "apertar".

Botões de verdade (<button>) e mais detalhes de aparência estão na aula Estilizando Botões.

7. Formas de escrever e qual usar

EscritaQuando usar
a { color: … }Uma cor só para todos os links e estados. Simples, e já resolve o "roxo de visitado" quando você não quer diferença.
a:link, a:visited, a:hover, a:activeCada estado com o seu visual. Sempre nessa ordem (LVHA).
a:hover, a:focus-visible { … }O mesmo destaque para o mouse e para o teclado.
.menu a { … }Links de uma parte do site (menu, rodapé), sem mexer nos outros.
.botao { … }Um link com cara de botão. Ponha a cor na classe, para valer em todos os estados.

Quando dá errado

Ordem trocada: o :hover não funciona (e o validador não reclama)

O que você vê: o link não muda com o mouse em cima, ou muda só enquanto não foi visitado.

$ cat l3.css
a:hover {
  color: crimson;
}
a:link {
  color: navy;
}
$ vnu --css l3.css
$

Por quê: especificidades iguais, vence a última regra (seção 3). Como consertar: L, V, H, A.

Nome errado: Unknown pseudo-element or pseudo-class 
$ cat l1.css
a:hoover {
  color: crimson;
}
$ vnu --css l1.css
"file:/home/ana/site/l1.css":1.3-1.8: error: CSS: Unknown pseudo-element or pseudo-class “:hoover”
$ vnu --css l6.css
"file:/home/ana/site/l6.css":1.3-1.10: error: CSS: Unknown pseudo-element or pseudo-class “:visitado”

O que você vê: nada muda no link.

O que significa: "pseudo-elemento ou pseudo-classe desconhecido". Repare na diferença para os erros de propriedade: com um seletor inválido, o navegador joga fora a regra inteira, com todas as declarações entre as chaves, e não só uma linha. E os nomes são sempre em inglês: :visited, não :visitado.

Como consertar: a:hover.

Um espaço antes dos dois-pontos: a :hover 
<style>
  a :hover {
    color: crimson;
  }
</style>
<p>Passe o mouse: <a href="#bolo">nada acontece</a>.</p>

O que você vê: o link não fica vermelho.

Por quê: o espaço é um combinador: a :hover quer dizer "qualquer elemento dentro de um a que esteja com o mouse em cima". Este link não tem nenhum elemento dentro, só texto. O validador não acusa: é um seletor válido, só não é o que você queria.

Como consertar: tudo junto, a:hover.

Pus a cor no parágrafo e o link continuou azul

O que você vê: p { color: darkgreen; } pinta o texto, mas os links dentro do parágrafo continuam azuis (seção 1).

Por quê: o navegador dá uma cor própria aos links, que vence a herança do pai. Como consertar: uma regra para o a (p a { color: darkgreen; }), ou, se quiser que o link tenha sempre a cor do texto em volta, a { color: inherit; }, mantendo o sublinhado para ele continuar parecendo link.

Tirei o sublinhado do li e o link continua sublinhado

O que você vê: nav li { text-decoration: none; } não muda nada nos links do menu.

Por quê: o sublinhado não é do li: é do a, posto pelo navegador. Como consertar: nav a { text-decoration: none; }.

Missão final: o menu da lojinha

Missão: monte o menu. (1) Os links do .menu: brancos (white), sem sublinhado, com display: inline-block e padding de 8px 14px. (2) Com o mouse em cima ou com o foco do teclado (:hover e :focus-visible), o fundo fica darkred. (3) No foco do teclado, um anel de 2px contínuo, branco. Confira passando o mouse no primeiro link, "Início", e, depois, clicando no branco do resultado e apertando Tab até o foco chegar nele.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="#inicio">Início</a>
  <a href="#bolos">Bolos</a>
  <a href="#salgados">Salgados</a>
  <a href="#contato">Contato</a>
</nav>

.menu {
  background-color: firebrick;
  padding: 6px;
}

.menu {
  background-color: firebrick;
  padding: 6px;
}

.menu a {
  display: inline-block;
  padding: 8px 14px;
  color: white;
  text-decoration: none;
}

.menu a:hover,
.menu a:focus-visible {
  background-color: darkred;
}

.menu a:focus-visible {
  outline: 2px solid white;
}

Como a cor branca está em .menu a, ela vale para todos os estados: os links visitados não ficam roxos. Num menu, isso é o que você quer; no meio de um texto, deixar o visitado diferente ajuda o leitor a saber onde já esteve.

Resumo

  • Links vêm azuis, sublinhados e roxos depois de visitados, e não herdam a cor do pai: estilize o próprio a.
  • color muda a cor; text-decoration: none tira o sublinhado (mantenha-o nos links de texto); text-underline-offset e text-decoration-thickness o deixam bonito.
  • Estados: :link (não visitado), :visited, :hover (mouse em cima), :active (clique). Sempre na ordem LVHA (LoVe HAte), porque com especificidades iguais vence a última regra.
  • :visited só aceita cores, por privacidade.
  • Junte :hover com :focus-visible e nunca apague o anel de foco.
  • Erros: ordem trocada e a :hover com espaço passam no validador; :hoover e :visitado dão Unknown pseudo-element or pseudo-class, e a regra inteira é ignorada.
