CSS Menos Movimento

Nas últimas aulas, o site da Ana ganhou cartões que levantam, selos que pulsam e avisos que tremem. Para a maioria das pessoas, é só um enfeite. Mas, para algumas, movimento na tela causa tontura, enjoo e dor de cabeça de verdade, às vezes por horas. Essas pessoas costumam ligar no sistema uma opção de "reduzir movimento", e o navegador conta isso ao CSS. Nesta aula você vai aprender a ouvir esse pedido.

Você vai aprender
  • Quem pede menos movimento, e onde fica essa opção no sistema.
  • A media query @media (prefers-reduced-motion: reduce).
  • O que reduzir, o que pode ficar e como trocar um movimento por um efeito calmo.
  • O jeito "movimento só para quem não pediu menos" (no-preference).
  • A rolagem suave e o "reset" de animações que você vai encontrar por aí.
  • Como testar, e os erros que o validador pega (e os que não pega).

Antes, veja Transições, Animações e Media Queries. As mensagens do validador saíram do validador W3C (vnu) na máquina fictícia da Ana. Os valores calculados foram conferidos no Chromium, com a preferência ligada e desligada.

A ideia: o motorista que vê alguém enjoado

A Ana dá carona para a tia, que enjoa em estrada de curva. Ela não deixa de levar a tia: só dirige mais devagar, sem frear de repente, e abre a janela. A viagem é a mesma, o destino é o mesmo; muda o jeito.

Com o site é igual. Quem pede menos movimento não quer um site sem graça nem sem informação. Quer o mesmo conteúdo, sem coisas que deslizam, giram, dão zoom ou pulam. O texto, as cores, os botões e o layout continuam iguais.

Quem pede, e onde

Pessoas com distúrbios do equilíbrio (labirintite, problemas do ouvido interno), enxaqueca, algumas pessoas autistas ou com TDAH, que se distraem com o que se mexe, e qualquer um que simplesmente acha animação demais cansativa. A opção fica nas configurações de acessibilidade do sistema. Os nomes mudam de versão para versão; procure algo como:

1. A pergunta: prefers-reduced-motion

.selo {
  animation: pulsar 1.2s ease-in-out infinite;
}

@media (prefers-reduced-motion: reduce) {
  .selo {
    animation: none;
  }
}
.selo { animation: … }
A animação de sempre, da aula Animações.
@media (…-motion: reduce)
"Se a pessoa prefere movimento reduzido". prefers-reduced-motion = "prefere movimento reduzido"; reduce = "reduzir". Como no tema escuro, a pergunta vai entre parênteses.
animation: none;
Desliga a animação. Esta regra tem o mesmo seletor e vem depois: pela cascata, vence quando o @media é verdadeiro.
ValorQuando a resposta é sim
reducea pessoa ligou "reduzir movimento" no sistema
no-preferencea pessoa não pediu nada (a maioria)

Conferido no Chromium: sem a preferência, o .selo fica com animation-name: pulsar; com reduce, animation-name: none.

Suporte

Funciona no Chrome e no Edge desde a versão 74, no Firefox desde a 63 e no Safari desde a 10.1 (segundo o MDN): todos os navegadores atuais. Não há motivo para não usar.

Como testar

  • No sistema: ligue a opção da tabela acima e recarregue a página.
  • No F12 (ilustrativo): no Chrome e no Edge, menu ⋮ do F12 → More tools → Rendering → "Emulate CSS media feature prefers-reduced-motion" → reduce. Também dá para apertar Ctrl+Shift+P no F12 e digitar reduced-motion. Os nomes dos menus são em inglês e mudam com a versão.
  • No editor do guia: diferente do tema escuro, o quadro não tem um botão para isso. Os quadros seguem a configuração do seu sistema (ou o que o F12 estiver fingindo para a página toda). Se você ligar "reduzir movimento", as caixas abaixo passam a mostrar a versão calma.

Experimente: com o seu sistema normal, o selo pulsa. Ligue "reduzir movimento" no sistema (ou finja no F12) e veja: ele para. Depois, troque o animation: none; por animation-duration: 4s; e repare que, em vez de parar, ele passa a pulsar bem devagar.

  50% {
    scale: 1.15;
  }
}

.selo {
  display: inline-block;
  background-color: #c2410c;
  color: white;
  padding: 2px 8px;
  border-radius: 10px;

}

@media (prefers-reduced-motion: reduce) {
  .selo {
    animation: none;
  }
}

2. O que reduzir, e o que pode ficar

"Reduzir" não quer dizer "tirar tudo". O que incomoda é o movimento que dá a sensação de que a tela (ou você) está se mexendo:

Reduza ou tirePode ficar
coisas que deslizam de longe (um painel que entra voando pela lateral)mudança de cor no hover
zoom e rotação (scale grande, rotate, o cartão que vira)um surgir curto com opacity (aparecer e sumir sem se mexer)
animações infinitas decorativas (o selo que pulsa)a mudança de sombra ou de borda
parallax (o fundo andando em velocidade diferente do texto) e a rolagem suaveum "carregando" mais lento ou mais discreto, porque ele informa algo

O "carregando" é o caso especial: se você simplesmente o desligar, a pessoa vê um círculo parado e pensa que a página travou. Melhor deixá-lo mais lento (animation-duration: 3s) ou trocá-lo por um texto "Carregando…".

Trocar, em vez de tirar

Um aviso que entra deslizando de baixo pode, para quem pede menos movimento, só surgir no lugar. A informação ("chegou um aviso") continua; some o deslocamento:

@keyframes entrar {
  from {
    opacity: 0;
    translate: 0 40px;
  }
}

@keyframes surgir {
  from {
    opacity: 0;
  }
}

.aviso {
  animation: entrar 0.5s ease-out;
}

@media (prefers-reduced-motion: reduce) {
  .aviso {
    animation-name: surgir;
  }
}

Repare que o bloco do @media troca só o nome da animação (animation-name): a duração e o ritmo continuam os da regra principal. E os dois @keyframes só têm o from: o fim é o estilo normal do aviso.

Missão: o cartão do bolo dá um zoom no hover. Acrescente, no fim do CSS, um bloco @media (prefers-reduced-motion: reduce) que tire a transição do .cartao (transition: none;). Quem não pediu nada continua vendo o zoom suave: passe o mouse para conferir.

<div class="cartao">
  <img src="assets/midia/bolo-400.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="200" height="150">
  <p>Bolo de cenoura</p>
</div>

  display: inline-block;
  margin: 20px;
  padding: 10px;
  border: 1px solid #ccc;
  border-radius: 8px;
  transition: transform 0.4s ease-out;
}

}

}

.cartao {
  display: inline-block;
  margin: 20px;
  padding: 10px;
  border: 1px solid #ccc;
  border-radius: 8px;
  transition: transform 0.4s ease-out;
}

.cartao:hover {
  transform: scale(1.08);
}

.cartao img {
  display: block;
}

@media (prefers-reduced-motion: reduce) {
  .cartao {
    transition: none;
  }
}

Com transition: none, o zoom ainda acontece, mas de uma vez, sem a parte "em movimento". Para quem pede menos movimento, o mais gentil seria tirar o zoom também, e marcar o hover com uma borda: experimente pôr, no mesmo bloco, .cartao:hover { transform: none; border-color: #c2410c; }.

3. O outro jeito: movimento só para quem não pediu menos

Até aqui, a animação é a regra, e o @media tira. Dá para fazer o contrário: o site começa calmo, e o movimento só é ligado dentro de @media (prefers-reduced-motion: no-preference):

.selo {
  display: inline-block;
}

@media (prefers-reduced-motion: no-preference) {
  .selo {
    animation: pulsar 1.2s ease-in-out infinite;
  }
}

A vantagem: se você esquecer de pensar no "reduzir" numa animação nova, o erro fica do lado seguro (a animação simplesmente não aparece para quem pediu menos). Com a preferência ligada, o Chromium mostrou animation-name: none no .selo; sem ela, pulsar.

JeitoComo éQuando usar
@media (… : reduce) tirando ou trocandoa animação é a regra; o bloco desliga ou acalmaquando você quer trocar o movimento por outro efeito (seção 2), e em sites que já existem
@media (… : no-preference) ligandoo site é calmo; o bloco liga o movimentoem sites novos, para efeitos que são só decoração

4. A rolagem suave

A propriedade scroll-behavior: smooth (aula Rolagem Suave) faz a página deslizar até o destino quando a pessoa clica num link interno, em vez de pular. É exatamente o tipo de movimento que incomoda. O jeito certo de usá-la é já dentro do no-preference:

@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}

5. O "reset" de animações

Você vai encontrar em muitos sites (e em resets de CSS, aula Reset e Normalize) um bloco como este:

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
*, *::before, *::after
Todos os elementos e os pseudo-elementos (aula Seletor Universal).
animation-duration: 0.01ms
Toda animação dura um centésimo de milésimo de segundo: acontece "de uma vez". Por que não 0s? Com uma duração quase zero, a animação ainda termina, e o estado final (o forwards da aula anterior) e os avisos de fim que o JavaScript espera continuam acontecendo.
animation-iteration-count: 1
As infinitas rodam uma vez só.
!important
Aqui está uma das poucas vezes em que o !important (aula !important) é aceito: o bloco precisa vencer qualquer animação do site, por mais específico que seja o seletor dela.

Funciona como uma rede de segurança, mas é bruto: tira também os efeitos inofensivos (os surgir suaves) e o "carregando". Prefira cuidar de cada animação, como nas seções 2 e 3, e use o reset, se quiser, só como garantia.

Quando dá errado

error: CSS: “reduced” is not a “prefers-reduced-motion” value

O que aconteceu: @media (prefers-reduced-motion: reduced), com d no fim. Com true, acontece o mesmo:

$ vnu --css reduced.css true.css
"file:/home/ana/mov/reduced.css":1.40-1.40: error: CSS: “reduced” is not a “prefers-reduced-motion” value
"file:/home/ana/mov/true.css":1.37-1.37: error: CSS: “true” is not a “prefers-reduced-motion” value

O navegador não reclama: a pergunta nunca tem resposta "sim", e o movimento nunca é reduzido. Quem pediu continua passando mal, e você não percebe, porque o seu sistema não tem a opção ligada.

Como consertar: os valores são reduce e no-preference.

O bloco não funciona (e o validador não reclama)

O que aconteceu: o nome da característica foi encurtado: @media (reduced-motion: reduce).

$ vnu --css nome.css
$

O validador do laboratório (vnu 26.10.12) não avisa, mas o navegador não conhece reduced-motion: uma pergunta desconhecida é sempre "não", e o bloco nunca vale. Por isso, teste de verdade (F12 ou sistema): não confie só no validador.

Como consertar: o nome completo, prefers-reduced-motion.

A animação continua mesmo com "reduzir movimento" ligado

O que aconteceu: o bloco @media veio antes da regra da animação, com o mesmo seletor:

@media (prefers-reduced-motion: reduce) {
  .selo {
    animation: none;
  }
}

.selo {
  animation: pulsar 1.2s infinite;
}

A mesma armadilha do tema escuro: o @media não dá prioridade nenhuma. As duas regras têm a mesma especificidade, e a que vem depois vence: a animação.

Como consertar: o bloco @media sempre depois das regras que ele muda. Ou use o jeito no-preference (seção 3), em que essa ordem não importa.

Tirou a animação, mas o movimento continua

O que aconteceu: o bloco tem animation: none, mas o movimento vinha de uma transição (um transition: transform 0.4s no hover). animation e transition são coisas diferentes: desligar uma não desliga a outra.

Como consertar: no bloco de "reduzir", cuide das duas: animation: none; e transition: none; (ou só nas propriedades de movimento).

O "carregando" parou e a página parece travada

O que aconteceu: o reset da seção 5 (ou um animation: none) parou também o ícone de carregando. Para a pessoa, um círculo parado parece um erro.

Como consertar: para o carregando, prefira deixar mais lento (animation-duration: 3s) ou mostrar um texto ("Carregando…").

Resumo

  • Movimento na tela causa tontura e enjoo em algumas pessoas. Elas ligam "reduzir movimento" no sistema, e o CSS fica sabendo por prefers-reduced-motion.
  • @media (prefers-reduced-motion: reduce) { … } depois das regras de animação: desligue (animation: none, transition: none) ou troque por algo calmo (animation-name: surgir).
  • Reduza deslizes, zooms, giros, parallax e animações infinitas decorativas. Cores, surgir com opacity e um carregando mais lento podem ficar.
  • O jeito seguro para efeitos novos: ligar o movimento só dentro de @media (prefers-reduced-motion: no-preference), inclusive a rolagem suave.
  • Teste no sistema ou no F12: o editor do guia não tem botão para isso, e o validador não percebe nome errado (reduced-motion).
