CSS Sintaxe

Você já escreveu as primeiras regras de CSS copiando o formato. Agora é hora de entender cada pedaço: o que é uma regra, um seletor, uma declaração, e para que serve cada sinal ({ }, :, ;). Saber os nomes certos ajuda a ler qualquer tutorial e qualquer mensagem de erro. E, como o CSS não avisa quando você erra, saber o que cada sinal faz é o que permite achar o erro sozinho.

Você vai aprender
  • Os nomes das partes: regra, seletor, bloco de declarações, declaração, propriedade e valor.
  • O papel de cada sinal: chaves, dois-pontos e ponto e vírgula.
  • O que é livre (espaços, quebras de linha, maiúsculas) e o que não é (o espaço entre o número e a unidade).
  • Valores com várias partes, como 2px solid teal.
  • O que acontece de verdade quando falta um ;, um : ou uma }, e o que o validador diz.

Os resultados são desenhados pelo seu navegador. As mensagens de erro são do validador W3C (vnu --css), rodado na máquina fictícia da Ana, na pasta ~/site.

A ideia: a etiqueta e a lista de instruções

Imagine a Ana organizando a mudança. Em cada caixa vai uma etiqueta dizendo para qual cômodo ela vai ("cozinha"), e um papel com as instruções: "frágil: sim; empilhar: não; abrir primeiro: sim".

Uma regra de CSS é exatamente isso. A etiqueta é o seletor (para quem são as instruções); o papel é o bloco de declarações; cada linha do papel é uma declaração, no formato "o quê: como".

1. As partes de uma regra

h1 {
  color: teal;
  text-align: center;
}
h1 { … }
A regra inteira (em inglês, rule ou ruleset): o seletor mais o bloco.
h1
O seletor: escolhe quem recebe o estilo. Aqui, todos os <h1>. Há muitos tipos de seletor; eles começam na aula O que é um Seletor.
{ e }
As chaves abrem e fecham o bloco de declarações: tudo o que está entre elas vale para o seletor.
color: teal;
Uma declaração: uma instrução completa.
color
A propriedade: o que mudar. O CSS tem centenas, cada uma com um nome fixo, em inglês.
:
Os dois-pontos separam a propriedade do valor. Leia como "é" ou "recebe".
teal
O valor: como fica. Cada propriedade aceita só certos valores: color aceita cores, text-align aceita left, center, right…
;
O ponto e vírgula separa uma declaração da próxima. É o sinal mais importante para evitar erros (veja Quando dá errado).

Em português, a regra inteira diz: "para todo h1: a cor é verde-azulado; o alinhamento do texto é centro".

2. Várias declarações e várias regras

Um bloco pode ter quantas declarações você quiser, e uma folha de estilo, quantas regras quiser. O navegador lê de cima para baixo:

Experimente: acrescente uma terceira declaração na regra do h1, por exemplo font-size: 40px;, numa linha nova antes da }. Depois crie uma regra nova, só para o p, com color: dimgray;.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>

h1 {
  color: teal;
  text-align: center;
}

O último ;

Como o ; separa declarações, o da última declaração é opcional: h1 { color: teal } funciona e o validador aceita. Mesmo assim, este guia sempre põe o ;. O motivo: amanhã você acrescenta uma linha embaixo, esquece o ; da linha de cima, e as duas param de funcionar (é o primeiro erro de Quando dá errado).

3. O que é livre: espaços, linhas e maiúsculas

Para o navegador, os espaços e as quebras de linha entre as partes não importam. As três regras abaixo são idênticas:

h1 { color: teal; text-align: center; }

h1{color:teal;text-align:center}

h1 {
  color: teal;
  text-align: center;
}

A primeira forma, numa linha só, é comum para regras com uma declaração. A segunda, toda espremida, é como os sites publicam o CSS para ficar menor (o arquivo "minificado"), mas é ruim de ler. A terceira é a deste guia: uma declaração por linha, recuo de 2 espaços.

Os nomes das propriedades e as palavras-chave dos valores também não diferenciam maiúsculas de minúsculas: COLOR: TEAL; funciona (conferido no Chromium) e o validador aceita. Mas a convenção de todo mundo é escrever em minúsculas, e algumas coisas diferenciam, sim: os nomes de classes (aula Seletor de Classe) e os nomes de arquivos, como em url("Bolo.jpg"). Escreva tudo em minúsculas e não precisa pensar nisso.

O que não é livre: o número e a unidade

Num valor com número, a unidade (px, rem, %…) vem colada no número: 18px. Com espaço (18 px) ou sem unidade (18), a declaração inteira é ignorada. As unidades têm aula própria: Unidades.

4. Valores com várias partes

Algumas propriedades recebem mais de uma coisa no valor. Aí os espaços e as vírgulas dentro do valor têm significado:

<style>
  h2 {
    border-bottom: 2px solid teal;
    font-family: "Trebuchet MS", Arial, sans-serif;
  }
</style>
<h2>Bolo de cenoura</h2>
2px solid teal
Três partes separadas por espaço, cada uma dizendo uma coisa da borda de baixo (border-bottom): a espessura, o tipo de linha (contínua) e a cor. No resultado, uma linha verde-azulada sob o título.
"Trebuchet MS", Arial, sans-serif
Uma lista de alternativas separadas por vírgula: "use Trebuchet MS; se não tiver, Arial; se não tiver, qualquer letra sem serifa". O nome com espaço vai entre aspas. A letra que aparece depende das fontes instaladas no seu computador (aula Fontes).

Regra geral: espaço separa partes de um mesmo valor; vírgula separa alternativas ou itens de uma lista; ponto e vírgula separa declarações. Cada propriedade com valor de várias partes é explicada na sua aula.

5. Regras @ e comentários

Além das regras comuns, você vai encontrar duas outras coisas numa folha de estilo:

  • Regras @ (em inglês, at-rules), que começam com arroba e dão instruções especiais, como @media ("só em telas pequenas") ou @font-face ("baixe esta fonte"). Cada uma tem a sua aula; a lista está em Regras @.
  • Comentários, entre /* e */, que o navegador ignora: são notas para quem lê o código. Aula Comentários.

Quando dá errado

Lembre: o CSS não mostra erro na tela. O navegador descarta o que não entende e continua lendo dali em diante. Saber até onde ele descarta é o que explica cada sintoma abaixo. (Todos conferidos no Chromium.)

Faltou o ;: duas declarações se perdem 
h1 {
  color: teal
  text-align: center;
  font-size: 40px;
}

O que você vê: o título preto e à esquerda, mas com a letra grande (40px). A cor e o alinhamento sumiram.

Por quê: sem o ;, o navegador acha que a declaração continua na linha de baixo e lê o valor da cor como teal text-align: center. Isso não é uma cor, então ele joga fora tudo, até o próximo ;. O font-size, depois do ;, funciona.

$ vnu --css pv.css
"file:/home/ana/site/pv.css":3.3-3.12: error: CSS: “color”: Missing a semicolon before the property name “text-align”.

O que significa: "falta um ponto e vírgula antes da propriedade text-align". O validador aponta a linha 3, mas o ; que falta é no fim da linha 2.

Como consertar: color: teal;.

Missão: o título deveria estar verde-azulado e centralizado, mas está preto e à esquerda. Ache o sinal que falta e conserte.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>

h1 {
  color: teal
  text-align: center;
}

h1 {
  color: teal;
  text-align: center;
}
Faltou o : (ou usou =): Parse Error 
h1 {
  color teal;
  text-align: center;
}

O que você vê: o título centralizado, mas preto. Só a declaração sem os dois-pontos se perdeu; a próxima, depois do ;, funcionou.

$ vnu --css doispontos.css
"file:/home/ana/site/doispontos.css":2.9-2.12: error: CSS: “color”: Parse Error.
$ vnu --css igual.css
"file:/home/ana/site/igual.css":2.11-2.14: error: CSS: “color”: Parse Error.

O que significa: "erro de leitura" na declaração de color. O segundo arquivo, igual.css, é o mesmo com color = teal;: o sinal de igual de outras linguagens não vale no CSS.

Como consertar: color: teal;, sempre com dois-pontos.

Faltou a }: a regra seguinte vai parar dentro da anterior, e o validador não avisa 
p {
  color: dimgray;

h2 {
  color: navy;
}

O que você vê: o parágrafo fica cinza, como devia, mas o h2 continua preto.

Por quê: como a regra do p não foi fechada, o navegador lê o h2 { … } como uma regra dentro da regra do p. O CSS de hoje permite regras dentro de regras (o "aninhamento", aula CSS Aninhado), e uma regra h2 dentro de p quer dizer "um h2 que esteja dentro de um p". Na página não há nenhum, então nada fica azul. A última } fecha a regra do h2, e a regra do p termina sozinha no fim do arquivo.

O que o validador diz: nada. Para ele, regras aninhadas são CSS válido:

$ vnu --css chave.css; echo "saida: $?"
saida: 0

(O echo mostra o código de saída do vnu: 0 quer dizer "nenhum erro".)

Como consertar: feche cada regra com } antes de começar a próxima. O recuo de 2 espaços ajuda a ver: se a h2 aparecesse recuada no editor (muitos editores recuam sozinhos), seria o sinal de que ela está dentro de outra regra.

Espaço entre o número e a unidade, ou unidade esquecida 
p {
  font-size: 18 px;
}

O que você vê: a letra do tamanho padrão (16px), como se a declaração não existisse. Com font-size: 18;, sem a unidade, acontece o mesmo.

$ vnu --css espaco.css
"file:/home/ana/site/espaco.css":2.17-2.18: error: CSS: “font-size”: Too many values or values are not recognized.
$ vnu --css semunidade.css
"file:/home/ana/site/semunidade.css":2.14-2.15: error: CSS: “font-size”: only “0” can be a “unit”. You must put a unit after your number.

O que significa: o primeiro, "valores demais ou não reconhecidos" (o validador vê 18 e px como duas coisas separadas); o segundo, "só o 0 pode ficar sem unidade. Você deve pôr uma unidade depois do número". Zero é zero em qualquer unidade, por isso margin: 0; é válido.

Como consertar: font-size: 18px;, número e unidade colados.

Resumo

  • Uma regra = seletor (quem) + bloco de declarações entre { }.
  • Uma declaração = propriedade (o que) : valor (como) ;.
  • Espaços, quebras de linha e maiúsculas entre as partes são livres; a convenção é minúsculas, uma declaração por linha, recuo de 2 espaços e ; sempre.
  • Dentro de um valor: espaço separa partes (2px solid teal), vírgula separa alternativas. Número e unidade vão colados (18px).
  • O navegador descarta só o que não entende: uma declaração com erro some; sem o ;, somem duas; sem a }, a regra seguinte vira "de dentro" e o validador não avisa.
