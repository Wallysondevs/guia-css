CSS Esconder

Um aviso que só aparece depois, a resposta de um enigma que o leitor revela, um menu que abre no celular: muitas vezes uma parte da página precisa ficar escondida. O CSS tem três jeitos principais de esconder, e eles não são iguais: um libera o espaço, outro guarda o lugar, e o terceiro deixa a coisa invisível, mas ainda clicável. Nesta aula você vai ver os três lado a lado e escolher o certo para cada caso.

Você vai aprender
  • display: none: some e os vizinhos ocupam o lugar.
  • visibility: hidden: some, mas o lugar fica reservado.
  • opacity: 0: invisível, mas ainda ocupa espaço e recebe cliques.
  • O que cada um faz com o teclado e com o leitor de tela.
  • O atributo hidden do HTML e a classe "só para leitor de tela".
  • Os erros: o hidden que não esconde, o filho que reaparece e o validador W3C.

Os resultados são desenhados pelo seu navegador. Mostrar e esconder com um clique precisa de JavaScript, que fica para o Guia JavaScript; aqui você aprende o lado do CSS, que é o que o JavaScript liga e desliga.

A ideia: tirar a cadeira ou só a pessoa

Imagine uma fileira de cadeiras num auditório, com uma pessoa em cada uma:

  • Tirar a cadeira da fileira: as outras se aproximam e fecham o buraco. É o display: none.
  • A pessoa sai, mas a cadeira fica: sobra um lugar vazio. É o visibility: hidden.
  • A pessoa veste uma capa de invisibilidade: ninguém a vê, mas ela continua sentada, e quem esbarrar nela sente. É o opacity: 0.

1. Os três lado a lado

Cada fileira tem três caixas, e a do meio está escondida de um jeito diferente:

<style>
  .caixa {
    display: inline-block;
    width: 80px;
    height: 50px;
    margin: 4px;
    background-color: #e8ecff;
    border: 2px solid navy;
    text-align: center;
  }
  .sem-display { display: none; }
  .invisivel   { visibility: hidden; }
  .transparente { opacity: 0; }
</style>
<p>display: none</p>
<div><span class="caixa">1</span><span class="caixa sem-display">2</span><span class="caixa">3</span></div>
<p>visibility: hidden</p>
<div><span class="caixa">1</span><span class="caixa invisivel">2</span><span class="caixa">3</span></div>
<p>opacity: 0</p>
<div><span class="caixa">1</span><span class="caixa transparente">2</span><span class="caixa">3</span></div>

Repare:

  • Com display: none, a caixa 3 encosta na 1: o lugar da 2 sumiu.
  • Com visibility: hidden e com opacity: 0, fica um buraco do tamanho da caixa 2 entre a 1 e a 3. Na tela, as duas fileiras parecem iguais; a diferença está no que você não vê (seção 4).

2. display: none: some de verdade

O valor none do display (aula display) diz ao navegador: "não desenhe esta caixa". O elemento continua no HTML, mas na página é como se não existisse: não ocupa espaço, não recebe clique, não recebe foco do Tab e o leitor de tela não o lê. Os filhos somem junto.

Missão: o aviso de "Promoção encerrada" não vale mais. Esconda-o com CSS, sem apagar do HTML, de um jeito que o texto de baixo suba e ocupe o lugar.

<link rel="stylesheet" href="style.css">
<h1>Lojinha da Ana</h1>
<p class="aviso">Promoção encerrada!</p>
<p>Bolos sob encomenda, com 2 dias de antecedência.</p>

.aviso {
  padding: 10px;
  background-color: gold;
}

.aviso {
  display: none;
  padding: 10px;
  background-color: gold;
}

É o jeito mais usado: um menu fechado, uma aba que não está escolhida, uma mensagem que só aparece em outra situação. Quando o JavaScript quer mostrar o elemento de novo, ele troca o none pelo display normal (block, flex…), ou tira a classe que tinha o none.

3. visibility: hidden: guarda o lugar

A propriedade visibility ("visibilidade") tem dois valores do dia a dia: visible (o padrão) e hidden ("escondido"). Escondido, o elemento não aparece, não recebe clique nem foco e o leitor de tela não o lê, mas o espaço dele continua reservado. Use quando a página não pode "pular" ao mostrar e esconder: uma resposta que vai aparecer no mesmo lugar, um aviso que não deve empurrar o resto.

Missão: esconda a resposta do enigma, mas sem que o "Próximo enigma" suba: o lugar da resposta deve continuar vazio, esperando.

<link rel="stylesheet" href="style.css">
<h2>Enigma da cozinha</h2>
<p>O que é, o que é: quanto mais quente, mais fresco?</p>
<p class="resposta">O pão!</p>
<p>Próximo enigma →</p>

.resposta {
  font-weight: bold;
  color: tomato;
}

.resposta {
  visibility: hidden;
  font-weight: bold;
  color: tomato;
}

Existe ainda o valor collapse, pensado para linhas e colunas de tabela: numa linha (<tr>), ele some com a linha sem desalinhar as colunas. Fora de tabelas, ele age como hidden.

4. opacity: 0: invisível, mas presente

A propriedade opacity ("opacidade"; aula Transparência) vai de 1 (opaco) a 0 (totalmente transparente). Com 0, o elemento fica invisível, mas continua lá para todo o resto: ocupa espaço, recebe cliques, recebe foco do Tab e o leitor de tela o lê.

Experimente: clique no espaço vazio entre "Antes" e "Depois": o botão invisível responde (o console do quadro mostra a mensagem). Troque o opacity: 0 por visibility: hidden e clique de novo: nada acontece.

<link rel="stylesheet" href="style.css">
<p>Antes</p>
<button class="fantasma" onclick="console.log('Clicou no botão invisível!')">Comprar</button>
<p>Depois</p>

.fantasma {
  opacity: 0;
  padding: 16px 32px;
}

O opacity: 0 sozinho quase nunca é o jeito certo de esconder. Ele aparece em animações: o elemento vai de 0 a 1 aos poucos, surgindo devagar (aula Transições), coisa que display e visibility não fazem sozinhos, porque mudam de uma vez.

5. O atributo hidden do HTML

O HTML também sabe esconder: o atributo hidden (aula Atributos Globais do Guia HTML). Por dentro, ele funciona com CSS: o navegador tem a regra [hidden] { display: none; } na folha de estilos dele.

<p>Este parágrafo aparece.</p>
<p hidden>Este tem hidden e não aparece.</p>
<p>Este também aparece.</p>

Use o hidden quando esconder faz parte do conteúdo ("esta parte ainda não vale"), e o CSS quando é questão de aparência ("no celular, este menu fica fechado"). E cuidado: por ser uma regra fraca do navegador, qualquer display seu passa por cima dela (veja Quando dá errado).

6. Escondido para os olhos, presente para o leitor de tela

Às vezes é o contrário: um texto deve ser lido pelo leitor de tela, mas não aparecer. Por exemplo, um botão de ícone "🛒" precisa de um nome, como "Carrinho". Nenhum dos três jeitos serve: display: none e visibility: hidden também escondem do leitor de tela, e opacity: 0 continua ocupando espaço. A solução é uma classe pronta, usada há anos em sites de todo o mundo:

.so-leitor {
  position: absolute;
  width: 1px;
  height: 1px;
  margin: -1px;
  padding: 0;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

<style>
  .so-leitor {
    position: absolute;
    width: 1px;
    height: 1px;
    margin: -1px;
    padding: 0;
    overflow: hidden;
    clip-path: inset(50%);
    white-space: nowrap;
    border: 0;
  }
</style>
<button>🛒 <span class="so-leitor">Carrinho</span></button>

Na tela, o botão mostra só o carrinho; o leitor de tela anuncia "🛒 Carrinho, botão" (o texto exato depende do leitor). A classe encolhe o texto para 1×1 pixel, tira-o do fluxo (position: absolute, aula position: absolute) e recorta o que sobrar (overflow, aula O que Transborda; clip-path, aula Recortes). Você não precisa entender cada linha agora: copie a classe inteira quando precisar. Muitos sites a chamam de sr-only ou visually-hidden.

Quando dá errado

O hidden não esconde: o elemento tem display: flex 
<style>
  .cartao {
    display: flex;
    gap: 8px;
    padding: 10px;
    background-color: gold;
  }
</style>
<div class="cartao" hidden>Cupom de 10%: BOLO10</div>
<p>O cupom acima deveria estar escondido.</p>

O que você vê: o cartão dourado aparece, mesmo com hidden.

Por quê: o hidden funciona pela regra [hidden] { display: none; } do navegador. O seu CSS sempre vence o do navegador na cascata (aula A Cascata), e o seu .cartao diz display: flex. O F12 confirma: na aba Computed, o display do cartão é flex. Nenhum validador avisa: o HTML e o CSS estão corretos, cada um sozinho.

Como consertar: diga no seu CSS o que fazer quando o cartão tiver hidden:

.cartao[hidden] {
  display: none;
}

O seletor .cartao[hidden] (uma classe e um atributo) é mais específico que .cartao e vence (aula Especificidade). Muitos sites põem uma regra geral, [hidden] { display: none; }, no começo do CSS.

O pai está escondido, mas um filho aparece 
<style>
  .rodape { visibility: hidden; }
  .destaque { visibility: visible; }
</style>
<p class="rodape">Texto do rodapé com um <strong class="destaque">destaque</strong> no meio.</p>

O que você vê: só a palavra "destaque", sozinha, no meio de um espaço vazio.

Por quê: o visibility é herdado (aula Herança): o filho fica hidden porque o pai está. Mas, se outra regra disser visible para o filho, ele volta a aparecer. Com display: none no pai isso não acontece: a caixa do pai não existe, e nada de dentro pode ser desenhado.

Como consertar: para esconder um bloco inteiro, com tudo o que tem dentro, prefira display: none.

visibility: none: o valor não existe 
.aviso {
  visibility: none;
}

O que você vê: o aviso continua aparecendo. No F12, a declaração aparece riscada no painel Styles, com um ícone de aviso.

$ vnu --css style.css
"file:/home/ana/site/style.css":2.15-2.18: error: CSS: “visibility”: “none” is not a “visibility” value.

O que significa: "none não é um valor de visibility". É a mistura mais comum: none é do display, e hidden é do visibility. O contrário, display: hidden, também não existe, e o validador diz “hidden” is not a “display” value.

Escondeu com opacity: 0, e o teclado ainda chega lá

O que acontece: um menu escondido com opacity: 0 continua recebendo o foco. Quem navega com Tab some de vista: o foco vai parar em links invisíveis, e o leitor de tela lê itens que ninguém vê. Experimente na caixa da seção 4: clique antes de "Antes" e aperte Tab; o foco vai para o botão invisível.

Como consertar: se é para esconder de verdade, use display: none ou visibility: hidden. Se precisa da animação do opacity, junte visibility: hidden no estado escondido.

Resumo

  • display: none: o elemento some e o espaço é liberado; sem clique, sem foco, sem leitor de tela. É o jeito mais usado.
  • visibility: hidden: some, mas guarda o lugar; também sem clique, foco e leitor de tela. É herdado, e um filho com visible reaparece.
  • opacity: 0: só fica invisível; continua ocupando espaço, recebendo clique e foco e sendo lido. Serve para animações.
  • O atributo hidden é um display: none do navegador: um display seu o desfaz; .cartao[hidden] { display: none; } conserta.
  • Para esconder só dos olhos, a classe .so-leitor.
  • Não troque os valores: display: none e visibility: hidden; visibility: none e display: hidden não existem.
