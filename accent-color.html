CSS accent-color e appearance

O site da Ana é laranja, mas as caixas de marcar do formulário de encomendas vêm azuis: é a cor que o navegador escolheu. Por muito tempo, trocar essa cor exigia esconder o campo e desenhar outro no lugar. Hoje existem dois caminhos. accent-color ("cor de destaque") troca a cor dos campos com uma linha, e o navegador cuida do resto. appearance: none ("aparência: nenhuma") tira o visual do navegador, para você desenhar o campo do zero. Esta aula mostra os dois, e quando usar cada um.

Você vai aprender
  • accent-color: a cor de caixas de marcar, botões de opção, controles deslizantes e barras de progresso.
  • Quais campos mudam e quais não mudam.
  • O contraste automático: o navegador escolhe a cor do "visto".
  • appearance: none: desenhar uma caixa de marcar do zero, sem perder o foco do teclado.
  • appearance: base-select, a novidade para o <select>.
  • Qual dos dois usar, e os erros reais do validador W3C.

Os campos de formulário vêm do Guia HTML (wallysondevs.github.io/guia-html). Os resultados são desenhados pelo seu navegador, e cada navegador desenha os campos do seu jeito: o que está descrito aqui foi conferido no Chromium. As mensagens de erro são do validador W3C (vnu) rodado na máquina fictícia da Ana (ana@notebook).

A ideia: o uniforme e a roupa sob medida

Um time pode comprar o uniforme pronto e só escolher a cor: a fábrica cuida do corte, das costuras e de deixar o número legível sobre a cor escolhida. Isso é o accent-color.

Ou pode mandar fazer uma roupa sob medida: fica do jeito exato que o time quer, mas cada detalhe (o tecido, o corte, o número) é responsabilidade dele. Isso é o appearance: none.

1. accent-color: uma linha, quatro campos

form {
  accent-color: tomato;
}
form
O seletor. O accent-color é herdado (aula Herança): posto no formulário, vale para todos os campos dentro dele. No Chromium, os input do formulário ficaram com accent-color: rgb(255, 99, 71) no estilo calculado, sem nenhuma regra própria.
accent-color
"Cor de destaque": a cor que o navegador usa nas partes coloridas dos campos (o quadradinho marcado, a bolinha escolhida, a parte cheia da barra).
tomato
Qualquer cor do CSS (nome, #hex, rgb(), hsl()…). O padrão é auto: a cor que o navegador ou o sistema escolher.

Lado a lado, o mesmo formulário com a cor padrão e com accent-color: tomato:

<style>
  .laranja {
    accent-color: tomato;
  }
  form {
    margin-bottom: 12px;
  }
</style>
<form>
  <p><strong>Padrão do navegador</strong></p>
  <label><input type="checkbox" checked> Com cobertura</label>
  <label><input type="radio" name="t1" checked> Pequeno</label>
  <input type="range" value="70" aria-label="Doçura">
  <progress value="60" max="100">60%</progress>
  <input type="text" value="Texto não muda" aria-label="Nome">
</form>
<form class="laranja">
  <p><strong>accent-color: tomato</strong></p>
  <label><input type="checkbox" checked> Com cobertura</label>
  <label><input type="radio" name="t2" checked> Pequeno</label>
  <input type="range" value="70" aria-label="Doçura">
  <progress value="60" max="100">60%</progress>
  <input type="text" value="Texto não muda" aria-label="Nome">

No Chromium, a primeira linha sai azul e a segunda, cor de tomate: a caixa marcada, a bolinha do botão de opção, a parte da esquerda do controle deslizante e a parte cheia da barra de progresso. A parte vazia do trilho e da barra também mudou, de cinza-claro para cinza-escuro: é o navegador ajustando o contraste com a cor nova. O campo de texto não muda nada. Os campos que o accent-color pinta (lista do MDN):

CampoO que muda de cor
<input type="checkbox"> (caixa de marcar)O fundo da caixa marcada
<input type="radio"> (botão de opção)O círculo escolhido
<input type="range"> (controle deslizante)A bolinha e a parte "cheia" do trilho
<progress> (barra de progresso)A parte cheia

Campos de texto, botões, <select> e datas não mudam: o estilo deles é feito com as propriedades de sempre (border, background-color, color…), na aula Estilizando Formulários.

O contraste automático

Repare no "visto" (✓) dentro da caixa marcada. Com a cor padrão, azul-escura, o visto é branco. Com uma cor clara, o navegador troca o visto para escuro, para ele continuar visível:

<style>
  p { font-family: sans-serif; }
  .navy { accent-color: navy; }
  .tomato { accent-color: tomato; }
  .gold { accent-color: gold; }
</style>
<p class="navy"><input type="checkbox" checked aria-label="navy"> <input type="radio" checked aria-label="navy"> navy</p>
<p class="tomato"><input type="checkbox" checked aria-label="tomato"> <input type="radio" checked aria-label="tomato"> tomato</p>
<p class="gold"><input type="checkbox" checked aria-label="gold"> <input type="radio" checked aria-label="gold"> gold</p>

No Chromium (foto ampliada): com navy, o visto e o anel interno do botão de opção são brancos; com tomato e gold, ficam cinza-escuros. Você escolhe só uma cor, e o navegador cuida da legibilidade. É a "fábrica do uniforme" da comparação.

Suporte

O accent-color funciona desde 2021–2022 no Chrome (93), Edge, Firefox (92) e Safari (15.4). Pela tabela do MDN, o Safari só passou a garantir o contraste automático do visto na versão 26.2, e o Chrome para Android ainda não garante: nesses, o visto pode ficar pouco visível sobre uma cor clara. Por isso, prefira cores de destaque com contraste bom contra o branco, como tomato escuro, navy, seagreen. Num navegador sem suporte, os campos só ficam com a cor padrão.

Missão: o formulário de encomendas da Ana é verde. Com uma regra no form, deixe as caixas, os botões de opção e a barra de progresso na cor seagreen.

Para o site inteiro

Como o accent-color é herdado, uma regra no :root (o html) pinta todos os campos do site: :root { accent-color: tomato; }. Junto com uma variável (--cor-principal, aula Variáveis), a cor do site e a dos campos ficam num lugar só.

2. appearance: none: desenhar do zero

Às vezes a Ana quer mais que uma cor: uma caixa de marcar quadrada com borda grossa, ou um <select> sem a setinha do sistema. Aí entra o appearance:

.lembrar {
  appearance: none;
}
appearance
"Aparência": se o campo usa o visual do sistema (auto, o padrão) ou não.
none
"Nenhuma": o navegador para de desenhar o visual do campo. O campo continua funcionando (marca, desmarca, recebe foco, é enviado no formulário), mas a aparência fica toda com você.

Cuidado: "toda com você" quer dizer toda. No Chromium, uma caixa de marcar com appearance: none e nada mais ficou com 0 × 0 px no estilo calculado: ela some da tela. Por isso, logo depois do none, vem o desenho novo:

.lembrar {
  appearance: none;
  width: 1.25rem;
  height: 1.25rem;
  border: 2px solid navy;
  border-radius: 4px;
  vertical-align: middle;
}

.lembrar:checked {
  background-color: navy;
  box-shadow: inset 0 0 0 3px white;
}
width / height
O tamanho da caixa nova: 1.25rem = 20 px com a fonte padrão.
border, border-radius
A borda azul-marinho com cantos levemente arredondados (aulas Bordas e Cantos Arredondados).
vertical-align: middle
Alinha a caixa com o meio do texto ao lado.
.lembrar:checked
A pseudo-classe :checked ("marcado") vale quando a caixa está marcada. É assim que a caixa desenhada por você mostra os dois estados.
box-shadow: inset 0 0 0 3px white
Uma "sombra" interna branca de 3 px, sem desfoque (aula Sombra): cria um anel branco entre a borda e o miolo azul.

Experimente: clique nas duas caixas para marcar e desmarcar. Depois, clique numa delas e aperte Tab: o contorno do foco continua aparecendo. Apague as regras de width e height e veja a caixa sumir.

<link rel="stylesheet" href="style.css">
<p><label><input class="lembrar" type="checkbox" checked> Lembrar meu endereço</label></p>
<p><label><input class="lembrar" type="checkbox"> Receber novidades</label></p>

.lembrar {
  appearance: none;
  width: 1.25rem;
  height: 1.25rem;
  border: 2px solid navy;
  border-radius: 4px;
  vertical-align: middle;
}

.lembrar:checked {
  background-color: navy;
  box-shadow: inset 0 0 0 3px white;
}

No Chromium, a caixa marcada é um quadrado com borda azul-marinho e miolo azul-marinho, separados por um anel branco; a desmarcada é só o quadrado com a borda. Com o foco (forçado na foto, como o Tab faria), aparece o contorno do navegador em volta da caixa: o appearance: none não apaga o foco. Mantenha assim: quem usa o teclado precisa ver onde está (aula CSS e Acessibilidade).

O <select>: appearance: none e base-select

No <select>, appearance: none tira a setinha do sistema; no Chromium, a caixa ficou só com o texto e uma borda fina, sem a seta. A seta, se você quiser, vem de uma imagem de fundo (aula Imagem de Fundo).

Há um valor mais novo, appearance: base-select, que deixa o <select> e a lista que se abre totalmente estilizáveis com CSS:

select,
::picker(select) {
  appearance: base-select;
}

No Chromium, o <select> com base-select ganhou um visual simples, com borda arredondada e uma seta preta, pronto para receber o seu CSS.

Recurso novo

appearance: base-select chegou no Chrome 135 (2025); pela tabela do MDN, o Firefox 149 e o Safari 27 também o têm. É recente: quem ainda não atualizou o navegador vê o <select> comum, que continua funcionando. O validador W3C (vnu 26.10.12) ainda não conhece o valor nem o ::picker(select), e reclama (veja Quando dá errado).

3. Qual usar

Você querUsePor quê
Só trocar a cor das caixas, opções, deslizantes e barrasaccent-colorUma linha; o navegador cuida do tamanho, do contraste, do tema escuro e do toque no celular.
Outro formato (borda grossa, cantos, ícone próprio)appearance: none + o seu CSSControle total, mas você desenha os dois estados (:checked), o tamanho e mantém o foco visível.
Um <select> sob medida, com a lista aberta estilizadaappearance: base-selectRecente; quem não tem fica com o <select> normal.
Campos de texto e botõesNenhum dos dois: border, background-color, padding…O accent-color não os afeta; eles já aceitam CSS comum.

Em CSS antigo você vai ver -webkit-appearance: none: é o mesmo appearance, da época dos prefixos (aula @supports e Compatibilidade). O appearance sem prefixo funciona em todos os navegadores principais desde março de 2022 (MDN).

Quando dá errado

accent-color num campo de texto: nada muda 
input[type="text"] {
  accent-color: tomato;
}

O que o leitor vê: o campo continua igual. O primeiro exemplo da aula mostra isso: o campo "Texto não muda" está dentro do formulário com accent-color: tomato.

Por quê: a declaração é válida e o campo até recebe o valor (o estilo calculado mostra a cor), mas um campo de texto não tem nenhuma parte "de destaque" para pintar. Para a borda de um campo de texto, use border-color; para a cor da barrinha que pisca, caret-color.

appearance: none sozinho: a caixa de marcar sumiu 
<style>
  .sumiu { appearance: none; }
</style>
<p><label><input class="sumiu" type="checkbox"> Aceito os termos</label></p>

O que o leitor vê: só o texto "Aceito os termos", sem caixa. No Chromium, o estilo calculado da caixa ficou com width: 0px e height: 0px.

Por quê: o none tirou o desenho do navegador, e nada foi posto no lugar. O campo continua lá: clicar no texto do <label> ainda marca e desmarca, mas ninguém vê. O validador não reclama.

Como consertar: depois do appearance: none, dê tamanho, borda e um estado :checked, como na seção 2. Ou, se você só queria mudar a cor, troque tudo por accent-color.

Valor inventado: is not a “accent-color” value 
form {
  accent-color: tomate;
}
.caixa {
  appearance: nenhum;
}

$ vnu --css estilo.css
"file:/home/ana/site/estilo.css":2.17-2.22: error: CSS: “accent-color”: “tomate” is not a “accent-color” value.
"file:/home/ana/site/estilo.css":5.15-5.20: error: CSS: “appearance”: “nenhum” is not a “appearance” value.

O que significa: "tomate não é um valor de accent-color" (a cor é tomato, em inglês) e "nenhum não é um valor de appearance" (é none). O navegador ignora as duas declarações: os campos ficam com a cor e a aparência padrão, e no F12 as duas linhas aparecem riscadas.

O validador ainda não conhece base-select

Com o CSS da seção 2 (select, ::picker(select) { appearance: base-select; }):

$ vnu --css estilo.css
"file:/home/ana/site/estilo.css":2.16-2.16: error: CSS: Parse Error.
"file:/home/ana/site/estilo.css":3.15-3.25: error: CSS: “appearance”: “base-select” is not a “appearance” value.

O que significa: o validador não entende o seletor ::picker(select) ("erro de leitura" na linha 2) e acha que "base-select não é um valor de appearance" (linha 3). Mas os dois existem e funcionam nos navegadores que já o têm (no Chromium, o estilo calculado ficou appearance: base-select). Validadores demoram um pouco para aprender recursos novos: aqui, a mensagem pode ser ignorada.

Missão final: a caixa sob medida

Missão: desenhe a caixa "Aceito os termos" do zero. Na .termos: tire o visual do sistema (appearance: none), dê tamanho (width e height de 1.25rem) e uma borda 2px solid tomato. Em .termos:checked, pinte o fundo de tomato. A caixa já começa marcada.

Resumo

  • accent-color pinta, com uma linha, as caixas de marcar, os botões de opção, os controles deslizantes e as barras de progresso. É herdado: ponha no form ou no :root.
  • O navegador escolhe a cor do visto para ter contraste (no Safari, só a partir da 26.2). Campos de texto e botões não mudam.
  • appearance: none tira o visual do sistema. O campo continua funcionando, mas some se você não desenhar tamanho, borda e o estado :checked. O foco continua visível: não o apague.
  • appearance: base-select deixa o <select> todo estilizável; é recente e o validador ainda não conhece.
  • Só a cor? accent-color. Outro formato? appearance: none.
