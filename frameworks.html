CSS Frameworks

Mais cedo ou mais tarde você vai ouvir: "por que escrever CSS na mão? Usa Bootstrap!" ou "hoje todo mundo usa Tailwind". Os dois são frameworks de CSS: um monte de CSS já escrito por outras pessoas, pronto para usar com classes no HTML. Esta aula é uma visão geral: o que cada um é, um exemplo pequeno, como eles funcionam por dentro, os prós e os contras, e quando faz sentido usar. Spoiler: tudo o que você aprendeu neste guia continua valendo, porque os frameworks são CSS.

Você vai aprender
  • O que é um framework de CSS, e os dois estilos principais: componentes (Bootstrap) e utilitários (Tailwind).
  • Um exemplo pequeno de cada um, com as versões atuais.
  • Como eles funcionam por dentro, com uma imitação feita à mão no editor.
  • Os prós, os contras e quando usar cada um (ou nenhum).
  • Os erros comuns: classe digitada errado e o seu CSS perdendo para o do framework.
Versões conferidas nos sites oficiais em outubro de 2026

Bootstrap: a versão estável é a 5.3.8 (getbootstrap.com); a 6 está em fase de testes (6.0.0-alpha.1). Tailwind CSS: versão 4.3 (tailwindcss.com). Frameworks mudam rápido: antes de começar um projeto, confira a versão no site de cada um.

A ideia: cozinhar do zero ou usar massa pronta

A Ana pode fazer a massa do bolo do zero ou comprar uma mistura pronta. A mistura é rápida e quase sempre dá certo, mas todo bolo de mistura tem um gostinho parecido, e se ela quiser mudar a receita precisa entender o que tem dentro do pacote. Fazer do zero dá mais trabalho e deixa o bolo do jeito dela.

Um framework de CSS é a mistura pronta: botões, cartões, grades e espaçamentos já feitos. Você ganha velocidade e perde um pouco de personalidade (e de controle). E, como na cozinha, quem sabe fazer do zero usa a mistura muito melhor.

1. Bootstrap: componentes prontos

O Bootstrap nasceu em 2011 e é um dos frameworks mais usados da web. A forma mais simples de experimentar é ligar o CSS dele por um CDN (um servidor público que entrega arquivos de bibliotecas). Este é o trecho oficial da documentação da versão 5.3.8:

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet" integrity="sha384-sRIl4kxILFvY47J16cr9ZwB07vP4J8+LH7qKQnuqkuIAvNWLzeN8tE5YBujZqJLB" crossorigin="anonymous">

<div class="card">
  <div class="card-body">
    <h2 class="card-title">Bolo de cenoura</h2>
    <p class="card-text">Com cobertura de chocolate.</p>
    <a href="bolo.html" class="btn btn-primary">Ver receita</a>
  </div>
</div>
<link href="…/bootstrap.min.css">
O CSS inteiro do Bootstrap, minificado (aula CSS Rápido). O integrity é uma "impressão digital" do arquivo: se alguém adulterar o arquivo no servidor, o navegador recusa.
class="card"
Um componente: a caixa com borda fina, cantos arredondados e fundo branco. O card-body dá o espaço interno; card-title e card-text, as margens do título e do texto.
class="btn btn-primary"
Duas classes juntas: btn é a forma de botão (preenchimento, cantos, fonte); btn-primary é a variação de cor (o azul principal). Trocar para btn-danger deixa o botão vermelho.

Repare que as classes dizem o que a coisa é (card, btn), como você aprendeu na aula Estilo de Código. Os componentes interativos (menu que abre, janela modal) precisam também do JavaScript do Bootstrap, que vem em outro arquivo.

Por dentro: um "mini-Bootstrap" feito à mão

Não há mágica: o arquivo do Bootstrap é um CSS como o seu, só que enorme. Na caixa abaixo, o arquivo mini-bootstrap.css é uma imitação com três componentes no mesmo estilo (os valores são parecidos com os do Bootstrap, mas não idênticos). Nada vem da internet: é tudo CSS desta aula.

Experimente: troque btn-primary por btn-perigo no segundo botão. Depois abra a aba mini-bootstrap.css e invente uma variação nova, .btn-sucesso, verde, no mesmo modelo das outras.

<link rel="stylesheet" href="mini-bootstrap.css">
<div class="card">
  <h2>Bolo de cenoura</h2>
  <p>Com cobertura de chocolate.</p>
  <a href="bolo.html" class="btn btn-primary">Ver receita</a>
  <a href="carrinho.html" class="btn btn-primary">Comprar</a>
</div>

  border-radius: 6px;
  font-family: sans-serif;
}

2. Tailwind CSS: uma classe para cada declaração

O Tailwind segue a ideia contrária: em vez de componentes prontos, ele dá classes utilitárias, cada uma com uma declaração só. Você monta o visual juntando classes no HTML:

<a href="bolo.html" class="inline-block bg-blue-600 text-white px-4 py-2 rounded-lg font-bold hover:bg-blue-700">
  Ver receita
</a>
ClasseA declaração que ela gera (Tailwind 4)
inline-blockdisplay: inline-block;
bg-blue-600background-color com o azul de tom 600 da paleta (as cores do Tailwind 4 são definidas em oklch(), aula Cores Modernas)
text-whitecolor branco
px-4 · py-2padding-inline: calc(var(--spacing) * 4); · padding-block: calc(var(--spacing) * 2); Com o --spacing padrão de 0.25rem, dá 1rem dos lados e 0.5rem em cima e embaixo (aula Propriedades Lógicas)
rounded-lgborder-radius: var(--radius-lg);, que vale 0.5rem (8px)
font-boldfont-weight: 700;
hover:bg-blue-700O prefixo hover: põe a declaração dentro de um :hover: o fundo escurece com o mouse em cima
md:flexO prefixo md: põe a declaração dentro de uma media query para telas médias ou maiores

Como se instala: o Tailwind gera o CSS

O Tailwind 4 não é um arquivo pronto. É um programa que lê o seu HTML, vê quais classes você usou e gera um CSS só com elas. O caminho oficial com a ferramenta de linha de comando (precisa do Node.js instalado):

@import "tailwindcss";

$ npm install tailwindcss @tailwindcss/cli
$ npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch

O --watch ("vigiar") deixa o programa rodando: cada vez que você salva o HTML, ele gera o output.css de novo, e é esse arquivo que a página liga com <link>. Os comandos são os da documentação oficial; não foram rodados no laboratório deste guia.

E o CDN do Tailwind?

Existe um atalho, o Play CDN: um <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script> que gera o CSS dentro do navegador. A própria documentação avisa: ele é feito "só para desenvolvimento" e não para o site publicado. O Tailwind 4 também pede navegadores recentes: Chrome 111, Safari 16.4 e Firefox 128 ou mais novos, segundo a página de compatibilidade dele.

Por dentro: um "mini-Tailwind" feito à mão

De novo, uma imitação: o arquivo mini-tailwind.css abaixo tem algumas classes com os mesmos nomes do Tailwind, escritas à mão (as cores são hexadecimais simples, não as do Tailwind de verdade). Repare como cada regra tem uma declaração só.

Missão: transforme o link num botão sem escrever CSS: só acrescentando classes do mini-tailwind.css no class do link. Ele precisa de fundo bg-blue-700, letra text-white, px-6, py-3, rounded-lg e font-bold. O inline-block já está lá.

<link rel="stylesheet" href="mini-tailwind.css">
<p>
  <a href="carrinho.html" class="inline-block">Comprar o bolo</a>
</p>

/* Imitação, feita à mão, de algumas classes do Tailwind */
.inline-block { display: inline-block; }
.bg-blue-700 { background-color: #1d4ed8; }
.bg-red-600 { background-color: #dc2626; }
.text-white { color: #ffffff; }
.px-6 { padding-inline: 1.5rem; }
.py-3 { padding-block: 0.75rem; }
.rounded-lg { border-radius: 0.5rem; }
.rounded-full { border-radius: 9999px; }
.font-bold { font-weight: 700; }
.no-underline { text-decoration-line: none; }

<link rel="stylesheet" href="mini-tailwind.css">
<p>
  <a href="carrinho.html" class="inline-block bg-blue-700 text-white px-6 py-3 rounded-lg font-bold">Comprar o bolo</a>
</p>

Depois de cumprir a missão, acrescente no-underline para tirar o sublinhado, e troque rounded-lg por rounded-full para um botão em forma de pílula. Viu o jeito Tailwind? O visual inteiro mora no HTML.

As regras de uma linha

O mini-tailwind.css usa regras de uma linha só, a exceção aceitável da aula Estilo de Código: cada regra tem uma declaração, e assim a lista fica fácil de ler.

Quando dá errado

Classe digitada errado: nada acontece, e ninguém avisa 
<style>
.btn-primary {
  padding: 6px 12px;
  background-color: #0d6efd;
  color: white;
}
</style>
<a href="bolo.html" class="btn-primry">Ver receita</a>

O que o leitor vê: um link comum, sem fundo azul. Por quê: btn-primry (faltou o "a") não casa com nenhuma regra. Para o HTML, qualquer nome de classe é válido, e o validador W3C não tem como saber quais classes existem no framework. Com frameworks, isso é o erro mais comum de todos, porque as classes são muitas e parecidas. Como achar: no F12, o elemento não mostra nenhuma regra do framework no painel de estilos. Os editores de código têm extensões que completam e conferem as classes do Tailwind e do Bootstrap.

O seu CSS perde para o do framework

A Ana quer o botão do Bootstrap na cor da lojinha e escreve, no style.css dela, .btn-primary { background-color: #c0392b; }. O botão continua azul. O motivo mais comum: o <link> do framework vem depois do dela. Os dois seletores têm a mesma especificidade, e no empate vence o que vem por último (aula A Cascata). Também acontece de o framework usar um seletor mais específico que o seu (aula Especificidade), e aí o F12 mostra a sua declaração riscada.

Como consertar: o <link> do framework primeiro e o seu depois; se ainda perder, um seletor tão específico quanto o dele. No Bootstrap 5.3, muitas cores também podem ser trocadas pelas variáveis CSS dele, que começam com --bs-. Evite o !important: ele resolve hoje e cria uma briga amanhã (aula !important).

Tailwind: a classe montada aos pedaços não aparece

No JavaScript, a Ana escreveu "bg-" + cor + "-600" para escolher a cor do botão. O botão ficou sem fundo. Por quê: o Tailwind lê os arquivos do projeto como texto, procurando nomes de classe inteiros. bg-red-600 não aparece escrito em lugar nenhum, então a regra dele não é gerada. A documentação oficial do Tailwind explica isso na parte sobre dynamic class names (nomes de classe dinâmicos). Como consertar: escreva os nomes inteiros no código (por exemplo, um objeto { vermelho: "bg-red-600", azul: "bg-blue-600" }).

CDN fora do ar ou sem internet

Com o framework ligado por CDN, um site aberto sem internet (ou com o CDN bloqueado pela rede da empresa) aparece "pelado", sem nenhum estilo. Para um site publicado, muitos projetos preferem copiar o arquivo do framework para a própria pasta (css/bootstrap.min.css). É também por isso que as caixas desta aula usam imitações locais.

Resumo

  • Um framework de CSS é CSS pronto, usado por classes no HTML. Os dois estilos: componentes (Bootstrap 5.3.8: card, btn btn-primary) e utilitários (Tailwind 4.3: px-4, rounded-lg, hover:bg-blue-700).
  • O Bootstrap entra com um <link> (e um script para os componentes interativos). O Tailwind 4 é um programa que lê o seu HTML e gera o CSS (@import "tailwindcss"; e a CLI); o Play CDN é só para testes.
  • Por dentro, é tudo CSS comum: você mesmo fez um mini-Bootstrap e um mini-Tailwind nesta aula.
  • Bootstrap: rápido, mas com cara padrão e muito CSS sobrando. Tailwind: visual livre e CSS enxuto, mas HTML cheio de classes e uma etapa de geração. CSS seu: controle total.
  • Erros comuns: classe digitada errado (ninguém avisa), o seu CSS ligado antes do framework (perde o empate) e, no Tailwind, nomes de classe montados aos pedaços.
