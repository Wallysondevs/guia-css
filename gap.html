CSS gap

Os cartões da lojinha da Ana estão lado a lado com Flexbox, mas grudados uns nos outros. O primeiro impulso é dar uma margin (margem) a cada cartão. Funciona… mais ou menos: aparece espaço também nas pontas, onde a Ana não queria. A propriedade gap (em inglês, "vão", "intervalo") resolve isso com uma linha só no pai: ela põe espaço entre os itens, e só entre eles.

Você vai aprender
  • Por que margin nos itens deixa espaço sobrando nas bordas da caixa.
  • Como escrever gap, parte por parte, e onde ele vai (no pai).
  • row-gap e column-gap: um espaço entre as linhas, outro entre as colunas, e o atalho com dois valores.
  • Onde o gap funciona (Flexbox, Grid) e onde ele não faz nada.
  • Outros jeitos de espaçar (margin, justify-content) e quando usar cada um.
  • Os erros mais comuns e as mensagens reais do validador W3C.

Antes, é bom ter visto Introdução ao Flexbox, Margem (margin) e Quebrando Linha (flex-wrap). Os exemplos com resultado são desenhados agora pelo seu navegador. As mensagens do validador saíram do validador W3C (vnu), na máquina fictícia da Ana (usuária ana, computador notebook).

A ideia: o rejunte do piso

Num piso de cerâmica, entre um azulejo e outro existe o rejunte: aquela faixa fininha, sempre da mesma largura. Repare que o rejunte fica só entre os azulejos: ninguém põe rejunte entre o último azulejo e a parede. E quem decide a largura do rejunte é o pedreiro, para o piso todo, e não cada azulejo.

O gap é esse rejunte. Ele é escrito uma vez, no pai, e o navegador põe o mesmo espaço entre cada par de itens vizinhos. A margin, ao contrário, é um espaço que cada item leva em volta de si, para todos os lados, inclusive para o lado da parede.

1. O problema da margin

Três cartões, cada um com margin: 8px (8 pixels de margem dos quatro lados):

<link rel="stylesheet" href="style.css">
<div class="vitrine">
  <div class="produto">Bolo</div>
  <div class="produto">Brigadeiro</div>
  <div class="produto">Sonho</div>
</div>

.vitrine {
  display: flex;
  width: 320px;
  border: 2px dashed gray;
}

.produto {
  margin: 8px;
  padding: 8px;
  background-color: tomato;
  color: white;
  font-family: sans-serif;
}

Olhe os espaços com atenção:

  • Entre dois cartões, o espaço é de 16 pixels: os 8 da direita do Bolo mais os 8 da esquerda do Brigadeiro. (No Flexbox, as margens vizinhas se somam; elas não se "fundem" como as margens de cima e de baixo de dois parágrafos.)
  • Entre o Bolo e a borda tracejada, o espaço é de 8 pixels, e também em cima e embaixo.

Ou seja: os espaços não são iguais, e as pontas ganharam um espaço que ninguém pediu. Dá para consertar com contas e regras extras (seção 5), mas existe um jeito direto.

2. A solução: gap no pai

Tire a margin dos cartões e escreva uma linha na .vitrine:

.vitrine {
  display: flex;
  gap: 16px;
}
.vitrine
O seletor: o pai (o elemento com display: flex). Como o rejunte, o gap é decidido por quem arruma os itens, e não por cada item.
gap
A propriedade: o "vão" entre os itens vizinhos.
16px
O tamanho do vão. Aceita as unidades de tamanho de sempre: px, rem, em, % (aula Unidades). 1rem é uma boa escolha: acompanha o tamanho da letra que o leitor escolheu no navegador.
;
Fecha a declaração.
<link rel="stylesheet" href="style.css">
<div class="vitrine">
  <div class="produto">Bolo</div>
  <div class="produto">Brigadeiro</div>
  <div class="produto">Sonho</div>
</div>

.vitrine {
  display: flex;
  gap: 16px;
  width: 320px;
  border: 2px dashed gray;
}

.produto {
  padding: 8px;
  background-color: tomato;
  color: white;
  font-family: sans-serif;
}

Agora o espaço entre os cartões é de 16 pixels, igual nos dois vãos, e o Bolo encosta na borda tracejada: nas pontas, nada. Se você quiser um respiro entre os cartões e a borda, isso é tarefa do padding do pai (aula Espaço Interno): um cuida da parede, o outro do rejunte.

3. Um espaço para as linhas, outro para as colunas

Quando os itens quebram em várias linhas (flex-wrap: wrap), existem dois tipos de vão: o que fica entre as linhas (em cima e embaixo) e o que fica entre as colunas (dos lados). O gap com um valor só usa o mesmo tamanho para os dois. Para tamanhos diferentes, existem três escritas:

EscritaO que faz
gap: 16px;16 pixels entre as linhas e entre as colunas
gap: 20px 8px;Dois valores: o primeiro é entre as linhas (row-gap), o segundo, entre as colunas (column-gap)
row-gap: 20px;Só o vão entre as linhas (row = "linha")
column-gap: 8px;Só o vão entre as colunas (column = "coluna")

Abaixo, a mesma vitrine duas vezes: com gap: 1rem (16 pixels nos dois sentidos) e com gap: 20px 8px:

  <div class="produto">Sonho</div>
  <div class="produto">Cookies</div>
  <div class="produto">Pão</div>
</div>

<p>gap: 20px 8px</p>

Na primeira, o espaço entre os cartões é o mesmo para os lados e para baixo. Na segunda, as linhas ficaram mais afastadas (20 pixels) e os cartões da mesma linha, mais perto (8 pixels). Para lembrar a ordem: é a mesma do margin: 20px 8px, primeiro o "em cima e embaixo", depois o "dos lados".

O que o F12 mostra

gap é um atalho para row-gap + column-gap. Na aba Computed do F12 (e no getComputedStyle do JavaScript), aparecem as duas propriedades longas, já em pixels: com gap: 1rem, row-gap e column-gap valem 16px (com a letra padrão de 16 pixels). Sem nenhum gap, as duas valem normal, que no Flexbox quer dizer zero.

4. Onde o gap funciona

O gap só tem efeito em elementos que arrumam os filhos num layout próprio:

  • display: flex (e inline-flex): o vão entre os itens flex;
  • display: grid (e inline-grid): o vão entre as linhas e colunas da grade (aula Introdução ao Grid);
  • textos em várias colunas (columns): o column-gap é o espaço entre as colunas de texto.

Num elemento comum (display: block), o gap é aceito, mas não faz nada (veja Quando dá errado).

Suporte nos navegadores

O gap no Grid existe há muito tempo. No Flexbox, ele chegou mais tarde: Chrome e Edge 84, Firefox 63, Safari 14.1 (iPhone/iPad: 14.5), todos de 2021 para trás. Segundo o caniuse.com, mais de 97% dos navegadores em uso já entendem. Em tutoriais antigos, você vai ver o Flexbox espaçado com margin justamente porque, na época, o gap não funcionava nele. E vai ver grid-gap, o nome antigo do gap no Grid: ainda funciona, mas use gap.

5. Formas de fazer a mesma coisa

Espaço entre itens tem vários caminhos. Veja os mais comuns, do mais antigo ao mais direto:

/* 1. margin em todos os itens: espaço dobrado no meio e sobra nas pontas */
.produto {
  margin: 8px;
}

/* 2. margin só a partir do segundo item (o "+" é o irmão de antes) */
.produto + .produto {
  margin-left: 16px;
}

/* 3. o espaço que sobra, distribuído entre os itens */
.vitrine {
  display: flex;
  justify-content: space-between;
}

/* 4. gap: o mesmo vão entre todos, nada nas pontas */
.vitrine {
  display: flex;
  gap: 16px;
}

O jeito 2 usa o combinador de irmão (aula Descendente, Filho e Irmãos): "todo .produto que vem logo depois de outro .produto". Funciona numa linha só, mas, quando os itens quebram de linha, o primeiro item da linha de baixo também ganha a margem e fica desalinhado. O jeito 3 não é um espaço fixo: o justify-content: space-between (aula justify-content) empurra o primeiro item para uma ponta, o último para a outra, e o vão é o que sobrar. Com poucos itens numa caixa larga, o vão fica enorme.

FormaEspaço nas pontas?Quando usar
gap no paiNãoQuase sempre, em Flexbox e Grid: um vão fixo e igual entre todos
justify-content: space-betweenNãoQuando os itens devem ir até as pontas e o vão pode variar (logo à esquerda, menu à direita). Dá para juntar com gap, que vira o vão mínimo
margin num itemDependePara afastar um item específico (o botão "Sair" mais longe dos outros), e não para espaçar todos
.item + .item { margin-left }NãoO jeito antigo, de antes do gap no Flexbox: reconheça, mas prefira o gap

Quando dá errado

CSS quase nunca mostra mensagem: o navegador ignora em silêncio o que não entende. Estes são os tropeços mais comuns com gap.

O gap não faz nada: o pai não é flex nem grid

O que aconteceu: a Ana escreveu gap: 16px numa div comum, esperando separar os parágrafos de dentro:

.receita {
  gap: 16px;
}

O que você vê: nada muda. O curioso: o validador não reclama, e o F12 mostra o gap: 16px normalmente no painel Styles (Estilos), sem riscar; na aba Computed, o row-gap aparece como 16px. A declaração é válida, só não tem efeito, porque num bloco comum não existem "itens" para separar.

Como consertar: ponha display: flex (com flex-direction: column, para continuar um embaixo do outro) ou display: grid no mesmo elemento. Ou, se a ideia era só afastar os parágrafos, use margin neles.

Espaço maior do que o esperado: gap + margin

O que aconteceu: a Ana pôs gap: 16px na vitrine, mas esqueceu a antiga margin: 8px nos cartões.

O que você vê: os dois se somam: entre os cartões ficam 8 + 16 + 8 = 32 pixels, e as pontas continuam com 8. Parece que o gap "não obedece".

Como consertar: escolha um. Ao adotar o gap, apague a margin que espaçava os itens. No F12, clique num cartão: o desenho da caixa (o box model, na aba Computed) mostra a margem que sobrou.

error: CSS: “gap”: Too many values or values are not recognized.

O que aconteceu: três valores, como se fosse uma margin: gap: 10px 20px 30px;.

$ vnu --css gap3.css
"file:/home/ana/flex/gap3.css":3.18-3.21: error: CSS: “gap”: Too many values or values are not recognized.

"Valores demais, ou valores não reconhecidos." O gap aceita um ou dois valores (linhas e colunas). O navegador ignora a declaração inteira: o vão volta a zero.

Como consertar: no máximo dois valores: gap: 10px 20px;.

error: CSS: “gap”: “,” is an incorrect operator.

O que aconteceu: os dois valores separados por vírgula: gap: 10px, 20px;.

$ vnu --css gapvirg.css
"file:/home/ana/flex/gapvirg.css":3.14-3.17: error: CSS: “gap”: “,” is an incorrect operator.

"A vírgula é um operador incorreto (aqui)." Em CSS, os valores de um atalho são separados por espaço. A declaração é ignorada.

Como consertar: gap: 10px 20px;, sem vírgula.

error: CSS: “gap”: “-10px” negative values are not allowed.

O que aconteceu: a Ana quis "juntar mais" os itens com um vão negativo: gap: -10px;.

$ vnu --css gapneg.css
"file:/home/ana/flex/gapneg.css":3.9-3.12: error: CSS: “gap”: “-10px” negative values are not allowed.

"Valores negativos não são permitidos." O menor vão possível é zero; a declaração é ignorada.

Como consertar: para encostar os itens, gap: 0 (ou apague o gap). Para sobrepor de propósito, o caminho é outro: margin negativa num item.

error: CSS: “gap”: Missing a semicolon before the property name “padding”.

O que aconteceu: faltou o ; depois do gap:

.fila {
  display: flex;
  gap: 1rem
  padding: 8px;
}
$ vnu --css gapsemponto.css
"file:/home/ana/flex/gapsemponto.css":4.3-4.9: error: CSS: “gap”: Missing a semicolon before the property name “padding”.

"Falta um ponto e vírgula antes da propriedade padding." Sem o ;, o navegador lê gap: 1rem padding: 8px como uma coisa só, que não faz sentido, e joga fora as duas declarações: some o vão e some o padding.

Como consertar: ; no fim de toda declaração, até na última.

Resumo

  • gap, escrito no pai flex ou grid, põe o mesmo espaço entre cada par de itens vizinhos, e nada nas pontas.
  • margin nos itens soma espaço no meio (8 + 8) e deixa sobra nas pontas; serve para afastar um item específico, não para espaçar todos.
  • gap: 20px 8px: primeiro entre as linhas (row-gap), depois entre as colunas (column-gap).
  • Espaço entre os itens e a borda é padding do pai.
  • Num bloco comum, o gap é aceito, mas não faz nada. Três valores, vírgula ou valor negativo: o validador reclama e o navegador ignora.
