CSS Media Queries

Uma media query ("consulta à mídia") é uma pergunta que o CSS faz ao navegador: "a tela tem pelo menos 700 pixels de largura?". Se a resposta for sim, as regras de dentro valem; se for não, são ignoradas. É assim que a mesma página mostra uma coluna no celular e três no computador, um menu em lista no celular e em linha no computador. Com a meta viewport no HTML e as larguras fluidas, as media queries completam o design responsivo.

Você vai aprender
  • A anatomia de @media (min-width: 700px) { … }.
  • min-width ("a partir de") e max-width ("até"), e a escrita nova com >= e <=.
  • Juntar perguntas com and, vírgula e not.
  • Os tipos de mídia (screen, print) e outras perguntas: orientação, mouse ou dedo, tema escuro.
  • Onde escrever e por que a ordem importa.
  • Os erros reais: parênteses, espaço depois do and, unidade, chave que falta, nome errado.

Os resultados são desenhados pelo seu navegador. Os quadros desta aula começam numa largura fixa: use os botões 375, 768 e cheia da barra do quadro para ver as media queries ligando e desligando. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: "se chover, leve o guarda-chuva"

Antes de sair, você confere o tempo: se estiver chovendo, leva o guarda-chuva; se não, sai sem ele. A roupa é a mesma; o guarda-chuva é o ajuste para aquela condição.

A media query é o "se" do CSS. A condição é sobre o lugar onde a página está sendo mostrada (a largura da tela, a impressora, o tema escuro do sistema), e o ajuste são as regras de dentro das chaves. O navegador refaz a pergunta o tempo todo: se o leitor gira o celular ou estreita a janela, as regras ligam e desligam na hora.

1. A primeira media query

Experimente: em 375 px, o aviso fica amarelo. Clique em 768: a tela passou de 600 px, e o aviso fica azul-marinho com letra branca. Volte para 375.

<link rel="stylesheet" href="style.css">
<h1>Lojinha da Ana</h1>
<p class="aviso">Encomendas até quinta-feira.</p>

.aviso {
  padding: 1rem;
  background-color: gold;
}

@media (min-width: 600px) {
  .aviso {
    background-color: navy;
    color: white;
  }
}
@media
Uma regra-arroba (at-rule): começa com @ e não estiliza nada sozinha; ela guarda outras regras.
(min-width: 600px)
A pergunta, sempre entre parênteses: "a largura da tela é de no mínimo 600 px?". A largura é a do viewport, a área da janela onde a página é desenhada (no editor, o quadro).
{
Abre o bloco da media query.
.aviso { … }
Regras normais, como as de fora, só que dentro do bloco. Repare na indentação: dois espaços a mais.
}
Fecha o bloco. São duas chaves no fim: a da regra .aviso e a da @media.

Repare que a regra de fora (amarela) continua valendo em qualquer largura. A de dentro só acrescenta por cima, a partir de 600 px: o fundo vira azul-marinho e a letra fica branca; o padding continua o mesmo, porque ninguém o mudou.

2. min-width e max-width

PerguntaQuer dizerVale em 375 px?Vale em 1024 px?
(min-width: 600px)largura de 600 px ou mais ("a partir de")NãoSim
(max-width: 600px)largura de 600 px ou menos ("até")SimNão
(min-width: 600px) and (max-width: 899px)de 600 até 899 pxNãoNão

Os dois incluem o número: em exatamente 600 px, min-width: 600px e max-width: 600px valem ao mesmo tempo. Por isso, quando usar os dois, faça um terminar um pixel antes de o outro começar (max-width: 599px e min-width: 600px).

Qual dos dois usar como base é a escolha entre "começar pelo celular" (min-width) e "começar pelo computador" (max-width). O guia recomenda o primeiro, e explica por quê na próxima aula, Mobile First.

A escrita nova: >= e <=

Desde 2023, todos os navegadores principais também entendem a pergunta escrita como uma conta (Chrome e Edge 104, Firefox 102, Safari 16.4; dados do MDN):

Escrita clássicaEscrita nova (range syntax)
(min-width: 600px)(width >= 600px)
(max-width: 599px)(width < 600px)
(min-width: 600px) and (max-width: 899px)(600px <= width < 900px)

A escrita nova é mais fácil de ler e resolve o problema do "pixel a mais", com o < que não inclui o número. Nos exemplos do guia, usamos a clássica, que você vai ver em quase todo código que existe; as duas funcionam.

Experimente: são três faixas, com três cores. O quadro começa em 768 px (verde). Clique em 375 (amarelo) e em cheia (azul, se a sua tela tiver espaço para mais de 900 px).

<link rel="stylesheet" href="style.css">
<p class="faixa">Em que faixa de tela estou?</p>

.faixa {
  padding: 1rem;
  background-color: gold;
}

@media (600px <= width < 900px) {
  .faixa {
    background-color: lightgreen;
  }
}

@media (width >= 900px) {
  .faixa {
    background-color: lightblue;
  }
}

Missão: em telas de 700 px ou mais, o título da Ana fica maior (font-size: 3rem) e da cor tomato. Escreva a media query no fim do style.css. O quadro está em 768 px. Depois clique em 375 e veja o título voltar ao normal.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Doces e salgados de fim de semana.</p>

h1 {
  font-size: 2rem;
}

h1 {
  font-size: 2rem;
}

@media (min-width: 700px) {
  h1 {
    font-size: 3rem;
    color: tomato;
  }
}

3. Juntar perguntas: and, vírgula e not

EscritaQuer dizer
@media (min-width: 600px) and (orientation: landscape)As duas coisas: 600 px ou mais e a tela deitada
@media (max-width: 599px), printUma ou outra: tela estreita, ou impressão (a vírgula é o "ou")
@media not printTudo, menos a impressão

Depois do and, sempre um espaço antes do parêntese: and (. Sem o espaço, a media query inteira deixa de valer (veja Quando dá errado).

4. Tipos de mídia e outras perguntas

Antes da pergunta, pode vir o tipo de mídia:

TipoQuando vale
allSempre (é o padrão quando você não escreve nenhum)
screenTelas: computador, celular, tablet, TV
printNa impressão e no "Salvar como PDF" (aula CSS para Impressão)

Por isso você vai ver muito @media screen and (min-width: 600px). O screen and é opcional: sem ele, a regra também vale na impressão, o que quase sempre é o que você quer.

E a largura não é a única pergunta:

PerguntaVale quandoUso típico
(orientation: landscape)A tela é mais larga que alta (deitada); portrait, em péAproveitar o celular deitado
(hover: hover)O aparelho principal consegue "passar por cima" (mouse)Efeitos de :hover só onde há mouse
(pointer: coarse)O apontador principal é impreciso (dedo); fine, mouseBotões maiores para o dedo
(prefers-color-scheme: dark)O sistema do leitor está no tema escuroAula Tema Escuro
(prefers-reduced-motion: reduce)O leitor pediu menos animação no sistemaAula Menos Movimento

Experimente: no computador, com mouse, o botão está com borda fina. Num celular ou tablet (toque), a regra (pointer: coarse) vale e o botão fica bem mais alto, fácil de acertar com o dedo. No quadro, a resposta depende do seu aparelho: os botões de largura não mudam o tipo de apontador.

<link rel="stylesheet" href="style.css">
<button type="button">Encomendar</button>

button {
  padding: 0.25rem 0.75rem;
}

@media (pointer: coarse) {
  button {
    padding: 1rem 2rem;
    font-size: 1.25rem;
  }
}

5. Onde escrever, e a ordem

Uma media query não deixa a regra mais forte. Na cascata, as regras de dentro de uma @media têm a mesma especificidade das de fora; quando a media query vale e as duas empatam, ganha a que vem depois no arquivo. Por isso:

  • Escreva a regra normal antes e a media query depois.
  • Há dois costumes, e os dois funcionam: as media queries todas no fim do arquivo, ou cada uma logo depois da regra que ela ajusta (mais fácil de achar).
  • Com o CSS aninhado, dá até para escrever a @media dentro da própria regra.

Também dá para pôr a condição no próprio <link> do HTML: <link rel="stylesheet" href="impressao.css" media="print">. O arquivo inteiro só vale na impressão. É mais usado para impressão do que para larguras de tela.

FormaQuando usar
@media no fim do style.cssProjetos pequenos; todos os ajustes num lugar
@media logo depois da regraProjetos médios e grandes; cada componente com os seus ajustes
<link media="print">Um arquivo inteiro só para impressão

Quando dá errado

A media query antes da regra normal: a de fora ganha

Erro de propósito: em 768 px, o aviso deveria ficar azul-marinho, e fica amarelo. Leve a @media para depois da regra .aviso.

<link rel="stylesheet" href="style.css">
<p class="aviso">Encomendas até quinta-feira.</p>

@media (min-width: 600px) {
  .aviso {
    background-color: navy;
    color: white;
  }
}

.aviso {
  padding: 1rem;
  background-color: gold;
}

O que você vê: em 768 px, o fundo continua amarelo, mas a letra fica branca (quase ilegível no amarelo). O color: white valeu, porque a regra de baixo não mexe na cor da letra; o background-color perdeu.

Por quê: as duas regras têm o mesmo seletor e a mesma força. Com empate, ganha a última do arquivo, e a última é a amarela. No F12, a declaração background-color: navy aparece riscada. O validador não reclama: não há erro de escrita.

Como consertar: regra normal antes, media query depois.

Sem parênteses: unrecognized media “min-width” 
$ cat sem-parenteses.css
@media min-width: 700px {
  h1 {
    color: navy;
  }
}
$ vnu --css sem-parenteses.css
"file:/home/ana/site/sem-parenteses.css":5.2-6.1: error: CSS: unrecognized media “min-width”.

O que significa: "mídia desconhecida: min-width". Sem os parênteses, o validador (e o navegador) leem min-width como um tipo de mídia, como screen ou print, e esse tipo não existe. O navegador ignora o bloco inteiro: o título nunca fica azul-marinho, em largura nenhuma.

Como consertar: a pergunta sempre entre parênteses: @media (min-width: 700px).

Sem espaço depois do and: Parse Error 
<style>
  @media (min-width: 700px) and(max-width: 999px) {
    h1 {
      color: navy;
    }
  }
</style>
<h1>Lojinha da Ana</h1>

O que você vê: em 768 px, que está entre 700 e 999, o título continua preto.

Por quê: grudado no parêntese, and( é lido como o nome de uma função, que não existe. A media query fica inválida e o navegador a trata como "nunca vale". O validador:

$ vnu --css and.css
"file:/home/ana/site/and.css":5.2-6.1: error: CSS: Parse Error.

Como consertar: and (max-width: 999px), com espaço.

Número sem unidade: only “0” can be a “unit” 
$ vnu --css sem-px.css
"file:/home/ana/site/sem-px.css":1.23-1.23: error: CSS: only “0” can be a “unit”. You must put a unit after your number

O que significa: em @media (min-width: 700), faltou o px. "Só o 0 pode ficar sem unidade. Você precisa pôr uma unidade depois do número." O navegador ignora o bloco.

Como consertar: (min-width: 700px). Também vale em (43.75em), que acompanha o tamanho de letra que o leitor escolheu no navegador.

Nome errado: o validador não avisa

O que acontece: com @media (min-widht: 700px) (as letras h e t trocadas), o navegador não conhece a pergunta e trata a media query como "nunca vale". O vnu --css 26.10.12 não mostra nada para esse arquivo.

Como achar: mude a largura (no quadro, ou arrastando a janela) e confira se o estilo liga. No F12, a regra de dentro de uma media query que não vale nem aparece no painel de estilos do elemento.

Esqueceu a } da @media: as regras de baixo entram nela 
<style>
  @media (min-width: 700px) {
    h1 {
      color: navy;
    }

  p {
    color: green;
  }
</style>
<h1>Lojinha da Ana</h1>
<p>Encomendas até quinta-feira.</p>

O que você vê: em 375 px, o parágrafo fica preto, e não verde. Em telas de 700 px ou mais, ele fica verde.

Por quê: a } que fecha a h1 foi entendida como o fim da regra, e a da @media nunca veio. A regra do p ficou dentro da media query, e só vale a partir de 700 px. O validador:

$ vnu --css chave.css
"file:/home/ana/site/chave.css":8.2-9.1: error: CSS: Parse Error.

Como consertar: feche a @media. A indentação ajuda a ver: a regra de dentro tem dois espaços a mais, e a } da @media fica na coluna 1.

Resumo

  • @media (pergunta) { regras }: as regras de dentro só valem quando a resposta é sim. O navegador pergunta de novo sempre que a janela muda.
  • min-width = "a partir de"; max-width = "até"; os dois incluem o número. Escrita nova: (width >= 600px), (600px <= width < 900px).
  • and (com espaço antes do parêntese), vírgula (= "ou"), not. Tipos: screen, print, all. Outras perguntas: orientation, hover, pointer, prefers-color-scheme, prefers-reduced-motion.
  • A media query não soma força: escreva-a depois da regra normal.
  • Erros: sem parênteses (unrecognized media), and( grudado ou } esquecida (Parse Error), número sem px (only “0” can be a “unit”). Nome errado (min-widht) o validador não vê: teste mudando a largura.
