CSS Aninhado

O CSS do cartão de receita da Ana começa a se repetir: .receita, .receita h2, .receita p, .receita:hover, .receita img… o mesmo começo em cada linha. Desde o fim de 2023, todos os navegadores entendem CSS aninhado (nesting): você escreve as regras do h2, do p e do :hover dentro da regra do .receita, e o seletor & quer dizer "este aqui, o de fora".

Você vai aprender
  • A ideia de aninhar: escrever o "endereço" uma vez só, como numa lista de compras separada por seção.
  • Como uma regra dentro da outra vira um seletor descendente (.receita h2).
  • O seletor &: &:hover, &.destaque, & > p e o contexto invertido (.tema-escuro &).
  • @media dentro da regra.
  • Até onde aninhar, e a especificidade que cresce sem você ver.
  • A diferença para o Sass (&__titulo não existe no CSS), e os erros que apagam regras inteiras.

Antes, é bom ter visto Descendente, Filho e Irmãos, Estados e Especificidade. Os resultados são desenhados agora pelo seu navegador, e as mensagens do validador saíram do validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook).

A ideia: a lista de compras por seção

A Ana poderia escrever a lista do mercado assim: "padaria: pão", "padaria: bolo", "padaria: sonho", "hortifrúti: cenoura", "hortifrúti: laranja". Funciona, mas ela repete "padaria" três vezes. Ninguém faz isso: a gente escreve "Padaria" uma vez, como título, e embaixo, recuado, os itens.

O CSS aninhado é a lista por seção. Em vez de repetir .receita no começo de cada seletor, você escreve .receita { … } uma vez e põe as outras regras dentro das chaves dele, recuadas. O navegador "monta" os seletores completos sozinho.

1. A mesma folha de estilo, nos dois jeitos

Primeiro, o CSS do cartão escrito do jeito que você já conhece, com cada seletor completo:

.receita {
  border: 2px solid firebrick;
  padding: 16px;
}

.receita h2 {
  color: firebrick;
}

.receita p {
  line-height: 1.6;
}

Agora o mesmo, aninhado:

.receita {
  border: 2px solid firebrick;
  padding: 16px;

  h2 {
    color: firebrick;
  }

  p {
    line-height: 1.6;
  }
}

As duas versões fazem exatamente a mesma coisa. Veja a aninhada funcionando (as abas são editáveis):

<link rel="stylesheet" href="style.css">
<article class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Massa fofinha, cobertura de chocolate e 50 minutos de forno.</p>
</article>
<h2>Fora do cartão</h2>

.receita {
  border: 2px solid firebrick;
  padding: 16px;

  h2 {
    color: firebrick;
  }

  p {
    line-height: 1.6;
  }
}

O título de dentro do cartão fica firebrick; o "Fora do cartão", não, porque está fora do .receita. É a regra .receita h2, só que escrita dentro.

.receita {
A regra de fora, a "mãe". Abre as chaves normalmente.
border: …; padding: …;
As declarações da própria .receita, como sempre.
h2 { … }
Uma regra aninhada: um seletor e as chaves dele, dentro das chaves da mãe. Vale para os h2 que estão dentro de um .receita: o navegador lê como .receita h2.
}
A última chave fecha a mãe. Cada { precisa do seu }: com o recuo de 2 espaços por nível, dá para conferir de olho.

Missão: reescreva a regra .receita h2 dentro da regra .receita, aninhada. O título tem de continuar firebrick.

  <h2>Torta de limão</h2>
  <p>Base crocante e creme azedinho.</p>
</article>

  padding: 16px;
}

.receita h2 {

  padding: 16px;

  }
}

2. O seletor &: "este aqui"

Sem nada na frente, uma regra aninhada é sempre descendente (um espaço entre a mãe e ela). Mas e o .receita:hover, que não é "algo dentro do .receita", e sim o próprio .receita com o mouse em cima? Para isso existe o & (lê-se "e comercial"): ele é trocado pelo seletor da mãe.

<style>
  .receita {
    border: 2px solid firebrick;
    padding: 8px 16px;
    margin-bottom: 8px;
    font-family: sans-serif;

    &:hover {
      background-color: lavenderblush;
    }

    &.destaque {
      border-width: 6px;
    }

    .tempo {
      color: gray;
    }
  }
</style>
<article class="receita">
  <h3>Bolo de cenoura</h3>
  <p class="tempo">50 minutos</p>
</article>
<article class="receita destaque">
  <h3>Torta de limão (receita da semana)</h3>
  <p class="tempo">40 minutos</p>
</article>

Os dois cartões têm a borda firebrick e o tempo em cinza; o segundo, que também tem a classe destaque, ganhou a borda bem mais grossa. Passe o mouse em cima de um cartão: o fundo fica rosado.

Escrito dentro de .receita { }O navegador entendeQuer dizer
h2 { } ou & h2 { }.receita h2um h2 em qualquer lugar dentro do cartão
> p { } ou & > p { }.receita > pum p que é filho direto
&:hover { }.receita:hovero próprio cartão, com o mouse em cima
&.destaque { }.receita.destaqueo cartão que tem também a classe destaque
&::before { }.receita::beforeo pseudo-elemento do cartão (aula ::before e ::after)
& + & { }.receita + .receitaum cartão logo depois de outro
.tema-escuro & { }.tema-escuro .receitao cartão quando está dentro de um .tema-escuro (o & no fim "inverte" o contexto)

Com espaço ou sem espaço: &.destaque × & .destaque

É o mesmo detalhe dos seletores normais. Sem espaço, &.destaque é o próprio cartão com as duas classes. Com espaço (ou sem o &), & .destaque e .destaque são um elemento dentro do cartão com a classe destaque. Para :hover, .classe, [atributo] e ::before grudados na mãe, o & é obrigatório.

Escrever o & mesmo quando não precisa? & h2 e h2 são iguais. Muita gente escreve o & sempre, para ficar claro que é uma regra aninhada, e porque navegadores de 2023 exigiam o & antes de um nome de elemento (veja a nota de suporte). As duas formas estão certas; o guia usa sem o & quando é descendente.

3. @media dentro da regra

Uma media query também pode ficar dentro da regra. Dentro dela, você escreve só as declarações, sem repetir o seletor:

.receita {
  padding: 8px;

  @media (min-width: 600px) {
    padding: 32px;
  }
}

É o mesmo que @media (min-width: 600px) { .receita { padding: 32px; } }. A vantagem: tudo o que muda o .receita, em qualquer tamanho de tela, fica junto. Experimente: numa tela de computador, o quadro tem mais de 600 pixels: a borda é azul-marinho e o espaço interno, grande. Clique em 375, na barra do quadro: abaixo de 600 pixels, o espaço interno encolhe e a borda volta a ser firebrick. O botão cheia volta à largura da coluna.

<link rel="stylesheet" href="style.css">
<article class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Troque a largura do quadro (375 · cheia) e compare.</p>
</article>

.receita {
  border: 4px solid firebrick;
  padding: 8px;

  @media (min-width: 600px) {
    border-color: navy;
    padding: 48px;
  }

  h2 {
    margin-top: 0;
  }
}

4. Até onde aninhar

Dá para aninhar dentro do aninhado, quantos níveis quiser:

.pagina {
  .conteudo {
    .receita {
      .ingredientes {
        li {
          color: gray;
        }
      }
    }
  }
}

O navegador monta .pagina .conteudo .receita .ingredientes li: cinco partes, uma especificidade alta (quatro classes e um elemento) e uma regra que só funciona se o HTML tiver exatamente essa árvore. Mudou o HTML, a regra para de valer. Na prática:

  • aninhe para agrupar o que é de um mesmo componente (o cartão, o menu, o formulário);
  • fique em dois ou três níveis, no máximo;
  • se o seletor completo, escrito por extenso, fosse comprido demais para você escrever, ele está comprido demais aninhado também.

A especificidade do &

O & vale como um :is() do seletor da mãe (aula :not(), :is() e :where()). Quando a mãe é uma lista com um ID, a regra aninhada herda a força do ID, mesmo para os elementos que só têm a classe:

<style>
  .receita, #receita-do-dia {
    p {
      color: firebrick;
    }
  }

  .receita p.tempo {
    color: navy;
  }
</style>
<div class="receita">
  <p class="tempo">50 minutos</p>
</div>

O texto ficou firebrick, e não navy. A regra aninhada vira :is(.receita, #receita-do-dia) p, que conta como um ID e um elemento (1, 0, 1), e ganha da .receita p.tempo (0, 2, 1), mesmo vindo antes. Por extenso, .receita p, #receita-do-dia p, a parte da classe teria só (0, 1, 1) e perderia. Mais um motivo para não usar ID em estilo.

5. CSS aninhado × Sass

Se você já viu Sass (ou SCSS), um pré-processador que transforma um CSS "turbinado" em CSS normal, o aninhamento é parecido, mas há uma diferença que pega muita gente. No Sass, &__titulo gruda texto no nome da mãe e vira .receita__titulo (o estilo de nomes da aula BEM). No CSS de verdade, isso não existe: o & é um seletor inteiro, e não um pedaço de texto. Veja em "Quando dá errado".

Suporte: o CSS aninhado funciona em todos os navegadores atuais desde dezembro de 2023 (o MDN o marca como Baseline: amplamente disponível): Chrome e Edge 120, Firefox 117 e Safari 17.2. Chrome/Edge 112–119 e Safari 16.5–17.1 tinham uma versão mais antiga, que não aceitava uma regra aninhada começando por um nome de elemento (h2 { }); nesses, escreva & h2 { }. Um navegador sem suporte ignora as regras aninhadas e aplica só as declarações da mãe. O validador W3C (vnu 26.10.12) já conhece o aninhamento e não dá erro nas formas certas.

6. Formas diferentes de fazer a mesma coisa

FormaExemploQuando usar
Seletores por extenso.receita h2 { }Regras soltas, CSS curto, ou quando o site precisa funcionar em navegadores de antes de 2024.
Aninhado, sem &.receita { h2 { } }Agrupar as partes de um componente.
Aninhado, com &.receita { & h2 { } &:hover { } }Obrigatório para estados, classes juntas e pseudo-elementos; opcional (por clareza) nos outros.

Quando dá errado

No CSS aninhado, um erro costuma apagar mais coisa do que uma declaração: pode sumir uma regra aninhada inteira, com todas as declarações dela. O resto da folha continua valendo.

error: CSS: Parse Error. — o &__titulo do Sass

O que aconteceu: a Ana copiou um hábito do Sass:

<style>
  .receita {
    color: navy;

    &__titulo {
      color: firebrick;
    }
  }
</style>
<div class="receita">
  <h2 class="receita__titulo">Bolo de cenoura</h2>
</div>

O título fica azul-marinho (o navy herdado do .receita), e não firebrick: o navegador jogou fora a regra &__titulo inteira. Para ele, __titulo grudado no & é um nome de elemento depois de outro seletor, e isso não é permitido. O validador:

$ vnu --css bem.css
"file:/home/ana/ninho/bem.css":4.4-4.4: error: CSS: Parse Error.

"Erro de leitura", na linha 4, a do } que fecha a regra quebrada.

Como consertar: escreva o nome completo da classe: .receita__titulo { … }, fora ou dentro da mãe (dentro, ele vira descendente: .receita .receita__titulo).

error: CSS: Parse Error. — faltou o ; antes da regra aninhada

O que aconteceu: a última declaração da mãe ficou sem ;, logo antes de uma regra aninhada:

<style>
  .receita {
    color: navy

    h2 {
      color: firebrick;
    }

    p {
      color: green;
    }
  }
</style>
<div class="receita">
  <h2>Bolo de cenoura</h2>
  <p>50 minutos</p>
</div>

O título fica preto: perdeu o firebrick e também o navy. Só o parágrafo ficou verde. Sem o ;, o navegador leu color: navy h2 { color: firebrick; } como uma declaração só, com um valor sem sentido, e jogou tudo fora. A regra do p, que vem depois, sobreviveu.

$ vnu --css sem-ponto-virgula.css
"file:/home/ana/ninho/sem-ponto-virgula.css":6.4-6.4: error: CSS: Parse Error.

Como consertar: color: navy;. O ; sempre, até na última declaração: no CSS aninhado, ele separa a declaração da regra que vem embaixo.

A classe junto não funcionou: faltou o &

O que aconteceu: a Ana quis o cartão com a classe destaque e escreveu .receita { .destaque { border-width: 6px; } }. Nada mudou no <article class="receita destaque">. Sem o &, a regra virou .receita .destaque: "um .destaque dentro do cartão". O validador não reclama: o seletor é válido, só não é o que ela queria.

Como consertar: &.destaque, sem espaço. O mesmo vale para &:hover: sem o &, :hover { } vira "qualquer coisa dentro do cartão com o mouse em cima".

Uma chave a mais ou a menos

O que aconteceu: com chaves dentro de chaves, é fácil esquecer de fechar uma. Se falta um }, todas as regras que vêm depois ficam "dentro" da regra aberta, e passam a valer só dentro dela (ou não valem mais). Os sintomas aparecem longe do erro: "o rodapé perdeu o estilo".

Como consertar: recuo de 2 espaços por nível, sempre; cada } alinhado com a linha que abriu a chave dele. Os editores de código (como o VS Code) destacam o par da chave em que o cursor está.

Resumo

  • CSS aninhado: regras dentro das chaves de outra regra. Escreve-se o começo do seletor uma vez só, e o que é de um componente fica junto.
  • Sem nada na frente, a regra aninhada é descendente: .a { b { } } = .a b. Com >, + ou ~ na frente, o combinador correspondente.
  • & = o seletor da mãe. Obrigatório para grudar: &:hover, &.destaque, &::before. No fim, inverte o contexto: .tema-escuro &.
  • @media pode ficar dentro da regra, só com as declarações.
  • Dois ou três níveis, no máximo. O & pesa como :is(): uma mãe com ID deixa as aninhadas fortes.
  • &__titulo é do Sass: no CSS, a regra é jogada fora. Um ; esquecido antes de uma regra aninhada apaga a declaração e a regra. Baseline desde dezembro de 2023 (Chrome/Edge 120, Firefox 117, Safari 17.2).
