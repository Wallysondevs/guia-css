CSS Escopo

No blog da Ana, cada receita é um cartão: título, foto, texto e, no fim, a área de comentários dos leitores. A regra "os parágrafos da receita são grandes e cor de tomate" acaba pegando também os parágrafos dos comentários, que estão dentro do cartão. O @scope ("escopo", o alcance de uma regra) resolve isso: ele diz onde começa e onde termina a área em que um grupo de regras vale.

Você vai aprender
  • A ideia de escopo: regras que valem "da porta para dentro" de um componente.
  • Como escrever @scope (.receita) { … } e estilizar o próprio componente com :scope.
  • O limite to (…), que deixa um "buraco" onde as regras não entram.
  • A proximidade: o escopo mais próximo vence, como no tema claro dentro do escuro.
  • @scope dentro de um <style> no meio da página.
  • O que é recente no suporte dos navegadores e os erros mais comuns.

Antes, é preciso ter visto Descendente, Filho e Irmãos, Especificidade e Herança; ajuda ter visto CSS Aninhado e @layer. Os resultados são desenhados agora pelo seu navegador, e as mensagens do validador saíram do validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook).

Recurso recente. O @scope funciona no Chrome e no Edge desde a versão 118 (2023), no Safari desde a 17.4 (2024), mas no Firefox só a partir da 146 (dezembro de 2025). O MDN o marca como Baseline 2026: funciona nos navegadores atuais, mas não em aparelhos e navegadores mais antigos. Num navegador sem suporte, o bloco @scope inteiro é ignorado. Veja na seção 7 como lidar com isso.

A ideia: as regras da casa

A casa da Ana tem regras: "tire o sapato", "fale baixo depois das 22h". Elas valem da porta para dentro; na calçada, não. Esse é o escopo das regras: o lugar onde elas valem.

E pode haver uma exceção: "menos no quarto do Pedro, que lá o quarto é dele". As regras da casa valem na sala, na cozinha, no corredor, mas não entram no quarto. É um escopo com um buraco no meio, como uma rosquinha.

O @scope faz as duas coisas no CSS: diz a "porta" (o elemento onde as regras começam a valer) e, se você quiser, o "quarto" (onde elas param).

1. O primeiro escopo

<style>
  @scope (.receita) {
    h2 {
      color: firebrick;
    }

    p {
      font-size: 1.1rem;
    }
  }
</style>
<article class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Massa fofinha e cobertura de chocolate.</p>
</article>
<h2>Outras receitas</h2>
<p>Em breve, a torta de limão.</p>

Dentro do .receita, o título ficou firebrick e o parágrafo, um pouco maior. Fora dele, o "Outras receitas" continua preto, e o parágrafo, no tamanho normal.

@scope
Uma regra @, como @media e @layer. Scope = "escopo", "alcance".
(.receita)
A raiz do escopo, entre parênteses: um seletor qualquer. As regras de dentro valem só nos elementos que estão dentro de um .receita. Os parênteses são obrigatórios.
{ h2 { … } p { … } }
As regras do escopo, com seletores normais. O h2 daqui quer dizer "um h2 dentro da raiz".

Até aqui, dá no mesmo que escrever .receita h2 e .receita p, com uma diferença na especificidade: dentro do @scope, o h2 pesa só como um elemento (0, 0, 1), porque o escopo não acrescenta nada ao seletor. Já o .receita h2 pesa uma classe e um elemento (0, 1, 1). O @scope mostra o seu valor nas próximas seções: o limite e a proximidade.

O próprio componente: :scope

Para estilizar a raiz (o próprio .receita), use o seletor :scope dentro do bloco:

@scope (.receita) {
  :scope {
    border: 2px solid firebrick;
    padding: 16px;
  }

  h2 {
    margin-top: 0;
  }
}

O :scope quer dizer "a raiz deste escopo". Ele pesa como uma classe (0, 1, 0). Um seletor sem nada na frente, como o h2, vale só para os elementos dentro da raiz, nunca para ela mesma. Também dá para escrever & no lugar de :scope, como no CSS aninhado; o guia usa :scope, mais claro.

2. O limite: to (…)

Agora o problema da Ana. Os comentários ficam dentro do cartão da receita, e ela não quer que as regras da receita entrem neles. Depois da raiz, escreva to ("até") e o limite, também entre parênteses:

<style>
  @scope (.receita) to (.comentarios) {
    :scope {
      border: 2px solid firebrick;
      padding: 0 16px;
      font-family: sans-serif;
    }

    p {
      color: firebrick;
      font-size: 1.2rem;
    }
  }

  .comentarios {
    background-color: whitesmoke;
    padding: 8px;
  }
</style>
<article class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Bata os ovos, a cenoura e o óleo no liquidificador.</p>
  <div class="comentarios">
    <p>Fiz e ficou ótimo! (Bia)</p>
  </div>
</article>

O parágrafo da receita ficou firebrick e maior. O comentário da Bia, dentro do quadro cinza-claro, continua preto e no tamanho normal, mesmo estando dentro do .receita: ele está no "buraco".

@scope (.receita)
A raiz: onde o escopo começa. A raiz faz parte do escopo (o :scope a alcança).
to
"Até".
(.comentarios)
O limite: onde o escopo termina. O limite não faz parte do escopo, e nada dentro dele também. É o buraco da rosquinha: em inglês, isso é chamado de donut scope, "escopo rosquinha".

Sem o @scope, para fazer isso você precisaria de um seletor que dissesse "um p dentro de .receita, mas não dentro de .comentarios", algo como .receita p:not(.comentarios p): difícil de ler e com uma especificidade alta.

Missão: o comentário do leitor também ficou firebrick. Ponha um limite no escopo, com to (.comentarios), para que as regras da receita não entrem nos comentários.

<link rel="stylesheet" href="style.css">
<article class="receita">
  <h2>Torta de limão</h2>
  <p>Misture o leite condensado com o suco de limão.</p>
  <section class="comentarios">
    <h3>Comentários</h3>
    <p>Ficou azedinha na medida! (Caio)</p>
  </section>
</article>

@scope (.receita) {
  p {
    color: firebrick;
  }
}

.comentarios {
  background-color: whitesmoke;
  padding: 8px;
}

@scope (.receita) to (.comentarios) {
  p {
    color: firebrick;
  }
}

.comentarios {
  background-color: whitesmoke;
  padding: 8px;
}

A herança atravessa o limite. O limite impede que os seletores do escopo alcancem os elementos do buraco. Mas propriedades herdadas (aula Herança), como color e font-family, passam de pai para filho normalmente. Se o :scope tiver color: navy, o .comentarios herda o navy do pai, e os parágrafos de dentro dele também (conferido no Chromium). Se não quiser isso, dê ao .comentarios a cor dele.

3. A proximidade: o escopo mais perto vence

Este é o problema que só o @scope resolve bem. O site da Ana tem um tema claro e um escuro, e às vezes um cartão claro aparece dentro de uma área escura, que está dentro de uma página clara. Com seletores comuns, quem vence é a regra que vem depois no arquivo, e não a mais próxima:

<style>
  .claro {
    background-color: white;
    padding: 8px;
  }
  .escuro {
    background-color: #222;
    padding: 8px;
  }
  .claro p {
    color: #222;
  }
  .escuro p {
    color: white;
  }
</style>
<div class="claro">
  <p>Página clara</p>
  <div class="escuro">
    <p>Área escura</p>
    <div class="claro">
      <p>Cartão claro dentro da área escura</p>
    </div>
  </div>
</div>

A última faixa, branca, parece vazia: o texto "Cartão claro dentro da área escura" está lá, mas em branco sobre branco. O p do cartão está dentro de um .claro e também dentro de um .escuro (mais acima). As duas regras valem para ele, com a mesma especificidade (0, 1, 1), e a do .escuro, que vem depois no arquivo, vence.

Agora com @scope:

<style>
  @scope (.claro) {
    :scope {
      background-color: white;
      padding: 8px;
    }
    p {
      color: #222;
    }
  }
  @scope (.escuro) {
    :scope {
      background-color: #222;
      padding: 8px;
    }
    p {
      color: white;
    }
  }
</style>
<div class="claro">
  <p>Página clara</p>
  <div class="escuro">
    <p>Área escura</p>
    <div class="claro">
      <p>Cartão claro dentro da área escura</p>
    </div>
  </div>
</div>

Agora o texto do cartão aparece, escuro sobre branco. Entre dois escopos que alcançam o mesmo elemento, o navegador conta quantos "degraus" há do elemento até cada raiz: do p do cartão até o .claro de dentro é um degrau; até o .escuro, dois. O escopo mais próximo vence, não importa a ordem no arquivo. Isso se chama proximidade de escopo.

Onde a proximidade entra na cascata

  1. Importância (!important).
  2. Camada (@layer).
  3. Especificidade.
  4. Proximidade de escopo (a novidade).
  5. Ordem no código.

Repare que a proximidade vem depois da especificidade: ela só desempata regras com a mesma especificidade. Uma regra comum mais específica, como .escuro p (0, 1, 1), vence o p de um escopo (0, 0, 1), por mais perto que o escopo esteja. E ela vem antes da ordem no código: uma regra de escopo vence uma regra comum de mesma especificidade escrita depois dela (no Chromium, @scope (.c) { p { font-weight: bold; } } ganhou de um p { font-weight: normal; } que vinha depois).

4. @scope dentro de um <style> no meio da página

Um <style> pode ficar dentro do <body>, no meio do HTML. Se ele tiver um @scope sem raiz, a raiz é o elemento pai do <style>:

<section>
  <style>
    @scope {
      p {
        color: purple;
      }
    }
  </style>
  <h2>Dica da semana</h2>
  <p>Peneire a farinha para o bolo ficar mais fofo.</p>
</section>
<p>Este parágrafo está fora da seção.</p>

Só o parágrafo da seção fica roxo; o de fora, não. É útil num pedaço de página que vem pronto de outro lugar (um bloco de anúncio, um trecho gerado por um sistema), que traz o próprio CSS sem afetar o resto. No site que você mesmo escreve, prefira o arquivo style.css com @scope (.classe).

5. Formas diferentes de limitar um estilo

FormaExemploQuando usar
Seletor descendente.receita p { }O caso simples, sem buraco e sem temas aninhados. Funciona em todos os navegadores.
Uma classe própria em cada parte (o jeito BEM).receita__texto { }Projetos grandes: cada elemento tem nome, e nenhum seletor "vaza". Dá mais trabalho no HTML.
CSS aninhado.receita { p { } }Agrupar as regras de um componente. É só outra forma de escrever .receita p: não cria limite nem proximidade.
@scope@scope (.receita) to (.comentarios) { p { } }Quando precisa de um limite (o buraco) ou de proximidade (temas e componentes uns dentro dos outros), nos navegadores atuais.

6. Quem ainda não entende @scope

Um navegador sem suporte ignora o bloco @scope inteiro, com todas as regras de dentro: o componente fica sem aqueles estilos. Para o seu site continuar usável, escreva antes o estilo básico com seletores comuns (.receita p { … }), que todos entendem, e use o @scope só para o refinamento: o limite e a proximidade. Quem tem um navegador antigo vê uma versão mais simples, mas legível.

Quando dá errado

error: CSS: Parse Error. — faltaram os parênteses

O que aconteceu: @scope .receita { … }, com o seletor da raiz sem parênteses.

<style>
  @scope .receita {
    p {
      color: firebrick;
    }
  }
</style>
<div class="receita">
  <p>Bata os ovos com o açúcar.</p>
</div>

O parágrafo continua preto: o bloco inteiro foi ignorado.

$ vnu --css sem-parenteses.css
"file:/home/ana/escopo/sem-parenteses.css":5.2-6.1: error: CSS: Parse Error.

"Erro de leitura", apontando para o fim do bloco, e não para a linha 1, onde está o erro.

Como consertar: @scope (.receita) { … }. A raiz e o limite vão sempre entre parênteses.

error: CSS: Parse Error. — until no lugar de to

O que aconteceu: @scope (.receita) until (.comentarios). "Until" também quer dizer "até", mas a palavra do CSS é to.

$ vnu --css until.css
"file:/home/ana/escopo/until.css":5.2-6.1: error: CSS: Parse Error.

O bloco inteiro é ignorado.

Como consertar: @scope (.receita) to (.comentarios).

A regra do escopo perdeu para uma regra comum

O que aconteceu: a Ana tem @scope (.cartao) { p { color: green; } } e, em outro lugar do arquivo, um antigo .cartao p { color: blue; }. Os parágrafos ficaram azuis. O p do escopo pesa (0, 0, 1); o .cartao p, (0, 1, 1). A especificidade vem antes da proximidade. O validador não reclama: não há erro.

Como consertar: tire a regra antiga, ou escreva a do escopo com :scope p, que pesa (0, 1, 1) e, empatada na especificidade, vence pela proximidade.

O limite "não funcionou" para a cor

O que aconteceu: @scope (.receita) to (.comentarios) { :scope { color: navy; } }, e os comentários ficaram azul-marinho também. O seletor não os alcançou, mas o color é herdado: o .comentarios pegou a cor do pai.

Como consertar: dê ao .comentarios a cor que você quer (.comentarios { color: black; }), ou ponha a cor nos elementos de texto (p, h2) do escopo, em vez de no :scope.

No celular de um leitor, o cartão perdeu todo o estilo

O que aconteceu: todo o visual do cartão estava dentro de um @scope, e o navegador do leitor é anterior ao suporte (por exemplo, um Firefox anterior à versão 146). O navegador ignorou o bloco inteiro.

Como consertar: o estilo básico com seletores comuns, e o @scope só para o que precisa dele (seção 6).

Referência rápida

CódigoO que faz
@scope (.a) { p { } }Os p dentro de um .a; o p pesa (0, 0, 1)
:scope { } (dentro do bloco)A própria raiz; pesa como uma classe
@scope (.a) to (.b) { }Dentro de .a, menos o .b e o que está dentro dele

Resumo

  • @scope (raiz) { … }: as regras de dentro só valem dentro da raiz. Os seletores sem nada na frente pesam só o que são (p = 0, 0, 1). :scope é a própria raiz.
  • @scope (raiz) to (limite): um escopo com buraco; o limite e o que está dentro dele ficam de fora. A herança (color, font-family) atravessa o limite.
  • Proximidade: entre escopos empatados na especificidade, vence o de raiz mais próxima. Cascata: importância → camada → especificidade → proximidade → ordem.
  • Num <style> no meio da página, @scope { } sem raiz vale para o pai do <style>.
  • Recente: Chrome/Edge 118, Safari 17.4, Firefox 146 (Baseline 2026). Sem suporte, o bloco inteiro é ignorado: deixe o básico fora do @scope.
  • Sem parênteses ou com until, o validador dá Parse Error e o navegador ignora o bloco.
