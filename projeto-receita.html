CSS Projeto: Página de Receita

No Guia HTML, a Ana montou a página do bolo de cenoura da avó: título, foto, informações, ingredientes, modo de preparo e uma dica. O conteúdo está todo lá, mas a página tem a cara de um documento de 1995: letra serifada, tudo colado na esquerda, nenhuma cor. Neste projeto você vai vestir essa página com CSS, em seis versões. Cada versão acrescenta uma coisa só, tem uma caixa "Experimente" com a página inteira até ali e uma missão para você fazer a mesma coisa com as próprias mãos.

Você vai aprender (juntando o que já viu)
  • A começar todo site pelo mesmo "chão": box-sizing, fonte, altura da linha e cores no body.
  • A fazer uma coluna de leitura centralizada com max-width e margin: 0 auto.
  • A deixar a foto caber em qualquer tela com width: 100% e height: auto.
  • A transformar uma lista de definições (<dl>) em três cartões com Flexbox.
  • A pintar os marcadores das listas com ::marker e destacar a dica com uma borda lateral.
  • A passar para duas colunas só em telas largas, com Grid dentro de um @media.

Cada passo usa uma aula do guia; o link fica ao lado, se você quiser rever. As mensagens do validador saíram do validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook). As descrições do resultado foram conferidas numa foto do Chromium; o resultado nas caixas é desenhado agora pelo seu navegador, com a foto de verdade do guia.

O que vamos construir

Pense numa receita escrita num caderno, e na mesma receita impressa num livro de culinária. O texto é igual; o livro tem margens, título colorido, foto bem enquadrada, um quadrinho com "tempo, rendimento, dificuldade" e, numa página larga, os ingredientes numa coluna estreita ao lado do modo de preparo. O HTML é o caderno; o CSS é o trabalho do diagramador do livro.

No fim, a página fica assim:

  • No celular (tela estreita): uma coluna só. Título laranja-escuro grande, a foto com cantos arredondados ocupando a largura toda, os cartões "Tempo" e "Rendimento" lado a lado e "Dificuldade" embaixo, depois os ingredientes com bolinhas laranja, o modo de preparo com números laranja em negrito e a dica numa caixa creme com uma barra laranja à esquerda.
  • No computador (tela de 48rem, ou 768 px, para cima): os três cartões numa linha só, e os ingredientes numa coluna estreita à esquerda do modo de preparo.

O HTML (é o mesmo em todas as versões)

É a receita do projeto do Guia HTML, um pouco mais curta e com algumas classes para o CSS se agarrar: receita no <main>, foto no <figure>, info na lista de informações, colunas em volta das duas seções e dica na citação. Repare que, dentro do <dl>, cada par <dt> + <dd> está dentro de um <div>: o HTML permite isso, e é esse <div> que vai virar um cartão na versão 4.

A primeira linha liga a folha de estilo, como na aula Três Jeitos de Usar CSS. Num site seu, essa linha fica no <head> de uma página completa; nas caixas do guia, basta o trecho.

Antes de começar

No computador, crie uma pasta receita com o index.html acima, um style.css vazio e a foto do bolo. Abra o index.html no navegador e, a cada versão, salve o style.css e aperte F5. Aqui no guia é mais fácil: cada caixa já tem as duas abas, index.html e style.css.

Com o style.css vazio, a página aparece como o navegador desenha "de fábrica": fundo branco, letra serifada preta (Times, na maioria dos computadores), o título em negrito e a foto no tamanho natural dela, 800 × 600 pixels. Num celular, a foto passa da borda da tela e a página ganha rolagem para o lado. As informações aparecem como uma lista de definições: "Tempo" numa linha, "1h10" recuado na linha de baixo.

Versão 1 · O chão da página: caixa, fonte e cores

Todo site começa pelas mesmas regras de base. Elas não fazem nada vistoso, mas tudo o que vem depois fica mais previsível.

*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
  color: #3b2f2a;
  background-color: #fff8f0;
}
*, *::before, *::after { box-sizing: border-box; }
Em todo elemento, a largura passa a incluir o preenchimento e a borda. Uma caixa de width: 100% com padding não passa mais da largura do pai. Aula: box-sizing: border-box.
margin: 0 no body
Tira os 8 px de margem que o navegador põe em volta da página. Quem vai cuidar do espaço é a coluna da versão 2. Aula: Margem.
font-family: system-ui, sans-serif
A fonte do sistema do leitor (Segoe UI no Windows, San Francisco no Mac e no iPhone, Roboto no Android…), sem baixar nada; se não houver, qualquer fonte sem serifa. Aula: Fontes.
line-height: 1.6
Cada linha ocupa 1,6 vez o tamanho da letra. Receita é texto para ler com a mão suja de farinha: linhas mais soltas cansam menos. Sem unidade, o número vale para os filhos também, cada um com o próprio tamanho de letra. Aula: Espaçamento.
color: #3b2f2a e background-color: #fff8f0
Um marrom muito escuro no texto e um creme bem claro no fundo: mais quentes que o preto no branco, e com contraste de sobra. Aulas: Cores Hexadecimais e Cor de Fundo.

O que muda na tela: o fundo fica creme, a letra vira a sem serifa do sistema, num marrom quase preto, e as linhas ganham ar. A página ainda encosta na borda esquerda (agora sem nem os 8 px de margem) e a foto continua no tamanho natural.

Versão 2 · Uma coluna de leitura e títulos com cor

Num monitor largo, uma linha de texto que vai de uma borda à outra é cansativa: o olho se perde ao voltar para o começo da linha seguinte. Os livros resolvem isso com margens; a gente resolve com uma coluna de largura máxima, centralizada.

.receita {
  max-width: 40rem;
  margin: 0 auto;
  padding: 1rem;
}

h1 {
  margin: 0 0 0.5rem;
  font-size: 2rem;
  line-height: 1.2;
  color: #c2410c;
}

h2 {
  color: #9a3412;
  border-bottom: 2px solid #fed7aa;
}

.resumo {
  font-size: 1.125rem;
}
max-width: 40rem
O <main> pode ser mais estreito, mas nunca mais largo que 40rem (640 px com a letra padrão de 16 px). Num celular, ele ocupa a tela toda; num monitor, para nos 640 px. É max-width, e não width, justamente para não passar da tela do celular. Aula: Largura e Altura.
margin: 0 auto
Margem de cima e de baixo 0; esquerda e direita auto, que divide igualmente o espaço que sobra. É o que centraliza a coluna. Aula: Centralizando Qualquer Coisa.
padding: 1rem
Um respiro de 16 px por dentro da coluna, para o texto não encostar na borda do celular. Aula: Espaço Interno.
h1 e h2
O título fica em 2rem, com line-height: 1.2 (título grande com linha solta fica esquisito quando quebra em duas linhas) e laranja-escuro #c2410c. Os subtítulos ganham um marrom-alaranjado e um sublinhado de borda (border-bottom) cor de pêssego. Aula: Bordas.

O que muda na tela: num quadro largo, o texto fica numa coluna no meio, com sobra de creme dos dois lados. O título fica laranja e quebra em duas linhas ("Bolo de cenoura com cobertura / de chocolate"); "Ingredientes" e "Modo de preparo" ganham a linha cor de pêssego embaixo, da largura da coluna. Mas olhe a foto: ela começa dentro da coluna e passa da borda direita, porque continua com os 800 px naturais dentro de uma coluna de 640. Na foto que tiramos com o quadro de 870 px, a página ficou com 971 px de largura e ganhou rolagem para o lado. É o assunto da versão 3.

Versão 3 · A foto que cabe em qualquer tela

A foto tem width="800" height="600" no HTML. Esses atributos dizem ao navegador a proporção da foto antes de ela chegar (ele reserva o espaço e a página não "pula"), mas também viram o tamanho dela quando o CSS não diz outra coisa. Agora o CSS vai dizer.

.foto {
  margin: 1.5rem 0;
}

.foto img {
  display: block;
  width: 100%;
  height: auto;
  border-radius: 12px;
}

.foto figcaption {
  margin-top: 0.5rem;
  font-size: 0.875rem;
  color: #6b5b53;
  text-align: center;
}
display: block
Uma imagem é, de fábrica, um elemento em linha: fica apoiada na linha do texto, com um vãozinho embaixo, reservado para as "pernas" de letras como g e p. Como bloco, o vão some. Aula: display.
width: 100% + height: auto
A largura passa a ser a da coluna (640 px no computador, a tela menos o preenchimento no celular), e a altura acompanha, mantendo a proporção 4:3 que os atributos informaram. Sem o height: auto, a altura continuaria nos 600 px do atributo e o bolo ficaria achatado. Aula: Imagens que se Adaptam.
border-radius: 12px
Arredonda os quatro cantos da foto. Aula: Cantos Arredondados.
.foto figcaption
A legenda fica menor (0.875rem, 14 px), num marrom mais claro e centralizada: informação de apoio, que não compete com o texto.

O que muda na tela: a foto encaixa exatamente na coluna, com os cantos arredondados, e a rolagem para o lado desaparece. No quadro de 375 px (um celular), ela fica com 343 × 257 px, os 375 menos 16 px de cada lado. A legenda "O bolo pronto, ainda morno." aparece pequena e centralizada embaixo.

Por que não max-width: 100%? Também funciona, e é o que muita gente usa: a foto encolhe se não couber, mas nunca cresce além dos 800 px dela. Aqui usamos width: 100% porque queremos a foto sempre da largura da coluna; na versão 6, quando a coluna passa de 800 px, ela cresce junto. Para uma foto pequena, como um avatar de 96 px, use max-width: esticada, ela ficaria borrada.

Versão 4 · Tempo, rendimento e dificuldade em cartões

As três informações rápidas são o que a pessoa procura primeiro ("dá tempo de fazer antes do almoço?"). Em vez de uma lista empilhada, vamos pô-las lado a lado, cada uma num cartão, como o quadrinho colorido dos livros de receita.

.info {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
  margin: 0 0 1.5rem;
}

.info div {
  flex: 1 1 8rem;
  padding: 0.5rem 1rem;
  background-color: #fff;
  border: 1px solid #fed7aa;
  border-radius: 8px;
}

.info dt {
  font-size: 0.75rem;
  text-transform: uppercase;
  letter-spacing: 0.05em;
  color: #9a3412;
}

.info dd {
  margin: 0;
  font-weight: 700;
}
.info { display: flex; }
Os filhos diretos do <dl>, os três <div>, ficam um ao lado do outro. Aula: Introdução ao Flexbox.
flex-wrap: wrap e gap: 0.75rem
Se não couberem numa linha, os cartões descem para a seguinte; entre eles, 12 px de espaço, nas duas direções. Aulas: Quebrando Linha e Espaço entre Itens.

Versão 6 · Duas colunas na tela larga

Na cozinha, a pessoa olha os ingredientes e o passo atual ao mesmo tempo. Num monitor, há espaço para isso: ingredientes numa coluna estreita, modo de preparo numa coluna larga ao lado. No celular, não há: continua tudo empilhado. Isso é mobile first: o CSS de antes é o do celular, e a regra nova só entra a partir de uma largura.

@media (min-width: 48rem) {
  .receita {
    max-width: 60rem;
  }

  .colunas {
    display: grid;
    grid-template-columns: 1fr 2fr;
    gap: 2rem;
  }
}
@media (min-width: 48rem) { … }
As regras de dentro só valem quando a área da página tem 48rem (768 px) ou mais. Dentro de uma caixa do guia, quem conta é a largura do quadro do resultado, não a da sua janela. Aulas: Media Queries e Mobile First.
.receita { max-width: 60rem; }
Na tela larga, a coluna pode chegar a 960 px, para caberem as duas colunas de dentro.
display: grid + grid-template-columns: 1fr 2fr
O .colunas vira uma grade de duas colunas: a primeira com 1 parte do espaço, a segunda com 2 partes. Os dois filhos (as duas <section>) caem um em cada coluna, na ordem do HTML. Aulas: Introdução ao Grid e Colunas.
gap: 2rem
32 px entre as duas colunas.

O que muda na tela: num quadro de 768 px, a página ocupa o quadro todo, a foto cresce junto (736 px de largura), os três cartões ficam numa linha, e "Ingredientes" fica numa coluna à esquerda com cerca de 235 px, ao lado de "Modo de preparo", com cerca de 469 px; cada título com a sua linha cor de pêssego. Num quadro de 870 px, é igual, só que mais largo (cerca de 269 e 537 px). No quadro de 375 px, nada disso acontece: a página fica igual à da versão 5, empilhada.

A largura do quadro: na barra de cada caixa há os botões 375 (celular), 768 (tablet) e cheia (a largura toda da caixa). O quadro da caixa abaixo já abre em 768 px. Numa janela de 1100 px, a largura "cheia" dá uns 728 px: menos que os 768 do @media, e a página fica empilhada. Não é erro, é o @media fazendo o trabalho dele.

Quando dá errado

A foto passa da coluna (e a página rola para o lado)

É o que você viu na versão 2: sem regra para a imagem, ela usa os 800 px dos atributos width e height, mesmo dentro de uma coluna de 640 px ou de uma tela de celular. A causa mais comum, depois de já ter escrito a regra, é esquecer o ;:

.foto img {
  display: block;
  width: 100%
  height: auto;
  border-radius: 12px;
}

O que você vê: no quadro de 375 px, os cantos continuam arredondados, mas a foto volta para 800 × 600 px, sai pela direita da tela, e a página inteira ganha rolagem para o lado; o resto (título, cartões, listas) continua na largura certa. Por quê: sem o ;, o navegador lê width: 100% height: auto como uma declaração de width com um valor sem sentido e a ignora inteira; a altura vai junto. No F12, a declaração aparece riscada. O validador diz:

$ vnu --css style.css
"file:/home/ana/receita/style.css":4.3-4.8: error: CSS: “width”: Missing a semicolon before the property name “height”.

"Falta um ponto e vírgula antes da propriedade height". A posição 4.3-4.8 (linha 4, colunas 3 a 8) aponta para a palavra height, mas o ; que falta é o do fim da linha 3.

A coluna não centraliza: ocupa a tela toda

.receita {
  max-width: 40 rem;
  margin: 0 auto;
  padding: 1rem;
}

O que você vê: num quadro largo, o texto vai de uma borda à outra, como antes da versão 2. O margin: 0 auto está certo, mas não tem o que centralizar: sem largura máxima, a coluna já é da largura toda. Por quê: o espaço entre 40 e rem transforma o valor em dois pedaços, um número sem unidade e uma palavra, e o navegador descarta a declaração. O estilo calculado do max-width fica none. O validador:

$ vnu --css style.css
"file:/home/ana/receita/style.css":2.17-2.19: error: CSS: “max-width”: Too many values or values are not recognized.

"Valores demais, ou valores não reconhecidos." Número e unidade andam sempre grudados: 40rem, 12px.

As duas colunas nunca aparecem

Dois jeitos comuns de errar o @media, cada um com a sua mensagem:

@media (min-width: 48 rem) {
  .colunas {
    display: grid;
  }
}

$ vnu --css style.css
"file:/home/ana/receita/style.css":1.26-1.26: error: CSS: only “0” can be a “unit”. You must put a unit after your number
@media min-width: 48rem {
  .colunas {
    display: grid;
  }
}

$ vnu --css style.css
"file:/home/ana/receita/style.css":5.2-6.1: error: CSS: unrecognized media “min-width”.

O que você vê, nos dois casos: mesmo no quadro de 768 ou 870 px, os ingredientes ficam em cima do modo de preparo; o .colunas continua display: block. Por quê: uma condição de @media que o navegador não entende é tratada como falsa, e o bloco inteiro é pulado, em silêncio. No primeiro, o espaço separa o número da unidade ("só o 0 pode ficar sem unidade: ponha uma unidade depois do número"). No segundo, faltaram os parênteses em volta de min-width: 48rem.

Um terceiro motivo, que o validador não pega: o @media está certo, mas a tela (ou o quadro) tem menos de 768 px. Antes de procurar erro, confira a largura: no celular, a página empilhada é o resultado certo.

O cartão não ficou ao lado: cada um numa linha

O display: flex foi parar no lugar errado:

.info div {
  display: flex;
}

O que você vê: os três cartões continuam um embaixo do outro. Dentro de cada um, o rótulo e o valor é que ficam lado a lado ("TEMPO 1h10"). Por quê: display: flex organiza os filhos do elemento que o recebe. Para os cartões ficarem lado a lado, quem precisa dele é o pai dos cartões, o .info. O validador não acusa nada: o CSS é válido, só não faz o que você queria.

Resumo

  • Comece pelo chão: box-sizing: border-box para todos, e fonte, altura de linha e cores no body.
  • Coluna de leitura: max-width + margin: 0 auto + um padding para o celular.
  • Foto que se adapta: display: block; width: 100%; height: auto;. Os atributos width e height do HTML continuam úteis: dão a proporção e evitam o "pulo" da página.
  • Cartões: display: flex no pai, com flex-wrap e gap; flex: 1 1 8rem nos filhos.
  • ::marker pinta bolinhas e números; border-left faz a barra de destaque.
  • Mobile first: o CSS de fora vale para todos; o @media (min-width: 48rem) acrescenta as duas colunas com Grid só onde cabem.
  • Quando algo "não pega", o navegador ignorou a declaração: procure o ; que faltou, o espaço entre número e unidade e os parênteses do @media. O validador acha esses três.
