CSS e HTML

HTML e CSS trabalham juntos, mas cada um tem o seu serviço. O HTML diz o que cada pedaço da página é: um título, uma lista, um link. O CSS diz como esse pedaço aparece: a cor, o tamanho, a posição. Nesta aula você vai ver a mesma receita da Ana com duas roupas diferentes, descobrir de onde vem o visual de uma página sem CSS e aprender a não usar o HTML para fazer o serviço do CSS.

Você vai aprender
  • A divisão de trabalho: estrutura (HTML) × aparência (CSS).
  • Como o mesmo HTML ganha caras bem diferentes só trocando o arquivo de CSS.
  • O visual padrão que o navegador dá a cada elemento, com os valores reais.
  • Por que escolher o elemento pelo significado, e não pelo tamanho ou pela cor.
  • Os elementos e atributos antigos de aparência (<font>, <center>, align, bgcolor) e o que o validador diz deles.

A ideia: a receita e o jeito de apresentar

Pense na receita do bolo de cenoura da Ana. O conteúdo é sempre o mesmo: o nome, a lista de ingredientes, o modo de preparo. Mas ela pode aparecer escrita à mão num caderno, impressa num cartaz colorido na padaria ou numa página de livro. O caderno não muda a receita; muda só a apresentação.

PerguntaQuem respondeExemplo
O que é isto?HTML (estrutura)"Bolo de cenoura" é o título da página; os ingredientes são uma lista.
Como isto aparece?CSS (aparência)O título é marrom, com uma linha dupla embaixo; a lista não tem bolinhas.

Essa separação tem nome: separar a estrutura (ou o conteúdo) da apresentação. Ela é a razão de o CSS existir.

1. O HTML diz o que é

Quando você escreve <h1>Bolo de cenoura</h1>, não está pedindo "letra grande". Está dizendo "este é o título principal da página". Quem usa essa informação:

  • o leitor de tela (o programa que lê a página em voz alta para quem não enxerga) anuncia "título nível 1" e deixa pular de título em título;
  • o Google e outros buscadores usam os títulos para entender do que a página trata;
  • o modo de leitura do navegador monta a versão "limpa" da página a partir dessa estrutura.

Nenhum deles enxerga a cor ou o tamanho da letra. Para eles, só a estrutura importa. (A escolha dos elementos pelo significado é o assunto do Guia HTML: wallysondevs.github.io/guia-html.)

Com o caderno.css: fundo creme (ivory, "marfim"), letra com serifa, título marrom com uma linha dupla embaixo e o subtítulo "Ingredientes" em itálico. Com o cartaz.css: fundo azul-escuro, letra branca e sem serifa, tudo centralizado, o título amarelo-ouro em maiúsculas e a lista sem as bolinhas.

Repare no título do cartaz: aparece "BOLO DE CENOURA", mas no HTML continua escrito "Bolo de cenoura". As maiúsculas são só aparência; o texto de verdade, que o leitor de tela e o Google recebem, não mudou. (Isso tem aula própria: Maiúsculas e Minúsculas.)

As propriedades desses arquivos (font-family, border-bottom, text-transform…) vão aparecer, cada uma, na sua aula. Aqui o que importa é a ideia: o HTML ficou parado e a página mudou de roupa.

3. O visual padrão do navegador

Uma página sem nenhum CSS não sai "sem estilo". O navegador tem uma folha de estilo própria (em inglês, user agent stylesheet, "folha do agente do usuário", que é o nome técnico do navegador) com um visual padrão para cada elemento:

<h1>Receitas da Ana</h1>
<p>Um bolo <em>muito</em> fofo, de <strong>cenoura</strong>. <a href="bolo.html">Ver a receita</a></p>
<ul>
  <li>3 cenouras</li>
</ul>

Os valores que o navegador usa (conferidos no Chromium, com a letra padrão de 16 pixels):

ElementoVisual padrãoEm CSS
<h1>letra 2 vezes maior, negritofont-size 32px, font-weight 700
<h2>letra 1,5 vez maior, negritofont-size 24px
<p>espaço em cima e embaixomargin-top 16px
<em>itálicofont-style: italic
<strong>negritofont-weight 700
<a href>azul e sublinhadocolor rgb(0, 0, 238), text-decoration underline
<ul>bolinhas, recuo à esquerdalist-style-type: disc, padding-left 40px
<body>uma margem fininha em volta da páginamargin 8px

Esses valores são sugestões, e cada navegador tem as suas (parecidas, mas não idênticas). O seu CSS pode mudar qualquer uma: um <h1> pode ficar pequeno, um <em> pode deixar de ser itálico. O elemento continua significando a mesma coisa. Como ver esses valores no seu navegador: aula Inspecionando com o F12.

Experimente: este CSS deixa o <h1> com a letra do tamanho normal (16 pixels). Ele continua sendo o título da página para o leitor de tela e para o Google. Troque 16px por 48px e veja o tamanho mudar sem mexer no HTML.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>

h1 {
  font-size: 16px;
}

4. Escolha pelo significado, ajuste pelo CSS

O erro mais comum de quem está começando: escolher o elemento pela aparência que ele tem por padrão. "O <h1> é grande demais, vou usar <h4>." Funciona na tela, mas a estrutura fica errada: para o leitor de tela, a página não tem título principal.

Você quer…Errado (HTML pela aparência)Certo (HTML pelo significado + CSS)
Um título principal menor<h4><h1> + font-size no CSS
Espaço entre dois parágrafos<br><br><br> ou <p>&nbsp;</p>margin no CSS (Margem)
Texto em itálico só por enfeite<em> (que quer dizer ênfase)font-style: italic no CSS
Uma citação com recuo<ul> sem itens, só pelo recuo<blockquote> + o recuo que quiser no CSS
Um menu de links em linhalinks soltos separados por |<nav> com lista + Flexbox

A regra de bolso: primeiro escreva o HTML como se o CSS não existisse, escolhendo cada elemento pelo que ele é. Depois dê a aparência com CSS.

5. O jeito antigo: HTML fazendo papel de CSS

Antes do CSS, a aparência era escrita no próprio HTML. Você ainda vai encontrar isso em sites velhos e em tutoriais antigos:

<body bgcolor="linen">
<center>Receitas da Ana</center>
<p><font color="red">Promoção!</font></p>
<p align="center">Bolo de fubá</p>
bgcolor="linen"
Cor de fundo da página. Hoje: background-color no CSS.
<center>
Centraliza o que está dentro. Hoje: text-align: center.
<font color="red">
Muda a cor (e o tamanho e a fonte) de um trecho. Hoje: color.
align="center"
Alinha um parágrafo. Hoje: text-align.

Por que isso foi abandonado:

  • Repetição: 30 promoções no site = 30 <font color="red">. Mudar a cor da promoção é editar 30 lugares. Com CSS, é uma linha.
  • Mistura: o HTML fica cheio de enfeites, difícil de ler e de manter.
  • Obsoleto: o HTML de hoje tirou esses elementos e atributos da lista do que é válido. Os navegadores ainda desenham (para não quebrar sites velhos), mas o validador reclama.

Quando dá errado

Aparência no HTML: The “font” element is obsolete. Use CSS instead. 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas</title>
</head>
<body>
<p><font color="red">Promoção!</font></p>
<center>Receitas da Ana</center>
<p align="center">Bolo de fubá</p>
</body>
</html>

$ vnu antigo.html
"file:/home/ana/site/antigo.html":8.4-8.21: error: The “font” element is obsolete. Use CSS instead.
"file:/home/ana/site/antigo.html":9.1-9.8: error: The “center” element is obsolete. Use CSS instead.
"file:/home/ana/site/antigo.html":10.1-10.18: info warning: The “align” attribute on the “p” element is obsolete. Use CSS instead.

O que significa: "o elemento font é obsoleto. Use CSS no lugar", o mesmo para o center, e um aviso (info warning, mais leve que um erro) para o atributo align do p. O próprio validador manda usar CSS. Com o bgcolor do <body> é igual:

$ vnu bg.html
"file:/home/ana/site/bg.html":7.1-7.22: info warning: The “bgcolor” attribute on the “body” element is obsolete. Use CSS instead.

O que o navegador faz: desenha tudo normalmente (vermelho, centralizado), por isso o erro passa despercebido. Só o validador avisa.

Como consertar: tire os enfeites do HTML e passe para o CSS. É a missão logo abaixo.

Missão: a página da Ana usa <center> e <font>. Tire os dois do index.html (deixe só o <h1> e o <p> com o texto) e faça o mesmo efeito com CSS: na aba style.css, o h1 centralizado (text-align: center;) e o p com color: firebrick;.

<link rel="stylesheet" href="style.css">

<p><font color="firebrick">Promoção: bolo de cenoura pela metade do preço!</font></p>

Um <h4> no lugar do <h1>, só pelo tamanho 
<h4>Receitas da Ana</h4>
<p>Bolo de fubá</p>

O que você vê: um título pequeno, do jeito que a Ana queria. Na tela, parece tudo certo.

O problema: a página ficou sem título principal. Quem navega pelos títulos com o leitor de tela encontra só um "título nível 4", como se faltassem três níveis acima dele. Num documento completo, o validador avisa (com um info warning, não um erro):

$ vnu titulo.html
"file:/home/ana/site/titulo.html":8.1-8.4: info warning: This document has heading elements but none of them has a computed heading level of 1.

"Este documento tem títulos, mas nenhum deles tem nível 1."

Como consertar: <h1> no HTML e o tamanho no CSS: h1 { font-size: 16px; }, como no "Experimente" da seção 3. Tamanhos de letra têm aula própria: Tamanho da Letra.

<br> para dar espaço: o validador não reclama 
<p>Bolo de fubá</p>
<br><br><br>
<p>Pão de queijo</p>

O que acontece: o espaço aparece, e o vnu não mostra erro nenhum: <br> é um elemento válido. Mas o <br> quer dizer "quebra de linha dentro do texto" (num endereço, num poema), não "espaço". O espaço fica preso no HTML, e para mudá-lo é preciso editar cada página.

Como consertar: tire os <br> e use a margem no CSS: p { margin-bottom: 48px; } (aula Margem).

Resumo

  • HTML = estrutura (o que cada coisa é). CSS = aparência (como ela aparece). Cada um no seu arquivo.
  • O mesmo HTML pode ganhar caras completamente diferentes trocando só o CSS.
  • Sem CSS, vale a folha padrão do navegador: <h1> com 32px e negrito, link azul e sublinhado, lista com bolinhas. São sugestões que o seu CSS muda.
  • Escolha o elemento pelo significado, nunca pela aparência padrão; ajuste o visual com CSS.
  • <font>, <center>, align e bgcolor são obsoletos: o validador manda "Use CSS instead".
  • <br> para dar espaço e <h4> no lugar do <h1> não dão erro no validador, mas deixam a estrutura errada.
