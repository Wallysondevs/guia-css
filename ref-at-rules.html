CSS Regras @

Quase todo o CSS é feito de regras "seletor + declarações". As regras @ (at-rules, "regras arroba") são diferentes: começam com @ e dão instruções ao navegador. "Só aplique isto em telas pequenas" (@media), "baixe esta fonte" (@font-face), "esta é uma animação" (@keyframes). Esta página lista todas, com um exemplo e a aula de cada uma.

Como usar esta página
  • Procure com Ctrl+F pelo nome (@media, @layer).
  • O comportamento nos erros foi conferido no Chromium, lendo as regras que o navegador guardou (document.styleSheets). As mensagens são do validador W3C (vnu 26.10.12).
  • O suporte vem dos dados do MDN (outubro de 2026). As regras recentes estão marcadas com novo.

Os dois formatos

Pense num caderno de receitas. Algumas anotações são uma linha só ("veja também o caderno da vó": @import). Outras são um bloco inteiro de receitas que só vale num caso ("para festas": @media).

@import url("tema.css");          /* formato 1: uma linha, termina em ; */

@media (max-width: 600px) {        /* formato 2: um bloco entre { } */
  .menu {
    flex-direction: column;
  }
}
@import
O nome da regra: @ grudado no nome.
url("tema.css");
No formato de uma linha, o que vem depois do nome termina com ;.
(max-width: 600px)
A condição (ou o "prelúdio"): quando ou para quem o bloco vale.
{ … }
O bloco. Dentro de @media, @supports, @container e @layer vão regras inteiras (seletor + chaves). Dentro de @font-face e @page, só declarações. Dentro de @keyframes, as etapas da animação.
}
Repare nas duas chaves de fechamento no fim: uma fecha o .menu, a outra fecha o @media. Esquecer a segunda é um dos erros mais comuns (veja abaixo).

Regras condicionais: "só se…"

RegraO bloco vale quando…ExemploAula
@mediaa tela (ou a impressora) cumpre a condição: largura, orientação, tema escuro, menos movimento…@media (min-width: 48rem) { … }Media Queries, Mobile First
@containero contêiner (um ancestral com container-type) cumpre a condição: um cartão que muda conforme o espaço que ele tem, não a tela@container (min-width: 30rem) { … }Container Queries
@supportso navegador entende uma propriedade, um valor ou um seletor@supports (display: grid) { … } · @supports selector(:has(a)) { … } · @supports not (…)@supports
Suporte: @media e @supports funcionam em todos. @container: Chrome 105, Firefox 110, Safari 16. O @supports selector(): Chrome 83, Firefox 69, Safari 14.1.

Regras de organização

RegraPara quêExemploAula
@importpuxa outro arquivo CSS para dentro deste. Tem de vir no começo, antes de qualquer regra (só @charset e @layer podem vir antes). Cada @import é mais um download em sequência: num site publicado, prefira vários <link> no HTML.@import url("tema.css") layer(tema);Organizando os Arquivos, CSS Rápido
@layercria camadas na cascata: uma camada declarada depois vence as de antes, não importa a especificidade@layer reset, base, componentes; e @layer base { … }@layer
@scope novolimita as regras a um pedaço da página (de .cartao até, opcionalmente, um limite)@scope (.cartao) to (.rodape) { img { … } }@scope
@charsetdiz a codificação do arquivo. Hoje, com tudo em UTF-8, quase nunca é preciso; se usar, é a primeira linha, exatamente @charset "utf-8";@charset "utf-8";—
@namespacepara CSS de documentos XML e SVG com espaços de nome; quase nunca em páginas HTML@namespace svg url(http://www.w3.org/2000/svg);—
Suporte: @layer: Chrome 99, Firefox 97, Safari 15.4. @scope chegou por último: Chrome 118, Firefox 146, Safari 26.4; em navegadores mais antigos o bloco inteiro é ignorado.

Fontes, animações e outras definições

RegraDefine…ExemploAula
@font-faceuma fonte para baixar: o nome que você vai usar no font-family e o arquivo@font-face { font-family: "Lato"; src: url("lato.woff2") format("woff2"); font-display: swap; }@font-face
@keyframesas etapas de uma animação (from, to ou porcentagens), com um nome que o animation usa@keyframes pulo { from { … } 50% { … } to { … } }Animações
@propertyuma variável com tipo (ângulo, cor, tamanho), valor inicial e herança. Com tipo, o navegador consegue animar a variável.@property --giro { syntax: "<angle>"; inherits: false; initial-value: 0deg; }Variáveis
@starting-style novoo estilo de "antes de aparecer": permite animar a entrada de um elemento que acabou de surgir (de display: none para visível, um <dialog> abrindo)@starting-style { .aviso { opacity: 0; } }Transições
@pagea folha na impressão: margens, tamanho@page { margin: 2cm; }Impressão
@counter-styleum estilo de numeração próprio para listas@counter-style estrela { system: cyclic; symbols: "★"; suffix: " "; }Listas
@font-feature-values, @font-palette-valuesnomes para recursos especiais de uma fonte / paletas de cores de fontes coloridas——

@position-try novoposições alternativas para um elemento ancorado (uma dica que troca de lado quando não cabe)——
Suporte: @font-face, @keyframes e @page funcionam em todos. @property: Chrome 85, Safari 16.4 e Firefox 128. @starting-style: Chrome 117, Firefox 129, Safari 17.5. @counter-style: Chrome 91, Firefox 33, Safari 17. @view-transition: Chrome 126 e Safari 18.2, ainda não no Firefox. @position-try: Chrome 125, Firefox 147, Safari 26. @function (funções feitas por você) e @custom-media ainda estão em teste: não use num site de verdade.

O que o validador W3C conhece

Testadas uma por uma no vnu 26.10.12, com CSS correto:

Passaram sem mensagemDeram erro, mas estão certas
@media (inclusive width >= 600px), @supports (inclusive selector()), @import … layer(), @layer, @scope, @font-face, @keyframes, @page, @counter-style, @charset@container, @property, @starting-style, @view-transition: todas com error: CSS: Unrecognized at-rule “@container” (e o nome de cada uma)

Unrecognized at-rule = "regra @ não reconhecida". Nas quatro da direita, o erro é do validador, que ainda não as conhece; os navegadores da nota acima entendem. Mas a mesma mensagem aparece quando o nome está errado (@keyframe, sem o "s"): confira a grafia antes de culpar o validador.

Experimente

Quatro regras @ juntas. Mude a largura da janela do navegador (ou abra o resultado numa aba nova com ↗ e estreite a janela) para ver o @media agir; troque o display: grid do @supports por algo que não existe, como display: gradezinha, e veja o bloco ser ignorado:

<link rel="stylesheet" href="style.css">
<h1>Padaria da Ana <span class="selo">novo!</span></h1>
<div class="vitrine">
  <p>Pão francês</p>
  <p>Pão de queijo</p>
  <p>Sonho</p>
</div>

@layer base, destaque;

@layer destaque {
  h1 { color: saddlebrown; }
}

@layer base {
  h1 { color: gray; }
  .vitrine p { padding: 0.5rem; background-color: wheat; }
}

@supports (display: grid) {
  .vitrine {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 0.5rem;
  }
}

@media (max-width: 30rem) {
  .vitrine { grid-template-columns: 1fr; }
}

@keyframes pulo {
  from { transform: translateY(0); }
  to { transform: translateY(-4px); }
}

.selo {
  display: inline-block;
  font-size: 0.9rem;
  color: white;
  background-color: tomato;
  padding: 0 0.25rem;
  animation: pulo 0.5s ease-in-out infinite alternate;
}

Repare no título: a camada base o pinta de cinza, mas a camada destaque foi declarada depois na primeira linha (@layer base, destaque;), então vence, mesmo vindo antes no arquivo. Ele fica marrom.

Quando dá errado

Erros numa regra @ costumam fazer um bloco inteiro sumir, e às vezes levam junto regras que estavam certas. Tudo abaixo foi conferido no Chromium:

EscritoO que o navegador fezO validador
@media screen and(max-width: 600px) { … } (sem espaço depois do and)guardou como @media not all: o bloco nunca vale, em tela nenhuma. Grudado no parêntese, and( vira o nome de uma "função" que não existe.Parse Error.
@media (max-widht: 600px) { … } (nome da condição errado)guardou o bloco, mas a condição desconhecida é sempre falsa: o bloco nunca valenenhuma mensagem
@media (max-width: 600px) sem a {, seguido de h1 { … }"engoliu" o h1 como parte da condição: ficou um @media not all { } vazio, e a regra do h1 sumiu. A regra seguinte voltou a funcionar.Parse Error.
@media (…) { sem a } final, com mais regras depoisas regras seguintes ficaram dentro do @media: só valem quando a condição vale. Se o @media é a última coisa do arquivo, o navegador fecha sozinho e nada muda (mas o validador reclama).Parse Error.
h1 { … } e depois @import url("tema.css");ignorou o @import: o arquivo nem é baixado@import are not allowed after any valid statement other than @charset and @import.
@keyframe pulo { … } (sem o "s")ignorou o bloco; a animação pulo não existe e nada se mexeUnrecognized at-rule “@keyframe”
Como achar no F12
  • No painel Styles (Estilos) da aba Elements, as regras que vêm de um @media aparecem com a condição escrita em cima. Se a regra que você esperava não aparece, a condição não está valendo (ou foi descartada).
  • Para testar larguras, use o modo de aparelhos do F12 (o ícone de celular e tablet) e arraste a largura.
  • Para testar prefers-color-scheme e prefers-reduced-motion sem mudar o sistema, o Chrome tem a aba Rendering (no menu ⋮ do F12, "More tools"), com opções para simular essas preferências.

@import are not allowed after any valid statement other than @charset and @import = "o @import não é permitido depois de nenhuma regra válida, a não ser @charset e @import". (O @layer sem bloco, como @layer base, tema;, também pode vir antes, pelo padrão.)

Missão

Missão: o selo "novo!" devia pular, mas não se mexe. (1) Conserte o nome da regra @ da animação. (2) Seja gentil com quem pediu menos movimento: acrescente um @media (prefers-reduced-motion: reduce) que desliga a animação do .selo (animation: none;).

<link rel="stylesheet" href="style.css">
<h1>Padaria da Ana <span class="selo">novo!</span></h1>

@keyframe pulo {
  from { transform: translateY(0); }
  to { transform: translateY(-4px); }
}

.selo {
  display: inline-block;
  color: white;
  background-color: tomato;
  animation: pulo 0.5s ease-in-out infinite alternate;
}

@keyframes pulo {
  from { transform: translateY(0); }
  to { transform: translateY(-4px); }
}

.selo {
  display: inline-block;
  color: white;
  background-color: tomato;
  animation: pulo 0.5s ease-in-out infinite alternate;
}

@media (prefers-reduced-motion: reduce) {
  .selo {
    animation: none;
  }
}

Resumo

  • Regras @ começam com @: algumas terminam em ; (@import, @layer a, b;), outras têm um bloco { }.
  • Condicionais: @media (a tela), @container (o contêiner), @supports (o navegador entende?).
  • Organização: @import (sempre no começo), @layer, @scope.
  • Definições: @font-face, @keyframes, @property, @starting-style, @page, @counter-style.
  • Um erro numa regra @ derruba o bloco inteiro: and( sem espaço, chave esquecida, nome errado.
  • O vnu 26.10.12 ainda não conhece @container, @property, @starting-style e @view-transition: o erro Unrecognized at-rule nelas é do validador.
