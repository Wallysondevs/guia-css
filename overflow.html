CSS overflow

Quando você dá uma altura fixa a uma caixa e põe dentro mais texto do que cabe, o que acontece? O texto não some nem encolhe: ele transborda, sai pela borda e passa por cima do que vem depois. A propriedade overflow ("transbordamento") decide o que fazer com essa sobra: deixar à mostra, cortar ou criar uma barra de rolagem. Nesta aula você vai ver cada opção e resolver o problema mais chato de sites no celular: a página que rola para o lado.

Você vai aprender
  • Quando um conteúdo transborda e o que o navegador faz por padrão.
  • Os valores visible, hidden, scroll, auto e clip, lado a lado.
  • overflow-x e overflow-y: cada direção separada.
  • Os usos do dia a dia: caixa de comentários com rolagem, cartão de cantos arredondados, tabela larga.
  • A página que rola para o lado no celular: como achar o culpado.
  • Os erros: overflow que não faz nada, sombra e foco cortados e o validador W3C.

Os resultados são desenhados pelo seu navegador. A aparência da barra de rolagem depende do sistema: no Windows e no Linux ela costuma ficar sempre à mostra; no macOS, no Android e no iPhone ela costuma aparecer só enquanto você rola.

A ideia: o copo cheio

Encha um copo além da boca: a água transborda e molha a mesa. Você tem três escolhas. Deixar transbordar (e molhar o que estiver em volta). Pôr uma tampa e jogar fora o que não coube. Ou trocar por uma garrafa com tampa de rosca, que guarda tudo e deixa você pegar aos poucos. No CSS, a caixa é o copo, o conteúdo é a água, e o overflow é a sua escolha.

1. O padrão: transborda à mostra

Uma caixa só transborda quando tem um tamanho fixo menor que o conteúdo. Sem height, a caixa cresce para caber tudo, e não há o que transbordar.

<style>
  .recado {
    height: 40px;
    width: 220px;
    border: 2px solid navy;
    background-color: #e8ecff;
  }
</style>
<div class="recado">Bolo de cenoura com cobertura de chocolate, fofinho, perfeito para o café da tarde de domingo com a família toda.</div>
<p>Este parágrafo vem depois do recado.</p>

A borda azul marca os 40px de altura da caixa. O texto que não coube sai por baixo da borda, sem o fundo azul-claro, e se mistura com o parágrafo seguinte. O parágrafo não desce para dar lugar: para a página, a caixa continua tendo 40px. Esse é o valor padrão, overflow: visible ("visível").

2. Os valores, lado a lado

As cinco caixas têm o mesmo texto e o mesmo tamanho. Só o overflow muda:

<style>
  .caixa {
    display: inline-block;
    vertical-align: top;
    width: 140px;
    height: 60px;
    margin: 6px 6px 50px;
    border: 2px solid navy;
    background-color: #e8ecff;
    font-size: 14px;
  }
  .visible { overflow: visible; }
  .hidden  { overflow: hidden; }
  .scroll  { overflow: scroll; }
  .auto    { overflow: auto; }
  .clip    { overflow: clip; }
</style>
<div class="caixa visible">visible: o texto que não cabe sai pela borda de baixo da caixa. Bolo de cenoura com cobertura de chocolate.</div>
<div class="caixa hidden">hidden: o texto que não cabe é cortado na borda da caixa. Bolo de cenoura com cobertura de chocolate.</div>
<div class="caixa scroll">scroll: o texto que não cabe fica guardado, e a caixa ganha barras. Bolo de cenoura com cobertura de chocolate.</div>
<div class="caixa auto">auto: a barra só aparece quando o texto não cabe, como aqui. Bolo de cenoura com cobertura de chocolate.</div>
<div class="caixa auto">auto: cabe.</div>
<div class="caixa clip">clip: corta como o hidden, e nem o JavaScript consegue rolar. Bolo de cenoura com cobertura de chocolate.</div>
ValorO que faz com a sobraRola?
visibleDeixa à mostra, fora da caixa (padrão)Não
hiddenCorta na borda da caixaNão com o mouse; o JavaScript e o foco do Tab ainda conseguem rolar
scrollGuarda dentro e mostra barras de rolagem, sempre, mesmo sem sobraSim
autoGuarda dentro e mostra a barra só quando precisaSim
clipCorta na borda, e a caixa não rola de jeito nenhumNão

Repare nas duas caixas auto: a primeira, com texto demais, ganha a barra de rolagem; a segunda, com texto curto, fica igual a uma caixa normal. Já a scroll reserva o lugar das barras mesmo quando não precisa delas (nos sistemas em que a barra fica sempre à mostra). Por isso, no dia a dia, auto é a escolha mais comum.

clip é mais novo

O overflow: clip funciona no Chrome e no Edge desde a versão 90, no Firefox desde a 81 e no Safari desde a 16: todos os navegadores atuais. Num navegador antigo, a declaração é ignorada e a caixa fica com visible. Na maioria dos casos, hidden dá o mesmo resultado na tela.

3. Uma direção de cada vez: overflow-x e overflow-y

O overflow é um atalho para duas propriedades: overflow-x (na horizontal, para os lados) e overflow-y (na vertical, para baixo). Com uma palavra, vale para as duas; com duas palavras, a primeira é a do x e a segunda a do y.

/* as duas direções */
.comentarios {
  overflow: auto;
}

/* só a vertical rola */
.lista {
  overflow-y: auto;
}

/* só a horizontal rola */
.tabela-rolagem {
  overflow-x: auto;
}
Uma regra escondida

Não dá para ter visible numa direção e corte ou rolagem na outra. Se você escreve overflow-y: hidden e deixa o x no padrão, o navegador troca o visible do x por auto. O F12 mostra isso na aba Computed: overflow-x: auto, mesmo sem você ter escrito.

Missão: os comentários estão vazando por cima do rodapé. Faça a caixa ganhar uma barra de rolagem só quando precisar, mantendo a altura de 120px.

5. A página que rola para o lado

No celular, você arrasta a página para cima e ela escorrega também para o lado, mostrando uma faixa vazia. Algum elemento está mais largo que a tela e transborda do <body>; como a página inteira tem overflow rolável, ela ganha rolagem horizontal. Os culpados de sempre:

CulpadoConserto
Uma imagem maior que a telaimg { max-width: 100%; height: auto; } (aula Imagens que se Adaptam)
Uma palavra ou endereço comprido, sem espaço para quebraroverflow-wrap: anywhere; (aula Texto que Não Cabe)
Uma tabela com muitas colunasA tabela dentro de uma <div> com overflow-x: auto (aula Tabelas)
Um width fixo em px maior que a telamax-width em vez de width (aula Largura e Altura)
Um elemento com width: 100% + padding e bordabox-sizing: border-box (aula box-sizing)

Experimente: a caixa tracejada faz o papel da tela do celular (260px). O endereço comprido transborda pela direita. Troque o overflow: visible por auto e veja a barra de rolagem aparecer só na caixa; depois volte para visible e acrescente overflow-wrap: anywhere; ao .tela: o endereço passa a quebrar e não sobra nada.

<link rel="stylesheet" href="style.css">
<div class="tela">
  <p>Receita completa em:</p>
  <p>https://receitasdaana.example/bolos/bolodecenouracomcoberturadechocolate</p>
</div>

.tela {
  width: 260px;
  border: 2px dashed gray;
  overflow: visible;
}
Não esconda o sintoma

Um body { overflow-x: hidden; } some com a rolagem para o lado, mas o conteúdo largo continua cortado, só que agora sem jeito de ver. Ache o culpado: no F12, procure o elemento que passa da borda direita da tela, ou teste apagar partes da página até a rolagem sumir. Conserte nele.

SituaçãoUse

Quando dá errado

overflow: auto e nenhuma barra aparece: a caixa não tem altura 
<style>
  .comentarios {
    overflow: auto;
    border: 1px solid #999999;
  }
</style>
<div class="comentarios">
  <p>Bia: Fiz no domingo e sumiu em minutos!</p>
  <p>Caio: Troquei a cobertura por brigadeiro.</p>
  <p>Duda: Dá para fazer sem ovos?</p>
</div>

O que você vê: a caixa mostra todos os comentários, sem barra de rolagem. Se a lista crescer, a caixa cresce junto.

Por quê: sem height (ou max-height), a caixa estica para caber o conteúdo; nada transborda, então o overflow não tem o que fazer. O validador não reclama: a declaração é válida.

Como consertar: dê um limite à caixa. max-height: 200px é melhor que height: com poucos comentários a caixa fica pequena, e só ganha barra quando passa dos 200px.

O hidden cortou a sombra e o contorno de foco 
<style>
  .cartao {
    overflow: hidden;
    padding: 2px;
    border: 1px dashed gray;
  }
  .cartao button {
    box-shadow: 0 0 0 12px tomato;
  }
</style>
<div class="cartao">
  <button>Comprar</button>
</div>

O que você vê: a moldura vermelha em volta do botão (uma sombra de 12px, aula Sombra) aparece fininha em cima, embaixo e à esquerda, cortada na borda da caixa tracejada. Só à direita, onde sobra espaço dentro da caixa, ela aparece inteira.

Por quê: o overflow: hidden corta tudo o que passa da borda: sombras, o contorno de foco (outline, que mostra onde está o Tab), menus que abrem para fora, selos pendurados no canto. Cortar o foco prejudica quem navega pelo teclado.

Como consertar: dê espaço (mais padding no pai), ponha o overflow: hidden só no elemento que precisa ser cortado (a foto, e não o cartão inteiro) ou use overflow: clip com overflow-clip-margin, que deixa uma margem antes do corte.

overflow: scrol: a declaração é ignorada 
.comentarios {
  height: 120px;
  overflow: scrol;
}

O que você vê: o texto continua transbordando, como se não houvesse overflow. No F12, a declaração aparece riscada no painel Styles, com um ícone de aviso.

$ vnu --css style.css
"file:/home/ana/site/style.css":3.13-3.17: error: CSS: “overflow”: “scrol” is not a “overflow” value.

O que significa: "scrol não é um valor de overflow". Faltou um l: scroll.

Resumo

  • O conteúdo transborda quando não cabe numa caixa de tamanho fixo. Por padrão (visible), a sobra aparece fora da caixa, por cima do que vem depois.
  • hidden e clip cortam; scroll mostra barras sempre; auto mostra a barra só quando precisa (o mais usado).
  • overflow-x e overflow-y controlam cada direção. visible numa direção vira auto se a outra não for visible.
  • Usos comuns: caixa de comentários com overflow-y: auto, tabela larga com overflow-x: auto, foto cortada nos cantos do cartão com overflow: hidden.
  • Página que rola para o lado: ache o elemento largo demais (imagem, palavra comprida, width fixo) em vez de esconder com overflow-x: hidden no body.
  • Erros: overflow sem limite de altura não faz nada; hidden corta também sombras e o foco; scrol não existe.
