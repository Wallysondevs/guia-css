CSS Mobile First

Com media queries, dá para fazer uma página responsiva de dois jeitos: começar pelo computador e ir tirando coisas para caber no celular, ou começar pelo celular e ir acrescentando coisas conforme a tela cresce. O segundo jeito se chama mobile first ("celular primeiro"), e é o que o guia recomenda: o CSS fica mais curto, mais fácil de entender e de consertar.

Você vai aprender
  • A diferença entre desktop first (max-width) e mobile first (min-width).
  • Por que começar pelo celular dá menos trabalho.
  • Uma página construída em três versões: celular, tablet e computador.
  • Como escolher os pontos de quebra, e em que ordem escrever as media queries.
  • Os erros mais comuns: a ordem trocada, os pontos sobrepostos e o conteúdo escondido no celular.

Os resultados são desenhados pelo seu navegador. Os quadros começam numa largura fixa: use os botões 375, 768 e cheia da barra do quadro para ver cada versão.

A ideia: a mochila e a mala

Para uma viagem curta, você enche primeiro uma mochila com o essencial: documento, escova de dente, uma muda de roupa. Se a viagem for maior e couber uma mala, você acrescenta: o casaco, o segundo sapato. Fazer o contrário dá mais trabalho: encher a mala até a boca e depois tentar enfiar tudo numa mochila, tirando peça por peça.

No CSS, a tela do celular é a mochila. Você escreve primeiro o que a página precisa em qualquer tela (cores, letras, uma coluna). Depois, em @media (min-width: …), acrescenta o que só faz sentido com mais espaço: colunas lado a lado, menu em linha, margens maiores.

1. O mesmo layout, dos dois jeitos

Um menu de três links: no celular, um embaixo do outro; a partir de 600 px, lado a lado. Primeiro, começando pelo computador (desktop first):

.menu a {
  display: block;
}

.menu {
  display: flex;
  gap: 1rem;
}

@media (max-width: 599px) {
  .menu {
    display: block;   /* desfaz o flex */
    gap: 0;           /* desfaz o gap */
  }
}

Agora começando pelo celular (mobile first):

.menu a {
  display: block;   /* no celular: cada link é um bloco, um embaixo do outro */
}

@media (min-width: 600px) {
  .menu {
    display: flex;
    gap: 1rem;
  }
}

O resultado é o mesmo. A diferença está no trabalho:

  • No desktop first, a media query desfaz o que foi feito antes. Cada propriedade do computador precisa de um "desfazer" no celular, e é fácil esquecer um (o gap, uma margem, uma largura).
  • No mobile first, o celular usa o comportamento normal das caixas de bloco (uma embaixo da outra, a largura toda), que já é quase o layout de celular. Os links são elementos em linha, por isso a base os transforma em blocos (display: block, aula display). A media query só acrescenta.

Experimente: o menu está escrito em mobile first. Em 375 px, um link embaixo do outro. Clique em 768: lado a lado.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="index.html">Início</a>
  <a href="bolos.html">Bolos</a>
  <a href="contato.html">Contato</a>
</nav>

.menu a {
  display: block;
  padding: 0.75rem;
  background-color: #fff3e0;
  margin-bottom: 0.25rem;
}

@media (min-width: 600px) {
  .menu {
    display: flex;
    gap: 1rem;
  }
}

Repare que no celular cada link virou uma faixa larga (display: block no a, com padding): fácil de tocar com o dedo. A partir de 600 px, o .menu vira flex e os três ficam lado a lado.

2. Uma página em três versões

Vamos construir a página da lojinha da Ana do jeito mobile first, uma versão de cada vez.

Versão 1: o celular (sem nenhuma media query)

Só o essencial: cores, letra, espaços, tudo numa coluna. É o CSS que vale em todas as telas.

Experimente: em 375 px, a página está pronta. Clique em cheia: tudo continua numa coluna só, e numa tela larga os cartões ficam compridos demais. É o que a versão 2 resolve.

<link rel="stylesheet" href="style.css">
<div class="pagina">
  <h1>Lojinha da Ana</h1>
  <div class="cartoes">
    <div class="cartao">Bolo de cenoura</div>
    <div class="cartao">Pão de queijo</div>
    <div class="cartao">Café coado</div>
  </div>
</div>

/* versão 1: celular, a base de tudo */
.pagina {
  padding: 1rem;
}

h1 {
  font-size: 1.75rem;
  color: tomato;
}

.cartoes {
  display: grid;
  gap: 1rem;
}

.cartao {
  padding: 2rem 1rem;
  background-color: #fff3e0;
  border: 2px solid tomato;
}

Repare na forma do arquivo: a base primeiro, e as media queries em ordem crescente (600, depois 900). Numa tela de 1024 px, as duas valem; a de 900 vem depois e ganha onde as duas mudam a mesma coisa (o grid-template-columns). Cada media query só tem o que muda naquela faixa: a cor do título, a borda e o fundo dos cartões nunca foram repetidos.

3. Escolhendo os pontos de quebra

  • Deixe o conteúdo mandar. Abra a versão de celular e vá alargando a janela. Quando os cartões ficarem largos demais, ou sobrar espaço vazio dos lados, ali está o ponto de quebra. Pode ser 560 px, 620 px; não precisa ser um número "de aparelho".
  • Poucos pontos. Dois ou três costumam bastar. Cada um a mais é um layout a mais para testar.
  • Mesmos pontos no site todo. Se o menu muda em 600 e os cartões em 620, entre 600 e 620 a página fica num meio-termo estranho. Com o tempo, você vai querer guardar os números num só lugar (o CSS com variáveis ajuda a organizar o resto; para os números das media queries, o costume é anotar num comentário no topo do arquivo).
  • Lembre do componente. Quando o que importa é o espaço de um cartão, e não da tela toda, existem as container queries.

Quando dá errado

As media queries fora de ordem: a menor ganha da maior

Erro de propósito: numa tela de 900 px ou mais, deveriam ser três colunas. Clique em cheia (se a sua tela for larga): continuam duas. Troque a ordem das duas @media.

<link rel="stylesheet" href="style.css">
<div class="cartoes">
  <div class="cartao">Bolo</div>
  <div class="cartao">Pão</div>
  <div class="cartao">Café</div>
</div>

.cartoes {
  display: grid;
  gap: 1rem;
}

.cartao {
  padding: 2rem 1rem;
  border: 2px solid tomato;
}

@media (min-width: 900px) {
  .cartoes {
    grid-template-columns: 1fr 1fr 1fr;
  }
}

@media (min-width: 600px) {
  .cartoes {
    grid-template-columns: 1fr 1fr;
  }
}

O que você vê: em 768 px, duas colunas (certo). Numa tela de 1024 px, também duas, e não três.

Por quê: em 1024 px, as duas media queries valem (1024 é mais que 900 e mais que 600). Com o mesmo seletor e a mesma força, ganha a última do arquivo, e a última é a de 600. No F12, o grid-template-columns: 1fr 1fr 1fr aparece riscado. O validador não reclama.

Como consertar: em mobile first, as media queries vão da menor largura para a maior: 600, depois 900.

Misturar min-width e max-width no mesmo número

O que acontece: com @media (max-width: 600px) para o celular e @media (min-width: 600px) para o tablet, numa tela de exatamente 600 px as duas valem, e a página mistura os dois layouts. Num site só com min-width, isso não acontece: cada faixa começa onde a outra começou.

Como consertar: escolha um jeito (mobile first: só min-width). Se precisar de uma faixa fechada, use max-width: 599px, ou a escrita nova (width < 600px).

Esconder conteúdo no celular

O que acontece: para "caber", a página esconde no celular uma parte (display: none na tabela de preços, no endereço da loja). Mas quem está no celular quer as mesmas informações, às vezes mais (o endereço, o telefone). Mobile first não é "versão reduzida": é o mesmo conteúdo, arrumado para a tela pequena.

Como consertar: reorganize em vez de esconder: uma coluna, a tabela rolando para o lado dentro de uma caixa (overflow-x: auto), o menu numa lista.

Base escrita para o computador, com min-width por cima

O que acontece: a regra de fora já tem grid-template-columns: 1fr 1fr 1fr, e a @media (min-width: 900px) repete as três colunas. No celular, as três colunas ficam espremidas: a base não é de celular. Usar min-width não basta; a regra de fora precisa ser a de celular.

Como consertar: confira a página em 375 px sem nenhuma media query (comente-as com /* */): o que aparece é a sua base, e tem de ficar bom no celular.

Resumo

  • Mobile first: a base do CSS (fora das media queries) é o layout do celular; as media queries com min-width acrescentam o que muda nas telas maiores.
  • Desktop first: a base é o computador, e as max-width desfazem coisas. Serve para consertar site antigo; em projeto novo, prefira mobile first.
  • Construa em versões: celular (sem media query), depois cada ponto de quebra, só com o que muda.
  • Media queries em ordem crescente (600, depois 900): fora de ordem, a menor ganha da maior.
  • Pontos de quebra onde o conteúdo pede, poucos e iguais no site todo. Não misture max-width: 600px com min-width: 600px. Não esconda conteúdo no celular: reorganize.
