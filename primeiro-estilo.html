CSS Primeiro Estilo

Chega de olhar: agora você vai escrever o seu primeiro CSS, do zero, como num site de verdade. Uma pasta, dois arquivos, uma regra. Depois, uma novidade de cada vez, até a página da Ana ganhar cor de fundo, letra nova e título centralizado. No fim, os tropeços que quase todo mundo tem na primeira vez, e como sair deles.

Você vai aprender
  • A montar a pasta do site com o index.html e o style.css.
  • A ligar os dois arquivos com o <link>.
  • A escrever a primeira regra e ver o resultado (salvar e recarregar).
  • A acrescentar instruções e regras, uma de cada vez, conferindo cada passo.
  • Os tropeços da primeira vez: o arquivo style.css.txt, o CSS escrito solto no HTML e o navegador que mostra a versão antiga.

Os comandos de terminal desta aula rodaram na máquina fictícia da Ana (usuária ana, computador notebook). Se você prefere criar pastas e arquivos clicando, no gerenciador de arquivos, o resultado é o mesmo.

A ideia: pintar uma parede de cada vez

Quem reforma uma casa pela primeira vez não pinta tudo de uma vez: pinta uma parede, dá um passo para trás, olha, e só então vai para a próxima. Se ficou feio, é fácil saber qual lata de tinta foi.

Com o CSS é igual. Escreva uma instrução, salve, recarregue a página e olhe. Funcionou? Próxima. Não funcionou? O problema está na última coisa que você escreveu. Esse ritmo, "escreve, salva, olha", evita a pior situação de quem começa: vinte linhas novas, nada funciona e nenhuma pista de onde está o erro.

1. A pasta e os dois arquivos

Todo site começa numa pasta. A da Ana se chama site e tem dois arquivos: a página e a folha de estilo.

$ mkdir site
$ cd site
$ touch index.html style.css
$ tree
.
├── index.html
└── style.css

1 directory, 2 files
mkdir site
Cria a pasta site (make directory, "criar pasta").
touch index.html style.css
Cria os dois arquivos, vazios.
tree
Mostra a pasta em forma de árvore: os dois arquivos lado a lado, na mesma pasta.

O nome style.css é o mais comum, mas qualquer nome serve (estilo.css, principal.css), desde que termine em .css e seja o mesmo no <link>. Siga a regra de sempre para nomes de arquivo: minúsculas, sem acento e sem espaço.

2. O HTML com o <link>

Abra o index.html no seu editor de texto e escreva uma página completa. A linha nova é a do <link>, dentro do <head>:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<link rel="stylesheet" href="style.css">
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>
<p>Toda semana, uma receita nova.</p>
</body>
</html>

Salve e abra o index.html no navegador (dois cliques no arquivo, ou arraste-o para uma janela do navegador). A página aparece com o visual padrão: letra com serifa, fundo branco, título preto. O style.css ainda está vazio, então não muda nada. Por que o <link> fica no <head> e o que o rel faz: aula Três Jeitos de Usar CSS.

3. A primeira regra

Agora abra o style.css e escreva:

h1 {
  color: teal;
}
h1
O seletor: todos os <h1> da página.
{
Abre a lista de instruções para o h1.
color: teal;
A instrução: cor do texto (color) = teal, um verde-azulado. Recuada com 2 espaços, para ficar claro que está dentro da regra.
}
Fecha a regra.

Agora o passo que todo mundo esquece:

  1. Salve o style.css (Ctrl+S).
  2. Volte ao navegador e recarregue a página (F5 ou Ctrl+R).

O navegador não fica vigiando os seus arquivos: ele lê o CSS quando carrega a página. Sem recarregar, você continua vendo a versão de antes.

Aqui no guia, a caixa faz isso por você: ela redesenha o resultado meio segundo depois que você para de digitar.

Experimente: esta é a página da Ana com a primeira regra. Troque teal por outras cores: purple, darkorange, crimson. Depois apague a regra inteira e veja o título voltar ao preto.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>
<p>Toda semana, uma receita nova.</p>

h1 {
  color: teal;
}

4. Mais uma instrução na mesma regra

A Ana quer o título no meio da página. A instrução nova vai dentro da mesma regra do h1, numa linha própria, com o seu ;:

h1 {
  color: teal;
  text-align: center;
}

text-align = "alinhamento do texto"; center = "centro". Salve, recarregue: o título fica verde-azulado e centralizado. Cada instrução cuida de uma coisa, e elas se somam. Uma regra pode ter quantas instruções você quiser, uma por linha.

5. Uma regra nova para outro elemento

Agora o fundo e a letra da página inteira. Isso não é do h1, é do <body>, o corpo da página. Uma regra nova, separada da primeira por uma linha em branco:

body {
  background-color: honeydew;
  font-family: sans-serif;
}

h1 {
  color: teal;
  text-align: center;
}
body
O seletor da nova regra: o elemento <body>, que envolve tudo o que aparece na página.
background-color: honeydew;
Cor de fundo (background = "fundo"): honeydew, um verde quase branco.
font-family: sans-serif;
A família da letra: sans-serif, "sem serifa", sem os pezinhos nas pontas. Cada computador usa a sua letra sem serifa padrão.

Salve e recarregue. O fundo da janela inteira fica verde-clarinho, e a letra muda em todos os textos, inclusive no título e nos parágrafos, mesmo que a regra seja só do body. É a herança: certas propriedades, como a fonte e a cor do texto, passam do pai para os filhos (aula Herança).

A ordem das regras no arquivo, aqui, não importa: o body em cima, o h1 embaixo, ou o contrário, dá o mesmo resultado, porque cada regra fala de um elemento diferente.

6. A terceira regra: os parágrafos

body {
  background-color: honeydew;
  font-family: sans-serif;
}

h1 {
  color: teal;
  text-align: center;
}

p {
  color: dimgray;
  font-size: 18px;
}

O seletor p pega os dois parágrafos de uma vez: os dois ficam cinza-escuros (dimgray) e com a letra um pouco maior (font-size = "tamanho da letra", 18 pixels em vez dos 16 do padrão). Uma regra, todos os parágrafos. Se a Ana escrever um terceiro parágrafo amanhã, ele já nasce com esse visual.

Experimente: esta é a página completa, com as três regras. Brinque com uma coisa de cada vez: troque honeydew por lavender, center por right, 18px por 22px. Repare como cada mudança aparece sozinha, sem mexer no resto.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>
<p>Toda semana, uma receita nova.</p>

body {
  background-color: honeydew;
  font-family: sans-serif;
}

h1 {
  color: teal;
  text-align: center;
}

p {
  color: dimgray;
  font-size: 18px;
}

O jeito de escrever deste guia

O navegador aceitaria tudo numa linha só (h1{color:teal;text-align:center}), mas as pessoas leem melhor assim, e é o padrão em todo o guia:

  • uma instrução por linha, recuada com 2 espaços;
  • um espaço depois dos dois-pontos (color: teal);
  • o ; sempre, até na última instrução (assim, quando você acrescenta uma linha embaixo, não esquece de pôr);
  • uma linha em branco entre uma regra e outra.

Por que cada sinal está ali, e o que acontece quando falta um: Regras, Seletores e Declarações.

Quando dá errado

Nada mudou: esqueceu de salvar ou de recarregar

O que você vê: a página igualzinha a antes, embora o CSS pareça certo no editor.

Por quê: o navegador mostra o arquivo salvo, na hora em que a página foi carregada. Muitos editores de texto marcam o arquivo não salvo com uma bolinha ou um asterisco no nome da aba.

Como consertar: Ctrl+S no editor, F5 no navegador. Vire um hábito: salvou, recarregou.

O navegador mostra a versão antiga do CSS

O que você vê: salvou, recarregou, e ainda assim nada mudou (acontece mais num site publicado do que num arquivo aberto do seu computador).

Por quê: para ser rápido, o navegador guarda uma cópia do style.css (o cache) e às vezes a reaproveita em vez de buscar a nova.

Como consertar: uma recarga "forçada", que ignora a cópia guardada: Ctrl+Shift+R (ou Ctrl+F5) no Chrome, no Edge e no Firefox; no Mac, Cmd+Shift+R no Chrome e no Firefox.

O arquivo virou style.css.txt

Alguns editores (e o Windows, que esconde as extensões dos arquivos) salvam o arquivo com um .txt escondido no fim. Na tela parece style.css, mas o nome de verdade é outro:

$ tree
.
├── index.html
└── style.css.txt

1 directory, 2 files

O que você vê: a página sem estilo nenhum. O <link> pede style.css, e esse arquivo não existe. O validador não avisa (ele não confere se o arquivo existe); o console do F12 mostra que o arquivo não carregou (aula Inspecionando com o F12).

Como consertar: renomeie o arquivo para style.css (no terminal, mv style.css.txt style.css). No Windows, ligue a opção do Explorador de Arquivos que mostra as extensões, para ver o nome completo. Ao salvar pela primeira vez, escolha "Todos os arquivos" no tipo, se o editor oferecer.

CSS escrito solto no HTML: ele aparece na página, como texto 
h1 {
  color: teal;
}
<h1>Receitas da Ana</h1>

O que você vê: o texto h1 { color: teal; } escrito no topo da página, numa linha só, e o título preto logo abaixo.

Por quê: dentro do HTML, fora de um <style>, o CSS é só texto, como qualquer frase. O navegador mostra o texto e não aplica nada. As quebras de linha somem porque, no HTML, várias linhas e espaços viram um espaço só.

Como consertar: o CSS vai no style.css (o melhor) ou, numa página de teste, entre <style> e </style> no <head>.

Escreveu tudo de uma vez e nada funciona

O que você vê: parte do CSS funciona, parte não, e você não sabe qual linha é a culpada.

Como consertar: volte ao ritmo da parede: apague (ou "desligue" com um comentário, aula Comentários) o que acabou de escrever e ponha de volta uma instrução por vez, olhando o resultado a cada uma. O F12 também mostra as instruções que o navegador ignorou (aula Inspecionando com o F12).
