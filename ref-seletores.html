CSS Seletores

O seletor é a parte da regra que diz quem recebe o estilo: "todos os parágrafos", "o botão com a classe comprar", "os links que estão dentro do menu". Esta página reúne todos os seletores do guia numa tabela de consulta: o que cada um escolhe, um exemplo, a força dele na disputa (a especificidade) e a aula que explica.

Como usar esta página
  • Para aprender do começo, vá à aula O que é um Seletor.
  • As pseudo-classes (:hover, :nth-child()…) e os pseudo-elementos (::before…) aparecem aqui em resumo; a lista completa está em Pseudo-classes e Pseudo-elementos.
  • Os exemplos usam a vida da Ana: o menu da lojinha, os cartões de produto, o formulário de contato.

A anatomia, para lembrar

nav .menu > a:hover {    /* o SELETOR é tudo antes da chave */
  color: tomato;
}

Lido da direita para a esquerda: "um <a>, com o mouse em cima (:hover), que é filho direto (>) de um elemento com a classe menu, que está em algum lugar dentro de um <nav>". É assim também que o navegador confere: começa pelo elemento e sobe procurando os pais.

Combinadores (as relações de família)

Um combinador liga dois seletores e diz qual é a relação entre eles no HTML. O espaço também é um combinador: nav a e nava são coisas muito diferentes.

CombinadorExemploEscolheEspecificidade do exemploAula
A B (espaço: descendente)nav atodo <a> que está em qualquer nível dentro de um <nav> (filho, neto, bisneto…)0-0-2Descendente, Filho e Irmãos
A > B (filho).menu > asó o <a> que é filho direto do .menu (os netos não)0-1-1Descendente, Filho e Irmãos
A + B (irmão seguinte)h2 + po <p> que vem logo depois de um <h2>, com o mesmo pai0-0-2Descendente, Filho e Irmãos
A ~ B (irmãos seguintes)h2 ~ ptodos os <p> que vêm depois de um <h2>, com o mesmo pai (não precisam estar colados)0-0-2Descendente, Filho e Irmãos

Não existe combinador "pai" nem "irmão anterior": o CSS sempre olha para baixo e para a frente. Para escolher um elemento pelo que ele contém, há o :has() (abaixo).

Combinadores ao vivo

Cada quadro tem o mesmo tipo de HTML e uma regra que pinta de amarelo os parágrafos escolhidos. O nome do seletor está no alto de cada quadro:

<style>
  .demo { margin: 0 0 0.75rem; padding: 0.5rem; border: 1px solid silver; font: 0.9rem/1.4 system-ui, sans-serif; }
  .demo p, .demo h3 { margin: 0.25rem 0; padding: 0.125rem 0.5rem; }
  .demo h3 { font-size: 0.9rem; background-color: lightsteelblue; }
  .demo blockquote { margin: 0 0 0 1.5rem; }
  .demo .nome { margin: 0 0 0.25rem; padding: 0; font: bold 0.85rem monospace; }
  .d1 div p { background-color: gold; }
  .d2 div > p { background-color: gold; }
  .d3 h3 + p { background-color: gold; }
  .d4 h3 ~ p { background-color: gold; }
</style>
<div class="demo d1">
  <p class="nome">div p (descendente)</p>
  <div><p>filho do div</p><blockquote><p>neto do div (dentro de um blockquote)</p></blockquote></div>
</div>
<div class="demo d2">
  <p class="nome">div > p (filho)</p>
  <div><p>filho do div</p><blockquote><p>neto do div (dentro de um blockquote)</p></blockquote></div>
</div>
<div class="demo d3">
  <p class="nome">h3 + p (irmão seguinte)</p>
  <h3>Título h3</h3><p>logo depois do h3</p><p>depois</p><p>depois</p>
</div>
<div class="demo d4">
  <p class="nome">h3 ~ p (irmãos seguintes)</p>
  <h3>Título h3</h3><p>logo depois do h3</p><p>depois</p><p>depois</p>
</div>

O que aparece: em div p, os dois parágrafos ficam amarelos, o filho e o neto (que está dentro de um <blockquote>, recuado). Em div > p, só o filho: o neto fica sem fundo. Em h3 + p, só o parágrafo colado no título (o título, em azul-claro, é só para você achar o <h3>). Em h3 ~ p, os três parágrafos depois do título. O "nome" de cada quadro também é um <p>, mas nenhuma das regras o escolhe: ele não está dentro de um <div> interno e vem antes do <h3>.

Escolhem pelo atributo do HTML e pelo valor dele. Todos valem 0-1-0, como uma classe.

Pseudo-classes e pseudo-elementos (resumo)

Juntando seletores (sem espaço)

Seletores colados descrevem o mesmo elemento; com espaço, são dois elementos diferentes. As especificidades se somam.

SeletorEscolheEspecificidade
a.botaoum <a> que tem a classe botao0-1-1
.cartao.destaqueum elemento com as duas classes (class="cartao destaque")0-2-0
.cartao .destaqueum elemento com a classe destaque dentro de um .cartao0-2-0
input[type="email"]:focuso campo de e-mail que está com foco0-2-1
nav .menu > a:hovero exemplo da anatomia0-2-2

Aninhamento com &

O CSS moderno deixa escrever uma regra dentro da outra; o & representa o seletor de fora. Aula: CSS Aninhado.

Escrito aninhadoEquivale a
.cartao { h2 { … } }.cartao h2 { … }
.cartao { > img { … } }.cartao > img { … }
.botao { &:hover { … } }.botao:hover { … } (o & colado: o mesmo elemento)
.cartao { &.destaque { … } }.cartao.destaque { … }
.cartao { .tema-escuro & { … } }.tema-escuro .cartao { … }

Especificidade: quem vence

Quando duas regras dão valores diferentes à mesma propriedade do mesmo elemento, vence a de seletor mais específico. A especificidade é contada em três colunas, IDs – classes – elementos, e comparada da esquerda para a direita, como um placar: 1-0-0 vence 0-15-0. Empate? Vence a regra que vem depois no CSS. Aulas: Especificidade e A Cascata.

Conta na coluna…Quem
IDs (1-0-0)#id
classes (0-1-0).classe, [atributo], pseudo-classes (:hover, :nth-child()…)
elementos (0-0-1)elemento, pseudo-elementos (::before…)
nada (0-0-0)*, os combinadores (>, +, ~, espaço), :where()
a do argumento mais forte:is(), :not(), :has()
acima de qualquer seletoro atributo style="…" no HTML; e, acima de tudo, uma declaração com !important (e por que evitar)
Boa prática: estilize com classes (0-1-0) e evite IDs no CSS: com especificidades parecidas, a ordem do arquivo decide, e fica fácil sobrescrever. Quando precisar de uma regra fraca de propósito (um reset, um tema), use :where(). Aula: Organizando Classes.

Experimente: o menu da lojinha

Missão: a regra .menu a pegou também o link do submenu. Mude o seletor para pintar de navy e pôr em negrito só os links que são filhos diretos do .menu ("Início" e "Bolos"); o link "Bolo de cenoura", do submenu, e o "blog", do parágrafo, ficam com a cor padrão.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="#">Início</a>
  <a href="#">Bolos</a>
  <div class="sub">
    <a href="#">Bolo de cenoura</a>
  </div>
</nav>
<p>Leia também o <a href="#">blog</a>.</p>

body {
  font-family: system-ui, sans-serif;
}

.sub {
  margin-left: 1rem;
}

.menu a {
  color: navy;
  font-weight: 700;
}

body {
  font-family: system-ui, sans-serif;
}

.sub {
  margin-left: 1rem;
}

.menu > a {
  color: navy;
  font-weight: 700;
}

Para brincar mais: troque o seletor por .menu a:not(.sub a), que dá o mesmo resultado, ou por a + a e veja quem é escolhido.

Quando dá errado

Um erro num grupo derruba a regra inteira

h1,
h2:hovr {
  color: tomato;
}

O que você vê: nem o <h1> fica tomate (o estilo calculado do color continua rgb(0, 0, 0)). Por quê: num grupo, se um dos seletores é inválido (:hovr não existe), o navegador descarta a regra toda, inclusive para os seletores certos. Dentro de :is() e :where() é diferente: eles são "tolerantes", e a parte errada é só ignorada (:is(h1, h2:hovr) pinta o h1; medido no Chromium). O validador:

$ vnu --css style.css
"file:/home/ana/sel/style.css":2.4-2.7: error: CSS: Unknown pseudo-element or pseudo-class “:hovr”

Um ID que começa com número

#2026 {
  color: navy;
}

O que você vê: o elemento com id="2026" não muda. Por quê: no HTML, id="2026" é permitido, mas no CSS um nome de ID ou de classe não pode começar com número. Escreva #\32 026 (escapando o "2"), use [id="2026"] ou, melhor, dê um nome que comece com letra (id="ano-2026"). O validador:

$ vnu --css style.css
"file:/home/ana/sel/style.css":1.1-1.5: error: CSS: Invalid ID selector.

Combinador em dobro

.menu >> a {
  color: navy;
}

O que você vê: os links não mudam. Por quê: >> não é um combinador do CSS (já foi proposto, e abandonado); o seletor é inválido, e a regra inteira é descartada. O validador se perde e aponta o fim da regra:

$ vnu --css style.css
"file:/home/ana/sel/style.css":3.2-4.1: error: CSS: Parse Error.

Um espaço a mais (ou a menos)

.cartao.destaque e .cartao .destaque são seletores válidos, e por isso o validador não reclama de nenhum dos dois, mas escolhem coisas diferentes (tabela acima). Se a regra "não pega", confira o espaço; no F12, o painel de estilos mostra só as regras que casam com o elemento selecionado: se a sua não aparece lá, o seletor não o escolheu. Resumo

  • Básicos: *, elemento, .classe, #id, [atributo] e o grupo A, B.
  • Combinadores: espaço (dentro, em qualquer nível), > (filho direto), + (irmão logo depois), ~ (irmãos depois). Colado = o mesmo elemento.
  • Pseudo-classes (:) escolhem por estado ou posição; pseudo-elementos (::), uma parte do elemento.
  • Especificidade: IDs – classes – elementos, comparada como placar; empate, vence a regra de baixo. :where() não pesa; :is(), :not() e :has() pesam o argumento mais forte.
  • Um seletor inválido num grupo derruba a regra inteira; dentro de :is()/:where(), não.
