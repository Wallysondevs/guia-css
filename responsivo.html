CSS Design Responsivo

A mesma página da Ana é aberta num celular de 375 pixels de largura, num tablet de 768 e num computador de 1440. Mais da metade das visitas de um site comum vem do celular. Uma página responsiva é a que se ajeita sozinha em cada uma dessas telas: no celular, uma coluna, letra legível e nada saindo pelo lado; no computador, o espaço aproveitado. Esta aula explica a ideia e mostra o problema que ela resolve. As próximas ensinam cada ferramenta.

Você vai aprender
  • O que é design responsivo, e o que acontece com uma página de largura fixa no celular.
  • Os ingredientes: a meta viewport, larguras fluidas, imagens flexíveis, itens que quebram linha e as media queries.
  • A troca de width fixo por max-width, a primeira coisa a fazer.
  • As larguras de tela mais comuns, e por que não decorar uma lista de aparelhos.
  • Como testar: os botões de largura do quadro do guia e o modo de dispositivo do F12.
  • As causas mais comuns da rolagem para o lado.

Os resultados são desenhados pelo seu navegador. Nesta aula e nas próximas, muitos quadros já começam numa largura fixa, como a tela de um celular, e a barra do quadro tem botões para trocar a largura (veja a seção 1).

A ideia: a roupa que serve em todo mundo

Uma camiseta de tamanho único, sem elástico, fica apertada em uns e sobra em outros. Uma roupa de malha estica e encolhe e serve em quase todo mundo; e quando a diferença é grande demais (uma criança e um adulto), a costureira faz um ajuste: dobra a barra, muda o corte.

O design responsivo é a roupa de malha: as caixas esticam e encolhem com a tela (larguras fluidas). E, onde esticar não basta, o CSS faz ajustes a partir de certas larguras (as media queries): três colunas viram uma, o menu vira uma lista.

O nome vem de um artigo de 2010 do designer Ethan Marcotte, "Responsive Web Design". Antes dele, era comum fazer dois sites: o normal e um "m.site" para celular. Hoje é um site só, com um HTML e um CSS que se adaptam.

1. O problema: a página de largura fixa

Muitas páginas antigas tinham uma largura fixa, pensada para o monitor da época: 960 pixels. Veja essa página num quadro de 375 pixels, a largura de um celular comum:

Experimente: o quadro começa com 375 px. Role o resultado para o lado: o texto sai da tela. Depois use os botões da barra do quadro: 768 (um tablet) e cheia (a largura toda da caixa, como uma janela de computador).

<link rel="stylesheet" href="style.css">
<div class="pagina">
  <h1>Lojinha da Ana</h1>
  <p>Bolos caseiros, pão de queijo e café coado, todo sábado, na Rua das Flores. Encomendas pelo site até quinta-feira.</p>
</div>

.pagina {
  width: 960px;
  background-color: #fff3e0;
  padding: 1rem;
}

Em 375 px, o fundo creme e o texto seguem para a direita, para fora do quadro: aparece uma barra de rolagem horizontal, e o leitor precisa arrastar a página para o lado a cada linha. É o erro mais comum de uma página que não é responsiva.

Os botões de largura do quadro

A barra de cada quadro do Guia CSS tem três botões: 375 (largura de um celular), 768 (um tablet) e cheia (a largura toda da caixa, que no computador fica perto da de uma janela pequena). Ao lado, o quadro mostra quantos pixels de largura a página lá dentro está enxergando. Para a página, o quadro é a janela: as porcentagens, as unidades de tela e as media queries respondem à largura dele. Quando uma missão começa numa largura, ela é conferida nessa largura.

2. Os ingredientes

Uma página responsiva usa quatro ingredientes, e cada um tem a sua aula:

IngredienteO que fazAula
A meta viewport no HTMLPede ao celular para usar a largura de verdade da tela, sem "fingir" que é um computadorA Meta Viewport
Larguras fluidasCaixas com max-width, %, fr, Flexbox e Grid, que acompanham a telaesta, flex-wrap, auto-fit
Imagens flexíveismax-width: 100%: a imagem nunca é mais larga que a caixaImagens que se Adaptam
Media queriesAjustes a partir de uma largura: "de 700 px para cima, duas colunas"Media Queries e Mobile First

A ordem importa: primeiro a página tem de caber (meta viewport, larguras fluidas, imagens flexíveis). Só depois vêm os ajustes de layout (media queries). Muita coisa nem precisa de media query: um bom max-width e um flex-wrap resolvem sozinhos.

3. Largura fluida: max-width no lugar de width

A troca mais simples, e a que mais resolve: em vez de "a página tem 960 px", diga "a página tem no máximo 960 px".

Experimente: em 375 px, a página cabe na tela. Clique em cheia: a página cresce até 960 px e para, centralizada pelo margin: 0 auto, se a caixa for larga o bastante.

<link rel="stylesheet" href="style.css">
<div class="pagina">
  <h1>Lojinha da Ana</h1>
  <p>Bolos caseiros, pão de queijo e café coado, todo sábado, na Rua das Flores. Encomendas pelo site até quinta-feira.</p>
</div>

.pagina {
  max-width: 960px;
  margin: 0 auto;
  background-color: #fff3e0;
  padding: 1rem;
}
max-width: 960px;
"Largura máxima" (aula Largura e Altura). A caixa ocupa a largura que tiver disponível, mas nunca passa de 960 px. Numa tela de 375 px, ela fica com a largura da tela; num monitor de 1440, para em 960 e não vira uma linha de texto comprida demais para ler.
margin: 0 auto;
Divide a sobra igualmente dos dois lados: a página fica no centro quando a tela é mais larga que 960 px (aula Centralizando).

Missão: o blog da Ana tem a página com width: 720px e, no celular, o texto sai da tela. Troque por uma largura máxima de 720 px, para a página caber nos 375 px do quadro.

<link rel="stylesheet" href="style.css">
<article class="pagina">
  <h1>Blog da Ana</h1>
  <p>Hoje testei a receita de pão de queijo com metade do polvilho azedo. Ficou mais macio e menos crocante.</p>
</article>

.pagina {
  width: 720px;
  margin: 0 auto;
  border-left: 4px solid tomato;
  padding-left: 1rem;
}

.pagina {
  max-width: 720px;
  margin: 0 auto;
  border-left: 4px solid tomato;
  padding-left: 1rem;
}

Depois de cumprir, clique em cheia e de volta em 375: a página acompanha o quadro, sem nunca passar de 720 px.

4. Responsivo sem media query: flex-wrap

Muitos layouts se adaptam sozinhos, só com caixas que quebram a linha quando não cabem. Três cartões com uma largura mínima e flex-wrap: wrap ficam lado a lado numa tela larga e um embaixo do outro no celular:

Experimente: em 375 px, um cartão por linha. Clique em 768 e depois em cheia: os cartões sobem para o lado, sem nenhuma regra nova.

<link rel="stylesheet" href="style.css">
<div class="vitrine">
  <div class="cartao">Bolo de cenoura</div>
  <div class="cartao">Pão de queijo</div>
  <div class="cartao">Café coado</div>
</div>

.vitrine {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}

.cartao {
  flex: 1 1 200px;
  padding: 2rem 1rem;
  background-color: #fff3e0;
  border: 2px solid tomato;
}

O flex: 1 1 200px diz "comece com 200 px, cresça para ocupar a sobra" (aula flex-grow, flex-shrink e flex-basis), e o flex-wrap: wrap manda para a linha de baixo o cartão que não cabe (aula flex-wrap). Em 375 px, cabe só um por linha; em 768, os três cabem lado a lado. O Grid tem um truque parecido, o repeat(auto-fit, minmax(200px, 1fr)) (aula repeat, minmax e auto-fit).

5. As larguras de tela

Há milhares de aparelhos, e cada ano aparecem novos. Em vez de decorar modelos, pense em faixas:

FaixaLargura (em pixels de CSS)Exemplos
Celularde 320 a uns 430Celulares em pé; 360, 375, 390 e 412 são muito comuns
Tablet / celular deitadode uns 600 a uns 1024Tablets em pé (768, 820), celulares deitados
Notebook e computadorde 1024 para cima1280, 1366, 1440, 1920

Esses são pixels de CSS, e não os pontinhos da tela. Um celular com tela de 1170 pontos de largura diz para o CSS que tem 390 px: cada pixel de CSS usa três pontos da tela, para a letra ficar nítida e do tamanho certo para o dedo. A meta viewport é a peça que faz o celular usar esses 390, e não fingir ser um computador (próxima aula).

Quebre onde o conteúdo pede, e não onde o aparelho manda

Os pontos em que o layout muda (os breakpoints, "pontos de quebra") não precisam ser 375 e 768. Faça assim: abra a página e vá alargando a janela. Quando o layout começa a ficar ruim (linha de texto comprida demais, espaço vazio sobrando, cartões espremidos), ali é o ponto. Um site testado assim funciona até em aparelhos que ainda não existem.

Testar no navegador de verdade

  • Arraste a borda da janela do navegador, deixando-a estreita e larga. É o teste mais rápido.
  • Modo de dispositivo do F12: no Chrome e no Edge, o F12 tem um botão com o desenho de um celular e um tablet (atalho Ctrl+Shift+M), que mostra a página na largura de um aparelho escolhido numa lista. O Firefox tem o "Modo de design responsivo" (Ctrl+Shift+M também). Os nomes dos menus mudam de versão para versão.
  • Um celular de verdade, sempre que der: o toque, o tamanho da letra e o teclado aparecendo só se sentem nele.

Quando dá errado: a rolagem para o lado

O sintoma é sempre o mesmo: no celular, a página "balança" para o lado, ou aparece uma barra de rolagem horizontal. A causa é um elemento mais largo que a tela. Os suspeitos de sempre:

Uma imagem maior que a tela 
<h1>Bolo de cenoura</h1>
<img src="assets/midia/bolo-800.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="800" height="600">

O que você vê: em 375 px, a foto de 800 px sai pela direita, cortada, e o quadro ganha a rolagem horizontal.

Por quê: por padrão, a imagem é desenhada no tamanho dela, sem olhar a caixa. Nenhum validador reclama: o HTML está certo.

Como consertar: img { max-width: 100%; height: auto; }, a regra que quase todo site tem (aula Imagens que se Adaptam).

Uma palavra ou um endereço comprido 
<p>Receita completa em https://lojinha.example/receitas/bolo_de_cenoura_com_cobertura_de_chocolate.html</p>

O que você vê: o endereço desce para a linha de baixo, mas nem ela basta: ele passa da borda direita do quadro, cortado, e aparece a rolagem para o lado.

Por quê: o navegador só quebra a linha nos espaços e em poucos sinais, como o hífen. Este endereço não tem espaço nem hífen (as palavras estão separadas por _), então vira uma "palavra" só, mais larga que a tela.

Como consertar: overflow-wrap: anywhere; no parágrafo (aula Texto que Não Cabe). Melhor ainda: um link com um texto curto no lugar do endereço.

Uma largura fixa escondida

O que acontece: a página tem max-width, mas uma tabela, um formulário ou um cartão lá dentro tem width: 500px (ou min-width). Basta um elemento assim para a página inteira ganhar a rolagem.

Como achar: no F12, no modo de dispositivo, passe o mouse pelos elementos na aba Elements/Elementos: o que passa da borda direita da tela é o culpado. Troque o width fixo por max-width, ou deixe o elemento rolar sozinho, por dentro (overflow-x: auto, aula overflow).

Não esconda o problema com overflow-x: hidden no body

Pôr body { overflow-x: hidden; } some com a barra de rolagem, mas o elemento continua largo demais: o pedaço que sobra fica cortado, e o leitor nem sabe que ele existe. Ache o elemento e conserte a largura dele.

Missão final: a vitrine que cabe no celular

Resumo

  • Design responsivo: um site só, que se adapta a qualquer largura de tela (termo de Ethan Marcotte, 2010).
  • Os ingredientes: a meta viewport, larguras fluidas (max-width, %, Flexbox, Grid), imagens flexíveis (max-width: 100%) e media queries para os ajustes.
  • Primeiro passo: max-width no lugar de width fixo. Muita coisa se adapta sem media query, com flex-wrap ou auto-fit.
  • Larguras em pixels de CSS: celular de 320 a 430, tablet de 600 a 1024, computador acima. Quebre onde o conteúdo pede.
  • Teste nos botões 375 / 768 / cheia do quadro, arrastando a janela, no modo de dispositivo do F12 e num celular de verdade.
  • Rolagem para o lado = um elemento mais largo que a tela (imagem, endereço comprido, largura fixa). Conserte o elemento; não esconda com overflow-x: hidden.
