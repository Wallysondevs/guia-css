CSS Organizando os Arquivos

O style.css da Ana começou com dez linhas. Hoje tem oitocentas: o reset, as cores, o menu, os cartões, o formulário, o rodapé, tudo misturado. Para mudar o botão, ela rola o arquivo inteiro procurando. Nesta aula você vai ver como arrumar o CSS de um site que cresceu: primeiro com seções dentro de um arquivo só, depois com vários arquivos numa pasta, e as duas formas de juntá-los na página (<link> e @import), com a ordem que importa.

Você vai aprender
  • Organizar um arquivo só com seções, comentários e um sumário.
  • Dividir o CSS numa pasta: reset, base, layout e componentes.
  • Ligar vários arquivos com vários <link>, e por que a ordem importa.
  • @import: como funciona, por que fica no topo, e por que deixa a página mais lenta.
  • Bons nomes de arquivo.
  • Os erros reais: caminho errado, @import fora do lugar e a ordem trocada.

Os resultados são desenhados pelo seu navegador; nas caixas desta aula, as abas viram arquivos numa pasta, como num site de verdade (inclusive css/base.css, dentro da pasta css). As saídas do terminal e do validador W3C (vnu) são da máquina fictícia da Ana (ana@notebook).

A ideia: a despensa da padaria

Numa despensa bagunçada, a farinha está atrás do detergente, e o fermento, em três lugares. Para arrumar, a Ana faz duas coisas: prateleiras com etiqueta (farinhas, laticínios, limpeza) e uma ordem de uso (o que entra primeiro na receita fica mais à mão). O CSS se arruma do mesmo jeito: cada coisa num lugar com nome, e uma ordem, porque no CSS a ordem decide quem vence (aula Cascata).

1. Um arquivo só, com seções

Para um site pequeno, um arquivo só é o melhor: um <link>, um download. O que falta é ordem dentro dele. Comentários (aula Comentários) viram as etiquetas das prateleiras:

/* ==========================================
   Receitas da Ana — style.css
   1. Reset
   2. Base (cores, fontes, textos)
   3. Layout (cabeçalho, conteúdo, rodapé)
   4. Componentes (botão, cartão, menu)
   ========================================== */

/* 1. Reset ================================= */
*,
*::before,
*::after {
  box-sizing: border-box;
}

/* 2. Base ================================== */
:root {
  --cor-principal: tomato;
}

body {
  margin: 0;
  font-family: sans-serif;
}

/* 3. Layout ================================ */
.topo {
  padding: 16px;
}

/* 4. Componentes =========================== */
.botao {
  background-color: var(--cor-principal);
}
O sumário no topo
Quem abre o arquivo vê, em cinco linhas, o que tem nele e em que ordem.
/* 1. Reset ==== */
Um cabeçalho de seção bem visível. Para ir até ele, use a busca do editor (Ctrl+F) com "1. Reset".
A ordem das seções
Do mais geral para o mais específico: primeiro o que vale para tudo (reset, base), depois a estrutura (layout), por fim as peças (componentes). Assim, uma regra de componente vem depois e pode ajustar uma regra geral.

Essa ordem, do geral para o específico, é a mesma em qualquer organização, num arquivo ou em vinte.

2. Vários arquivos numa pasta

Quando o arquivo fica grande demais, ou várias pessoas mexem nele ao mesmo tempo, cada seção vira um arquivo. A pasta do site da Ana ficou assim:

$ tree padaria

O tree ("árvore") mostra as pastas e os arquivos em forma de árvore: 4 directories, 9 files é "4 pastas, 9 arquivos" (a própria padaria conta como pasta). O tree lista os nomes em ordem alfabética, não na ordem de uso. O que vai em cada arquivo:

A vantagem: para mudar o botão, a Ana abre botao.css, que tem trinta linhas, e não procura num arquivo de oitocentas.

3. Ligando os arquivos: vários <link>

Cada arquivo ganha um <link> no <head>, na ordem do geral para o específico:

<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <link rel="stylesheet" href="css/reset.css">
  <link rel="stylesheet" href="css/base.css">
  <link rel="stylesheet" href="css/layout.css">
  <link rel="stylesheet" href="css/componentes/cartao.css">
</head>
href="css/reset.css"
Um caminho relativo: "a pasta css, ao lado desta página, e o arquivo reset.css dentro dela" (os caminhos são os do Guia HTML, Caminhos Relativos e Absolutos).
A ordem dos <link>
Para o navegador, os arquivos se juntam um depois do outro, como se fossem um só, na ordem dos <link>. Entre duas regras de mesma especificidade, vence a do arquivo de baixo. Por isso o reset vem primeiro e os componentes por último.

Experimente: esta caixa tem quatro abas, como quatro arquivos: a página e três CSS dentro da pasta css. O base.css deixa os títulos navy, e o cartao.css, que vem depois, deixa o título do cartão tomato. Troque a ordem dos dois últimos <link> e veja o título do cartão ficar azul-marinho.

<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/base.css">
<link rel="stylesheet" href="css/cartao.css">
<h1>Receitas da Ana</h1>
<article class="cartao">
  <h2 class="cartao__titulo">Bolo de cenoura</h2>
</article>

*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
  padding: 16px;
}

h1,
h2,
.cartao__titulo {
  color: navy;
  font-family: sans-serif;
}

.cartao {
  padding: 16px;
  border: 2px solid tomato;
}

.cartao__titulo {
  margin: 0;
  color: tomato;
}

No Chromium, com a ordem original, o título do cartão sai cor de tomate (rgb(255, 99, 71) no estilo calculado). Com o cartao.css antes do base.css, sai azul-marinho (rgb(0, 0, 128)): as duas regras .cartao__titulo têm a mesma especificidade, e a que vem depois vence.

Missão: a Ana criou o arquivo css/botao.css (está na aba), mas o botão continua sem estilo: falta ligar o arquivo. Acrescente o <link> que falta no index.html, depois do base.css.

<link rel="stylesheet" href="css/base.css">
<h1>Encomendas</h1>
<button class="botao">Encomendar</button>

body {
  font-family: sans-serif;
}

.botao {
  padding: 8px 16px;
  border: none;
  background-color: tomato;
  color: white;
}

<link rel="stylesheet" href="css/base.css">

4. A outra forma: @import

Em vez de vários <link> no HTML, um arquivo CSS pode puxar outros:

@import url("reset.css");
@import url("base.css");
@import url("componentes/cartao.css");

/* regras deste arquivo, se houver */
@import
"Importar": uma regra com arroba que traz outro arquivo CSS para este ponto.
url("reset.css")
O caminho do arquivo, relativo ao arquivo CSS onde o @import está (e não à página). Como o style.css está dentro de css/, "reset.css" é css/reset.css.
No topo
Os @import têm de vir antes de qualquer regra do arquivo. Depois de uma regra, o navegador ignora o @import (veja Quando dá errado).

Aí a página precisa de um <link> só, para o css/style.css. Parece mais arrumado, mas tem um custo: o navegador só descobre os arquivos importados depois de baixar e ler o style.css. Com vários <link> no HTML, ele vê todos de uma vez e baixa ao mesmo tempo. Com @import, baixa em etapas, e a página demora mais para aparecer (aula CSS Rápido).

Experimente: aqui a página liga só o css/style.css, e ele importa o reset.css e o base.css. Apague a linha do @import do base.css e veja o título perder a cor.

<link rel="stylesheet" href="css/style.css">
<h1>Receitas da Ana</h1>
<p>Tudo veio de um <code>&lt;link&gt;</code> só.</p>

@import url("reset.css");
@import url("base.css");

p {
  color: dimgray;
}

body {
  margin: 0;
  padding: 16px;
}

h1 {
  color: tomato;
  font-family: sans-serif;
}

@import com camada

O @import aceita uma camada da cascata: @import url("reset.css") layer(reset);. Tudo o que vem do arquivo entra na camada reset, que perde para as outras (aula @layer). É uma forma de garantir que o reset nunca vença, mesmo fora de ordem.

5. Nomes de arquivo

As mesmas regras dos nomes de página do Guia HTML:

  • Minúsculas, sem acento, sem espaço, palavras com hífen: cartao-receita.css, e não Cartão Receita.css. Num servidor de verdade, Base.css e base.css são arquivos diferentes.
  • O nome diz o que tem dentro: botao.css tem o bloco .botao. Nada de novo.css, teste2.css, style-final-agora-vai.css.
  • Uma pasta css/ separada das imagens (img/) e dos scripts (js/).

Quando dá errado

O caminho errado: o CSS não carrega

Experimente: o arquivo está em css/base.css, mas o <link> aponta para base.css, sem a pasta. Veja a mensagem no console embaixo do quadro e conserte o href.

<link rel="stylesheet" href="base.css">
<h1>Receitas da Ana</h1>

h1 {
  color: tomato;
}

O que o leitor vê: o título preto, sem estilo nenhum. Num site publicado, o navegador pede base.css ao servidor, recebe um "404: não encontrado" e segue sem o CSS. No editor do guia, o console do quadro avisa: Não foi possível carregar "base.css" (<link>). Confira o nome e o caminho do arquivo.

Por quê: o caminho é relativo à página: base.css é "o arquivo ao lado da página", e ele está dentro de css/. O validador não acusa, porque ele não confere se o arquivo existe. No F12, a aba Network ("Rede") mostra o pedido em vermelho, com o código 404.

Como consertar: href="css/base.css".

@import depois de uma regra: @import are not allowed after any valid statement 
h1 {
  color: navy;
}
@import url("reset.css");

$ vnu --css css/errado.css
"file:/home/ana/padaria/css/errado.css":4.26-5.1: error: CSS: @import are not allowed after any valid statement other than @charset and @import.

O que significa: "@import não é permitido depois de nenhuma instrução válida, a não ser @charset e outros @import". Ou seja: os @import vêm primeiro.

O que o leitor vê: o arquivo importado não é carregado, e tudo o que ele tinha some da página. O resto do arquivo (o h1) continua valendo. No Chromium, com o reset.css (que tem body { margin: 0; }) importado depois da regra do h1, o body continuou com margin-top: 8px, a margem do navegador; com o @import na primeira linha, ficou 0px.

Como consertar: leve os @import para as primeiras linhas.

A ordem dos <link> trocada: o reset desfaz o seu estilo 
<link rel="stylesheet" href="css/base.css">
<link rel="stylesheet" href="css/reset.css">

O que o leitor vê: se o base.css tem body { margin: 2rem; } e o reset.css tem body { margin: 0; }, a página fica sem margem: o reset, carregado depois, venceu. Nenhuma mensagem aparece; no F12, o margin: 2rem do base.css aparece riscado. É o mesmo erro da aula Reset e Normalize, agora entre arquivos.

Como consertar: do geral para o específico: reset, base, layout, componentes.

Resumo

  • Site pequeno: um arquivo só, com um sumário no topo e seções marcadas por comentários.
  • Site maior: uma pasta css/ com reset.css, base.css, layout.css e um arquivo por componente. O tree mostra a árvore.
  • Vários <link> se juntam na ordem em que aparecem; entre regras iguais, vence o arquivo de baixo. Ordem: do geral para o específico.
  • @import url("arquivo.css"); só no topo do CSS, com o caminho relativo ao próprio CSS. Funciona, mas baixa em etapas: prefira vários <link> (ou uma ferramenta que junte tudo).
  • Nomes em minúsculas, sem acento nem espaço, dizendo o que há dentro.
  • Caminho errado: o CSS não carrega e o validador não avisa; o console do editor e a aba Network do F12, sim.
