CSS Herança

Você escreve body { color: darkslateblue; } e todo o texto da página muda de cor: títulos, parágrafos, itens de lista. Mas nenhuma regra falou de h1, p ou li. Quem levou a cor até eles foi a herança: algumas propriedades passam do elemento pai para os filhos, e dos filhos para os netos, sozinhas. Nesta aula você vai ver quais passam, quais não passam, e como controlar isso.

Você vai aprender
  • O que é herdar, e por que isso economiza muito CSS.
  • Quais propriedades são herdadas (as de texto) e quais não são (as de caixa).
  • Por que uma regra que fala do próprio elemento sempre vence o valor herdado.
  • As palavras inherit, initial, unset e revert.
  • Os sustos comuns: o link que não herda a cor, o botão que não herda a fonte, o fundo que "parece" herdado.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: o sotaque e a roupa

Uma criança herda dos pais o sotaque: ninguém precisa ensinar, ela fala do jeito da casa. Mas não herda a roupa: se o pai usa casaco, o filho não sai de casaco por isso. E se a escola ensina outro jeito de falar, vale o que a escola ensinou.

No CSS:

  • As propriedades de texto (cor, fonte, tamanho da letra, alinhamento) são como o sotaque: passam para os filhos.
  • As propriedades de caixa (borda, margem, preenchimento, fundo, largura) são como a roupa: não passam.
  • Uma regra que fala diretamente do filho é a escola: ela sempre vence o que veio de casa.

1. A herança em ação

Experimente: a regra fala só do <body>. A cor e o itálico chegaram ao título, ao parágrafo, à lista e ao <strong>. A borda, não: ela ficou só em volta do <body>. Troque a cor por darkgreen e veja tudo mudar junto.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com <strong>cobertura de chocolate</strong>.</p>
<ul>
  <li>Farinha</li>
  <li>Cenoura</li>
</ul>

body {
  color: darkslateblue;
  font-style: italic;
  border: 2px solid crimson;
}

Se a borda fosse herdada, cada título, parágrafo, item e até o <strong> no meio da frase ganhariam uma borda própria: um desastre. Por isso as propriedades de caixa não são herdadas. Já a cor e a fonte, você quase sempre quer iguais no texto todo: por isso elas são.

Repare também no <strong>: ele é neto do <body> (filho do <p>), e recebeu a cor mesmo assim. A herança desce de geração em geração: o <p> herdou do <body>, e o <strong> herdou do <p>.

Missão: a Ana quer todo o texto do cardápio em marrom (saddlebrown). Escreva uma regra, para o body, e deixe a herança levar a cor ao título, ao parágrafo e aos itens. Nada de regras para h1, p ou li.

<link rel="stylesheet" href="style.css">
<h1>Cardápio da Padaria</h1>
<p>Tudo feito hoje cedo.</p>
<ul>
  <li>Pão de queijo</li>
  <li>Bolo de fubá</li>
</ul>

/* escreva a regra aqui */

body {
  color: saddlebrown;
}

2. Quem herda e quem não herda

Cada propriedade do CSS já nasce definida como "herdada" ou "não herdada" (a página de cada propriedade no MDN diz, na tabela de resumo, em "Herdada: sim/não"). Não precisa decorar: quase sempre a regra do sotaque e da roupa acerta.

Herdadas (texto)Não herdadas (caixa e posição)
colorbackground-color, background-image
font-family, font-size, font-weight, font-styleborder, outline
line-height, letter-spacingmargin, padding
text-align, text-transform, text-shadowwidth, height
list-style (o tipo de marcador)display, position
visibility, cursoropacity, box-shadow

Algumas pegadinhas da tabela: text-decoration (o sublinhado) não é herdada, mas o risco do pai é desenhado por cima do texto dos filhos, e parece herança; e opacity não é herdada, mas o filho fica transparente junto com o pai, porque está desenhado dentro dele.

3. A regra do próprio elemento sempre vence

O valor herdado é o mais fraco de todos. Qualquer regra que fale diretamente do elemento ganha dele, não importa a especificidade da regra do pai: até um seletor de ID no pai perde para um simples seletor de elemento no filho.

<style>
  #receita {
    color: darkslateblue;
  }
  p {
    color: darkgreen;
  }
</style>
<div id="receita">
  <h2>Bolo de fubá</h2>
  <p>Fofinho, com erva-doce.</p>
</div>

O título ficou azul-ardósia (herdado do #receita), mas o parágrafo ficou verde: a regra p, com pontuação (0, 0, 1), fala dele diretamente, e isso basta. A especificidade só compara regras que pegam o mesmo elemento; o #receita pega o <div>, e não o <p>.

As regras do navegador também contam

Isso explica dois sustos clássicos. A folha padrão do navegador tem regras que falam diretamente de alguns elementos, e elas vencem a sua herança:

  • os links têm uma regra de cor (azul, roxo depois de visitados): não herdam a cor do pai;
  • os botões e campos de formulário têm regras de fonte: não herdam a fonte nem o tamanho de letra do pai.
<style>
  body {
    color: darkslateblue;
    font-family: Georgia, serif;
    font-size: 18px;
  }
</style>
<p>Veja o <a href="bolo.html">bolo de fubá</a>.</p>
<button type="button">Encomendar</button>

O parágrafo herdou tudo, mas o link continuou azul, e o botão ficou com a letra menor e com outra fonte: a regra do navegador fala dele diretamente. (O tamanho exato varia; no Chrome, a letra do botão é de 13,33 px.)

4. Pedindo a herança: inherit

A palavra inherit ("herdar") pode ser usada como valor de qualquer propriedade. Ela diz: "use o valor do pai", mesmo que a propriedade não seja herdada, e mesmo que exista outra regra do navegador.

Experimente: com color: inherit, o link ficou da cor do texto, e com font: inherit o botão ficou com a mesma fonte e o mesmo tamanho do resto da página. Apague uma das regras e veja o navegador voltar ao padrão dele.

<link rel="stylesheet" href="style.css">
<p>Veja o <a href="bolo.html">bolo de fubá</a>.</p>
<button type="button">Encomendar</button>

body {
  color: darkslateblue;
  font-family: Georgia, serif;
  font-size: 18px;
}

a {
  color: inherit;
}

button {
  font: inherit;
}
color: inherit
"A cor do meu pai." O link fica da cor do parágrafo em volta. Ele continua sublinhado (o sublinhado é outra propriedade), então ainda dá para ver que é link.
font: inherit
font é um atalho que junta font-family, font-size, font-weight e outras. font: inherit manda herdar todas de uma vez. Essa regra aparece em quase todo reset moderno, para os botões e campos acompanharem o texto.

As outras palavras: initial, unset e revert

Existem outras três palavras que funcionam em qualquer propriedade. Você vai usá-las bem menos:

ValorQuer dizerExemplo
inheritO valor do paia { color: inherit; }: o link com a cor do texto
initialO valor inicial da propriedade, o da especificação do CSS (não o do navegador)color: initial dá preto (o inicial de color), e não a cor do pai
unsetComo se nenhuma regra sua existisse: herda se a propriedade é herdada; senão, usa o inicialcolor: unset herda; border: unset tira a borda
revertVolta ao estilo do navegador para aquele elementoh1 { font-weight: revert; } devolve o negrito do título

Quando dá errado

"O fundo foi herdado", mas não foi 
<style>
  .cartao {
    background-color: lightyellow;
    border: 2px solid gray;
    padding: 8px;
  }
</style>
<div class="cartao">
  <p>Bolo de fubá</p>
</div>

O que você vê: o parágrafo aparece sobre o fundo amarelo, como se tivesse herdado a cor de fundo.

Por quê: o fundo do <p> é transparente (o valor inicial de background-color). Você está vendo, através dele, o fundo do cartão que está atrás. Se o fundo fosse herdado, cada filho pintaria o seu próprio amarelo; no F12, o background-color calculado do <p> aparece como rgba(0, 0, 0, 0), ou seja, transparente.

O link não fica da cor do texto

O que você vê: com .rodape { color: white; } num rodapé escuro, os links do rodapé continuam azuis, quase invisíveis no fundo escuro.

Por quê: o navegador tem uma regra própria para a cor dos links, e uma regra que fala do elemento sempre vence a herança (seção 3).

Como consertar: .rodape a { color: inherit; }, ou uma cor própria para os links (aula Estilizando Links).

inherited no lugar de inherit 
<style>
  p {
    color: darkslateblue;
  }
  a {
    color: inherited;
  }
</style>
<p>Veja o <a href="bolo.html">bolo de fubá</a>.</p>

O que você vê: o link continua azul.

Por quê: a palavra é inherit (o verbo, "herdar"), e não inherited ("herdado"). Com um valor que ele não conhece, o navegador ignora a declaração. O validador avisa:

$ vnu --css herda.css
"file:/home/ana/site/herda.css":2.10-2.18: error: CSS: “color”: “inherited” is not a “color” value.

O que significa: "inherited não é um valor de color". No F12, a declaração aparece riscada, com um ícone de aviso.

Mudou a fonte do body e o formulário não acompanhou

O que você vê: o site inteiro em Georgia, tamanho 18 px, e os campos e botões com a letra pequena e outra fonte.

Por quê: <button>, <input>, <select> e <textarea> recebem do navegador uma regra de fonte própria.

Como consertar: button, input, select, textarea { font: inherit; } no começo do CSS.

SituaçãoO que acontece

Exercícios

1. A palavra

Complete para o link usar a cor do texto em volta:

a { color: ; }

2. O atalho da fonte

Complete para os botões herdarem a fonte e o tamanho de letra, de uma vez:

button { : inherit; }

3. Onde pôr

Em qual elemento você põe a cor do texto para ela valer na página inteira, por herança?

{ color: darkslateblue; }

4. Qual destas propriedades não é herdada?

5. Com #receita { color: navy; } e p { color: darkgreen; }, de que cor fica um <p> dentro do #receita?

6. Um parágrafo dentro de um cartão amarelo aparece com fundo amarelo. O que aconteceu?

Resumo

  • Herança: algumas propriedades passam do pai para os filhos e netos, sem regra para eles.
  • Herdam as de texto (cor, fonte, tamanho, alinhamento, espaçamento). Não herdam as de caixa (borda, margem, preenchimento, fundo, largura).
  • O valor herdado é o mais fraco: qualquer regra que fale do próprio elemento vence, inclusive as do navegador. Por isso links não herdam a cor, e botões não herdam a fonte.
  • inherit pede o valor do pai; initial, o inicial; unset, "como se não houvesse regra"; revert, o do navegador.
  • Fundo "herdado" quase sempre é fundo transparente deixando ver o do pai.
