CSS Fontes (font-family)

A fonte (o desenho das letras) muda a "cara" de um site mais do que qualquer cor. Uma receita da vovó combina com letras clássicas; o cardápio de uma hamburgueria, com letras modernas. No CSS, quem escolhe a fonte é a propriedade font-family ("família da fonte"). Ela tem um detalhe que pega todo iniciante: o navegador só consegue usar uma fonte que existe no computador de quem está lendo. Por isso, você sempre escreve uma lista, com plano B.

Você vai aprender
  • As famílias genéricas (serif, sans-serif, monospace…) desenhadas lado a lado.
  • Como escrever uma lista de fontes com plano B: Georgia, "Times New Roman", serif.
  • Quando o nome da fonte precisa de aspas.
  • Quais fontes quase todo computador tem, e por que nem todo.
  • Por que basta escolher a fonte no body, e por que os botões não obedecem.
  • Como ver no F12 qual fonte foi usada de verdade.
  • Os erros, inclusive os que o validador não pega: "serif" com aspas e a vírgula esquecida.

Os quadros "Resultado" são desenhados agora pelo seu navegador, com as fontes do seu computador: se você comparar com um amigo, alguns exemplos podem sair diferentes, e esse é justamente o assunto da aula. As mensagens do validador saíram do validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook).

A ideia: o pedido com plano B

A Ana liga para a padaria: "quero um pão de fermentação natural; se não tiver, um pão italiano; se também não tiver, qualquer pão salgado". Ela sabe que a padaria pode não ter o primeiro, então deixa alternativas, e a última é tão geral que sempre existe.

A font-family é esse pedido. Você lista as fontes da preferida para a menos preferida, e termina com uma família genérica ("qualquer fonte sem serifa") que todo navegador tem. O navegador pega a primeira da lista que existir no computador do leitor.

1. As famílias genéricas

São cinco palavras-chave (mais uma moderna) que não são uma fonte, e sim um tipo de fonte. O navegador troca cada uma pela fonte daquele tipo que o sistema tiver:

<style>
  .serif { font-family: serif; }
  .sans { font-family: sans-serif; }
  .mono { font-family: monospace; }
  .cursiva { font-family: cursive; }
  .fantasia { font-family: fantasy; }
  .sistema { font-family: system-ui; }
</style>
<p class="serif">serif: Bolo de cenoura da Ana</p>
<p class="sans">sans-serif: Bolo de cenoura da Ana</p>
<p class="mono">monospace: Bolo de cenoura da Ana</p>
<p class="cursiva">cursive: Bolo de cenoura da Ana</p>
<p class="fantasia">fantasy: Bolo de cenoura da Ana</p>
<p class="sistema">system-ui: Bolo de cenoura da Ana</p>

No Resultado acima, as três primeiras linhas devem estar bem diferentes umas das outras em qualquer computador: com pezinhos, sem pezinhos e com letras de largura fixa. As três últimas dependem do seu sistema; no computador Linux do laboratório do guia, por exemplo, a cursive e a fantasy saíram iguaizinhas à serif, sem nada de "letra à mão" ou "decorativa". Por isso o guia usa no dia a dia só serif, sans-serif, monospace e system-ui.

2. A lista com plano B

Para escolher uma fonte específica, escreva o nome dela e, depois, as alternativas, separadas por vírgula:

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

h1 {
  font-family: Georgia, "Times New Roman", serif;
}

p {
  font-family: Verdana, Arial, sans-serif;
}
font-family
A propriedade: a família (o desenho) da fonte.
Georgia
A 1ª escolha: uma fonte com serifa que vem no Windows e no Mac.
,
A vírgula separa as opções. Ela é obrigatória: sem ela, o navegador acha que é tudo um nome só (veja "Quando dá errado").
"Times New Roman"
O plano B. O nome tem espaços, então vai entre aspas (próxima seção).
serif
O último recurso: a genérica, que sempre existe. Sempre termine a lista com uma genérica do mesmo tipo das outras.

Como o navegador decide, letra por letra: ele procura Georgia no computador do leitor; se achar, usa e pronto. Se não, tenta Times New Roman; se também não houver, usa a fonte serif padrão do sistema. Repare que a genérica final é do mesmo tipo das outras: se faltarem todas, o título continua com serifa, como você planejou.

Na caixa acima, troque o Georgia por Fonte Que Não Existe. O título continua com serifa: o navegador pulou para o plano B.

Missão: o cardápio da padaria está com a fonte padrão do navegador (com serifa). Faça o body usar Verdana, com sans-serif como plano B.

<link rel="stylesheet" href="style.css">
<h1>Padaria da Ana</h1>
<p>Pão francês quentinho às 7h e às 17h.</p>

body {
  color: #333;
}

body {
  color: #333;
  font-family: Verdana, sans-serif;
}

3. Aspas: quando usar

O nome de uma fonte pode ir com ou sem aspas. A regra prática:

CasoExemploAspas?
Nome de uma palavraGeorgia, VerdanaNão precisa
Nome com espaço"Times New Roman", "Courier New"Use (funciona sem, mas as aspas evitam surpresas)
Nome que começa com número ou tem símbolos"3D Letras"Obrigatório
Família genéricaserif, sans-serif, monospaceNunca: com aspas, vira o nome de uma fonte chamada "serif", que não existe

Aspas simples ('Times New Roman') e duplas ("Times New Roman") funcionam igual; escolha uma e use sempre.

4. Fontes que (quase) todo computador tem

Algumas fontes vêm instaladas no Windows e no Mac há décadas, e por isso são chamadas de fontes seguras (web-safe fonts):

<style>
  .arial { font-family: Arial, sans-serif; }
  .verdana { font-family: Verdana, sans-serif; }
  .tahoma { font-family: Tahoma, sans-serif; }
  .georgia { font-family: Georgia, serif; }
  .times { font-family: "Times New Roman", serif; }
  .courier { font-family: "Courier New", monospace; }
</style>
<p class="arial">Arial: Bolo de cenoura da Ana</p>
<p class="verdana">Verdana: Bolo de cenoura da Ana</p>
<p class="tahoma">Tahoma: Bolo de cenoura da Ana</p>
<p class="georgia">Georgia: Bolo de cenoura da Ana</p>
<p class="times">Times New Roman: Bolo de cenoura da Ana</p>
<p class="courier">Courier New: Bolo de cenoura da Ana</p>

No Windows e no Mac, cada linha sai com a fonte do próprio nome. Mas "segura" não é garantida: celulares Android e computadores Linux não trazem a maioria delas. Lá, cada linha cai no plano B (a genérica do final), e algumas linhas ficam iguais entre si. É por isso que a genérica no fim da lista não é enfeite: é ela que salva o desenho nesses aparelhos.

E se eu quiser uma fonte que ninguém tem?

Você pode mandar o arquivo da fonte junto com o site, e aí ela aparece igual para todo mundo. É o assunto da próxima aula: Fontes da Internet (@font-face).

A lista do sistema

Muitos sites modernos usam a fonte de cada sistema, que é bonita, legível e não precisa ser baixada:

body {
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
}

Lendo a lista: a fonte do sistema (system-ui); a mesma coisa em Safaris antigos (-apple-system); a do Windows (Segoe UI); a do Android (Roboto); e, no fim, qualquer sem serifa.

5. Basta escolher no body: a herança

A font-family é herdada: os elementos de dentro usam a fonte do elemento de fora, a não ser que tenham uma regra própria (aula Herança). Por isso o costume é escolher a fonte do texto uma vez, no body, e só mudar o que for diferente, como os títulos:

<style>
  body {
    font-family: Verdana, sans-serif;
  }
  h1 {
    font-family: Georgia, serif;
  }
</style>
<h1>Receitas da Ana</h1>
<p>Tudo aqui herdou a fonte do <strong>body</strong>: o parágrafo, o negrito e a <a href="#">lista de receitas</a>.</p>
<ul>
  <li>Bolo de cenoura</li>
  <li>Torta de limão</li>
</ul>
<button>Ver receita</button>

O título tem a regra dele (com serifa). O parágrafo, o negrito, o link e a lista herdaram a fonte do body, sem serifa. Mas repare no botão: ele está com outra fonte, e menor.

Botões e campos não herdam

Os elementos de formulário (<button>, <input>, <select>, <textarea>) vêm com uma fonte própria, definida pelo navegador. No Chrome, o valor calculado da font-family de um botão é Arial, com 13.3333px de tamanho, por mais que o body diga outra coisa. Para eles seguirem o resto da página, use a palavra inherit ("herde"):

button,
input,
select,
textarea {
  font-family: inherit;
  font-size: inherit;
}

Essa regra aparece em quase todo "reset" de CSS (aula Reset e Normalize).

6. Qual fonte foi usada de verdade? (F12)

O valor calculado da font-family é a lista inteira, como você escreveu: Georgia, "Times New Roman", serif. Ele não diz qual das três o navegador conseguiu usar. Para saber, no Chrome e no Edge: abra o F12 (aula Inspecionando com o F12), selecione o elemento, vá na aba Computed e role até o fim: a seção Rendered Fonts ("fontes desenhadas") mostra o nome da fonte usada. No Firefox, a aba equivalente se chama Fonts. (Descrição ilustrativa: os nomes das abas mudam um pouco entre versões.)

É também por isso que as missões do guia não conferem a fonte desenhada: ela depende do computador de cada leitor.

Quando dá errado

Com fontes, o "dar errado" é traiçoeiro: na maioria dos casos, o navegador simplesmente cai em outra fonte, e você pode nem perceber. Todas as linhas abaixo queriam letras de largura fixa (monospace):

<style>
  body { font-family: sans-serif; }
  .certo { font-family: "Courier New", monospace; }
  .aspas { font-family: "monospace"; }
  .virgula { font-family: Courier New monospace; }
  .ponto { font-family: Courier; monospace; }
</style>
<p class="certo">"Courier New", monospace (o certo)</p>
<p class="aspas">"monospace" com aspas</p>
<p class="virgula">Courier New monospace sem vírgula</p>
<p class="ponto">Courier; monospace com ponto e vírgula</p>

A primeira linha é a única garantida. A terceira, sem vírgula, ficou com a fonte padrão do navegador, com serifa: nem a sem serifa do body ela usou. A segunda e a quarta dependem do computador, e isso é justamente o perigo: no computador Linux do laboratório do guia, as duas saíram com largura fixa, porque o Linux tem um "apelido" de fonte chamado monospace e uma fonte parecida com a Courier. No Windows e no Mac, a segunda segue a regra do CSS e cai na fonte padrão, com serifa; a quarta só tem largura fixa se existir uma fonte chamada Courier. "Funciona no meu computador" não quer dizer que funciona no do leitor.

Nenhuma mensagem: font-family: "monospace"; (genérica com aspas)

O que aconteceu: com aspas, "monospace" deixa de ser a família genérica e vira o nome de uma fonte chamada "monospace", que, em geral, não existe. A lista acaba sem nenhuma fonte disponível, e o navegador usa a fonte padrão dele (no Chrome, normalmente com serifa). Em alguns sistemas Linux, um apelido com esse nome "salva" o erro, e você nem percebe. O validador acha tudo normal: um nome de fonte entre aspas é permitido.

Como consertar: genéricas nunca levam aspas: font-family: "Courier New", monospace;.

Nenhuma mensagem: font-family: Courier New monospace; (faltou a vírgula)

O que aconteceu: sem vírgula, as três palavras viram um nome só: uma fonte chamada "Courier New monospace". Ela não existe, e o resultado é o mesmo do caso anterior. O validador também não reclama:

$ cat varios.css
body { font-family: Georgia, "Times New Roman", serif; }
.a { font-family: Times New Roman, serif; }
.b { font-family: system-ui, sans-serif; }
.c { font-family: "monospace"; }
.d { font-family: Courier New monospace; }
.e { font-family: Arial, sans serif; }
$ vnu --css varios.css
$

As seis linhas passam sem nenhuma mensagem, inclusive as três erradas (.c, .d e .e, onde sans serif separado vira o nome de uma fonte inexistente). O validador confere a forma, e não se a fonte existe.

Como consertar: vírgula entre cada opção, e nomes compostos entre aspas: "Courier New", monospace; sans-serif com hífen.

error: CSS: “sans-serif”: Parse Error.

O que aconteceu: ponto e vírgula no lugar da vírgula: font-family: Arial; sans-serif;.

$ vnu --css pontovirgula.css
"file:/home/ana/fontes/pontovirgula.css":2.23-2.32: error: CSS: “sans-serif”: Parse Error.

O ; encerra a declaração depois de Arial: a lista ficou sem plano B. O sans-serif sobra sozinho, como se fosse o nome de uma propriedade, e o validador se perde nele. No navegador, quem não tem Arial cai na fonte padrão.

Como consertar: font-family: Arial, sans-serif;.

error: CSS: “font-family”: Unknown dimension.

O que aconteceu: um nome de fonte que começa com número, sem aspas: font-family: 1Lojinha, sans-serif;.

$ vnu --css numero.css
"file:/home/ana/fontes/numero.css":2.16-2.23: error: CSS: “font-family”: Unknown dimension.

"Dimensão desconhecida": o CSS leu 1Lojinha como o número 1 seguido de uma unidade chamada "Lojinha" (como 1px ou 1rem). A declaração inteira é ignorada.

Como consertar: aspas: font-family: "1Lojinha", sans-serif;.

error: CSS: “font-family”: Parse Error. (aspas sem fechar)

O que aconteceu: font-family: "Open Sans, sans-serif;, sem fechar as aspas.

$ vnu --css aspas.css
"file:/home/ana/fontes/aspas.css":2.39-2.39: error: CSS: “font-family”: Parse Error.

Tudo depois da aspa virou parte de um nome, até o fim da linha. A declaração é ignorada.

Como consertar: feche as aspas logo depois do nome: "Open Sans", sans-serif.

error: CSS: “font”: “Arial” is not a “font” value.

O que aconteceu: font: Arial;. A propriedade font (sem -family) é um atalho que exige pelo menos o tamanho e a família juntos.

$ vnu --css font.css
"file:/home/ana/fontes/font.css":2.9-2.13: error: CSS: “font”: “Arial” is not a “font” value.

Como consertar: para só a família, use font-family: Arial, sans-serif;. (O atalho certo seria font: 16px Arial, sans-serif;, com o tamanho da aula font-size.)

Resumo

  • font-family escolhe a fonte com uma lista: o navegador usa a primeira que existir no computador do leitor.
  • Termine sempre com uma genérica do mesmo tipo: serif, sans-serif ou monospace (ou system-ui). cursive e fantasy são imprevisíveis.
  • Vírgula entre as opções; aspas em nomes com espaço (obrigatórias se começar com número); genéricas nunca com aspas.
  • "Fontes seguras" (Arial, Verdana, Georgia…) vêm no Windows e no Mac, mas não em todo aparelho.
  • A fonte é herdada: escolha no body. Botões e campos não herdam: font-family: inherit.
  • O valor calculado é a lista inteira; a fonte usada de verdade aparece no F12 (Rendered Fonts).
  • Genérica com aspas, vírgula esquecida e sans serif separado passam no validador, mas a fonte cai no padrão do navegador.
