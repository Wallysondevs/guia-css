CSS :has()

Até aqui, todo seletor andava num sentido só: de fora para dentro. .cartao img escolhe a imagem dentro do cartão; nunca o cartão. Durante vinte anos, "pintar o cartão que tem uma imagem" foi um pedido famoso e impossível, resolvido com classes extras ou JavaScript. A :has() resolve no CSS: ela escolhe um elemento pelo que ele tem dentro (ou logo depois dele). Por isso ganhou o apelido de "seletor do pai".

Você vai aprender
  • Escolher um elemento pelo que ele tem dentro: .cartao:has(img).
  • Só filhos diretos (:has(> …)) e o irmão que vem depois (:has(+ …)).
  • Reagir ao estado de um campo: label:has(input:checked).
  • O contrário, com :not(:has(…)), e a quantidade de itens.
  • A especificidade e o suporte dos navegadores.
  • Os erros que o validador não vê.

Os resultados são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens do validador W3C (vnu) foram colhidas na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: as caixas da mudança

Na mudança, a Ana escreve na caixa: "frágil". Ela não escreve isso em cada copo; escreve na caixa, porque a caixa tem copos dentro. Quem carrega olha a caixa por fora e já sabe como tratar.

A :has() faz o mesmo: ela olha dentro do elemento e, se achar o que procura, a regra vale para o elemento de fora. "A caixa que tem copo" vira .caixa:has(.copo), e quem recebe o estilo é a caixa.

1. O cartão que tem imagem

Experimente: os dois cartões têm a mesma classe, mas só o que tem imagem ganhou a borda e o fundo. Apague o <img> do primeiro e veja a borda sumir; ponha uma imagem no segundo e veja ela aparecer.

<article class="cartao">

<article class="cartao">
  <h2>Pão de queijo</h2>
</article>

  padding: 0.5rem 1rem;
  margin-bottom: 1rem;
}

  border: 2px solid tomato;
  background-color: #fff3e0;
}

2. Filho direto e irmão de depois

Dentro da :has(), o seletor pode começar com um combinador (aula Combinadores). O ponto de partida é o próprio elemento:

SeletorEscolhe
.cartao:has(img)O cartão com uma imagem em qualquer lugar dentro dele
.cartao:has(> img)O cartão com uma imagem como filha direta (não neta)
h2:has(+ p)O h2 que tem um p logo depois dele
h2:has(~ ul)O h2 que tem um ul em algum lugar depois dele, no mesmo pai

O :has(+ …) é um "seletor do irmão de antes", outra coisa que o CSS não tinha. Veja: o título com um subtítulo logo depois perde a margem de baixo, para os dois ficarem juntos:

Experimente: o primeiro h2 tem um p.subtitulo logo depois e fica colado nele; o segundo, não. Apague o p.subtitulo e veja o espaço voltar.

<link rel="stylesheet" href="style.css">
<h2>Bolo de cenoura</h2>
<p class="subtitulo">A receita da avó</p>
<p>Rende 12 fatias.</p>
<h2>Pão de queijo</h2>
<p>Rende 30 unidades.</p>

h2:has(+ .subtitulo) {
  margin-bottom: 0;
}

.subtitulo {
  margin-top: 0;
  color: dimgray;
  font-style: italic;
}

3. Reagir a um campo de formulário

A :has() pode procurar um elemento num estado: :checked (marcado), :focus (com o cursor), :invalid (com valor errado). Assim, o que está em volta do campo reage a ele, sem JavaScript.

Experimente: marque e desmarque os sabores: a linha inteira fica dourada quando a caixinha está marcada. Depois clique no campo de observações e veja a caixa em volta dele ganhar a borda azul.

<link rel="stylesheet" href="style.css">
<form>
  <p><label><input type="checkbox" name="sabor" value="cenoura" checked> Cenoura</label></p>
  <p><label><input type="checkbox" name="sabor" value="fuba"> Fubá</label></p>
  <div class="campo">
    <label>Observações <input type="text" name="obs"></label>
  </div>
</form>

label:has(input:checked) {
  background-color: gold;
  font-weight: bold;
}

.campo {
  padding: 0.5rem;
  border: 2px solid silver;
}

.campo:has(input:focus) {
  border-color: navy;
}

"Cenoura" já começa marcada, então a linha dela já aparece dourada e em negrito. O label não tem estado nenhum; quem tem é o input dentro dele, e a :has() leva a informação para fora.

Missão: na escolha de entrega, a opção marcada fica com o fundo lightgreen. Escreva a regra com label:has(…); não ponha classes no HTML.

<link rel="stylesheet" href="style.css">
<form>
  <p><label><input type="radio" name="entrega" value="buscar" checked> Vou buscar na lojinha</label></p>
  <p><label><input type="radio" name="entrega" value="casa"> Entregar em casa</label></p>
</form>

label {
  padding: 0.3rem;
}

label {
  padding: 0.3rem;
}

label:has(input:checked) {
  background-color: lightgreen;
}

Depois de cumprir a missão, clique em "Entregar em casa": o fundo verde muda de linha.

4. O contrário e a quantidade

Quem não tem: :not(:has(…))

Junte com a :not(): .cartao:not(:has(img)) é "o cartão que não tem imagem". Bom para dar um fundo colorido ao cartão que ficaria sem graça.

Listas compridas: :has(> li:nth-child(4))

Se a lista tem um quarto item, ela tem quatro ou mais. Com isso, o CSS consegue mudar o desenho conforme a quantidade:

Experimente: a primeira lista tem 3 itens e fica numa coluna; a segunda tem 5 e se divide em duas. Apague dois itens da segunda e veja ela voltar a uma coluna.

<link rel="stylesheet" href="style.css">
<h3>Bolo de fubá</h3>
<ul>
  <li>Fubá</li>
  <li>Ovos</li>
  <li>Leite</li>
</ul>
<h3>Bolo de cenoura</h3>
<ul>
  <li>Cenouras</li>
  <li>Ovos</li>
  <li>Óleo</li>
  <li>Açúcar</li>
  <li>Farinha</li>
</ul>

ul {
  width: 300px;
}

ul:has(> li:nth-child(4)) {
  columns: 2;
}

O columns: 2 divide o conteúdo em duas colunas, como num jornal. O :nth-child(4) é da aula :first-child, :last-child e :nth-child.

5. Especificidade e suporte

Na conta da especificidade, a :has() funciona como a :is(): vale o seletor mais forte de dentro dela. .cartao:has(img) é 0, 1, 1 (a classe do cartão mais o img); .cartao:has(.foto) é 0, 2, 0.

Suporte da :has()

Funciona nos navegadores atuais: Safari desde a versão 15.4 (março de 2022), Chrome e Edge desde a 105 (agosto de 2022) e Firefox desde a 121 (dezembro de 2023), o último a chegar (dados do MDN, outubro de 2026). Num navegador mais velho, a regra com :has() é ignorada inteira. Por isso, use a :has() para melhorar a página, e não para fazê-la funcionar: sem a borda do cartão, a receita continua legível. Para testar se o navegador entende, existe @supports selector(:has(a)) (aula @supports e Compatibilidade).

E o desempenho?

Para saber se um elemento "tem" alguma coisa, o navegador precisa olhar dentro dele, e refazer a conta quando o conteúdo muda. Os navegadores otimizaram isso, e numa página comum você não sente diferença. Só evite regras muito largas, como body:has(…) ou :has(*) sem nada na frente, numa página enorme que muda o tempo todo.

Quando dá errado

Espaço antes do :has: o estilo vai para outro elemento 
<style>
  .cartao :has(img) {
    border: 2px solid tomato;
  }
</style>
<article class="cartao">
  <img src="assets/midia/bolo-400.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="200" height="150">
  <h2>Bolo de cenoura</h2>
</article>

O que você vê: nenhuma borda.

Por quê: com o espaço, o seletor quer dizer "um elemento dentro do cartão que tem uma imagem dentro dele". A imagem é filha direta do cartão, e não há nada entre os dois, então ninguém casa. O validador não reclama: o seletor é válido.

Como consertar: cole: .cartao:has(img).

:has() dentro de :has(): o validador aceita, o navegador não 
<style>
  .vitrine:has(.cartao:has(img)) {
    border: 2px solid tomato;
  }
</style>
<div class="vitrine">
  <article class="cartao">
    <img src="assets/midia/bolo-400.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="200" height="150">
  </article>
</div>

O que você vê: nenhuma borda em volta da vitrine.

Por quê: a regra do CSS proíbe uma :has() dentro de outra (o navegador poderia entrar numa conta sem fim). O navegador considera o seletor inválido e joga a regra fora. O vnu 26.10.12 não conhece essa proibição: para o mesmo arquivo, ele não mostra nada. Pseudo-elementos dentro da :has() (p:has(::before)) também são proibidos, e o validador também fica quieto.

Como consertar: aqui, uma :has() com o caminho inteiro basta: .vitrine:has(.cartao img).

:has() vazia: Parse Error 
$ cat vazio.css
.cartao:has() {
  color: red;
}
$ vnu --css vazio.css
"file:/home/ana/site/vazio.css":1.13-1.13: error: CSS: Parse Error.
"file:/home/ana/site/vazio.css":1.13-1.13: error: CSS: Parse Error.

O que significa: "erro de análise" na coluna 13, o ): a :has() precisa de alguma coisa entre os parênteses. (O validador repete a mesma linha duas vezes.) O navegador ignora a regra inteira.

Como consertar: diga o que procurar: .cartao:has(img).

Um erro dentro da :has() derruba a regra

O que acontece: diferente da :is(), a lista dentro da :has() não perdoa: em .cartao:has(img, a:hoverr), o erro de digitação no :hoverr faz o navegador ignorar a regra inteira, e o cartão com imagem também fica sem estilo. O validador avisa: Unknown pseudo-element or pseudo-class “:hoverr”.

Como consertar: corrija o nome (:hover), ou separe em duas regras.

Resumo

  • A:has(B) escolhe o A que tem um B dentro: o estilo vai para o de fora, o "pai".
  • Com combinador: :has(> B) (filho direto), :has(+ B) (logo depois), :has(~ B) (depois, no mesmo pai).
  • Com estados: label:has(input:checked), .campo:has(input:focus). Com :not(): .cartao:not(:has(img)). Com contagem: ul:has(> li:nth-child(4)).
  • Especificidade: a do seletor mais forte de dentro. Suporte: todos os navegadores atuais (o Firefox só desde a 121, dezembro de 2023); use para melhorar, não para fazer funcionar.
  • Espaço antes do :has muda o sentido. :has() dentro de :has() e pseudo-elementos lá dentro são ignorados pelo navegador, e o vnu não avisa. :has() vazia dá Parse Error. Um seletor errado dentro dela derruba a regra.
