CSS Seletores de Atributo

Num formulário, todos os campos são <input>: o de nome, o de e-mail, a caixinha de marcar. Como pintar só o de e-mail, sem pôr uma classe em cada um? Olhando o atributo: o campo de e-mail é o que tem type="email". Os seletores de atributo escolhem elementos pelo que está escrito nos atributos do HTML: o tipo do campo, o endereço do link, o idioma, o texto alternativo da imagem.

Você vai aprender
  • Escolher quem tem um atributo: img[alt].
  • Escolher pelo valor exato: input[type="email"].
  • Escolher pelo começo (^=), pelo fim ($=), por um pedaço (*=) e por uma palavra (~=) do valor.
  • A letra i, que ignora maiúsculas e minúsculas.
  • A força (especificidade) desses seletores, e quando é melhor usar uma classe.
  • Os erros reais: a aspa que falta, o colchete que falta e o espaço no lugar errado.

Os resultados são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a etiqueta da mala

No aeroporto, as malas passam todas pela mesma esteira. O funcionário não abre cada uma: ele lê a etiqueta. "Destino: Recife" vai para um carrinho, "Destino: Manaus" vai para outro. Ele pode até separar por um pedaço da etiqueta: "todas as que começam com GRU".

No HTML, os atributos são as etiquetas: type="email", href="https://…", lang="pt-BR". O seletor de atributo lê a etiqueta e escolhe os elementos, sem você precisar pôr uma classe em cada um.

1. Quem tem o atributo: [atributo]

Experimente: só o link com title ficou com o sublinhado pontilhado. Ponha um title no segundo link e veja.

<link rel="stylesheet" href="style.css">
<p><a href="bolo.html" title="Rende 12 fatias">Bolo de cenoura</a></p>
<p><a href="pao.html">Pão de queijo</a></p>

a[title] {
  text-decoration-style: dotted;
  cursor: help;
}
a
O elemento: links.
[title]
Os colchetes guardam o nome do atributo. Sem valor, o seletor quer dizer "que tem o atributo title", com qualquer valor (até vazio).
a[title]
Colado, sem espaço: "um a que tem title". É o mesmo jeito de juntar de p.destaque (aula Seletor de Classe).

Sem nada na frente, [title] escolhe qualquer elemento com title: links, imagens, abreviações.

2. O valor exato: [atributo="valor"]

O uso mais comum: campos de formulário pelo type.

Experimente: os três campos são input, mas cada regra pega um só. Troque o type do primeiro campo para email e veja ele ganhar a borda azul.

<link rel="stylesheet" href="style.css">
<p><label>Nome <input type="text" name="nome"></label></p>
<p><label>E-mail <input type="email" name="email"></label></p>
<p><label><input type="checkbox" name="novidades"> Quero novidades</label></p>

input[type="email"] {
  border: 2px solid navy;
}

input[type="checkbox"] {
  width: 1.25rem;
  height: 1.25rem;
}
[type="email"]
"Cujo atributo type é exatamente email". Nem mais, nem menos: type="emails" não casa.
"email"
As aspas são opcionais quando o valor é uma palavra simples ([type=email] funciona). Com espaço, ponto, barra ou dois-pontos, elas são obrigatórias. Use sempre aspas e nunca precisa pensar nisso.

Repare no resultado: só o campo de e-mail tem a borda azul-marinho de 2 pixels; a caixinha de marcar ficou maior; o campo de nome ficou como o navegador desenha.

Missão: no formulário de encomendas, os campos de e-mail e de telefone ficam com a borda verde (border: 2px solid green;). Use seletores de atributo, sem pôr classes no HTML. Dica: dá para juntar os dois seletores com vírgula (aula Agrupando Seletores).

<link rel="stylesheet" href="style.css">
<p><label>Nome <input type="text" name="nome"></label></p>
<p><label>E-mail <input type="email" name="email"></label></p>
<p><label>Telefone <input type="tel" name="telefone"></label></p>

input {
  padding: 0.3rem;
}

input {
  padding: 0.3rem;
}

input[type="email"],
input[type="tel"] {
  border: 2px solid green;
}

3. Um pedaço do valor: ^=, $= e *=

Às vezes você não sabe o valor inteiro, só um pedaço. Três sinais resolvem, e cada um lembra um símbolo que você talvez já conheça:

SeletorCasa quando o valor…Para lembrarExemplo de uso
[href^="https"]começa com https^ é "começo" nas expressões regularesLinks para outros sites
[href$=".pdf"]termina com .pdf$ é "fim" nas expressões regularesLinks para arquivos PDF
[href*="receita"]contém receita em qualquer lugar* é "qualquer coisa"Links que falam de receitas

Experimente: cada link casa com uma regra diferente. Mude o endereço do terceiro link para cardapio.pdf e veja qual regra ele passa a seguir.

<link rel="stylesheet" href="style.css">
<ul>
  <li><a href="https://example.com">Receitas do mundo</a></li>
  <li><a href="assets/midia/receita-bolo.pdf">Receita do bolo (PDF)</a></li>
  <li><a href="sobre.html">Quem é a Ana</a></li>
</ul>

a[href^="https"] {
  color: darkgreen;
}

a[href^="https"]::after {
  content: " ↗";
}

a[href$=".pdf"] {
  font-weight: bold;
  color: firebrick;
}

Repare: o primeiro link (que começa com https) fica verde-escuro e ganha a setinha ↗ no fim, criada pelo ::after; o segundo (que termina em .pdf) fica em negrito, vermelho-tijolo; o terceiro, um endereço do próprio site, continua azul e sublinhado, como todo link. O leitor sabe, antes de clicar, que um vai sair do site e o outro vai baixar um arquivo.

^="https" ou ^="http"?

[href^="http"] pega os dois tipos, http:// e https://, porque https também começa com http. É o jeito mais seguro de marcar "link para fora".

4. Uma palavra do valor: ~= e |=

Alguns atributos guardam uma lista de palavras separadas por espaço, como class="cartao novo" ou rel="noopener noreferrer". O ~= procura uma palavra inteira da lista:

SeletorCasa comNão casa com
[rel~="noopener"]rel="noopener noreferrer"rel="noopeners"
[rel*="noopener"]rel="noopener noreferrer" e também rel="noopeners"—
[lang|="pt"]lang="pt" e lang="pt-BR" (a palavra, ou ela seguida de hífen)lang="pten"

O |= foi feito para idiomas: [lang|="pt"] pega português do Brasil e de Portugal. No dia a dia, os dois aparecem bem menos que os da seção 3. Para classes, não use [class~="novo"]: o seletor de classe .novo faz exatamente a mesma coisa e é mais fácil de ler.

5. Maiúsculas e minúsculas: a letra i

O valor diferencia maiúsculas de minúsculas: [href$=".pdf"] não pega CARDAPIO.PDF. Um i (de insensitive, "sem diferenciar") antes do ] resolve:

Experimente: apague o i da regra e veja o segundo link perder o negrito.

<link rel="stylesheet" href="style.css">
<p><a href="cardapio.pdf">Cardápio de segunda</a></p>
<p><a href="CARDAPIO-SABADO.PDF">Cardápio de sábado</a></p>

a[href$=".pdf" i] {
  font-weight: bold;
}

6. A força do seletor de atributo

Na conta da especificidade, um seletor de atributo vale o mesmo que uma classe: [type="email"] e .email empatam. input[type="email"] soma um elemento e fica igual a input.email.

SeletorEspecificidade (ID, classe, elemento)
input0, 0, 1
[type="email"]0, 1, 0
input[type="email"]0, 1, 1
.formulario input[type="email"]0, 2, 1

Atributo ou classe?

SituaçãoUsePor quê
O HTML já diz o que o elemento é (type, href, lang, disabled)AtributoNão precisa repetir a informação numa classe. Um campo novo de e-mail já sai estilizado.
Marcar links para fora do site ou para arquivosAtributo (^=, $=)O endereço já diz; ninguém precisa lembrar de pôr a classe.
Um estilo de aparência (cartão, destaque, botão principal)ClasseNão depende de atributo nenhum; é decisão de visual.
Estado ligado ou desligado (aria-expanded="true", aria-current="page")AtributoO mesmo atributo que avisa o leitor de tela pinta a tela: os dois nunca ficam em desacordo.

Experimente: o menu marca a página atual com aria-current="page" (no Guia HTML, ele avisa o leitor de tela "página atual"). O CSS usa o mesmo atributo para destacar o link. Passe o aria-current="page" para "Receitas".

<link rel="stylesheet" href="style.css">
<nav>
  <a href="index.html" aria-current="page">Início</a>
  <a href="receitas.html">Receitas</a>
  <a href="sobre.html">Sobre</a>
</nav>

nav a {
  margin-right: 1rem;
}

nav a[aria-current="page"] {
  font-weight: bold;
  text-decoration: none;
  border-bottom: 3px solid tomato;
}

Quando dá errado

Valor com : e / sem aspas: Parse Error

Erro de propósito: o link deveria ficar verde. Ponha aspas em volta do endereço, dentro dos colchetes.

<link rel="stylesheet" href="style.css">
<p><a href="https://example.com">Receitas do mundo</a></p>

a[href=https://example.com] {
  color: green;
}

O que você vê: o link continua azul. Nenhuma mensagem na página.

Por quê: sem aspas, o valor só pode ser uma palavra simples (letras, números, hífen e _). Os : e as / de https:// quebram o seletor, e o navegador joga fora a regra inteira. O validador:

$ vnu --css sem-aspas.css
"file:/home/ana/site/sem-aspas.css":1.27-1.27: error: CSS: Parse Error.

O que significa: "erro de análise", na linha 1, coluna 27 (o ], onde ele desistiu de entender o seletor). A mensagem é curta e não diz o motivo: quando ela aponta para dentro de colchetes, desconfie das aspas.

Como consertar: a[href="https://example.com"]. Aspas sempre.

Esqueceu o ]: o resto do arquivo some

Erro de propósito: o parágrafo deveria ficar verde, e a regra dele está certa. Feche o colchete da primeira regra ("email"]) e veja as duas funcionarem.

<link rel="stylesheet" href="style.css">
<p>Assine as novidades da lojinha:</p>
<input type="email" name="email">

input[type="email" {
  color: navy;
}

p {
  color: green;
}

O que você vê: o parágrafo continua preto, apesar de a regra do p estar perfeita.

Por quê: o navegador abriu o colchete e ficou esperando o ] para fechar. Enquanto não acha, tudo vira parte do seletor: as chaves, o color: navy;, o p, a regra seguinte inteira. No fim do arquivo, ele tem um "seletor" gigante e sem sentido, e joga tudo fora. Um colchete (ou uma chave, ou uma aspa) aberto pode apagar o resto do CSS. O validador:

$ vnu --css colchete.css
"file:/home/ana/site/colchete.css":1.12-1.18: error: CSS: Parse Error.

Como consertar: feche o colchete. Quando várias regras param de funcionar ao mesmo tempo, procure um ], } ou aspa que falta antes da primeira regra quebrada.

Espaço antes do [: o seletor procura outro elemento 
<style>
  a [href^="https"] {
    color: green;
  }
</style>
<p><a href="https://example.com">Receitas do mundo</a></p>

O que você vê: o link continua azul.

Por quê: o espaço é o combinador descendente (aula Combinadores). a [href^="https"] quer dizer "um elemento com href que começa com https, dentro de um a". Dentro do link só há texto. O seletor é válido, então o validador não diz nada.

Como consertar: a[href^="https"], colado.

Valor exato quando era um pedaço

O que acontece: a[href="https"] só casa com um link cujo endereço é exatamente a palavra https, e esse link não existe. Nada fica verde, e o validador não reclama.

Como consertar: para "começa com", é ^=: a[href^="https"].

Resumo

  • Os colchetes escolhem pelo atributo do HTML: [alt] (tem), [type="email"] (valor exato).
  • Pedaços do valor: ^= começa com, $= termina com, *= contém. Palavras: ~= (uma palavra da lista) e |= (idiomas, pt e pt-BR).
  • Um i antes do ] ignora maiúsculas: [href$=".pdf" i].
  • A força é igual à de uma classe. Use atributo quando o HTML já diz o que o elemento é (tipo, endereço, idioma, aria-current); use classe para decisões de aparência.
  • Aspas sempre. Valor com : ou / sem aspas, ou um ] esquecido, dá Parse Error no validador; o colchete aberto apaga também as regras seguintes. Espaço antes do [ muda o sentido, e o validador não avisa.
