CSS Reset e Normalize

Abra uma página sem nenhum CSS e ela já tem estilo: o título é grande e em negrito, a lista tem bolinhas e recuo, o texto não encosta na borda da janela. Quem fez isso foi o navegador, com uma folha de estilos própria, que vem antes da sua. Esses estilos padrão são úteis, mas alguns atrapalham: a fonte dos botões é menor que a do texto, uma foto grande estoura a tela do celular. Um reset é um pequeno trecho de CSS, no começo do seu arquivo, que acerta esses pontos antes de você começar. Nesta aula você vai ver os estilos do navegador, os jeitos de lidar com eles e montar um reset moderno curto, entendendo cada linha.

Você vai aprender
  • Os estilos que o navegador põe em toda página, com os valores medidos.
  • O reset "agressivo" (* { margin: 0; padding: 0; }) e por que ele estraga as listas.
  • A diferença entre reset e normalize.
  • Um reset moderno de cinco regras, explicado linha por linha.
  • Onde pôr o reset: no começo do arquivo, num arquivo próprio ou numa camada.
  • O que dá errado: o reset no fim do arquivo, a imagem que pula de linha, e a mensagem real do validador.

Os resultados são desenhados pelo seu navegador. Os valores em pixels foram medidos no Chromium, com o estilo calculado (outros navegadores têm valores parecidos, mas não idênticos: é justamente o assunto da aula). As mensagens de erro são do validador W3C (vnu) rodado na máquina fictícia da Ana (ana@notebook), na pasta ~/site.

A ideia: a casa alugada

A Ana alugou uma casa para abrir a padaria. A casa veio com paredes pintadas, cortinas e uma estante. Ela tem três opções:

  • Deixar tudo como veio e decorar por cima. Rápido, mas a cortina verde não combina com nada.
  • Esvaziar e pintar tudo de branco antes de decorar. Fica tudo do jeito dela, mas ela tem que comprar de novo até o que era útil, como a estante. Esse é o reset agressivo.
  • Consertar só o que incomoda: trocar a cortina, prender a estante que balançava, e manter o resto. Esse é o reset moderno desta aula.

1. O que o navegador já faz

Esta página não tem nenhum CSS do autor. Tudo o que você vê é o estilo do navegador (a folha de estilos do user agent, "agente do usuário", o nome técnico do navegador):

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura.</p>
<ul>
  <li>3 cenouras</li>
  <li>3 ovos</li>
</ul>
<button>Encomendar</button>
<input type="text" value="Seu nome" aria-label="Nome">

2. O reset agressivo: zerar tudo

Por muitos anos, o primeiro passo de todo CSS era este:

* {
  margin: 0;
  padding: 0;
}

O seletor universal * (aula Seletor Universal) zera a margem e o preenchimento de todos os elementos. Com a mesma página de cima, o Chromium desenhou tudo grudado: o título encostado no parágrafo, o parágrafo na lista, e a lista sem as bolinhas. As bolinhas ficam do lado de fora do texto, no espaço do padding-left; com o padding zerado (o estilo calculado ficou padding-left: 0px), elas foram parar fora da janela. Para ter a página de volta, você precisaria reescrever as margens de cada título, parágrafo e lista: é a casa pintada de branco, sem a estante.

Houve resets ainda mais agressivos, como o de Eric Meyer (2007–2011, em domínio público), que também deixava o h1 do tamanho do texto. Eles faziam sentido quando os navegadores eram muito diferentes entre si. Hoje não são mais necessários.

3. Normalize: igualar os navegadores

A outra escola é o normalize: em vez de apagar os estilos do navegador, ele mantém os úteis e corrige só as diferenças entre um navegador e outro, para a página sair igual em todos. Os mais conhecidos são o normalize.css (de Nicolas Gallagher e Jonathan Neal) e o modern-normalize (de Sindre Sorhus, que se descreve como "Normalize browsers' default style", "normalizar o estilo padrão dos navegadores"). Os dois são de código aberto, com licença MIT: você pode usá-los no seu site, desde que mantenha o aviso de licença que vem no arquivo.

ResetNormalize
O que faz com os estilos do navegadorRemove ou trocaMantém os úteis, corrige as diferenças
A página depois dele"Crua": você estiliza tudoParecida com o padrão, igual em todos os navegadores

Na prática, os resets modernos ficaram no meio do caminho: poucos ajustes, cada um com um motivo. É o que você vai montar agora.

4. Um reset moderno, linha por linha

Este é o reset deste guia: cinco regras curtas. Ideias parecidas aparecem em vários resets conhecidos (por exemplo, o "A Modern CSS Reset" de Josh W. Comeau, em joshwcomeau.com, que ele publica em domínio público). Este aqui foi escrito para a aula, e você não precisa copiar nenhum outro.

/* 1. Largura que inclui borda e preenchimento */
*,
*::before,
*::after {
  box-sizing: border-box;
}

/* 2. Sem a margem do navegador; linhas mais abertas */
body {
  margin: 0;
  line-height: 1.5;
}

/* 3. Imagens e vídeos nunca maiores que o espaço */
img,
picture,
video,
svg {
  display: block;
  max-width: 100%;
  height: auto;
}

/* 4. Campos com a fonte do resto da página */
input,
button,
textarea,
select {
  font: inherit;
}

/* 5. Palavras compridas quebram em vez de estourar */
h1,
h2,
h3,
p {
  overflow-wrap: break-word;
}
*, *::before, *::after
Todos os elementos, e também os pseudo-elementos ::before e ::after (aula ::before e ::after), que o * sozinho não pega.
box-sizing: border-box
A largura que você escreve passa a incluir a borda e o preenchimento: width: 200px com padding: 20px continua com 200 px. Sem isso, a caixa teria 240 px. No Chromium, o campo de texto do exemplo passou de content-box para border-box (aula box-sizing).
body { margin: 0; }
Tira os 8 px do navegador. O texto passa a encostar na borda: é de propósito. O espaço da página agora é decisão sua (um padding no main, por exemplo), e um cabeçalho com fundo colorido pode ir de ponta a ponta.
line-height: 1.5
Altura da linha de 1,5 vez o tamanho da letra, sem unidade: com a fonte de 16 px, 24 px (foi o valor calculado no Chromium). Textos ficam mais fáceis de ler. Por ser herdada, vale para a página toda.
img, picture, video, svg
Os elementos de mídia.
display: block
Por padrão, a imagem é inline, como uma letra, e fica com um vãozinho embaixo (o espaço das "pernas" das letras, como no g). Como bloco, o vão some e ela ocupa a linha dela.
max-width: 100%; height: auto
A imagem nunca fica mais larga que o espaço onde está, e a altura acompanha a proporção. No Chromium, a foto de 400 × 300 num quadro de 300 px ficou com 300 × 225, em vez de estourar (aula Imagens que se Adaptam).
input, button, textarea, select
Os campos de formulário.
font: inherit
O atalho font (família, tamanho, peso, altura da linha…) com o valor inherit ("herdar"): o campo usa a mesma fonte do elemento em volta. Os campos não herdam a fonte sozinhos; no Chromium, o botão passou de 13,33 px para 16 px, com a mesma família do texto.
overflow-wrap: break-word
Uma palavra que não cabe na linha (um endereço comprido, um nome sem espaço) é quebrada, em vez de sair pela lateral da tela (aula Texto que Não Cabe).

O que este reset não faz, de propósito: não mexe nos títulos, nos parágrafos nem nas listas. As margens do h1 e do p e as bolinhas da lista continuam, porque são úteis. No Chromium, com o reset, o h1 continuou com font-size: 32px e margin-top: 21.44px, e a lista com padding-left: 40px.

5. Onde pôr o reset

O reset tem de vir antes dos seus estilos, para eles poderem mudar o que o reset fez. Três formas:

FormaComoQuando usar
No começo do style.cssAs cinco regras nas primeiras linhas, com um comentário /* Reset */Sites pequenos, um arquivo só. É o mais simples.
Num arquivo próprio<link rel="stylesheet" href="reset.css"> antes do <link> do style.cssQuando o CSS é dividido em vários arquivos (aula Organizando os Arquivos).
Numa camada@layer reset { … }, declarada primeiro (aula @layer)Projetos maiores: a camada do reset perde para as outras mesmo que a ordem dos arquivos mude.

Missão: o cartão da Ana tem width: 200px, mas fica mais largo por causa da borda e do preenchimento, e o botão tem letra pequena. No começo do style.css, antes das regras que já estão lá, escreva três regras do reset: o box-sizing: border-box para todos (*, *::before, *::after), o margin: 0 no body e o font: inherit nos campos (input, button, textarea, select).

<link rel="stylesheet" href="style.css">
<div class="cartao">
  <p>Bolo de cenoura</p>
  <button>Encomendar</button>
</div>

.cartao {
  width: 200px;
  padding: 20px;
  border: 4px solid tomato;
}

*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
}

input,
button,
textarea,
select {
  font: inherit;
}

.cartao {
  width: 200px;
  padding: 20px;
  border: 4px solid tomato;
}

Quando dá errado

O reset no fim do arquivo: apagou o seu estilo 
body {
  margin: 2rem;
}

/* … o resto do site … */

/* Reset */
body {
  margin: 0;
}

O que o leitor vê: a página encostada na borda, como se o margin: 2rem não existisse.

Por quê: as duas regras têm o mesmo seletor (body), a mesma especificidade, e pela cascata vence a última (aula Cascata). O reset, posto no fim, desfez o estilo da Ana. No F12, o margin: 2rem aparece riscado, vencido pela regra de baixo. O validador não reclama: as duas declarações estão corretas.

Como consertar: o reset sempre no começo (ou numa camada @layer, que não depende da ordem).

img { display: block; } e o ícone no meio da frase 
<style>
  img {
    display: block;
    max-width: 100%;
    height: auto;
  }
</style>
<p>Feito com amor <img src="assets/midia/favicon-32.png" alt="(bolo)" width="16" height="16"> pela Ana.</p>

O que o leitor vê: o ícone, que deveria ficar no meio da frase, vai para uma linha própria, quebrando o texto em três pedaços.

Por quê: o reset transformou toda imagem em bloco, e um bloco ocupa a linha inteira (aula display). Para fotos é ótimo; para um ícone dentro do texto, não.

Como consertar: uma regra para a exceção, depois do reset: .icone { display: inline; vertical-align: middle; }, e class="icone" na imagem. O reset dá o padrão; os seus estilos tratam os casos especiais.

Erro de digitação no reset: Too many values or values are not recognized 
*,
*::before,
*::after {
  box-sizing: border box;
}

$ vnu --css reset.css
"file:/home/ana/site/reset.css":4.22-4.24: error: CSS: “box-sizing”: Too many values or values are not recognized.

O que significa: "box-sizing: valores demais, ou valores não reconhecidos". O box-sizing aceita uma palavra, e o validador encontrou duas (border e box, a coluna 22 a 24 da linha 4 é o box). O valor é border-box, com hífen.

O que o leitor vê: o reset parece não funcionar só nessa parte: as caixas continuam com content-box e as larguras somam a borda. O resto do reset continua valendo, porque o navegador ignora só a declaração errada. No F12, a linha aparece riscada.

Resumo

  • O navegador tem uma folha de estilos própria (user agent stylesheet): margem de 8 px no body, títulos grandes, listas com recuo, campos com letra de 13,33 px, imagens sem limite de largura.
  • O reset agressivo (* { margin: 0; padding: 0; }) apaga até o que era útil, como as bolinhas das listas. O normalize mantém os padrões úteis e iguala os navegadores (normalize.css e modern-normalize, licença MIT).
  • Um reset moderno curto: box-sizing: border-box para todos, body sem margem e com line-height: 1.5, mídia com display: block; max-width: 100%; height: auto, campos com font: inherit, textos com overflow-wrap: break-word.
  • O reset vem antes dos seus estilos: no começo do arquivo, num reset.css ligado primeiro ou numa @layer.
  • Os casos especiais (o ícone no meio da frase) ganham uma regra própria depois do reset.
