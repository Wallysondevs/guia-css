CSS "Meu CSS Não Funciona"

Você escreveu a regra, salvou, recarregou… e nada mudou. Acontece com todo mundo, todo dia. O CSS quase nunca mostra mensagem de erro: o navegador simplesmente ignora o que não entendeu e segue em frente. Esta página junta os problemas mais comuns, cada um com o sintoma, como achar no F12 e como resolver. Todos os comportamentos foram conferidos no Chromium; as mensagens são do validador W3C (vnu 26.10.12).

Como usar esta página
  • Comece pelo roteiro de 5 perguntas: ele encontra quase todos os problemas.
  • Depois procure o seu sintoma na tabela ou com Ctrl+F ("riscada", "flex", "margem", "cache").
  • O F12 (as ferramentas do desenvolvedor) é explicado na aula Inspecionando com o F12. Os nomes dos painéis aqui são os do Chrome e do Edge (em inglês e, entre parênteses, em português); no Firefox, os nomes mudam um pouco, mas as mesmas informações estão lá.

O roteiro: 5 perguntas, nesta ordem

Pense num chuveiro que não esquenta. Antes de trocar a resistência, você confere: tem energia? O disjuntor está ligado? A chave está no "inverno"? Com o CSS é igual: das causas mais simples para as mais difíceis. Clique com o botão direito no elemento teimoso, escolha Inspecionar, e pergunte:

  1. O arquivo CSS carregou? Na aba Network (Rede), recarregue a página: o style.css aparece com status 200? Um 404 (vermelho) ou a ausência do arquivo = problema no <link> (veja abaixo). No Console, um 404 também aparece.
  2. A regra aparece no painel Styles (Estilos)? Com o elemento selecionado na aba Elements (Elementos), o painel mostra todas as regras que casam com ele. Se a sua não está lá, o seletor não casa (veja abaixo) ou a regra inteira foi descartada por um erro de escrita (veja abaixo).
  3. A declaração está riscada? Riscada com um ícone de aviso = o navegador não entendeu (nome ou valor errado). Riscada sem aviso = entendeu, mas outra regra venceu (veja abaixo). Apagada (em cinza, com um ícone de informação) = vale, mas não faz efeito ali, como um justify-content num elemento que não é flex (veja abaixo).
  4. Qual é o valor final? A aba Computed (Calculado) mostra o valor que o navegador usou, já resolvido (rgb(…), px). Clique na setinha ao lado para ver de qual regra ele veio.
  5. É o arquivo certo, salvo, e não é cache? Parece bobo, mas é comum: você editou outra cópia do arquivo, não salvou, ou o navegador mostra a versão antiga (veja abaixo).

href="style.css", e o arquivo está na pasta css/o caminho é relativo ao HTML: href="css/style.css" (aula Três Jeitos de Usar CSS).

2. Erros de escrita (o navegador não entendeu)

O ; esquecido

#aviso {
  color: red
  background-color: lightyellow;
}

Sintoma: nenhuma das duas funciona, não só a primeira. Por quê: sem o ;, o navegador lê tudo como um valor só: a cor seria "red background-color: lightyellow", que não é cor nenhuma. Medido no Chromium: a regra ficou vazia (#aviso { }), com a cor preta e o fundo transparente. No F12: a declaração aparece riscada, com aviso. Solução: ; no fim de toda declaração, até da última (aí não é obrigatório, mas evita o erro quando você acrescentar outra linha).

A } esquecida

.titulo {
  color: green;

.preco {
  color: green;
}
.rodape {
  color: green;
}

Sintoma: o .titulo funciona, mas o .preco, o .rodape e tudo o que vem depois param de funcionar (ou funcionam só em alguns lugares). Por quê: desde o CSS aninhado, uma regra pode ficar dentro de outra. Sem a }, o navegador entende que o .preco e o .rodape estão dentro do .titulo: vira ".preco que está dentro de um .titulo". Medido no Chromium: a regra guardada foi .titulo { color: green; & .preco { … } & .rodape { … } }. No F12: procure as regras no Styles: elas aparecem com o seletor do pai na frente. Solução: conte as chaves; um editor com recuo automático (indentação) mostra o problema na hora. Veja CSS Aninhado.

O comentário com //

// estilos da padaria
h1 {
  color: green;
}
p {
  color: green;
}

Sintoma: o h1 fica preto; o p funciona. Por quê: o CSS não tem comentário de linha com // (isso é do JavaScript). O navegador lê "// estilos da padaria h1" como um seletor, que é inválido, e descarta a regra inteira. Medido: só o p sobrou nas regras guardadas. Solução: o único comentário do CSS é /* … */ (aula Comentários).

5. Surpresas de layout (o CSS está certo, o resultado não)

Pai sem display: flex (ou grid)

justify-content, align-items, gap e flex-direction vão no pai, e só funcionam se ele for flex ou grid. flex: 1, align-self e order vão nos filhos diretos. O validador não reclama: o CSS é válido, só não tem efeito. No F12: o Chrome mostra a declaração apagada, com um ícone de informação que explica por que ela não faz efeito; e o selo flex ou grid ao lado do elemento, na aba Elements, só aparece num contêiner de verdade. Veja Flexbox.

width e height num elemento inline

Num <span> ou <a>, width: 200px; height: 50px; não muda nada. Medido no Chromium: o span continuou com 8px de largura (a largura da letra) e 17px de altura, embora a aba Computed mostrasse width: 200px. Por quê: elementos inline têm o tamanho do texto. Solução: display: inline-block ou block (aula display).

A margem que colapsa

Duas surpresas, as duas medidas no Chromium:

  • Margens vizinhas não se somam. Um parágrafo com margin-bottom: 20px seguido de outro com margin-top: 30px ficaram a 30px um do outro, e não 50px: a maior "engole" a menor.
  • A margem do filho vaza para fora do pai. Um <p> com margin-top: 30px dentro de uma <div> com fundo cinza, sem borda nem padding: o topo da div e o topo do p ficaram na mesma altura, e os 30px apareceram acima da div, fora do fundo cinza.

No F12: passe o mouse no elemento na aba Elements: a margem aparece pintada de laranja na página. Solução: use padding no pai em vez de margem no filho, ou faça o pai flex/grid (display: flex; flex-direction: column;), onde as margens não colapsam; ou use gap. Veja Margem.

O caminho do url()

Dentro de um arquivo CSS, o caminho do url() é relativo ao arquivo CSS, e não ao HTML. Com o CSS em css/style.css e a imagem em img/bolo.jpg, url("img/bolo.jpg") procura css/img/bolo.jpg, que não existe. O certo é url("../img/bolo.jpg") (o ../ sobe uma pasta). No F12: a aba Network mostra o 404 com o endereço completo que o navegador tentou. A missão do fim desta página tem esse defeito. Veja Imagem de Fundo.

O hidden que não esconde

Com <div class="menu" hidden> e .menu { display: flex; } no CSS, o menu aparece. Medido no Chromium: display calculado flex, com 18px de altura. Por quê: o atributo hidden só funciona porque o navegador tem uma regra própria [hidden] { display: none; }, e qualquer regra sua com display vence a do navegador. Solução: acrescente [hidden] { display: none !important; } no seu CSS (um dos poucos usos razoáveis do !important), ou esconda com uma classe. Veja Escondendo.

z-index que não funciona

O z-index só vale em elemento com position diferente de static (ou em item de flex e grid). E um elemento nunca passa à frente de algo que está fora do "grupo" (contexto de empilhamento) do pai dele: um z-index: 9999 não ajuda se o pai está atrás. Veja Camadas.

A @media que não vale

  • No celular, a página aparece encolhida e a @media não age: falta <meta name="viewport" content="width=device-width, initial-scale=1"> no head (aula A Meta Viewport).
  • A regra da @media está riscada: a @media veio antes da regra comum, e a regra comum, que vem depois e tem a mesma especificidade, vence. Ponha as @media no fim.
  • Escrita: and(max-width…) sem espaço, nome errado (max-widht), chave esquecida. Veja Regras @.

6. Mudei e nada mudou: cache e arquivo errado

Para economizar internet, o navegador guarda uma cópia do CSS (o cache) e pode continuar usando a cópia velha depois que você mudou o arquivo.

ParaFaça
recarregar ignorando o cacheCtrl+Shift+R ou Ctrl+F5 (no Mac, Cmd+Shift+R)
nunca usar cache enquanto trabalhaF12, aba Network, marque Disable cache (Desativar cache). Só vale com o F12 aberto.
conferir qual versão o navegador temF12, aba Sources (Fontes): abra o style.css e veja se a sua mudança está lá
obrigar os visitantes do site a baixar a versão novamude o endereço do arquivo a cada versão: href="style.css?v=2" (aula CSS Rápido)

Se a mudança não está no Sources mesmo depois do Ctrl+Shift+R: você não salvou o arquivo, editou uma cópia em outra pasta, ou o <link> aponta para outro arquivo. Num site publicado, o servidor pode demorar alguns minutos para mostrar a versão nova.

7. Peça ajuda ao validador

O validador W3C do CSS (jigsaw.w3.org/css-validator, ou o vnu --css no terminal) aponta a linha exata de muitos destes erros. Mas lembre:

  • ele não acha erro de lógica: seletor que não casa, especificidade, pai sem flex, margem que colapsa, cache;
  • às vezes ele reclama do que está certo, porque ainda não conhece um recurso novo (@container, unidades cqi, image-set()): veja Regras @ e Funções;
  • depois de um Parse Error, conserte o primeiro e valide de novo: um erro pode gerar outros.

Resumo

  • O CSS não dá erro: ignora o que não entendeu. Investigue com o F12, na ordem: carregou? a regra aparece? está riscada? qual o valor calculado? é o arquivo certo?
  • Riscada com aviso = escrita errada. Riscada sem aviso = perdeu para outra regra. Apagada = sem efeito ali.
  • ; esquecido derruba duas declarações; } esquecida aninha as regras seguintes; // derruba a regra seguinte.
  • Classes diferenciam maiúsculas; ponto no CSS, sem ponto no HTML.
  • Alinhamentos precisam de pai flex/grid; width não age em inline; margens colapsam; url() é relativo ao arquivo CSS; display desfaz o hidden.
  • Mudou e nada mudou: Ctrl+Shift+R e "Disable cache".
