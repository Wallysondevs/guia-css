CSS Especificidade

Na aula A Cascata, você viu que, quando duas regras brigam, o seletor "mais específico" ganha, antes mesmo da ordem no código. Mas o que é "mais específico"? O navegador não adivinha: ele conta. Cada seletor recebe uma pontuação de três números, (a, b, c), e quem tem a pontuação maior vence. Nesta aula você vai aprender a fazer essa conta de cabeça.

Você vai aprender
  • A contagem (a, b, c): IDs, classes e elementos.
  • Como comparar duas pontuações, coluna por coluna.
  • Uma tabela de seletores já contados.
  • O que conta zero: *, os combinadores e o :where().
  • Por que onze classes não vencem um ID.
  • Como escrever CSS com especificidade baixa, fácil de mudar depois.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código.

A ideia: o quadro de medalhas

Na Olimpíada, os países são ordenados pelo quadro de medalhas. Primeiro olha-se o ouro. Quem tem mais ouro fica na frente, não importa quantas pratas o outro tenha. Só se o ouro empatar, olha-se a prata. Só se a prata empatar, o bronze.

PaísOuroPrataBronzePosição
A1001º: o único com ouro
B01102º: muita prata, mas nenhum ouro
C0253º: perdeu na prata, o bronze nem foi olhado

1. Contando um seletor

Para contar, leia o seletor da esquerda para a direita e ponha cada pedaço na sua coluna. Vamos contar #menu .item a:hover:

#menu
Um ID: a = 1.
(espaço)
Um combinador: não conta nada.
.item
Uma classe: b = 1.
a
Um elemento: c = 1.
:hover
Uma pseudo-classe: conta como classe, b = 2.

Resultado: (1, 2, 1). Lê-se "um, dois, um": um ID, duas classes, um elemento.

2. Comparando: coluna por coluna

Para saber quem ganha, compare a coluna a. Quem tiver mais, ganha, e acabou. Se empatar, compare a b. Se empatar de novo, a c. Se empatar nas três, a especificidade empatou, e quem decide é a ordem no código: a última ganha.

Não é um número de três algarismos

É tentador juntar (0, 11, 0) em "110" e achar que ganha de (1, 0, 0), "100". Não ganha: as colunas não "vão um" como na conta de somar. Onze pratas nunca viram um ouro. Escreva sempre com vírgulas, (0, 11, 0), para não se confundir.

Experimente: quatro regras disputam a cor do mesmo link, com a pontuação de cada uma no comentário. A de maior pontuação, #menu a (1, 0, 1), ganha, e o link fica azul-marinho, mesmo sendo a primeira regra. Apague a regra #menu a e descubra quem ganha depois dela. E depois? Conte antes de olhar o resultado.

<link rel="stylesheet" href="style.css">
<nav id="menu" class="menu">
  <a href="index.html" class="ativo">Início</a>
</nav>

/* (1, 0, 1) */
#menu a {
  color: navy;
}

/* (0, 2, 0) */
.menu .ativo {
  color: crimson;
}

/* (0, 1, 1) */
.menu a {
  color: darkgreen;
}

/* (0, 0, 2) */
nav a {
  color: saddlebrown;
}

Sem o #menu a, ganha .menu .ativo (0, 2, 0): vermelho. Sem ele também, ganha .menu a (0, 1, 1): verde. Por último, nav a (0, 0, 2): marrom. A posição das regras no arquivo não influiu em nenhuma dessas disputas, porque nenhuma pontuação empatou.

O que conta zero

  • O seletor universal * (aula Seletor Universal).
  • Os combinadores: espaço, >, + e ~ (aula Combinadores). .menu > li e .menu li têm a mesma pontuação.
  • A pseudo-classe :where(), com tudo o que estiver dentro dela: :where(#topo) a é só (0, 0, 1).

Os casos especiais

  • :is(), :not() e :has() não contam por si mesmos: valem a pontuação do seletor mais forte dentro dos parênteses. p:not(.aviso) é (0, 1, 1), e :is(#topo, .menu) a é (1, 0, 1). Detalhes na aula :not(), :is() e :where().
  • O atributo style no HTML não tem seletor e não entra na conta: ele ganha de qualquer pontuação (aula A Cascata).
  • !important também não é especificidade: ele muda o andar da disputa (aula !important).

4. Subindo a pontuação de propósito

Quando uma regra sua perde, a saída é escrever um seletor com pontuação maior ou igual à da vencedora (se for igual, a sua tem de vir depois). Suba o mínimo necessário.

Missão: o link da página atual (class="ativo") devia ser vermelho (crimson), mas a regra #menu a ganha. Conte as duas pontuações e mude o seletor da regra de baixo para ele ganhar. Sem mexer no HTML e sem !important. O outro link tem de continuar azul-marinho.

<link rel="stylesheet" href="style.css">
<nav id="menu">
  <a href="index.html" class="ativo">Início</a>
  <a href="receitas.html">Receitas</a>
</nav>

#menu a {
  color: navy;
}

.ativo {
  color: crimson;
}

#menu a {
  color: navy;
}

#menu .ativo {
  color: crimson;
}

#menu a é (1, 0, 1) e .ativo é (0, 1, 0): perde no ouro. #menu .ativo é (1, 1, 0): empata no ouro e ganha na prata. Repare na corrida que começou: para vencer um ID, você precisou de outro ID. É por isso que a próxima seção existe.

5. A boa prática: especificidade baixa e parecida

Um CSS fácil de mudar é aquele em que quase todas as regras têm pontuação baixa e parecida, como (0, 1, 0) ou (0, 1, 1). Assim, para mudar algo, basta uma regra de mesma força, escrita depois. Na prática:

FaçaEvitePor quê
.ativo, .preco#menu a, #conteudo .precoUm ID no seletor obriga toda regra que quiser mudá-lo a ter um ID também
.menu-linkheader nav ul li aCorrentes longas somam pontos e quebram se o HTML mudar
Uma classe a mais no HTMLUm seletor mais comprido no CSSA classe deixa a pontuação baixa
Consertar a regra que ganha!importantO !important só desloca a briga para um andar acima

Quando dá errado

Muitas classes contra um ID 
<style>
  #aviso {
    color: navy;
  }
  .caixa .nota.destaque.urgente {
    color: crimson;
  }
</style>
<div class="caixa">
  <p id="aviso" class="nota destaque urgente">Fechado no feriado.</p>
</div>

O que você vê: o aviso continua azul-marinho.

Por quê: (1, 0, 0) contra (0, 4, 0). Decide na coluna a: um ID contra nenhum. Pode empilhar quantas classes quiser.

Como consertar: troque o id do estilo por uma classe (.aviso, (0, 1, 0)); o id pode continuar no HTML para âncoras e JavaScript (aula Seletor de ID).

"A minha regra vem depois e mesmo assim perde" 
<style>
  ul li {
    color: navy;
  }
  li {
    color: darkgreen;
  }
</style>
<ul>
  <li>Farinha</li>
</ul>

O que você vê: o item fica azul-marinho.

Por quê: a ordem só decide no empate. ul li é (0, 0, 2) e li é (0, 0, 1): perdeu no bronze, antes de a ordem ser olhada.

Como consertar: conte as duas antes de culpar a ordem. Aqui, ul li também na regra de baixo, ou uma classe nos itens.

A corrida do "mais forte" 
.preco { color: darkgreen; }                          /* (0, 1, 0) */
.cardapio .preco { color: darkgreen; }                /* (0, 2, 0) */
#conteudo .cardapio .preco { color: darkgreen; }      /* (1, 2, 0) */
#conteudo .cardapio .preco { color: darkgreen !important; }

O que acontece: cada vez que uma regra perde, alguém escreve uma mais forte. Em pouco tempo o arquivo está cheio de seletores enormes e de !important, e qualquer mudança vira uma investigação.

Como evitar: pontuação baixa desde o começo (seção 5). Em projetos grandes, :where() (que zera a pontuação) e @layer ajudam a manter a ordem.

Missão final: tirando o ID do estilo

Missão: deixe o CSS do menu com especificidade baixa. (1) No HTML, troque id="menu" por class="menu". (2) No CSS, troque #menu por .menu nas duas regras. (3) Confira: o link ativo continua vermelho e o outro, azul-marinho? Se não, conte as pontuações e ajuste o seletor do ativo.

<link rel="stylesheet" href="style.css">
<nav id="menu">
  <a href="index.html" class="ativo">Início</a>
  <a href="receitas.html">Receitas</a>
</nav>

#menu a {
  color: navy;
}

#menu .ativo {
  color: crimson;
}

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="index.html" class="ativo">Início</a>
  <a href="receitas.html">Receitas</a>
</nav>

.menu a {
  color: navy;
}

.menu .ativo {
  color: crimson;
}

Depois da troca, as pontuações caíram de (1, 0, 1) e (1, 1, 0) para (0, 1, 1) e (0, 2, 0). A relação entre as duas continua a mesma (o ativo ganha na prata), mas agora qualquer regra futura com uma ou duas classes consegue mudar o menu, sem precisar de ID nem de !important.

Resumo

  • A especificidade é uma pontuação de três colunas, (a, b, c): IDs; classes, atributos e pseudo-classes; elementos e pseudo-elementos.
  • Compare coluna por coluna, da esquerda para a direita. Não é um número: (0, 11, 0) perde para (1, 0, 0).
  • Empate nas três colunas: a última regra ganha.
  • *, combinadores e :where() contam zero. :is(), :not() e :has() valem o argumento mais forte.
  • O atributo style e o !important não são especificidade: estão acima dela na cascata.
  • Boa prática: pontuações baixas e parecidas, com classes; sem IDs no estilo e sem correntes longas.
