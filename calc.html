CSS calc()

"A largura toda, menos 40 pixels." "Dois rem e mais 4 pixels." "Um terço do espaço, descontando os vãos." Medidas assim aparecem o tempo todo num layout, e misturam unidades diferentes: % com px, rem com vw. Você não sabe quanto é 100% em pixels (depende da tela), então não dá para fazer a conta de cabeça. A função calc() deixa a conta para o navegador, que faz na hora de desenhar.

Você vai aprender
  • A forma de calc() e as quatro operações: +, -, * e /.
  • A regra dos espaços em volta do + e do -.
  • As regras da multiplicação e da divisão.
  • Parênteses e a ordem das contas.
  • calc() com variáveis.
  • Usos comuns, e quando min(), max(), clamp() ou o gap fazem melhor.
  • Os erros que o validador W3C pega e os que ele deixa passar.

A ideia: a prateleira do marceneiro

A Ana pede ao marceneiro: "uma prateleira da largura da parede, menos 2 centímetros de cada lado". Ele não precisa saber a largura da parede antes: mede na hora, tira os 4 centímetros e corta. O calc() é esse pedido: você escreve a conta, e o navegador mede o espaço e faz a conta quando desenha a página, de novo a cada vez que a janela muda de tamanho.

1. A primeira conta

.aviso {
  width: calc(100% - 40px);
}
calc(
A função de conta (calculate, "calcular"). Ela pode ir em qualquer lugar onde caberia um número, um tamanho, um ângulo ou um tempo.
100%
A largura toda do pai.
-
A operação: menos. Com espaço dos dois lados, sempre (veja a seção 2).
40px)
Quarenta pixels, e o parêntese que fecha a função.

Experimente: a coluna tracejada tem 300 pixels. Troque o 40px por 100px, ou o - por + (e veja o aviso passar da coluna).

<link rel="stylesheet" href="style.css">
<div class="coluna">
  <p class="aviso">Encomendas com um dia de antecedência.</p>
</div>

.coluna {
  width: 300px;
  border: 2px dashed gray;
}

.aviso {
  width: calc(100% - 40px);
  background-color: lightyellow;
}

O aviso fica com 260px (300 − 40, conferido no Chromium): a faixa amarela termina antes da borda tracejada, deixando 40 pixels livres à direita. Na aba Computed do F12 aparece só o resultado, 260px; a conta fica na aba de estilos, como você escreveu.

2. As quatro operações

OperaçãoExemploRegra
+ somarcalc(2rem + 4px)Espaço dos dois lados. Os dois lados têm de ser do mesmo tipo (dois tamanhos, ou dois números)
- subtraircalc(100% - 40px)O mesmo: espaço dos dois lados, tipos iguais
* multiplicarcalc(16px * 2)Um dos lados tem de ser um número puro (sem unidade)
/ dividircalc(100% / 3)Divida por um número puro; nunca por zero

Por que o espaço no + e no -? Porque o hífen também faz parte de nomes e de números negativos. 100%-40px, grudado, é lido como "100%" seguido de "−40px" (um número negativo), sem conta entre eles. No * e no /, o espaço é opcional, mas use igual, para ler melhor.

margin-top: calc(2rem + 4px)36px (32 + 4)
height: calc((100px - 60px) / 2)20px

3. Parênteses e a ordem das contas

Como na matemática da escola: multiplicação e divisão primeiro, depois soma e subtração. Para mudar a ordem, use parênteses (sem escrever calc de novo):

.cartao {
  /* três cartões numa linha, com dois vãos de 16px entre eles */
  width: calc((100% - 2 * 16px) / 3);
}

Lendo de dentro para fora: 2 * 16px = 32px (os dois vãos); 100% - 32px = o espaço que sobra para os cartões; dividido por 3 = a largura de cada um. Num pai de 300px, cada cartão fica com (300 − 32) ÷ 3 = 89,33 pixels.

Para colunas, prefira Flexbox e Grid

A conta acima era o jeito de fazer colunas antes do Flexbox e do Grid. Hoje, display: grid; grid-template-columns: repeat(3, 1fr); gap: 16px; faz a mesma coisa sem conta nenhuma (aula Colunas). O calc() continua útil para os casos em que não há uma propriedade pronta.

4. calc() com variáveis

Com variáveis, o calc() mostra o seu melhor: um valor guardado numa variável e outros valores derivados dele por conta.

:root {
  --espaco: 12px;
}

.cartao {
  padding: var(--espaco);
  margin-bottom: calc(var(--espaco) * 2);
}

.faixa {
  margin-left: calc(-1 * var(--espaco));
  width: calc(100% + 2 * var(--espaco));
}
calc(var(--espaco) * 2)
O dobro do espaço: 24px. Mude --espaco e a margem acompanha.
calc(-1 * var(--espaco))
O espaço com sinal trocado: −12px. Uma margem negativa puxa a faixa para a esquerda, por cima do padding do cartão.
calc(100% + 2 * var(--espaco))
A largura do conteúdo do cartão mais os dois paddings: a faixa vai de uma borda à outra do cartão.

E se a variável guarda só um número, é o calc() que dá a unidade: calc(var(--colunas) * 1px). Escrever var(--colunas)px não funciona.

calc() ou min(), max() e clamp()?

As funções da aula min(), max() e clamp() já aceitam contas por dentro, sem escrever calc: clamp(1rem, 0.9rem + 1vw, 2rem). Use calc() quando você quer uma conta; use as outras quando quer escolher entre valores ou pôr limites.

Quero…Use
Uma conta com unidades diferentescalc(100% - 40px)
Uma conta com tetomin(100% - 40px, 600px)
Uma conta com piso e tetoclamp(1rem, 0.9rem + 1vw, 2rem)
Espaço entre itens de uma linha ou gradegap, sem conta (aula gap)
Suporte

calc() funciona em todos os navegadores há mais de dez anos (o MDN marca "Baseline: amplamente disponível"). Pode usar sem preocupação.

Quando dá errado

Com calc() errado, o navegador ignora a declaração inteira e o elemento fica como se ela não existisse. Nos exemplos abaixo, cada caixa está dentro de um pai de 300px; com o erro, todas ficam com a largura toda, 300px (conferido no Chromium).

.a {
  width: calc(100%-40px);
}
.b {
  width: calc(100% - 40);
}
.c {
  width: calc(10px * 2px);
}
.d {
  width: calc(100% - 40px;
}
.e {
  width: calc(100% - 40px);
  margin-top: calc(2rem + 4px);
  padding: calc(var(--espaco) * 2);
  height: calc((100vh - 60px) / 2);
}

$ vnu --css calc.css
"file:/home/ana/site/calc.css":2.24-2.24: error: CSS: “width”: Parse Error.
"file:/home/ana/site/calc.css":8.25-8.25: error: CSS: “width”: One operand must be a number.
"file:/home/ana/site/calc.css":11.22-11.25: error: CSS: “width”: Parse Error.
Sem espaços em volta do - (linha 2): Parse Error

100%-40px não é uma conta: são dois valores lado a lado. "Erro de leitura" na linha 2. Como consertar: calc(100% - 40px).

Número sem unidade numa soma (linha 5): o validador não pega

100% - 40 tenta tirar um número de um tamanho: 40 o quê? O navegador recusa a declaração (a caixa fica com os 300px), mas o validador vnu não mostra erro nenhum para essa linha. Repare: o arquivo tem quatro linhas com problema, e o validador acusa três. Não confie só no validador; confira o resultado. Como consertar: calc(100% - 40px).

Multiplicar dois tamanhos (linha 8): One operand must be a number

"Um dos operandos tem de ser um número": 10px * 2px daria "20 pixels quadrados", que não é uma largura. Como consertar: calc(10px * 2).

Faltou fechar o parêntese (linha 11): a regra seguinte também some

O que você vê: a caixa .d fica com 300px, e a caixa .e, que estava certa, também perde os estilos. Num teste com .e { width: 100px; background-color: gold; } logo depois, a caixa .e ficou com 300px e sem o fundo dourado (conferido no Chromium).

Por quê: enquanto um parêntese está aberto, o navegador acha que ainda está dentro da função: o ;, o } e a regra seguinte inteira viram "parte da conta". O validador acusa a linha 11 (Parse Error), mas não diz que a regra de baixo foi engolida.

Como consertar: conte os parênteses: cada ( precisa do seu ). Quando uma regra "certa" para de funcionar sem motivo, olhe a regra de cima.

Resumo

  • calc() faz contas com unidades diferentes (100% - 40px); o navegador resolve na hora de desenhar, e de novo quando a tela muda.
  • + e - com espaço dos dois lados e tipos iguais; * com um número puro de um lado; / por um número puro.
  • Parênteses mudam a ordem: calc((100% - 32px) / 3).
  • Com variáveis: calc(var(--espaco) * 2), calc(-1 * var(--espaco)), calc(var(--n) * 1px).
  • min(), max() e clamp() aceitam contas direto; para vãos entre itens, gap é melhor que conta.
  • Erro na conta: a declaração é ignorada. O validador pega o - grudado e a multiplicação de tamanhos, mas não o número sem unidade (100% - 40). Um parêntese sem fechar engole até a regra seguinte.
