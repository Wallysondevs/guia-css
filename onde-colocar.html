CSS Onde Colocar

Você já sabe o que é CSS. Falta saber onde escrevê-lo para o navegador encontrar. São três lugares possíveis: dentro da própria tag, num bloco <style> no começo da página ou num arquivo separado, chamado com <link>. Nesta aula você vai usar os três, ver o alcance de cada um e entender por que o arquivo separado é o jeito que você vai usar quase sempre.

Você vai aprender
  • O atributo style: CSS dentro de uma tag, para um elemento só.
  • O elemento <style>: CSS no <head>, para a página inteira.
  • O arquivo .css com <link rel="stylesheet">: um CSS para o site inteiro.
  • Qual dos três usar, e por quê.
  • Os erros reais: o nome do arquivo errado, o <link> sem rel, o <style> fora do lugar e as tags HTML dentro do arquivo de CSS.

A ideia: o bilhete, o quadro de avisos e o manual

Imagine que a Ana tem uma padaria e quer passar instruções para a equipe:

  • um bilhete colado num bolo: "este aqui vai com cobertura extra". Vale só para aquele bolo;
  • um aviso no quadro da cozinha: "hoje, todos os bolos com cobertura de chocolate". Vale para aquela cozinha;
  • o manual da padaria, uma cópia em cada loja: "nossos bolos sempre levam cobertura". Vale para todas as lojas, e mudar o manual muda todas de uma vez.

1. No atributo style (dentro da tag)

Todo elemento HTML aceita o atributo style. Dentro das aspas vão as instruções de CSS, só para aquele elemento:

<h1 style="color: firebrick;">Receitas da Ana</h1>
<h1>Receitas do Beto</h1>
style="…"
O atributo de estilo. É um atributo como href ou alt: vai dentro da tag de abertura, com o valor entre aspas.
color: firebrick;
Uma instrução de CSS: a propriedade color ("cor"), os dois-pontos, o valor firebrick e o ponto e vírgula. Repare que não tem seletor nem chaves: o "quem" já é o próprio elemento.

No resultado, só o primeiro título ficou vermelho-escuro. O segundo, sem o atributo, continua preto. Para mais de uma instrução, separe com ; dentro das mesmas aspas:

<p style="color: navy; font-size: 24px; text-align: center;">Promoção de bolo de cenoura!</p>

Fica azul-marinho, maior e centralizado. E já dá para sentir o problema: a linha cresce, o HTML fica difícil de ler, e se houver dez promoções no site, são dez cópias dessa linha.

Experimente: mude a cor no style do primeiro parágrafo. Depois tente deixar o segundo parágrafo igual ao primeiro: você vai ter de copiar o atributo inteiro.

<p style="color: darkgreen; font-size: 20px;">Bolo de cenoura: R$ 30</p>
<p>Pão de queijo: R$ 2</p>

2. No elemento <style> (no <head>)

O elemento <style> guarda regras de CSS completas, com seletor e chaves, e vale para a página inteira. O lugar dele é o <head>:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<style>
  h1 {
    color: firebrick;
  }
</style>
</head>
<body>
<h1>Receitas da Ana</h1>
<h1>Receitas do Beto</h1>
</body>
</html>
<style>
Abre o bloco de CSS. Tudo até o </style> é lido como CSS, e não como HTML.
h1 { color: firebrick; }
Uma regra completa: o seletor h1 diz "todos os <h1> desta página".
</style>
Fecha o bloco.

Agora os dois títulos ficaram vermelho-escuros, com uma regra só. Bem melhor que o atributo. Mas a regra mora dentro desta página: a página sobre.html não sabe que ela existe, e teria de ter a sua própria cópia.

3. Num arquivo separado, com <link>

O jeito recomendado: as regras vão para um arquivo só de CSS, com a extensão .css, e cada página o chama com um <link> no <head>. Na pasta do site da Ana:

$ ls
index.html  sobre.html  style.css
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<link rel="stylesheet" href="style.css">
</head>
<body>
<h1>Receitas da Ana</h1>
</body>
</html>

h1 {
  color: firebrick;
}
<link
O elemento que liga a página a outro arquivo. Não tem tag de fechamento.
rel="stylesheet"
A relação com o arquivo: stylesheet = "folha de estilo". É o rel que diz ao navegador "aplique este arquivo como CSS". Sem ele, o arquivo é ignorado.
href="style.css"
O endereço do arquivo, como no <a href>. Aqui, o arquivo style.css na mesma pasta.
style.css
Só regras de CSS. Sem <style>, sem <html>: é texto puro com CSS.

O sobre.html leva o mesmo <link> no <head>. As duas páginas usam o mesmo arquivo. Mudou o style.css, mudaram as duas. Com 50 páginas, é a mesma coisa: um arquivo, um lugar para mexer.

Nas caixas "Experimente" deste guia, cada aba é um arquivo da mesma pasta. A caixa abaixo tem duas páginas e um CSS:

Experimente: na aba style.css, troque firebrick por darkgreen. Depois clique no link "Sobre a Ana" no resultado: a outra página também mudou, porque as duas chamam o mesmo arquivo.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p><a href="sobre.html">Sobre a Ana</a></p>

<link rel="stylesheet" href="style.css">
<h1>Sobre a Ana</h1>
<p><a href="index.html">Voltar ao início</a></p>

h1 {
  color: firebrick;
}
Nas abas, sem <head>?

As abas index.html das caixas começam direto no <link>, sem <!DOCTYPE>, <html> e <head>, para o código ficar curto. O navegador põe o <link> no <head> sozinho. No seu site de verdade, escreva a página completa, como no index.html acima.

Por que o arquivo separado é o melhor

  • Um lugar só: o visual do site inteiro fica num arquivo. Trocar a cor da marca é editar uma linha.
  • HTML limpo: o HTML fica só com a estrutura (aula HTML e CSS), mais fácil de ler.
  • Mais rápido: o navegador baixa o style.css uma vez e guarda uma cópia (o cache). Nas outras páginas do site, ele reaproveita a cópia em vez de baixar de novo. O CSS no <style>, ao contrário, vem repetido dentro de cada página.
  • Trabalho em equipe: uma pessoa mexe no HTML, outra no CSS, sem pisar uma no arquivo da outra.

4. Quem vence quando os três falam do mesmo elemento

Você pode usar mais de um jeito na mesma página. Quando eles discordam, o atributo style ganha das regras do <style> e do arquivo:

<style>
  h1 {
    color: navy;
  }
</style>
<h1 style="color: firebrick;">Receitas da Ana</h1>
<h1>Receitas do Beto</h1>

O primeiro título fica vermelho-escuro (venceu o atributo); o segundo, sem atributo, fica azul-marinho (vale a regra do <style>). Entre o <style> e o arquivo, quem vem depois no código vence. Por que é assim, e todas as regras desse "desempate", é o assunto de A Cascata e Especificidade.

Esse poder do atributo style é justamente um problema: uma cor escondida numa tag ganha do seu arquivo de CSS, e você passa minutos procurando por que a mudança no style.css "não funciona".

Quando dá errado

O nome do arquivo no href está errado: nada muda

Experimente (erro de propósito): o arquivo se chama style.css, mas o href pede estilo.css. Repare no console embaixo do resultado e conserte o href.

<link rel="stylesheet" href="estilo.css">
<h1>Receitas da Ana</h1>

h1 {
  color: firebrick;
}

O que você vê: o título preto, como se o CSS não existisse. O navegador procurou estilo.css, não achou e seguiu em frente sem CSS. Não aparece nada na página; o editor do guia avisa no console: Não foi possível carregar "estilo.css" (<link>). Confira o nome e o caminho do arquivo. Num site de verdade, o aviso aparece no console do F12 (aula Inspecionando com o F12).

O que o validador diz: nada. Ele confere se o HTML está bem escrito, e não se o arquivo existe.

Como consertar: o href tem de ter o nome exato do arquivo, com as mesmas maiúsculas e minúsculas (Style.css é outro arquivo num servidor de verdade) e o caminho certo, se ele estiver em outra pasta (css/style.css). Organizar o CSS em pastas: aula Organizando os Arquivos de CSS.

Esqueceu o rel: Element “link” is missing one or more of the following attributes 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas</title>
<link href="style.css">
</head>
<body>
<h1>Receitas da Ana</h1>
</body>
</html>

O que você vê: o título preto. O arquivo existe e o href está certo, mas sem rel="stylesheet" o navegador não sabe que aquilo é uma folha de estilo e não a aplica.

$ vnu semrel.html
"file:/home/ana/site/semrel.html":6.1-6.23: error: Element “link” is missing one or more of the following attributes: “itemprop”, “property”, “rel”.

O que significa: "falta ao elemento link um destes atributos: itemprop, property, rel". Os dois primeiros são de outros usos do <link>; para CSS, o que falta é o rel.

Como consertar: <link rel="stylesheet" href="style.css">.

Tags HTML dentro do arquivo .css: Style sheets should not include HTML syntax

A Ana copiou o bloco do <style> para o arquivo, com as tags junto:

$ cat style.css
<style>
h1 {
  color: firebrick;
}

p {
  color: navy;
}
</style>
$ vnu --css style.css
"file:/home/ana/site/style.css":1.1-1.7: error: CSS: Parse Error. Style sheets should not include HTML syntax.
"file:/home/ana/site/style.css":11.1-11.8: error: Stray end tag “style”.

O que o navegador faz (conferido no Chromium): o <style> da primeira linha "gruda" no seletor da regra seguinte, que vira <style> h1, um seletor que não existe. A regra inteira do h1 é jogada fora, e o título fica preto. A regra do p, depois dela, funciona: o parágrafo fica azul-marinho. O resultado é o pior possível: metade do CSS funciona, e parece que o problema está no h1.

O que significa: "erro de leitura: folhas de estilo não devem ter sintaxe de HTML" (na linha 1) e "tag de fechamento style perdida". A segunda mensagem aponta a linha 11, que nem existe no arquivo: depois do primeiro erro, o validador se perde. Conserte o primeiro erro e rode de novo.

Como consertar: apague o <style> e o </style>. O arquivo .css só tem CSS.

<style> no <body>: not allowed outside an “@scope” rule 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas</title>
</head>
<body>
<style>
  h1 { color: tomato; }
</style>
<h1>Receitas da Ana</h1>
</body>
</html>

O que o navegador faz: aplica o estilo mesmo assim (o título fica vermelho). Por isso o erro passa despercebido.

$ vnu stylebody.html
"file:/home/ana/site/stylebody.html":9.3-9.4: error: Style rule “h1” not allowed outside an “@scope” rule in a “style” element in “body”.

O que significa: "a regra h1 não é permitida fora de uma regra @scope num style dentro do body". Em português: um <style> no <body> só é válido com um recurso avançado, o @scope (aula Escopo). Para o CSS comum, o lugar é o <head>.

Como consertar: mova o <style> para dentro do <head>, ou, melhor ainda, passe as regras para o style.css.

  • Três lugares para o CSS: o atributo style (um elemento), o elemento <style> no <head> (uma página) e o arquivo .css com <link rel="stylesheet" href="…"> (o site inteiro).
    • 
  
  • Use o arquivo separado: um lugar só para mexer, HTML limpo e o navegador reaproveita a cópia em todas as páginas.
    • 
  
  • No atributo style não há seletor nem chaves. Ele vence as regras do <style> e do arquivo, e é por isso que atrapalha.
    •

    • 
  
  • Sem rel="stylesheet", o arquivo é ignorado. Tags HTML dentro do .css derrubam a primeira regra. <style> no <body> funciona, mas é inválido.
