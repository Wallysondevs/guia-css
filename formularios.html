CSS Formulários

Um formulário sem CSS funciona, mas parece um rascunho: rótulos e campos amontoados na mesma linha, letras menores que as do resto da página, campos de tamanhos diferentes. Nesta aula você vai arrumar o formulário de encomendas da Ana, passo a passo: rótulos em cima, campos da mesma largura, letra igual à da página, um foco bem visível e um aviso vermelho quando o e-mail estiver errado.

Você vai aprender
  • Como o navegador desenha um formulário sem CSS, e por quê.
  • display: block nos rótulos (label) para empilhar.
  • font: inherit: os campos com a mesma letra da página.
  • width: 100% + box-sizing: border-box: campos do mesmo tamanho, sem passar da borda.
  • Borda, cantos e espaço interno dos campos; o textarea e o resize.
  • Foco visível com :focus-visible, e por que nunca apagar o contorno.
  • Campos inválidos com :user-invalid (e o problema do :invalid).
  • O texto de exemplo (::placeholder) e os erros do validador W3C.

O HTML dos formulários (<form>, <label>, <input>…) é assunto do Guia HTML. Aqui ele já está pronto e certo: cada campo tem o seu <label for="…">. Os botões têm aula própria, Estilizando Botões.

A ideia: o formulário de papel

Pense numa ficha de papel bem feita: cada pergunta em cima do seu espaço, todos os espaços do mesmo tamanho, alinhados, com letra legível. Quem preenche sabe onde está e o que falta. O CSS faz isso na tela, e acrescenta duas coisas que o papel não tem: um destaque no campo que está sendo preenchido (o foco) e um aviso no campo errado.

1. O ponto de partida: sem CSS

O formulário de encomendas da Ana, só com a largura do formulário definida (300 pixels):

<link rel="stylesheet" href="style.css">
<form class="encomenda">
  <label for="nome">Nome</label>
  <input type="text" id="nome" name="nome" placeholder="Ana Souza">
  <label for="email">E-mail</label>
  <input type="email" id="email" name="email">
  <label for="sabor">Sabor</label>
  <select id="sabor" name="sabor">
    <option>Cenoura</option>
    <option>Fubá</option>
  </select>
  <label for="recado">Recado</label>
  <textarea id="recado" name="recado" rows="3"></textarea>
  <button>Encomendar</button>
</form>

.encomenda {
  width: 300px;
}

Três problemas aparecem:

  • Tudo na mesma linha, quebrando onde der: "Nome [campo] E-mail", "[campo] Sabor [lista] Recado". O <label>, o <input> e os outros campos são elementos em linha (display: inline e inline-block, aula display), como palavras numa frase.
  • A letra dos campos é diferente da letra da página: menor (13.3333px, contra 16px do texto, conferido no Chromium) e de outra família. O textarea usa até letra de máquina de escrever (monospace). Os campos não herdam a fonte da página (aula Herança): o navegador dá a eles uma fonte própria.
  • Cada campo tem um tamanho: o texto, a lista e a caixa de recado têm larguras diferentes.

2. Rótulos em cima: display: block

Basta transformar o rótulo em bloco: ele ocupa a linha toda e empurra o campo para baixo. Um pouco de margem separa uma pergunta da outra:

label {
  display: block;
  margin-top: 12px;
  margin-bottom: 4px;
  font-weight: 700;
}

O rótulo em cima do campo é o mais fácil de ler, inclusive no celular, onde não há espaço ao lado. E deixe o rótulo sempre visível: ele diz o que o campo pede, e clicar nele leva o foco para o campo (graças ao for).

3. A mesma letra: font: inherit

input,
select,
textarea {
  font: inherit;
}
input, select, textarea
Três seletores agrupados com vírgula (aula Agrupando Seletores): a regra vale para os três tipos de campo.
font
O atalho que junta font-family, font-size, font-weight, font-style e line-height.
inherit
"Herdar": em vez do valor do navegador, use o mesmo valor do pai. Com isso, o campo fica com a letra do formulário, que herdou do body.

Depois dessa regra, o texto digitado nos campos fica com 16px, a mesma letra da página. Além de ficar mais bonito, letra de 16px ou mais evita outro problema: no iPhone, o Safari dá zoom na página ao tocar num campo com letra menor que 16px.

4. A mesma largura: width: 100% e box-sizing

Para todos os campos terem a largura do formulário, use width: 100%. Mas cuidado com o espaço interno (padding) e a borda:

<link rel="stylesheet" href="style.css">
<form class="encomenda">
  <label for="nome">Nome</label>
  <input type="text" id="nome" name="nome">
  <label for="email">E-mail</label>
  <input class="certo" type="email" id="email" name="email">
</form>

.encomenda {
  width: 300px;
  border-right: 2px dashed gray;
}

label {
  display: block;
}

input {
  width: 100%;
  padding: 8px 10px;
}

.certo {
  box-sizing: border-box;
}

A linha tracejada marca o fim do formulário (300 pixels). O campo "Nome" passa da linha: o width: 100% deu 300 pixels só para o conteúdo, e o navegador somou por fora os 20 do padding (10 de cada lado) e os 4 da borda. O campo "E-mail", com box-sizing: border-box, fica exatamente nos 300: o padding e a borda passam a contar dentro da largura (aula box-sizing).

Missão: os dois campos passam da linha tracejada e têm a letra menor que a da página. Complete a regra do input para que eles fiquem dentro dos 300 pixels e com a mesma letra da página.

5. Borda, cantos e o textarea

Com a base pronta, o resto é o modelo de caixa que você já conhece: borda, cantos arredondados, espaço interno. Juntando tudo:

<link rel="stylesheet" href="style.css">
<form class="encomenda">
  <label for="nome">Nome</label>
  <input type="text" id="nome" name="nome" placeholder="Ana Souza">
  <label for="email">E-mail</label>
  <input type="email" id="email" name="email">
  <label for="sabor">Sabor</label>
  <select id="sabor" name="sabor">
    <option>Cenoura</option>
    <option>Fubá</option>
  </select>
  <label for="recado">Recado</label>
  <textarea id="recado" name="recado" rows="3"></textarea>
  <button>Encomendar</button>
</form>

body {
  font-family: system-ui, sans-serif;
}

.encomenda {
  width: 300px;
}

label {
  display: block;
  margin-top: 12px;
  margin-bottom: 4px;
  font-weight: 700;
}

input,
select,
textarea {
  font: inherit;
  width: 100%;
  padding: 8px 10px;
  border: 1px solid #888;
  border-radius: 6px;
  box-sizing: border-box;
}

textarea {
  resize: vertical;
}

button {
  font: inherit;
  margin-top: 16px;
  padding: 8px 16px;
}

Agora os rótulos estão em negrito, em cima de cada campo; o nome, o e-mail, a lista de sabores e o recado têm a mesma largura, a mesma borda cinza e os mesmos cantos arredondados; e a letra dos campos é a mesma da página.

O resize do textarea

O cantinho de baixo, à direita, do textarea deixa o leitor puxar a caixa para aumentá-la. Por padrão, ela cresce para os dois lados (resize: both), e pode passar da largura do formulário. resize: vertical deixa crescer só para baixo:

ValorO leitor pode puxar…
bothPara os dois lados (padrão do textarea)
verticalSó a altura: o mais usado
horizontalSó a largura
noneNada (evite: quem escreve muito quer ver o texto todo)
E o select, as caixas de marcar e os botões de rádio?

A lista (<select>) aceita borda, letra e espaço, como acima, mas a setinha e a lista que abre são desenhadas pelo sistema. As caixas de marcar (checkbox) e os botões de rádio mudam de cor com uma linha só, accent-color; para ir além, existe o appearance. Os dois estão na aula accent-color e appearance.

6. O foco: :focus-visible

O campo que está recebendo o que você digita está "em foco". O navegador já desenha um contorno nele, mas o padrão às vezes é discreto. Para quem usa o teclado (Tab de campo em campo), ver onde está o foco é essencial. A pseudo-classe :focus-visible (aula Estados) vale quando o campo está em foco e o navegador acha que o contorno deve aparecer:

input:focus-visible,
select:focus-visible,
textarea:focus-visible {
  outline: 3px solid #c2410c;
  outline-offset: 2px;
}
:focus-visible
"Em foco, e o foco deve aparecer". Num campo de texto, vale tanto com o teclado quanto com o clique, porque você vai digitar ali.
outline
O contorno (aula outline): fica por fora da borda e não ocupa espaço, então nada na página se mexe quando ele aparece.
outline-offset: 2px
Afasta o contorno 2 pixels da borda, deixando um respiro entre os dois.

Clique no campo "Nome" de qualquer formulário desta aula, ou use o Tab, para ver o foco padrão do navegador. Com a regra acima (ela está na solução da missão final, no fim da aula), o campo ganha um contorno laranja grosso, um pouco afastado da borda, acompanhando os cantos arredondados.

Nunca apague o foco sem pôr outro no lugar

outline: none sozinho é um dos erros de acessibilidade mais comuns da web: quem navega pelo teclado perde o rumo, sem saber em que campo está. Se o contorno padrão não combina com o site, troque por outro (outra cor, uma borda mais grossa, uma sombra), nunca deixe sem nada.

7. Campos inválidos: :user-invalid

O HTML já sabe quando um campo está errado: um type="email" sem e-mail válido, um required vazio (Guia HTML, Validação). O CSS pode pintar esse campo. Há duas pseudo-classes:

Pseudo-classeVale quando…Problema
:invalido campo está inválido, sempreUm campo obrigatório vazio já aparece vermelho quando a página abre, antes de a pessoa digitar qualquer coisa. Parece uma bronca antes da hora.
:user-invalido campo está inválido e a pessoa já mexeu nele (digitou e saiu do campo, ou tentou enviar)Nenhum: é o comportamento que se espera. Funciona em todos os navegadores atuais desde novembro de 2023 (MDN, "Baseline").

Experimente: o primeiro campo usa :invalid e já começa vermelho. No segundo, com :user-invalid, digite ana@ e clique fora: só então ele fica vermelho. Complete para ana@example.com e o vermelho some na hora.

<link rel="stylesheet" href="style.css">
<form>
  <label for="e1">E-mail (com :invalid)</label>
  <input class="cedo" type="email" id="e1" name="e1" required>
  <label for="e2">E-mail (com :user-invalid)</label>
  <input class="na-hora" type="email" id="e2" name="e2" required>
</form>

label {
  display: block;
  margin-top: 12px;
}

input {
  font: inherit;
  padding: 6px;
  border: 2px solid gray;
}

.cedo:invalid {
  border-color: crimson;
  background-color: mistyrose;
}

.na-hora:user-invalid {
  border-color: crimson;
  background-color: mistyrose;
}
A cor não pode ser o único aviso

Quem não distingue vermelho de verde, ou usa leitor de tela, não percebe só a cor. A mensagem do próprio navegador ("Inclua um @ no endereço de e-mail", ao enviar) continua aparecendo; num site completo, escreva também o erro em texto, perto do campo.

8. O texto de exemplo: ::placeholder

O placeholder é o texto cinza dentro do campo vazio ("Ana Souza"). O pseudo-elemento ::placeholder (aula Outros Pseudo-elementos) muda a cor dele:

input::placeholder {
  color: #767676;
}

O cinza #767676 é o mais claro que ainda tem contraste suficiente num fundo branco (4,5 para 1, o mínimo recomendado para texto). O placeholder é só um exemplo de resposta: ele some quando a pessoa começa a digitar, então nunca o use no lugar do <label>.

9. Resumo das escolhas

Quero…Use
Rótulo em cima do campolabel { display: block; }

Quando dá errado

O campo passa da borda do formulário

O que você vê: com width: 100% e padding, o campo fica 24 pixels mais largo que o formulário (veja a seção 4).

Por quê: o box-sizing padrão do input é content-box (conferido no Chromium): a largura vale só para o conteúdo, e o espaço interno e a borda são somados por fora.

Como consertar: box-sizing: border-box; nos campos (ou em todos os elementos, com *, *::before, *::after { box-sizing: border-box; }, aula box-sizing).

A letra do campo continua pequena 
form {
  font-size: 1.125rem;
}

O que você vê: os rótulos ficam com a letra maior, mas o texto dentro dos campos continua com 13.3333px.

Por quê: o navegador dá aos campos uma fonte própria, que vence a herança. Mudar a fonte do pai não chega até eles.

Como consertar: font: inherit; nos campos.

Erro de digitação no seletor: a regra inteira some 
input:foucs {
  outline: 3px solid #c2410c;
}
textarea {
  resize: vertical-only;
}
input {
  border: 1px solid #88;
}

O que você vê: o foco continua com o contorno padrão, o textarea ainda cresce para os lados, e a borda do campo continua a do navegador. Nenhuma das três declarações funcionou. No F12, as declarações com valor errado aparecem riscadas; a regra com o seletor errado nem aparece no painel de estilos do campo, porque não casa com nada.

$ vnu --css form.css
"file:/home/ana/site/form.css":1.7-1.11: error: CSS: Unknown pseudo-element or pseudo-class “:foucs”
"file:/home/ana/site/form.css":5.11-5.23: error: CSS: “resize”: “vertical-only” is not a “resize” value.
"file:/home/ana/site/form.css":8.21-8.23: error: CSS: “border”: “#88” is not a valid color 3 or 6 hexadecimals numbers.

O que significa:

  • "Pseudo-elemento ou pseudo-classe desconhecido: :foucs". Com o seletor inválido, o navegador descarta a regra inteira, com todas as declarações dentro. O certo é :focus.
  • "vertical-only não é um valor de resize": é só vertical.
  • "#88 não é uma cor válida de 3 ou 6 dígitos hexadecimais" (aula Cores Hexadecimais): faltou um dígito, #888. Como a cor é inválida, o atalho border inteiro é ignorado.
outline: none: o foco sumiu 
input:focus {
  outline: none;
}

O que você vê: ao clicar no campo ou chegar nele pelo Tab, nada indica que ele está em foco.

O que o validador diz: nada; o CSS é válido. O problema é de acessibilidade: quem usa o teclado não sabe onde está.

Como consertar: apague a regra, ou troque o contorno por outro bem visível (seção 6).

Resumo

  • Sem CSS, rótulos e campos ficam na mesma linha (são elementos em linha), com letras e larguras diferentes.
  • label { display: block; } põe o rótulo em cima do campo. Rótulo sempre visível; o placeholder é só exemplo.
  • Os campos não herdam a fonte: font: inherit;. Com 16px, o iPhone não dá zoom ao tocar no campo.
  • width: 100% + box-sizing: border-box: campos da largura do formulário, sem passar dela.
  • resize: vertical no textarea.
  • Foco visível com :focus-visible e outline; nunca outline: none sem outro destaque no lugar.
  • :user-invalid avisa o erro depois que a pessoa mexeu no campo; :invalid avisa cedo demais.
  • Seletor com erro de digitação (:foucs) derruba a regra inteira; o validador avisa Unknown pseudo-element or pseudo-class.
