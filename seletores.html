CSS Seletores

Toda regra de CSS começa com um seletor: a parte que diz quem vai receber o estilo. Até agora você usou os mais simples, como h1 e p. Mas e se a Ana quiser destacar só um dos parágrafos? Ou só os links do menu? É para isso que existem vários tipos de seletor. Esta aula é o mapa: o que um seletor faz, os tipos que você vai aprender nas próximas aulas e os erros que fazem um seletor não pegar ninguém.

Você vai aprender
  • O que o seletor faz: escolhe elementos da página, todos os que combinam com ele.
  • Um mapa dos tipos de seletor, cada um com a sua aula.
  • A testar seletores ao vivo, num laboratório.
  • Como conferir quais elementos um seletor pega, no F12.
  • Os erros reais: o seletor que não pega ninguém (sem nenhum aviso), as maiúsculas, o espaço que muda o sentido e o seletor inválido que derruba a regra inteira.

A ideia: chamar pessoas numa sala

A Ana está numa festa e quer passar um recado. Ela pode chamar as pessoas de vários jeitos:

  • "Todos os cozinheiros, venham aqui" (um tipo de pessoa);
  • "Quem está com crachá amarelo" (um grupo marcado de propósito);
  • "Beto, o da mesa 3" (uma pessoa só, pelo nome);
  • "Todo mundo!" (todos);
  • "Os cozinheiros que estão na cozinha" (pelo lugar onde estão).

O seletor é esse chamado. O navegador olha cada elemento da página e pergunta: "este combina com o chamado?". Os que combinam recebem as declarações da regra; os outros ficam como estavam.

1. O seletor escolhe; as declarações aplicam

p {
  background-color: yellow;
}
p
O seletor: "todos os elementos <p>". Se a página tiver dez parágrafos, os dez são escolhidos. Se não tiver nenhum, ninguém é escolhido, e nada acontece (sem erro).
{ background-color: yellow; }
O que acontece com os escolhidos: fundo amarelo.

Repare que o seletor não diz "o primeiro parágrafo" nem "os parágrafos da linha 5". Ele descreve uma característica (o tipo do elemento, uma classe, a posição dentro de outro elemento), e o navegador procura todos os que a têm. Por isso a mesma regra continua funcionando quando você acrescenta parágrafos novos.

Os seletores também se combinam: p.destaque (um <p> que tenha a classe destaque), nav a:hover (um link do menu com o mouse em cima). A lista completa está na referência Seletores.

Quando dois seletores pegam o mesmo elemento

No laboratório, o parágrafo da classe destaque é escolhido tanto por p quanto por .destaque. Se duas regras derem cores diferentes para ele, quem vence? Depende de quão "específico" é cada seletor: uma classe vence um nome de elemento, mesmo vindo antes no arquivo. Esse desempate é o assunto de Especificidade; por enquanto, basta saber que ele existe.

4. Conferindo um seletor no F12

Quando um seletor não funciona, a primeira pergunta é: "ele pega quem eu acho que pega?". Duas formas de conferir (aula Inspecionando com o F12):

  • Pelo elemento: inspecione o elemento que devia mudar. Se a regra não aparece no painel Styles, o seletor não pega esse elemento.
  • Pelo seletor: no Chrome e no Edge, a busca do painel Elements (Ctrl+F com o painel aberto) aceita seletores: digite .destaque e ela mostra quantos elementos combinam e pula de um em um.

Quando dá errado

Um seletor errado quase nunca dá erro: ele simplesmente não escolhe ninguém, e a regra fica sem efeito. (Comportamentos conferidos no Chromium.)

O seletor não pega ninguém: nenhum aviso 
.Destaque {
  color: teal;
}

paragrafo {
  color: navy;
}

O que você vê: nada muda. O parágrafo com class="destaque" continua preto, e os parágrafos também.

Por quê: as duas regras estão escritas certinho, mas não descrevem nenhum elemento da página. O nome da classe diferencia maiúsculas de minúsculas: .Destaque não pega class="destaque". E não existe elemento <paragrafo>: o seletor de elemento usa o nome da tag em inglês (p).

$ vnu --css nada.css; echo "saida: $?"
saida: 0

O que o validador diz: nada. Ele confere o CSS sozinho, sem olhar o HTML, então não sabe que a página não tem esses elementos. Para o CSS, paragrafo é um nome de elemento possível.

Como consertar: copie o nome da classe do HTML para o CSS, letra por letra; use o nome da tag como no HTML (p, li, h2). Os nomes de elemento, esses sim, aceitam maiúsculas: P funciona igual a p numa página HTML. Mas escreva sempre em minúsculas.

Um espaço a mais muda o sentido: p .destaque × p.destaque 
p .destaque {
  color: navy;
}

O que você vê: o parágrafo <p class="destaque"> continua preto.

Por quê: num seletor, o espaço tem significado: é o combinador "dentro de". p .destaque quer dizer "um elemento com a classe destaque que esteja dentro de um <p>". O parágrafo não está dentro de outro parágrafo; ele é o parágrafo. Sem espaço, p.destaque quer dizer "um <p> que tem a classe destaque", que é o que a Ana queria.

O que o validador diz: nada; os dois seletores são válidos. Aula Descendente, Filho e Irmãos.

Seletor inválido num grupo: a regra inteira cai 
h1, h2:hovr {
  color: teal;
}

O que você vê: o h1 continua preto, embora a parte h1 do seletor esteja certa.

Por quê: :hovr não existe (é :hover). Quando uma parte de um grupo de seletores é inválida, o navegador descarta a regra inteira, não só a parte errada.

$ vnu --css grupo.css
"file:/home/ana/site/grupo.css":1.8-1.11: error: CSS: Unknown pseudo-element or pseudo-class “:hovr”

O que significa: "pseudo-elemento ou pseudo-classe desconhecida: :hovr".

Como consertar: h1, h2:hover. Mais sobre grupos: Agrupando Seletores.

Resumo

  • O seletor diz quem recebe o estilo. O navegador aplica a regra a todos os elementos que combinam, e a nenhum se não houver.
  • Os tipos: elemento (p), classe (.destaque), id (#topo), universal (*), grupo (h1, h2), combinadores (nav a), atributo, pseudo-classe (:hover) e pseudo-elemento (::first-letter). Cada um tem a sua aula.
  • Seletor que não pega ninguém não dá erro, nem no validador. Confira no F12 se a regra aparece no elemento.
  • Classes diferenciam maiúsculas de minúsculas. Um espaço muda o sentido (p .destaque ≠ p.destaque).
  • Uma parte inválida num grupo de seletores derruba a regra inteira.
