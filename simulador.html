CSS O Editor do Guia

Em quase toda aula deste guia aparecem caixas Experimente: você escreve o HTML numa aba, o CSS em outra, e vê a página pronta logo embaixo, desenhada pelo seu próprio navegador. Não precisa instalar nada, criar arquivo nem abrir outra janela. Nesta página você conhece cada parte do editor, aprende a mudar a largura do quadro (para ver a página como num celular), a ligar o tema escuro, a cumprir missões e a mandar o seu CSS para o validador. Ainda não sabe CSS? Sem problema: aqui você só mexe em cores. O resto vem nas próximas aulas.

Você vai aprender
  • As partes de uma caixa Experimente: as abas index.html e style.css, o código, o Resultado e a missão.
  • Por que a aba style.css só vale com o <link> no HTML.
  • Como ver a página com a largura de um celular (375 px), de um tablet (768 px) ou cheia.
  • Como ligar o tema escuro só no quadro.
  • Missões que pedem para você passar o mouse em cima de algo.
  • Como mandar o seu HTML ou o seu CSS para o validador do W3C.
  • O que o editor não faz e o que muda num site publicado.

A ideia: um caderno de rascunho que desenha a página

Pense numa parede e numa lata de tinta. Você pinta um pedaço, olha, não gostou, pinta de novo. Com CSS é igual: você muda uma cor, olha o resultado, muda de novo. O editor do guia deixa esse "olhar" instantâneo: você digita, e meio segundo depois o navegador desenha a página outra vez no quadro Resultado.

O resultado é de verdade: é o mesmo navegador que você usa para ver qualquer site. Se você errar o nome de uma propriedade, o quadro mostra exatamente o que o navegador faz: ele ignora a linha errada, sem aviso nenhum, e segue com o resto.

Repare no index.html: não há <!DOCTYPE html>, <html>, <head> nem <body>. É só um pedaço de página, para o exemplo ficar curto. O editor desenha esse pedaço como se ele estivesse dentro de uma página completa. O <link> da primeira linha vai para o <head>, como o navegador faria. Quando o código tem a página inteira, o editor desenha exatamente o que você escreveu.

A aba style.css só vale com o <link>

No editor, cada aba é um arquivo de uma pasta, como no seu computador. Um arquivo style.css parado na pasta não faz nada: é o <link rel="stylesheet" href="style.css"> do HTML que manda o navegador buscá-lo. Sem o <link>, a aba style.css é ignorada, igual num site de verdade (aula Três Jeitos de Usar CSS).

Missão: o style.css já deixa o título azul-marinho (navy), mas o index.html ainda não o carrega. Na primeira linha do index.html, acrescente <link rel="stylesheet" href="style.css">.

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

h1 {
  color: navy;
}

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

Mudou o CSS? O quadro desenha de novo a página que está aberta. Também funcionam outros nomes e pastas, como num site: uma aba css/estilo.css com href="css/estilo.css".

O quadro "Resultado" embaixo do código

Nas aulas, muitos exemplos são só para ler, e não para editar. Mesmo assim, o navegador desenha cada um logo embaixo, num quadro Resultado do tamanho do conteúdo. Nesses exemplos curtos, o CSS vem num <style> dentro do próprio HTML:

<style>
  h2 { color: seagreen; }
  li { color: gray; }
</style>
<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras</li>
  <li>3 ovos</li>
</ul>

Quer mexer no exemplo? Clique em copiar e cole numa caixa Experimente.

A largura do quadro: celular, tablet e cheia

Uma página bem feita se ajeita na tela de um celular e na de um computador. Para ver isso sem trocar de aparelho, use os botões da barra do Resultado:

A página dentro do quadro "acha" que a janela tem essa largura. Do lado dos botões aparece a largura atual, por exemplo 375 px. Quando o quadro fica mais largo que a caixa, aparece uma barra de rolagem embaixo dele.

Experimente na caixa abaixo. Você ainda não precisa entender o @media do CSS (ele vem na aula Media Queries): só clique em 375, 768 e cheia e veja os cartões trocarem de lugar e de cor.

<link rel="stylesheet" href="style.css">
<div class="cartoes">
  <p class="cartao">Bolo de cenoura</p>
  <p class="cartao">Pão de queijo</p>
  <p class="cartao">Brigadeiro</p>
</div>

.cartoes {
  display: flex;
  gap: 1rem;
}
.cartao {
  flex: 1;
  margin: 0;
  padding: 1rem;
  background-color: wheat;
}
/* telas estreitas (até 600 px): um cartão embaixo do outro */
@media (max-width: 600px) {
  .cartoes {
    flex-direction: column;
  }
  .cartao {
    background-color: lightblue;
  }
}

Algumas caixas já começam com uma largura certa, quando a aula é sobre celular. Numa missão assim, o texto avisa ("com o quadro em 375 px"), e é nessa largura que a missão confere. Se você trocar a largura, a missão diz embaixo em qual ela confere.

O tema escuro (◐)

Muita gente usa o celular e o computador no modo escuro. Um site pode ter cores próprias para quem escolheu esse modo (aula Tema Escuro). O botão ◐ da barra liga o modo escuro só no quadro, sem mexer no seu computador nem no tema do guia. Clique nele na caixa abaixo:

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Clique no ◐ da barra do Resultado.</p>

body {
  background-color: white;
  color: black;
}
/* para quem escolheu o modo escuro */
@media (prefers-color-scheme: dark) {
  body {
    background-color: #222;
    color: white;
  }
}
E o "menos movimento"?

Existe outra preferência parecida: a de quem pede menos animação na tela (aula Respeitando Quem Prefere Menos Movimento). Essa o editor não consegue ligar no quadro. Para testar, use as ferramentas do navegador (F12), que sabem fingir essa preferência (aula Inspecionando com o F12), ou a opção de reduzir as animações nas configurações de acessibilidade do seu sistema.

Missões com o mouse

A missão olha a página desenhada, e não o texto do código: ela pergunta ao navegador qual é a cor, o tamanho, a margem de cada elemento. Algumas regras de CSS só valem quando o mouse está em cima de algo (aula Estados: :hover, :focus e :active). Nessas missões, depois de mudar o código, passe o mouse em cima do elemento: é aí que a missão confere.

Missão: com o mouse em cima, o botão fica vermelho-escuro (darkred). Troque essa cor por navy (azul-marinho) e depois passe o mouse no botão.

<link rel="stylesheet" href="style.css">
<button class="botao">Comprar bolo</button>

.botao {
  background-color: tomato;
  color: white;
  border: 0;
  padding: 0.5rem 1rem;
}
/* com o mouse em cima */
.botao:hover {
  background-color: darkred;
}

.botao {
  background-color: tomato;
  color: white;
  border: 0;
  padding: 0.5rem 1rem;
}
/* com o mouse em cima */
.botao:hover {
  background-color: navy;
}

Enquanto você não passa o mouse, a missão diz Ainda falta: .botao com background-color: rgb(0, 0, 128) quando o mouse está em cima (passe o mouse sobre .botao para conferir). Repare no rgb(0, 0, 128): é o nome navy do jeito que o navegador guarda as cores por dentro (aula rgb()). Num celular, sem mouse, toque no botão.

Validar no W3C

Quando o CSS tem um erro, o navegador não reclama: ele pula a declaração errada e pronto. Para achar o erro, existe o validador do W3C, o mesmo que os profissionais usam. Abra a aba style.css da caixa abaixo e clique em Validar no W3C:

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>

h1 {
  colr: tomato;
}
  • O editor pergunta antes, porque o código vai para a internet (para o site validator.w3.org).
  • Ele valida a aba que está aberta: index.html confere o HTML (e o CSS de um <style> dentro dele), style.css confere o CSS.
  • As mensagens vêm em inglês, com a linha e a coluna. Neste exemplo: Error (linha 2, coluna 9): “colr”: Property “colr” doesn't exist. Quer dizer: a propriedade colr não existe (o certo é color). Repare que a coluna 9 é a do valor (tomato), e não a do nome: o erro está na mesma linha.
  • O validador confere o CSS sozinho: ele não sabe se os seletores casam com o seu HTML. Um .cartao que não existe na página não é erro para ele.
  • Alguns recursos muito novos do CSS (como o @container) o validador ainda não conhece e marca como erro, embora os navegadores atuais entendam. O editor mostra esses como Error (falso), com uma explicação.

Missões, Restaurar e Ver solução

Algumas caixas têm uma missão. Embaixo da caixa aparece o andamento:

  • Missão em andamento… e, logo abaixo, o que ainda falta, por exemplo Ainda falta: h1 com color: rgb(0, 0, 128) (hoje color é rgb(0, 0, 0)).
  • ✔ Missão cumprida! quando tudo confere.

A missão confere de novo a cada mudança: no código, na largura do quadro, no mouse e no fim de uma animação.

O editor × um site publicado

O que funciona igual

  • Tudo o que o navegador faz sozinho: todo o CSS (cores, fontes, Flexbox, Grid, animações, @media), o HTML, as imagens.
  • Os caminhos relativos entre as abas (style.css, css/estilo.css) e as imagens de assets/midia/, no HTML e no url() do CSS.
  • A cascata: o seu CSS é o único da página do quadro. O estilo do guia não vaza para o quadro, e o seu não vaza para o guia.

Modo completo e modo simples

Para que as abas funcionem como arquivos de uma pasta, o editor liga no seu navegador um pequeno "servidor de mentirinha", o service worker. É o modo completo, o que você vê no guia publicado na internet (endereço com https://).

Às vezes o navegador não deixa ligar esse servidor: com o guia aberto direto do disco (file://), numa janela anônima do Firefox ou com o recurso bloqueado. Aí o editor usa o modo simples, e o CSS continua igual. A diferença: o style.css entra embutido na página, e o <link> passa a apontar para o código embutido. Uma missão que confere o href="style.css" do <link> não é cumprida nesse modo. Para ver tudo funcionando, abra o guia pela internet.

Quando dá errado

O CSS não pega: o título continua preto

Três causas, da mais comum para a menos comum. 1) Falta o <link rel="stylesheet" href="style.css"> no index.html: o navegador nem busca o CSS. 2) O href tem outro nome: com href="estilos.css" e a aba style.css, o console embaixo do quadro diz Não foi possível carregar "estilos.css" (<link>). Confira o nome e o caminho do arquivo. 3) Falta o rel="stylesheet": nada carrega, e o console não avisa nada.

Uma linha do CSS não faz nada, e não aparece erro

O navegador pulou a declaração: o nome da propriedade está errado (colr), o valor não existe (color: azul), ou faltou o ; da linha de cima (aí as duas linhas viram uma só, e as duas são puladas). O console do editor não mostra erros de CSS, porque o navegador não avisa. Use Validar no W3C na aba style.css, ou o F12 (aula Inspecionando com o F12).

A missão diz "passe o mouse sobre .botao para conferir"

A missão é de :hover: ela só confere com o mouse em cima do elemento. Passe o mouse no botão (no celular, toque nele).

A missão diz "a missão é conferida com o quadro em 375 px"

Você trocou a largura do quadro, e a missão é sobre a tela de celular. Clique em 375.

A imagem de fundo não aparece

Confira o nome na tabela das imagens (bolo.jpg não existe: os nomes têm o tamanho, como bolo-800.jpg) e se o elemento tem altura: uma div vazia tem 0 px de altura, e o fundo some junto.

Resumo

  • As caixas Experimente desenham o seu HTML e o seu CSS com o seu navegador, ao vivo, num quadro separado da página do guia.
  • Cada arquivo é uma aba; a aba style.css só vale com o <link rel="stylesheet" href="style.css"> no HTML.
  • Os botões 375 · 768 · cheia mudam a largura do quadro (celular, tablet, caixa toda); o ◐ liga o tema escuro só no quadro.
  • A missão confere a página desenhada: as cores e os tamanhos que o navegador calculou. Nas missões de :hover, passe o mouse no elemento.
  • Erros de CSS não aparecem no console: o navegador pula a linha errada. Use Validar no W3C na aba style.css.
  • As imagens de exemplo ficam em assets/midia/: bolo-800.jpg, logo-lojinha-400.png, avatar-ana-96.png e outras.
  • Restaurar volta ao original; Ver solução mostra uma solução.
  • Próximo passo: escrever o seu primeiro CSS do zero, em Seu Primeiro Estilo.
