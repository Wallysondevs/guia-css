CSS DevTools (F12)

O CSS não mostra mensagens de erro na tela. Então como descobrir por que o título não ficou azul? Todo navegador de computador traz uma ferramenta para isso: as ferramentas do desenvolvedor (em inglês, DevTools), que abrem com a tecla F12. Com elas você clica em qualquer pedaço da página e vê quais regras de CSS chegaram até ele, quais perderam, quais o navegador ignorou, e ainda pode mudar o CSS ao vivo. Nesta aula você vai conhecer os quatro lugares que mais vai usar.

Você vai aprender
  • A abrir o F12 e a escolher um elemento da página para inspecionar.
  • O painel Elements (o HTML) e o painel Styles (as regras de CSS do elemento).
  • Os dois motivos para uma declaração aparecer riscada: perdeu para outra regra, ou o navegador não a entendeu.
  • A mudar o CSS ao vivo, e por que essas mudanças somem ao recarregar.
  • O painel Computed, com o valor final de cada propriedade, e o Console, que avisa quando o arquivo de CSS não carregou.
Sobre os nomes nesta aula

Cada navegador desenha as suas ferramentas de um jeito, e elas mudam um pouco a cada versão. Esta aula usa os nomes em inglês do Chrome e do Edge (que têm as mesmas ferramentas). No Firefox, o painel Elements se chama Inspector, e o Styles se chama Rules. Se o seu navegador estiver em português, os nomes aparecem traduzidos. As ideias são as mesmas em todos. As figuras desta página são ilustrações, e não fotos do F12.

A ideia: o raio-X da página

Olhando a página, você vê o resultado: o título preto. O F12 é um raio-X: mostra por dentro por que ele está preto. Lá aparece a regra que você escreveu, a regra padrão do navegador, a declaração que perdeu a disputa e a que tinha um erro de digitação. Em vez de adivinhar, você olha.

O jeito do botão direito é o melhor para começar: as ferramentas abrem com o elemento em que você clicou já escolhido. Elas aparecem num painel ao lado ou embaixo da página (dá para mudar a posição).

Funciona no Chrome, no Edge e no Firefox. No Safari, do Mac, as ferramentas do desenvolvedor precisam ser ativadas antes, nas configurações avançadas do Safari. No celular, não há F12: as ferramentas são para o computador.

No editor deste guia

O quadro de resultado de cada caixa é uma página dentro da página (um <iframe>). O botão direito → Inspecionar em cima do resultado abre o F12 direto no elemento de dentro do quadro, com o CSS que você escreveu na aba style.css. Experimente nas caixas desta aula.

2. Elements: o HTML como o navegador montou

O painel Elements mostra o HTML da página em forma de árvore: o <html>, dentro dele o <head> e o <body>, e assim por diante. As setinhas abrem e fecham cada elemento.

  • Passe o mouse sobre uma linha: o elemento correspondente fica destacado na página, com cores mostrando o conteúdo, o espaço interno e a margem.
  • Clique numa linha: esse elemento passa a ser o selecionado, e o resto das ferramentas mostra informações sobre ele.

Um detalhe importante: o que aparece ali não é o seu arquivo, e sim o HTML como o navegador montou, já com os consertos que ele fez (um </p> que faltava, um <tbody> que ele acrescentou). Se a árvore está diferente do seu código, o seu HTML tem algum problema; confira no validador.

3. Styles: as regras do elemento escolhido

Ao lado (ou embaixo) do Elements fica o painel Styles. Ele lista todas as regras de CSS que pegam o elemento selecionado, com as que vencem por cima. Para este CSS:

h1 {
  color: navy;
}

p {
  color: dimgray;
}

h1 {
  color: teal;
  text-align: centre;
}

selecionando o <h1>, o painel Styles mostra algo assim:

O que cada parte quer dizer:

style.css:9
De onde vem a regra: o arquivo e a linha. É um link: clicar nele abre o arquivo naquela linha. A regra do p não aparece, porque não pega o h1.
user agent stylesheet
A folha de estilo padrão do navegador (aula HTML e CSS). É dela que vem o título grande e em negrito. Ela fica por último: qualquer regra sua vence.
color: navy
Riscada sem aviso: a declaração é válida, mas perdeu. Outra regra mais forte (aqui, a do teal, que vem depois no arquivo) define a mesma propriedade. Quem vence e por quê: A Cascata.
text-align: centre ⚠
Riscada com um ícone de aviso: o navegador não entendeu a declaração e a ignorou. centre é a grafia britânica; o CSS só conhece center. Passe o mouse no ícone: o navegador diz se o problema é a propriedade ou o valor.

Essa é a pergunta que o Styles responde: "minha declaração chegou até o elemento?"

Missão: o título devia estar centralizado. Clique com o botão direito no título do resultado, escolha Inspecionar e procure a declaração riscada com o aviso no painel Styles. Depois conserte o valor na aba style.css desta caixa.

Os estilos herdados

Mais abaixo no Styles aparecem, separadas, regras de outros elementos, os "pais" do selecionado (por exemplo, a regra do body). Elas estão ali porque algumas propriedades, como a fonte e a cor do texto, passam do pai para os filhos. Lá, só as propriedades herdáveis aparecem normais; as outras ficam apagadas. Aula Herança.

4. Editar ao vivo

O painel Styles não é só para ler. Dá para mexer no CSS e ver a página mudar na hora:

  • Mudar um valor: clique no valor (teal), digite outro e aperte Enter. Em números, as setas ↑ e ↓ do teclado aumentam e diminuem o valor.
  • Desligar uma declaração: passe o mouse sobre ela; aparece uma caixinha de marcar ao lado. Desmarcada, a declaração fica desligada, como se estivesse num comentário (aula Comentários).
  • Acrescentar uma declaração: clique no espaço vazio dentro da regra, perto da }, e digite a propriedade, Tab, o valor.
As mudanças no F12 são temporárias

Você mudou o CSS na cópia que o navegador tem na memória, e não no seu arquivo. Ao recarregar a página, tudo volta. O F12 é o lugar de experimentar; quando achar o valor certo, copie para o style.css e salve.

Isso também quer dizer que você pode mexer em qualquer site do mundo sem estragar nada: abra o F12 num site de notícias, troque a cor do título, recarregue, e ele volta ao normal. É um jeito ótimo de aprender olhando o CSS dos outros.

5. Computed: o valor final

O Styles mostra as regras como foram escritas, inclusive as que perderam. O painel Computed ("calculado") mostra só o resultado final: para cada propriedade, o valor que o navegador está usando, depois de resolver a disputa entre as regras, a herança e as conversões.

Os valores ali já vêm convertidos: as cores aparecem como rgb(…) (o teal vira rgb(0, 128, 128)), os tamanhos em pixels (o 2em do <h1> padrão vira 32px) e o bold vira 700. Há uma caixa de busca para filtrar a lista (digite color) e, ao abrir uma propriedade, aparece qual regra deu aquele valor.

Esses mesmos valores finais estão disponíveis para o JavaScript, com getComputedStyle(). Uma curiosidade, para conferir no console do editor:

Experimente: o console embaixo do resultado mostra os valores calculados do título. Troque teal por tomato na aba style.css e veja o valor mudar para rgb(255, 99, 71). O tamanho é o padrão do navegador, já convertido em pixels.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<script>
  const titulo = document.querySelector("h1");
  console.log(getComputedStyle(titulo).color);
  console.log(getComputedStyle(titulo).fontSize);
</script>

h1 {
  color: teal;
}

No mesmo painel Computed, o Chrome mostra um desenho de caixas com a margem, a borda, o espaço interno e o tamanho do elemento (no Firefox, ele fica num painel chamado Layout). Ele vai ser útil na aula O Modelo de Caixa.

6. Console: o CSS que não carregou

Se a regra nem aparece no Styles, talvez o arquivo de CSS nem tenha chegado. A aba Console do F12 mostra os arquivos que falharam. Num site publicado, com o <link> pedindo um estilo.css que não existe, o Chromium escreve:

Failed to load resource: the server responded with a status of 404

"Falha ao carregar o recurso: o servidor respondeu com o código 404" (não encontrado). O navegador mostra também o endereço do arquivo, e o texto depois do 404 varia de servidor para servidor. A aba Network ("rede") lista todos os arquivos que a página pediu, com o código de cada um: 200 é "chegou", 404 é "não existe". Aberto direto do disco (file://), o erro aparece com outro texto, mas no mesmo lugar.

No editor do guia, o aviso aparece no console embaixo do resultado (aula Três Jeitos de Usar CSS).

Quando dá errado

Mudei no F12, recarreguei e voltou tudo

Por quê: o F12 muda a cópia na memória, e não o arquivo. É assim de propósito.

Como consertar: copie o valor que funcionou para o style.css, salve e recarregue.

A minha regra não aparece no Styles

Por quê: três suspeitos, nesta ordem: (1) o arquivo não carregou (veja o Console: nome errado no href, falta o rel="stylesheet"); (2) o seletor não pega esse elemento (você selecionou o <p>, mas a regra é do h2; ou o nome da classe está diferente); (3) a regra foi descartada inteira por um erro de sintaxe antes dela, como um // no lugar de comentário (aula Comentários).

Como consertar: confira na ordem; o validador (vnu --css) acha o terceiro caso.

Está riscada, sem aviso nenhum

Por quê: a declaração está certa, mas perdeu. Uma regra que vem depois, ou uma mais específica, define a mesma propriedade. No Styles, procure mais acima a mesma propriedade, não riscada: é a que venceu.

Como consertar: decida qual das duas deve valer e apague a outra (é o caso da missão final). Não "conserte" com !important (aula !important (e Por que Evitar)).

Resumo

  • F12 (ou botão direito → Inspecionar) abre as ferramentas do desenvolvedor no elemento escolhido.
  • Elements: o HTML como o navegador montou. Styles: todas as regras que pegam o elemento, com arquivo e linha, e a folha padrão do navegador por último.
  • Riscado sem aviso = válido, mas perdeu para outra regra. Riscado com aviso = o navegador não entendeu (propriedade ou valor errado). Não aparece = o seletor não pega o elemento ou o arquivo não carregou.
  • Dá para editar ao vivo (valores, caixinhas de ligar e desligar), mas tudo volta ao recarregar: copie o que funcionou para o style.css.
  • Computed: o valor final, já convertido (rgb(0, 128, 128), 32px). Console: o arquivo de CSS que deu 404.
