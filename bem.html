CSS Organizando Classes (BEM)

No começo, dar nome às classes é fácil: .titulo, .caixa, .vermelho. Mas o site da Ana cresceu: tem cartões de receita, um menu, um rodapé, um formulário. Um dia ela muda a cor do .titulo do cartão, e o título do menu muda junto, porque os dois usavam a mesma classe. O BEM é uma convenção de nomes (uma combinação entre as pessoas do projeto, não um recurso do CSS) que evita isso: cada classe diz a que parte do site ela pertence.

Você vai aprender
  • Por que nomes soltos (.titulo) brigam entre si num site grande.
  • As três partes do BEM: Bloco (.cartao), Elemento (.cartao__titulo) e Modificador (.cartao--destaque).
  • Por que o modificador vem junto com a classe base.
  • A vantagem escondida: todas as regras com a mesma especificidade.
  • Quando o BEM ajuda, e as outras formas (@scope, classes utilitárias).
  • Os erros comuns, inclusive o &__titulo que não funciona no CSS aninhado de verdade.

Os resultados são desenhados pelo seu navegador; os valores calculados foram conferidos no Chromium, e as mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (ana@notebook), na pasta ~/site.

A ideia: as etiquetas da mudança

Na mudança da padaria, a Ana escreveu "PANELAS" numa caixa. Só que tem panela da cozinha, panela da vitrine e panela do depósito: no caminhão, ninguém sabe onde cada caixa vai. Na segunda vez, ela escreveu etiquetas completas:

  • COZINHA: o cômodo, que existe por si só. É o bloco.
  • COZINHA — panelas: uma coisa que pertence à cozinha. É o elemento.
  • COZINHA — panelas (frágil): as mesmas panelas, numa versão especial. É o modificador.

A etiqueta é mais comprida, mas não tem como errar o lugar. O BEM faz o mesmo com as classes.

1. O problema: dois .titulo

Experimente: a Ana queria só o título do cartão em tomato, mas o título do menu também mudou. Troque tomato por navy e veja os dois mudarem juntos.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <p class="titulo">Padaria da Ana</p>
</nav>
<article class="caixa">
  <h2 class="titulo">Bolo de cenoura</h2>
  <p class="preco">R$ 35,00</p>
</article>

.menu {
  padding: 8px;
  background-color: #eee;
}

/* Para o título do cartão... */
.titulo {
  color: tomato;
}

O nome .titulo não diz de quem é o título. Num site com dez componentes, cada um com um título, a regra de um vaza para os outros. Uma saída é escrever .caixa .titulo (só os títulos dentro da caixa), mas isso aumenta a especificidade e cria outros problemas (veja a seção 4).

2. As três partes do BEM

BEM vem de Bloco, Elemento, Modificador. A convenção nasceu na empresa russa Yandex e hoje é uma das mais usadas.

<article class="cartao cartao--destaque">
  <h2 class="cartao__titulo">Bolo de cenoura</h2>
  <p class="cartao__preco">R$ 35,00</p>
</article>
cartao
O bloco: um pedaço da página que faz sentido sozinho e pode ser reaproveitado (um cartão, um menu, um formulário de busca). Nome simples, em minúsculas, com hífen se tiver duas palavras: cartao-receita.
cartao__titulo
Um elemento: uma parte do bloco que não faz sentido fora dele. O nome é o do bloco, dois sublinhados (__) e o nome da parte. Lê-se "o título do cartão".
cartao--destaque
Um modificador: uma versão diferente do bloco (ou do elemento). O nome é o do bloco, dois hífens (--) e a variação. Lê-se "cartão, versão destaque".
class="cartao cartao--destaque"
O modificador vem junto com a classe base, separado por espaço. O .cartao dá o visual normal; o .cartao--destaque só acrescenta o que muda.

E o CSS, com uma classe por regra:

/* Bloco */
.cartao {
  padding: 16px;
  border: 2px solid #ccc;
}

/* Elementos */
.cartao__titulo {
  margin: 0;
  color: navy;
}

.cartao__preco {
  font-weight: bold;
}

/* Modificador */
.cartao--destaque {
  border-color: tomato;
}

Agora o título do cartão (.cartao__titulo) e o título do menu (.menu__titulo) têm nomes diferentes e nunca se misturam, mesmo que alguém escreva o menu daqui a um ano.

ParteFormatoExemplos
Bloco.bloco.cartao, .menu, .busca, .cartao-receita
Elemento.bloco__elemento.cartao__titulo, .menu__link, .busca__campo
Modificador do bloco.bloco--modificador.cartao--destaque, .menu--escuro
Modificador do elemento.bloco__elemento--modificador.cartao__preco--promocao, .menu__link--ativo

3. O modificador: uma versão diferente

A Ana quer que o bolo da semana tenha a borda laranja e o preço em promoção, em vermelho. Em vez de criar um cartão novo inteiro, ela acrescenta modificadores:

Experimente: os dois cartões usam o mesmo bloco. O segundo tem dois modificadores a mais. Tire o cartao--destaque do segundo e ele volta ao normal; ponha no primeiro e ele ganha a borda.

<link rel="stylesheet" href="style.css">
<article class="cartao">
  <h2 class="cartao__titulo">Pão de queijo</h2>
  <p class="cartao__preco">R$ 2,50</p>
</article>
<article class="cartao cartao--destaque">
  <h2 class="cartao__titulo">Bolo de cenoura</h2>
  <p class="cartao__preco cartao__preco--promocao">R$ 29,90</p>
</article>

.cartao {
  margin-bottom: 12px;
  padding: 16px;
  border: 2px solid #ccc;
}

.cartao--destaque {
  border-color: tomato;
}

.cartao__titulo {
  margin: 0;
  color: navy;
}

.cartao__preco {
  font-weight: bold;
}

.cartao__preco--promocao {
  color: firebrick;
}

No Chromium, os dois cartões têm o mesmo preenchimento, o mesmo título azul-marinho e o preço em negrito; só o segundo tem a borda cor de tomate e o preço vermelho-escuro (firebrick). O .cartao--destaque só escreve o que muda (border-color); o resto vem do .cartao.

4. A vantagem escondida: especificidade igual

Sem BEM, para mirar no título do cartão, é comum escrever seletores compostos:

.caixa .titulo { color: navy; }        /* especificidade 0,2,0 */
.caixa.destaque .titulo { color: red; } /* especificidade 0,3,0 */

Cada regra nova precisa de um seletor mais "forte" para vencer a anterior, e logo aparece um !important (aula !important). Com BEM, toda regra é uma classe só, com especificidade 0,1,0 (aula Especificidade). Quem vence é simplesmente quem vem depois no arquivo. Por isso, no CSS, os modificadores ficam depois das classes que eles modificam.

Regra do BEMPor quê
Uma classe por seletor (.cartao__titulo, e não .cartao .cartao__titulo)Especificidade baixa e igual; o nome já diz a quem pertence
Sem seletor de elemento (.cartao h2) nem de idTrocar o h2 por h3 no HTML não quebra o CSS
Elemento de elemento é só elemento: .cartao__titulo, e não .cartao__corpo__tituloNomes curtos, e o HTML pode mudar de estrutura sem renomear
Modificador sempre junto da base (class="cartao cartao--destaque")O modificador só acrescenta; a base dá o resto

5. BEM e as outras formas

FormaComo evita o vazamentoQuando usar
BEMNomes únicos por bloco: .cartao__tituloSites e equipes de qualquer tamanho; funciona em qualquer navegador, sem ferramenta.
CSS aninhado (.cartao { & .titulo { … } })O seletor final é .cartao .titulo: só os títulos dentro do cartãoPara agrupar no arquivo (aula CSS Aninhado); a especificidade sobe.
@scopeAs regras valem só dentro de um bloco (aula Escopo)Recurso recente; nomes curtos (.titulo) sem vazar.
Classes utilitárias (.texto-vermelho, .p-4)Cada classe faz uma coisa só, em qualquer lugarFrameworks como o Tailwind (aula Frameworks).

Não existe uma escolha certa para todos. O importante é que o projeto inteiro use a mesma convenção: um CSS com metade dos nomes em BEM e metade soltos tem os problemas dos dois.

Quando dá errado

Só o modificador, sem a classe base 
<article class="cartao--destaque">
  <h2 class="cartao__titulo">Bolo de cenoura</h2>
</article>

O que o leitor vê: com o CSS da seção 3, o cartão perde o preenchimento, a margem e a borda inteira: sobra só o título e o texto, soltos. No Chromium, o padding-top ficou 0px e a borda, border-top-style: none.

Por quê: o .cartao--destaque só tem o border-color, e uma cor de borda sem a borda (o estilo e a largura, que estão no .cartao) não desenha nada. O preenchimento também mora no .cartao, que não está mais no elemento. O validador não reclama: para o HTML, qualquer nome de classe é válido.

Como consertar: class="cartao cartao--destaque", sempre a base junto.

&__titulo no CSS aninhado: a regra some 
.cartao {
  padding: 1rem;
  &__titulo {
    color: navy;
  }
}

Quem vem do Sass (uma ferramenta que gera CSS) está acostumado a escrever &__titulo para gerar .cartao__titulo. No Sass, funciona. No CSS aninhado de verdade, que o navegador entende sozinho, não: o & representa o seletor de fora inteiro, e não um pedaço de texto para colar.

O que o leitor vê: o título continua preto. No Chromium, a regra aninhada &__titulo foi descartada (só sobrou o padding do cartão), e o estilo calculado do .cartao__titulo ficou color: rgb(0, 0, 0).

$ vnu --css estilo.css
"file:/home/ana/site/estilo.css":5.4-6.2: error: CSS: Parse Error.

O que significa: "erro de leitura": o validador não entendeu o bloco aninhado e só se acha de novo no fim dele (linhas 5 e 6).

Como consertar: no CSS do navegador, escreva o nome inteiro, numa regra própria: .cartao__titulo { color: navy; }. Com BEM, aninhar nem é necessário: os nomes já dizem a quem cada classe pertence.

Um sublinhado só, ou nomes diferentes no HTML e no CSS

O que acontece: o HTML tem class="cartao_titulo" (um sublinhado) e o CSS tem .cartao__titulo (dois). Para o navegador, são nomes completamente diferentes, e a regra não pega. Nenhum validador avisa: o do HTML não olha o CSS, e o do CSS não olha o HTML.

Como achar: no F12, clique no elemento: o painel de estilos não mostra a regra .cartao__titulo, porque ela não casa com ele. Compare o nome da classe, letra por letra. Copiar e colar o nome, em vez de redigitar, evita o problema.

Missão final: o bloco botão

Missão: crie o bloco botao em BEM. No CSS: .botao com fundo firebrick (um vermelho-tijolo; branco no tomato teria pouco contraste, aula CSS e Acessibilidade), texto branco, sem borda e com padding: 8px 16px e font-size: 1rem; e o modificador .botao--grande, depois, com font-size: 1.25rem. No HTML, os dois botões ganham class="botao", e o "Encomendar" também o modificador.

<link rel="stylesheet" href="style.css">
<button>Ver receita</button>
<button>Encomendar</button>

/* Bloco: botao */

<link rel="stylesheet" href="style.css">
<button class="botao">Ver receita</button>
<button class="botao botao--grande">Encomendar</button>

/* Bloco: botao */
.botao {
  padding: 8px 16px;
  border: none;
  background-color: firebrick;
  color: white;
  font-size: 1rem;
}

/* Modificador */
.botao--grande {
  font-size: 1.25rem;
}

Resumo

  • Nomes soltos (.titulo) vazam entre partes do site. O BEM dá a cada classe um "sobrenome": o bloco a que ela pertence.
  • Bloco .cartao; elemento .cartao__titulo (dois sublinhados); modificador .cartao--destaque (dois hífens), sempre junto com a base.
  • Uma classe por seletor: especificidade igual em tudo, sem guerra de seletores nem !important. Modificadores depois da base, no arquivo.
  • No CSS aninhado do navegador, &__titulo não funciona (é coisa do Sass): escreva o nome inteiro.
  • Os validadores não conferem se o nome no HTML é o mesmo do CSS: use o F12.
