Novidades do CSS

O CSS mudou mais entre 2023 e 2026 do que nos dez anos anteriores. Coisas que antes exigiam JavaScript ou truques (escolher o pai pelo filho, um componente que se adapta ao espaço dele, um balão grudado num botão, uma caixa de texto que cresce sozinha) agora são uma linha de CSS. Esta aula é um mapa: o que chegou, onde ele já funciona, onde aprender mais neste guia, e como usar o que é novo sem quebrar o site de quem tem um navegador antigo.

Você vai aprender
  • O selo Baseline: como saber se um recurso já pode ser usado.
  • A lista do que chegou de 2023 a 2026, com a data em que passou a funcionar em todos os navegadores principais.
  • Exemplos ao vivo de cinco novidades que ainda não apareceram no guia: text-wrap: balance, light-dark(), @starting-style, anchor positioning e field-sizing.
  • O que ainda está chegando, e por que esperar.
  • Como usar o novo com segurança, e por que o validador às vezes "não conhece" o que o navegador já entende.
Datas conferidas no MDN em outubro de 2026

Todas as datas desta aula são as do selo Baseline nas páginas do MDN (developer.mozilla.org), conferidas em outubro de 2026. Elas mudam com o tempo, sempre para melhor: o que hoje é "limitado" pode virar Baseline no ano que vem. Os exemplos ao vivo foram conferidos no Chromium 155.

A ideia: o selo "pode usar"

Um recurso novo do CSS não chega a todos ao mesmo tempo. Primeiro ele aparece num navegador, depois em outro, e o último às vezes demora anos. Para não ter de conferir navegador por navegador, existe o Baseline ("linha de base"), um selo que aparece no topo das páginas do MDN e do caniuse.com. Pense no selo de "aprovado" de um alimento: você não precisa ler o laudo do laboratório, só olhar o selo.

2. Cinco novidades ao vivo

Os exemplos abaixo são desenhados pelo seu navegador. Se ele for antigo, alguns não vão funcionar, e isso já é uma lição: confira o selo antes de contar com o recurso.

text-wrap: balance: títulos equilibrados

Um título longo numa caixa estreita costuma quebrar com uma linha cheia e uma palavra sozinha embaixo. Com text-wrap: balance ("quebra de texto: equilibrada"), o navegador distribui as palavras para as linhas ficarem de tamanho parecido:

<style>
h2 {
  max-width: 16em;
  font-family: sans-serif;
  border: 1px dashed #999999;
}
.equilibrado {
  text-wrap: balance;
}
</style>
<h2>Bolo de cenoura com cobertura de mel</h2>
<h2 class="equilibrado">Bolo de cenoura com cobertura de mel</h2>

No Chromium 155, o primeiro título quebra com "Bolo de cenoura com cobertura" na primeira linha e só "de mel" na segunda; o equilibrado fica com "Bolo de cenoura com" e "cobertura de mel", duas linhas de tamanho parecido. A caixa tracejada mostra que a largura disponível é a mesma: o balance só escolhe outros pontos de quebra. As linhas exatas dependem da fonte e da largura do seu navegador. O MDN avisa que o balance só age em textos curtos (até 6 linhas no Chromium e 10 no Firefox): é para títulos, não para parágrafos. Para parágrafos existe text-wrap: pretty, que evita uma palavra sozinha na última linha; segundo o caniuse (out. 2026), ele funciona no Chrome, no Edge e no Safari 26, mas ainda não no Firefox, onde o parágrafo só quebra do jeito normal.

Missão: equilibre as linhas do título da receita com text-wrap: balance. Depois apague a linha e compare.

<link rel="stylesheet" href="style.css">
<h1>Pão de queijo mineiro de liquidificador para o café da tarde</h1>

h1 {
  max-width: 14em;
  font-family: sans-serif;
}

h1 {
  max-width: 14em;
  font-family: sans-serif;
  text-wrap: balance;
}

light-dark(): duas cores numa linha

Na aula Tema Escuro você usa @media (prefers-color-scheme: dark) para trocar as cores. A função light-dark() encurta isso: o primeiro valor vale no tema claro, o segundo no escuro. Ela só funciona se a página disser que aceita os dois temas, com color-scheme: light dark:

Experimente: aperte o botão ◐ da barra do quadro para trocar o tema que a página "vê". O fundo e o texto trocam de cor sem nenhum @media. Depois apague a linha do color-scheme e aperte o ◐ de novo: as cores não trocam mais.

<link rel="stylesheet" href="style.css">
<div class="aviso">A lojinha fecha às 18h no sábado.</div>

:root {
  color-scheme: light dark;
}
.aviso {
  padding: 12px;
  border-radius: 8px;
  font-family: sans-serif;
  background-color: light-dark(#fff3cd, #3d3200);
  color: light-dark(#5c4400, #ffe69c);
}

@starting-style: animar a chegada

Uma transição (aula Transições) anima a mudança de um valor para outro. Mas um elemento que acabou de aparecer (que estava com display: none, por exemplo) não tinha valor "de antes", e por isso aparecia de uma vez. O @starting-style ("estilo de partida") diz de onde ele parte:

Experimente: marque a caixinha "Mostrar o aviso": o aviso aparece aos poucos, descendo um pouquinho. Desmarque e marque de novo. Troque 0.8s por 3s (nas duas) para ver em câmera lenta, e apague o bloco @starting-style para comparar: o aviso surge de uma vez.

<link rel="stylesheet" href="style.css">
<input type="checkbox" id="mostrar" class="mostrar">
<label for="mostrar">Mostrar o aviso</label>
<div class="aviso">Bolo saindo do forno!</div>

.aviso {
  display: none;
  margin-top: 12px;
  padding: 12px;
  background-color: #fff3cd;
  font-family: sans-serif;
  transition: opacity 0.8s, transform 0.8s;
}
.mostrar:checked ~ .aviso {
  display: block;
  opacity: 1;
  transform: translateY(0);
}

@starting-style {
  .mostrar:checked ~ .aviso {
    opacity: 0;
    transform: translateY(-20px);
  }
}

O seletor .mostrar:checked ~ .aviso quer dizer "o .aviso que vem depois da caixinha marcada" (aulas Combinadores e Estados). Uma transição só começa quando um valor muda: um elemento que já estava na página quando ela abriu não tem de onde partir, e por isso o exemplo usa a caixinha para fazer o aviso chegar depois.

Anchor positioning: grudar um elemento no outro

Balões de dica e menus que abrem embaixo de um botão sempre precisaram de JavaScript para calcular a posição. Agora o botão ganha um nome de âncora (anchor-name), e o balão diz em que âncora se prende (position-anchor) e de que lado (position-area):

Experimente: o balão azul-marinho fica grudado em cima do botão, centralizado com ele, embora no HTML ele venha depois do botão. Troque top por bottom ou por right, ou mude o margin-left do botão: o balão vai junto.

<link rel="stylesheet" href="style.css">
<p>Escolha o seu bolo e clique para comprar.</p>
<button class="comprar" type="button">Comprar</button>
<div class="dica">Frete grátis hoje!</div>

body {
  font-family: sans-serif;
}
.comprar {
  margin-top: 48px;
  margin-left: 80px;
  anchor-name: --botao-comprar;
}
.dica {
  position: absolute;
  position-anchor: --botao-comprar;
  position-area: top;
  margin-bottom: 4px;
  padding: 4px 8px;
  border-radius: 4px;
  background-color: navy;
  color: white;
}

field-sizing: content: o campo que cresce

Experimente: digite uma mensagem longa, com várias linhas, na caixa de recado. Ela cresce com o texto, sem barra de rolagem. Apague a linha do field-sizing e digite de novo.

<link rel="stylesheet" href="style.css">
<label for="recado">Recado para a Ana</label>
<textarea id="recado">Oi, Ana!</textarea>

label {
  display: block;
  font-family: sans-serif;
}
textarea {
  field-sizing: content;
  min-width: 12em;
  max-width: 100%;
  min-height: 2lh;
}

O 2lh é uma unidade nova também: lh vale a altura de uma linha do texto, então min-height: 2lh é "no mínimo duas linhas".

4. Como usar o novo com segurança

A regra de ouro: o recurso novo melhora a página de quem tem, e quem não tem ainda recebe uma página que funciona. Isso tem nome: melhoria progressiva. Três formas:

FormaExemploQuando usar
Não faz falta: só usetext-wrap: balance;Enfeites: quem não tem vê o título quebrado do jeito antigo, e tudo bem
Declaração reserva antesbackground-color: #fff3cd;
background-color: light-dark(#fff3cd, #3d3200);		Valores novos: o navegador antigo ignora a segunda linha (não entende) e fica com a primeira
@supports@supports (anchor-name: --a) { … }Quando o recurso novo precisa de várias regras juntas, ou quando o jeito antigo atrapalharia o novo (aula @supports)

A "declaração reserva" funciona por causa de uma regra que você viu no guia todo: o navegador ignora em silêncio o que não entende. Para o navegador antigo, light-dark(…) é um valor inválido, e a declaração some, deixando a anterior valer.

Quando dá errado

O validador "não conhece" o que o navegador já entende 
textarea {
  field-sizing: content;
}
.comprar {
  anchor-name: --botao-comprar;
}

$ vnu --css style.css
"file:/home/ana/site/style.css":2.17-2.23: error: CSS: “field-sizing”: Property “field-sizing” doesn't exist.
"file:/home/ana/site/style.css":5.16-5.22: error: CSS: “anchor-name”: Property “anchor-name” doesn't exist.

O que significa: "a propriedade não existe". Mas existe: as duas funcionam nos quatro navegadores principais atualizados (Baseline 2026). O validador de CSS (o vnu 26.10.12 do laboratório) também não reconhece o @starting-style:

$ vnu --css chegada.css
"file:/home/ana/site/chegada.css":1.1-1.15: error: CSS: Unrecognized at-rule “@starting-style”

Por quê: o validador é atualizado à mão, e anda atrás dos navegadores. Já text-wrap: balance, light-dark(), @scope e o aninhamento passam sem erro no mesmo validador. O que fazer: quando o validador acusar uma propriedade nova, confira no MDN antes de apagar. Se o MDN mostrar o selo Baseline, o erro é do validador, não seu. Erros de digitação de verdade (feild-sizing) ele continua pegando.

Funciona no meu computador, não no celular da cliente

A Ana usou field-sizing: content e mostrou o site no notebook dela, com o Chrome atualizado. A cliente abriu num celular de quatro anos, sem atualizações: a caixa de recado ficou do tamanho padrão, com barra de rolagem. Por quê: recurso "recém-disponível" quer dizer "nas versões atuais". O navegador antigo ignorou a declaração. Como evitar: para cada recurso novo, pergunte "e se não funcionar?". Aqui, a caixa ainda funciona (só não cresce): é uma melhoria progressiva aceitável. Se o recurso fosse essencial, precisaria de uma reserva.

light-dark() sem color-scheme: sempre a cor clara

Sem color-scheme: light dark na página (ou no elemento), o navegador acha que a página só tem tema claro, e o light-dark() devolve sempre o primeiro valor, mesmo com o sistema em modo escuro. Você testou isso na caixa da seção 2. O validador não acusa nada: o CSS está correto, só falta uma linha.

Missão final: o cartão com recursos novos

Missão: modernize o cartão da receita. (1) No :root, diga que a página aceita os dois temas: color-scheme: light dark. (2) Troque o fundo do .cartao por light-dark(#ffffff, #2b2b3a), e a cor do texto por light-dark(#222222, #f5f5f5). (3) Mova a regra do h2 para dentro da regra do .cartao (aninhamento) e acrescente text-wrap: balance nela. Depois aperte o ◐ do quadro para ver o tema escuro.

<link rel="stylesheet" href="style.css">

  <h2>Bolo de cenoura com cobertura de chocolate da vovó</h2>
  <p>Rende 12 fatias. 50 minutos.</p>
</div>

:root {
  font-family: sans-serif;
}
.cartao {
  max-width: 18em;
  padding: 16px;
  border: 1px solid #cccccc;
  border-radius: 8px;
  background-color: #ffffff;
  color: #222222;
}
.cartao h2 {
  margin-top: 0;
}

  font-family: sans-serif;
  color-scheme: light dark;

.cartao {
  max-width: 18em;
  padding: 16px;

  border-radius: 8px;

  }
}

Resumo

  • O selo Baseline do MDN e do caniuse diz se um recurso já funciona nos quatro navegadores principais: "amplamente disponível" (pode usar), "recém-disponível" (versões atuais; tenha uma reserva) ou "limitado" (espere).
  • De 2023 a 2026 chegaram: @container, oklch(), subgrid, :has(), aninhamento, text-wrap, light-dark(), @property, @starting-style, content-visibility, view transitions, anchor positioning, @scope, field-sizing.
  • Ainda chegando (out. 2026): if(), animações ligadas à rolagem, o <select> estilizável.
  • Melhoria progressiva: o novo melhora para quem tem; quem não tem recebe uma página que funciona (declaração reserva antes, ou @supports).
  • O validador anda atrás dos navegadores: field-sizing, anchor-name e @starting-style aparecem como erro no vnu 26.10.12. Confira no MDN antes de apagar.
