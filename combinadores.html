CSS Descendente, Filho e Irmãos

Às vezes o que identifica um elemento não é o nome nem a classe, e sim onde ele está: os links que ficam dentro do menu, os itens de primeiro nível de uma lista, o parágrafo que vem logo depois de um título. Os combinadores juntam dois seletores e dizem qual é a relação entre eles na página. São quatro: o espaço, o >, o + e o ~.

Você vai aprender
  • A página como uma árvore de família: pai, filho, neto, irmão.
  • O descendente (espaço): nav a.
  • O filho (>): .menu > li.
  • O irmão logo depois (+): h2 + p.
  • Os irmãos depois (~): h2 ~ p.
  • Quando usar cada um, e os erros: um elemento no meio do caminho, o irmão que vem antes, procurar o pai.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a árvore da família

O navegador guarda a página como uma árvore, igual a uma árvore genealógica. Quem está dentro de um elemento é descendente dele. Veja esta lista:

<ul class="menu">
  <li>Bolos
    <ul>
      <li>Fubá</li>
      <li>Cenoura</li>
    </ul>
  </li>
  <li>Pães</li>
</ul>
ParentescoNa lista acima
Filho: está diretamente dentro"Bolos" e "Pães" são filhos do ul.menu
Neto (e bisneto…): está dentro de um filho"Fubá" e "Cenoura" são netos do ul.menu (filhos do ul de dentro)
Descendente: filho, neto, bisneto, qualquer nívelOs quatro <li> são descendentes do ul.menu
Irmãos: têm o mesmo pai"Bolos" e "Pães" são irmãos; "Fubá" e "Cenoura" também

Cada combinador fala de um desses parentescos:

CombinadorExemploLê-se
espaço.menu litodo li dentro do .menu, em qualquer nível
>.menu > litodo li que é filho direto do .menu
+h2 + po p que vem logo depois de um h2, com o mesmo pai
~h2 ~ ptodo p que vem depois de um h2, com o mesmo pai

Em todos eles, quem recebe o estilo é o elemento da direita, o último do seletor. O da esquerda só diz onde procurar.

1. Descendente: o espaço

O espaço entre dois seletores quer dizer "dentro de". O caso clássico: os links do menu com uma cor, os links do texto com outra.

Experimente: nav a pegou só os dois links dentro do <nav>; o link do parágrafo continua com a cor normal. Troque o seletor por só a e veja os três mudarem.

<link rel="stylesheet" href="style.css">
<nav>
  <a href="index.html">Início</a>
  <a href="receitas.html">Receitas</a>
</nav>
<p>Veja o <a href="bolo.html">bolo de fubá</a>.</p>

nav a {
  color: darkgreen;
  font-weight: bold;
}
nav
O "ancestral": onde procurar.
(espaço)
O combinador descendente: "em qualquer lugar dentro de". Um espaço basta; vários espaços ou uma quebra de linha valem o mesmo.
a
Quem recebe o estilo: os <a> que estão dentro de um <nav>, seja como filhos, netos ou mais fundo.

Os dois lados podem ser qualquer seletor: .receita li, #topo a, footer .aviso. E dá para encadear: .receita ul li é "um li dentro de um ul dentro de um .receita". Mas evite correntes longas: quanto mais comprido o seletor, mais ele depende da estrutura do HTML, e mais difícil fica de vencer depois (aula Especificidade).

2. Filho: o >

O descendente pega todos os níveis. Numa lista dentro de lista, isso nem sempre é o que você quer:

Missão: a Ana queria a barra vermelha só nas categorias ("Bolos" e "Pães"), mas .menu li pôs a barra nos subitens também. Troque o espaço por > para pegar só os filhos diretos do .menu.

<link rel="stylesheet" href="style.css">
<ul class="menu">
  <li>Bolos
    <ul>
      <li>Fubá</li>
      <li>Cenoura</li>
    </ul>
  </li>
  <li>Pães</li>
</ul>

.menu li {
  border-left: 4px solid crimson;
  padding-left: 8px;
}

.menu > li {
  border-left: 4px solid crimson;
  padding-left: 8px;
}

No começo, há duas barras: uma comprida, à esquerda de tudo, e uma mais curta, mais para dentro, ao lado de "Fubá" e "Cenoura". Com .menu > li, a barra de dentro some e fica só a de fora. Ela desce ao lado da sublista inteira porque a sublista está dentro do item "Bolos", e emenda com a barra de "Pães", logo abaixo. Os espaços em volta do > são opcionais (.menu>li também funciona), mas com eles fica mais fácil de ler.

Cuidado com o que passa de pai para filho

Na caixa acima, troque a borda por font-weight: bold;, ainda com .menu > li. "Fubá" e "Cenoura" também ficam em negrito! Não porque o seletor os pegou, mas porque o negrito (assim como a cor e a fonte) passa de pai para filho por herança, e eles estão dentro de "Bolos". A borda não passa: por isso a missão usa a borda. Para tirar o negrito dos subitens, seria preciso uma regra para eles: .menu li li { font-weight: normal; }.

3. Irmão logo depois: o +

O + pega o elemento que vem imediatamente depois de outro, com o mesmo pai. Um uso comum: deixar diferente o primeiro parágrafo depois de cada título, a "linha fina" das revistas.

Experimente: em cada seção, só o primeiro parágrafo depois do <h2> ficou maior e em itálico. Troque o + por ~ (próxima seção) e compare.

<link rel="stylesheet" href="style.css">
<h2>Ingredientes</h2>
<p>Para uma forma média.</p>
<p>Use fubá fino.</p>
<h2>Modo de preparo</h2>
<p>Leva 50 minutos.</p>
<p>Bata tudo no liquidificador.</p>

h2 + p {
  font-size: 1.2rem;
  font-style: italic;
}
h2
O ponto de referência.
+
"O próximo irmão": o elemento seguinte, com o mesmo pai. Só ele, e só se for o logo depois.
p
Quem recebe o estilo, se o próximo irmão do h2 for um <p>. Se for outra coisa (uma imagem, uma lista), ninguém recebe.

Outro uso famoso: li + li { border-top: 1px solid gray; }, uma linha entre os itens de uma lista. Todo item que tem um item antes dele ganha a linha em cima; o primeiro, que não tem ninguém antes, fica sem. Linha só entre os itens, sem sobrar nas pontas.

4. Irmãos depois: o ~

O ~ (til) é o primo largo do +: pega todos os irmãos que vêm depois, não só o primeiro.

<style>
  h2 ~ p {
    color: darkslateblue;
  }
</style>
<p>Receita da vó Lurdes.</p>
<h2>Ingredientes</h2>
<p>Para uma forma média.</p>
<ul>
  <li>2 xícaras de fubá</li>
</ul>
<p>Use fubá fino.</p>

Os dois parágrafos depois do <h2> ficaram azul-ardósia, mesmo com a lista no meio do caminho. O primeiro parágrafo, que vem antes do título, não mudou: o ~ e o + só olham para a frente.

5. Qual usar

Você querUseExemplo
Tudo de um tipo dentro de uma áreaespaçonav a, .receita img
Só o primeiro nível (listas dentro de listas, menus)>.menu > li
O elemento logo depois de outro+h2 + p, li + li
Todos os que vêm depois de outro, no mesmo nível~h2 ~ p
Algo que tenha um filho de certo tipo (o "pai")Nenhum combinador: :has().cartao:has(img) (aula :has())

Na dúvida, prefira uma classe no próprio elemento: .linha-fina não quebra se alguém puser uma imagem entre o título e o parágrafo. Combinadores são ótimos para estruturas que não mudam (o menu, a lista) e para não precisar pôr classe em tudo.

Quando dá errado

O > não acha: tem um elemento no meio 
<style>
  .cartao > p {
    color: crimson;
  }
</style>
<div class="cartao">
  <div class="corpo">
    <p>Bolo de fubá</p>
  </div>
</div>

O que você vê: o parágrafo continua preto.

Por quê: o <p> é neto do .cartao, e não filho: entre os dois existe o div.corpo. O > só desce um nível. O validador não reclama: o seletor é válido, só não acha ninguém.

Como consertar: .cartao p (qualquer nível) ou .corpo > p. Na aula Inspecionando com o F12, a aba de elementos mostra a árvore da página, com cada nível mais para a direita: é o jeito de descobrir quem é pai de quem.

O + não acha: o vizinho mudou 
<style>
  h2 + p {
    font-style: italic;
  }
</style>
<h2>Bolo de cenoura</h2>
<img src="assets/midia/bolo-400.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="200" height="150">
<p>Com cobertura de chocolate.</p>

O que você vê: o parágrafo não ficou em itálico.

Por quê: o irmão logo depois do <h2> é a imagem, e não o parágrafo. O + não pula ninguém.

Como consertar: h2 ~ p (qualquer irmão depois), ou uma classe no parágrafo, que não depende da ordem.

Procurando o pai: ul < li não existe 
$ cat menor.css
ul < li {
  color: crimson;
}
$ vnu --css menor.css
"file:/home/ana/site/menor.css":3.2-4.1: error: CSS: Parse Error.

O que significa: "erro de leitura". Não há combinador < no CSS, nem um "irmão de antes" (-): os combinadores só descem na árvore e só andam para a frente. O validador aponta o fim da regra (linha 3, coluna 2, depois do }), e não o <: ele só percebe que a regra inteira não fazia sentido quando chega ao fim dela. O navegador ignora a regra toda.

Como consertar: para "o pai que tem tal filho", o CSS moderno tem o :has(): ul:has(li.destaque) (aula :has(): o Seletor do Pai).

Combinador sem nada depois: Parse Error 
$ cat mais.css
h2 + {
  color: crimson;
}
$ vnu --css mais.css
"file:/home/ana/site/mais.css":3.2-4.1: error: CSS: Parse Error.

O que significa: o + precisa de um seletor dos dois lados. Com o lado direito vazio, a regra inteira é ignorada. O mesmo vale para > e ~, e para dois combinadores seguidos (ul > > li).

Referência rápida

SeletorNomePega
A BDescendenteTodo B dentro de A, em qualquer nível
A > BFilhoTodo B que é filho direto de A
A + BIrmão adjacenteO B logo depois de A, com o mesmo pai
A ~ BIrmãos geraisTodo B depois de A, com o mesmo pai
Quem recebe o estilo é sempre o da direita. Não há combinador para o pai nem para o irmão de antes (para o pai, :has()).

Resumo

  • Combinadores dizem a relação entre dois seletores na árvore da página. Quem recebe o estilo é sempre o da direita.
  • Espaço: descendente, qualquer nível (nav a). >: filho direto (.menu > li).
  • +: o irmão logo depois (h2 + p, li + li). ~: todos os irmãos depois (h2 ~ p).
  • Os combinadores só descem e só andam para a frente. Para o pai, :has().
  • Quando não pega: um elemento no meio (para o >), um vizinho diferente (para o +), ou o irmão que vem antes. Combinador sem seletor do lado é Parse Error.
