CSS para Impressão

Muita gente ainda imprime receitas, currículos e ingressos. Se ninguém pensou nisso, o papel sai com o menu do site, o botão "Imprimir", o fundo escuro gastando tinta e links que ninguém consegue clicar. Com um bloco @media print, a mesma página ganha uma segunda roupa, só para o papel. Nesta aula a receita da Ana vai sair da impressora limpa e legível.

Você vai aprender
  • O bloco @media print { … }: regras que só valem na impressão.
  • O que costuma mudar no papel: esconder menu e botões, fundo branco, letra preta.
  • Como imprimir o endereço de cada link com ::after e attr(href).
  • Quebras de página (break-before, break-inside) e as margens do papel (@page).
  • Duas formas de organizar: o bloco no mesmo arquivo ou um arquivo só para o papel (media="print").
  • Como ver a prévia sem gastar papel, e os erros que fazem as regras de impressão sumirem.

Antes, é bom ter feito a aula Media Queries (@media): o @media print é uma media query, só que para o papel em vez de para a largura da tela.

A ideia: a roupa de sair e a roupa de trabalho

Você é a mesma pessoa na festa e no trabalho, mas troca de roupa conforme o lugar. Com a página é igual: o conteúdo (o HTML) é um só; a aparência (o CSS) pode mudar conforme o lugar onde ela aparece. A tela do computador é um lugar; a folha de papel é outro.

Na telaNo papel
O menu leva a outras páginasNinguém clica no papel: o menu só ocupa espaço
O botão "Imprimir" é útilUm botão impresso não serve para nada
Fundo escuro com letra clara é confortávelFundo escuro gasta tinta e, se o navegador não imprimir o fundo, a letra clara some no papel branco

A página rola sem fimO papel tem folhas: um título pode cair sozinho no pé da página

1. O bloco @media print

As regras que você escreve dentro do bloco só valem quando a página vai para a impressora (ou para "Salvar como PDF", que é uma impressão também). Na tela, o navegador as ignora.

.menu {
  background-color: tomato;
}

@media print {
  .menu {
    display: none;
  }
}
@media
Uma regra-at (começa com @): "as regras aqui dentro só valem numa condição". É a mesma @media das telas pequenas.
print
O tipo de mídia: "impressão". Os outros tipos que importam são screen ("tela") e all ("todos", o padrão quando você não diz nada).
{ … }
As chaves do bloco. Dentro delas vão regras CSS completas, cada uma com o seu seletor e as suas chaves. São duas chaves para fechar: a da regra e a do bloco.
.menu { display: none; }
Uma regra comum: esconde o menu. Como está dentro do bloco, só esconde no papel (display: none tem aula própria: Escondendo).

Repare que a regra de fora (background-color: tomato) continua valendo no papel também: o @media print não apaga o resto do CSS, só acrescenta regras. Como ele vem depois no arquivo, ganha os empates da cascata (aula A Cascata). Por isso o bloco de impressão costuma ficar no fim do style.css.

2. O que costuma mudar no papel

Não existe uma lista obrigatória, mas quase todo bloco de impressão faz as mesmas coisas:

O quêComoPor quê
Esconder o que não serve no papelnav, .imprimir, footer form { display: none; }Menu, botões, formulários de busca e anúncios não funcionam impressos
Fundo branco, letra pretabody { background-color: white; color: black; }Economiza tinta e garante contraste, mesmo numa impressora preto e branco
Links pretosa { color: black; }Azul-claro ou amarelo ficam pálidos no papel
Usar a largura todamain { width: auto; max-width: none; }A folha já tem margens; colunas laterais desperdiçam papel
Letra em ptbody { font-size: 12pt; }O ponto (pt) é a unidade das gráficas; 12pt é o tamanho de um texto comum impresso (aula Unidades)
O fundo já não sai, mesmo sem CSS

Para economizar tinta, os navegadores não imprimem cores e imagens de fundo por padrão: na janela de impressão, a opção de "gráficos de fundo" vem desmarcada. Por isso uma página com fundo escuro e letra clara sai com letra clara em papel branco, quase invisível, se você não mudar a cor do texto no @media print. Quando o fundo é importante (a cor de uma etiqueta "Sem glúten", um gráfico), a propriedade print-color-adjust: exact; pede ao navegador que imprima as cores daquele elemento como estão. É Baseline 2025 no MDN: funciona nas versões atuais do Chrome, Edge, Firefox e Safari, mas não em navegadores antigos, que conheciam só o nome com prefixo -webkit-print-color-adjust.

3. O endereço dos links no papel

Num papel, "Receitas do mundo" sublinhado não diz aonde ir. O pseudo-elemento ::after (aula ::before e ::after) junto com a função attr() escreve o endereço logo depois do texto:

@media print {
  a[href^="http"]::after {
    content: " (" attr(href) ")";
  }
}
a[href^="http"]
Só os links cujo href começa com http: os links para outros sites (aula Seletores de Atributo). Os links internos, como receitas.html, não ganham o endereço, porque no papel ele não ajudaria ninguém.
::after
Cria um pedacinho de texto depois do conteúdo do link.
content: " (" attr(href) ")"
O texto criado, em três partes coladas: " (" (espaço e parêntese), o valor do atributo href, e ")".

Na prévia de impressão do Chromium, o parêntese com o endereço sai sublinhado também, como o resto do link: o ::after fica dentro do <a> e recebe o sublinhado dele. Tudo bem: o sublinhado até ajuda a ver que o endereço faz parte do link.

4. Quebras de página

O papel é cortado em folhas. Sem cuidado, um título "Modo de preparo" pode cair sozinho na última linha de uma folha, com o texto dele na folha seguinte. Três propriedades decidem onde o corte pode e onde não pode acontecer:

Propriedade e valorO que fazExemplo de uso
break-before: page;Começa uma folha nova antes do elementoCada receita de um livro de receitas numa folha própria
break-after: page;Começa uma folha nova depois do elementoUma capa sozinha na primeira folha
break-inside: avoid;Evita cortar o elemento no meioUma tabela, uma foto com legenda, a lista de ingredientes
break-after: avoid;Evita cortar logo depois do elementoTítulos (h2), para não ficarem órfãos no pé da folha
@media print {
  .receita {
    break-before: page;
  }
  h2 {
    break-after: avoid;
  }
  ul,
  figure {
    break-inside: avoid;
  }
}

As palavras avoid ("evitar") são um pedido, não uma ordem: se uma tabela for maior que a folha inteira, o navegador corta mesmo assim. Já o page do break-before é obedecido.

O jeito antigo: page-break-*

Em CSS antigo você vai ver page-break-before: always;, page-break-after e page-break-inside: avoid;. Eles ainda funcionam (o navegador os traduz para break-before e cia.), mas os nomes de hoje são os sem page-. O break-inside é "amplamente disponível" no MDN desde 2019.

5. A folha de papel: @page

A regra-at @page fala da folha, não dos elementos: o tamanho do papel e as margens em volta do conteúdo.

@page {
  size: A4;
  margin: 2cm;
}
@page
"A página impressa". Não tem seletor de elemento: vale para todas as folhas.
size: A4;
O tamanho do papel: A4, A5, letter (o "carta" americano), ou medidas, como size: 10cm 15cm;. Junte landscape para a folha deitada: size: A4 landscape;.
margin: 2cm;
A margem da folha. No papel, cm e mm fazem sentido de verdade: 2cm medem 2 centímetros na régua.
Suporte

O @page com margin funciona há muitos anos. O descritor size é Baseline 2024 no MDN: funciona nas versões atuais do Chrome, Edge, Firefox e Safari. Mesmo assim, a pessoa pode escolher outro papel na janela de impressão, e a escolha dela vence: trate o size como uma sugestão.

6. Duas formas de organizar

Forma 1: o bloco no fim do style.css

É o que você viu até aqui. Tudo num arquivo só, e o bloco de impressão no fim, para vencer os empates.

Forma 2: um arquivo só para o papel

O atributo media do <link> diz para qual mídia o arquivo inteiro vale. Com media="print", o arquivo imprimir.css só entra na impressão, e dentro dele não precisa de @media:

<link rel="stylesheet" href="style.css">
<link rel="stylesheet" href="imprimir.css" media="print">

.menu {
  display: none;
}
body {
  background-color: white;
  color: black;
}

O <link> de impressão vem depois do principal, pelo mesmo motivo de antes: ganhar os empates. O navegador baixa o arquivo mesmo na tela (para ter na hora de imprimir), mas sem atrasar o desenho da página.

FormaQuando usar
@media print { … } no fim do style.cssO normal: poucas regras de impressão, um arquivo a menos para baixar e para lembrar
<link … media="print"> com um imprimir.cssMuitas regras de impressão (um site de receitas, um currículo), ou quando outra pessoa cuida só da versão impressa
@import url("imprimir.css") print;Evite: o @import atrasa o carregamento (aula CSS Rápido)

7. Como ver a prévia sem gastar papel

  1. A janela de impressão: aperte Ctrl+P (no Mac, Cmd+P). A prévia mostra as folhas com as suas regras de impressão. Escolha "Salvar como PDF" como impressora e nada sai no papel.
  2. O F12: no Chrome e no Edge, o painel de renderização das ferramentas do desenvolvedor (Rendering) tem uma opção para emular o tipo de mídia print: a própria aba passa a mostrar a versão de papel, e você inspeciona os elementos como sempre. Os nomes dos menus mudam de versão para versão; procure por "Rendering" e "CSS media type" (aula Inspecionando com o F12).
  3. O truque do screen: troque print por screen por um instante, como na seção 1.

Quando dá errado

Faltou fechar a chave do @media: o resto do CSS some da tela 
@media print {
  .menu {
    display: none;
  }

h1 {
  color: navy;
}
p {
  color: tomato;
}

O que o leitor vê: na tela, o título e o parágrafo ficam pretos, como se as regras de h1 e p não existissem. No Chromium, conferido: o h1 fica com a cor calculada rgb(0, 0, 0) na tela e rgb(0, 0, 128) (o navy) na impressão.

Por quê: a chave do bloco nunca foi fechada. O navegador entende que tudo até o fim do arquivo está dentro do @media print: as regras de h1 e p viraram regras de impressão. Nenhuma mensagem aparece; a indentação torta é a única pista.

O que o validador diz:

$ vnu --css style.css
"file:/home/ana/site/style.css":8.2-9.1: error: CSS: Parse Error.

"Erro de leitura" no fim do arquivo: o validador chegou ao fim sem achar a chave que faltava.

Como consertar: feche o bloco logo depois da última regra de impressão. Indente as regras de dentro com 2 espaços: assim a chave que falta salta aos olhos.

Nome da mídia errado: unrecognized media 
@media printer {
  .menu {
    display: none;
  }
}

O que o leitor vê: na impressão, o menu continua lá. Conferido no Chromium com a mídia de impressão: o .menu fica com display: block.

Por quê: printer (ou impressao, em português) não é um tipo de mídia. O navegador não dá erro: só considera que a condição nunca é verdadeira, e o bloco inteiro fica de fora, na tela e no papel.

$ vnu --css style.css
"file:/home/ana/site/style.css":5.2-6.1: error: CSS: unrecognized media “printer”.

"Mídia não reconhecida: printer". Como consertar: os tipos de mídia são só print, screen e all.

O display: none ficou fora do bloco: o menu some da tela também 
@media print {
  body {
    color: black;
  }
}
.menu {
  display: none;
}

O que o leitor vê: o menu desapareceu do site inteiro. Por quê: a regra do .menu está depois da chave que fecha o bloco, então vale em qualquer mídia. O validador não reclama: o CSS está correto, só faz outra coisa. Como consertar: mova a regra para dentro das chaves do @media print.

A letra sumiu no papel

O que o leitor vê: o site tem fundo escuro e letra clara. Na tela, ótimo; no papel, a letra sai cinza-clarinha, quase invisível. Por quê: o navegador não imprimiu o fundo (veja a nota da seção 2), mas imprimiu a letra com a cor da tela. Como consertar: no @media print, body { background-color: white; color: black; }, e confira os outros elementos que têm cor própria (links, títulos, rodapé).

Escrevi display: nada

Um valor que não existe faz o navegador ignorar a declaração (o elemento continua aparecendo), e o validador aponta a linha:

$ vnu --css style.css
"file:/home/ana/site/style.css":3.14-3.17: error: CSS: “display”: “nada” is not a “display” value.

"nada não é um valor de display". O valor certo é none.

Resumo

  • @media print { … } guarda regras que só valem no papel (e no PDF). Elas se somam às regras normais; o bloco fica no fim do arquivo para vencer os empates.
  • No papel: esconda menu, botões e formulários (display: none), use fundo branco e letra preta, links pretos, letra em pt.
  • Os navegadores não imprimem fundos por padrão; print-color-adjust: exact pede as cores de verdade quando elas importam.
  • a[href^="http"]::after { content: " (" attr(href) ")"; } imprime o endereço dos links externos.
  • Quebras: break-before: page (folha nova), break-inside: avoid e break-after: avoid (pedidos para não cortar). page-break-* é o nome antigo.
  • @page { size: A4; margin: 2cm; } fala da folha. Alternativa ao bloco: <link … media="print">.
  • Prévia: Ctrl+P, a emulação de mídia do F12 ou trocar print por screen por um instante.
  • Erros: chave do bloco sem fechar (o resto do CSS vira só de impressão; Parse Error) e mídia com nome errado (unrecognized media; o bloco é ignorado).
