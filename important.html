CSS !important (e Por que Evitar)

Toda pessoa que aprende CSS descobre, mais cedo ou mais tarde, o "botão de pânico": escrever !important depois de um valor faz aquela declaração ganhar de quase tudo. Funciona na hora. E é por funcionar tão bem que ele causa tanto estrago: cada !important obriga o próximo conserto a ser outro !important. Nesta aula você vai ver o que ele faz de verdade na cascata, os poucos casos em que ele é a ferramenta certa e o que usar no lugar dele.

Você vai aprender
  • Onde se escreve o !important e o que ele faz.
  • Por que ele vence até o atributo style, e o que acontece quando dois !important brigam.
  • A "corrida do !important": por que ele torna o CSS difícil de mudar.
  • Os usos legítimos: CSS de terceiros, style que você não controla, classes utilitárias.
  • As alternativas: especificidade, ordem, :where(), @layer.
  • Os erros: !important no lugar errado, !importante e a herança que não leva o !important.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a fila preferencial

No banco, existe a fila normal e a fila preferencial. Quem está na preferencial é atendido antes de todo mundo da fila normal, não importa a hora em que chegou. Funciona bem enquanto a preferencial é pequena. Agora imagine que todo mundo descobriu um jeito de entrar nela: a preferencial vira uma segunda fila normal, tão lenta quanto a primeira, e o problema voltou, só que maior.

O !important é a fila preferencial das declarações. E o CSS com !important em todo lugar é a preferencial lotada.

1. Como se escreve

Experimente: a regra #aviso (um ID!) diz azul-marinho, mas o aviso ficou vermelho-escuro: a declaração com !important passou na frente. Apague o !important e veja o ID ganhar de novo.

<link rel="stylesheet" href="style.css">
<p id="aviso" class="aviso">Fechado no feriado.</p>

.aviso {
  color: darkred !important;
}

#aviso {
  color: navy;
}
color: darkred
Uma declaração comum: propriedade, dois-pontos, valor.
!important
Depois do valor e antes do ;. O ! não é "não", como em outras linguagens: aqui ele só marca a palavra important ("importante"). Um espaço entre os dois (! important) também é aceito, mas ninguém escreve assim.
;
Fecha a declaração, como sempre.

O !important vale para uma declaração, e não para a regra inteira. Numa regra com três declarações, só a que tem a marca vai para a fila preferencial; as outras continuam normais.

2. O que ele faz na cascata

Lembre os critérios da cascata: primeiro origem e importância, depois camadas, especificidade e ordem. O !important atua no primeiro critério. Por isso ele passa na frente de tudo o que vem depois: de qualquer especificidade, de qualquer ordem, e até do atributo style.

<style>
  .aviso {
    color: darkred !important;
  }
</style>
<p class="aviso" style="color: navy;">O style normal perde.</p>
<p class="aviso" style="color: navy !important;">O style com !important ganha.</p>

O primeiro parágrafo ficou vermelho-escuro: o !important da folha de estilo venceu o style normal. O segundo ficou azul-marinho: quando os dois lados têm !important, a disputa recomeça entre eles, e o style volta a ganhar.

Dois !important brigando

Quando duas declarações com !important disputam a mesma propriedade, tudo volta a ser como antes, só que no andar de cima: ganha a mais específica e, no empate, a última. Ou seja, o !important não resolveu a briga: só a mudou de andar.

Origens invertidas

No andar de cima, a ordem das origens se inverte: o !important do usuário (quem lê a página) ganha do !important do autor (quem fez a página). Isso é de propósito: quem precisa de letras maiores ou de mais contraste pode configurar o navegador, ou uma extensão, com !important, e a sua página não consegue desfazer. É por isso que o !important existe.

3. Por que evitar: a corrida

Veja como um único !important contamina o CSS:

  1. A Ana quer o preço verde e a regra perde. Em vez de entender por quê, ela escreve .preco { color: darkgreen !important; }. Funciona.
  2. Um mês depois, ela quer o preço em promoção vermelho: .promocao .preco { color: crimson; }. Não funciona: o !important do verde ganha de qualquer regra normal, por mais específica que seja.
  3. Ela escreve .promocao .preco { color: crimson !important; }. Funciona, porque agora as duas estão no andar de cima e esta é mais específica.
  4. Depois vem o preço esgotado, o preço do tema escuro… cada um com o seu !important, cada um mais específico que o anterior.

No fim, o andar de cima tem tantas regras quanto o de baixo, com o mesmo problema de antes e um seletor mais comprido em cada uma. E quem chega depois (outra pessoa, ou a própria Ana daqui a um ano) não tem mais nenhuma "fila preferencial" para usar.

4. Quando o !important é a ferramenta certa

Existem poucos casos legítimos. Em todos eles, o !important é uma decisão consciente, e não um conserto às pressas:

CasoExemploPor quê
Vencer um style que você não pode editarUm plugin ou um script põe style="color: …" no HTMLSó o !important vence o style
Vencer o CSS de terceiros com seletores enormesUm widget de comentários com #widget div.lista > pVocê não pode mudar o CSS dele
Classes utilitárias, que têm de valer sempre.escondido { display: none !important; }Quem põe essa classe quer o elemento escondido, sem exceção
Preferências do leitorDesligar animações para quem pede menos movimento (aula Respeitando Quem Prefere Menos Movimento)A acessibilidade tem de ganhar de qualquer animação do site

Missão: um plugin da loja da Ana escreve o aviso com style="color: gray;", e ela não consegue mudar esse HTML (finja que ele vem pronto do plugin: não mexa no index.html). Faça o aviso ficar darkred pelo style.css. Este é um dos poucos casos em que o !important é a resposta certa.

<link rel="stylesheet" href="style.css">
<p class="aviso" style="color: gray;">Frete grátis acima de R$ 100.</p>

.aviso {
  color: darkred;
}

.aviso {
  color: darkred !important;
}

5. O que usar no lugar

Quando a sua regra perde, descubra por que ela perde (no F12, a declaração riscada e a vencedora acima dela) e escolha o conserto pelo motivo:

MotivoConsertoAula
Empate, e a outra regra vem depoisMova a sua para depois, ou junte as duasA Cascata
A outra regra é mais específicaSuba a sua só o necessário (.cardapio .preco)Especificidade
A outra regra usa IDTroque o ID por classe no estiloSeletor de ID
Um CSS de base com seletores fortes demaisReescreva-o com :where(), que zera a especificidade:where()
Muitos arquivos brigando (reset, framework, o seu)Organize em camadas@layer

Quando dá errado

O !important antes do valor 
$ cat antes.css
p {
  color: !important darkred;
}
$ vnu --css antes.css
"file:/home/ana/site/antes.css":2.21-2.27: error: CSS: “color”: Parse Error.

O que significa: "erro de leitura em color". O !important vai depois do valor. Escrito antes, a declaração inteira fica inválida e é ignorada: nem o darkred vale.

Como consertar: color: darkred !important;

!importante, em português 
$ vnu --css portugues.css
"file:/home/ana/site/portugues.css":2.30-2.30: error: CSS: Parse Error.
"file:/home/ana/site/portugues.css":3.2-4.1: error: CSS: Parse Error.

O que significa: o CSS só conhece a palavra em inglês. Com !importante, a declaração inteira é ignorada, e o validador ainda se perde até o fim da regra.

Depois do ponto e vírgula 
<style>
  .aviso {
    color: darkred; !important
  }
  #aviso {
    color: navy;
  }
</style>
<p id="aviso" class="aviso">Fechado no feriado.</p>

O que você vê: o aviso fica azul-marinho.

Por quê: o ; fechou a declaração color: darkred, que ficou normal (e perde para o ID). O !important sobrou sozinho, sem declaração, e foi ignorado. O validador acusa Parse Error.

O !important não passa por herança 
<style>
  .cartao {
    color: crimson !important;
  }
  p {
    color: navy;
  }
</style>
<div class="cartao">
  <h2>Bolo de fubá</h2>
  <p>Fofinho, com erva-doce.</p>
</div>

O que você vê: o título ficou vermelho, mas o parágrafo ficou azul-marinho, mesmo com o !important no cartão.

Por quê: o !important vale na disputa pelo próprio elemento, o .cartao. O título herdou o vermelho porque nenhuma regra fala dele. O parágrafo tem uma regra própria (p), e uma regra do próprio elemento sempre vence um valor herdado, com ou sem !important no pai (aula Herança).

Missão final: desligando o !important

Missão: a Ana encheu o CSS do menu de !important e, mesmo assim, o link ativo ("Início") está azul-marinho, e não vermelho. Apague todos os !important e faça o link ativo ficar crimson, com o outro link em azul-marinho. Conte as especificidades e ajuste o seletor que está perdendo.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="index.html" class="ativo">Início</a>
  <a href="receitas.html">Receitas</a>
</nav>

.menu a {
  color: navy !important;
}

.ativo {
  color: crimson !important;
}

.menu a {
  color: navy;
}

.menu .ativo {
  color: crimson;
}

Por que o !important não resolveu? Porque as duas regras tinham !important: as duas subiram para o andar de cima, e lá a disputa foi decidida pela especificidade, como seria embaixo. .menu a (0, 1, 1) ganhava de .ativo (0, 1, 0). Com .menu .ativo (0, 2, 0) e nenhum !important, o ativo ganha pelo motivo certo, e qualquer regra futura de duas classes consegue mudá-lo.

Resumo

  • propriedade: valor !important; põe a declaração na "fila preferencial": ela ganha de todas as declarações normais, de qualquer especificidade e até do atributo style.
  • Entre dois !important, valem de novo a especificidade e a ordem. O do usuário ganha do do autor, para a acessibilidade.
  • Usado como conserto, ele começa uma corrida: cada mudança futura precisa de outro !important, mais específico.
  • Usos legítimos: vencer style ou CSS de terceiros que você não controla, classes utilitárias, preferências do leitor.
  • No lugar dele: descubra por que a regra perde e conserte pela causa (ordem, especificidade, ID, :where(), @layer).
  • Erros: antes do valor ou !importante invalidam a declaração; depois do ; ele é ignorado; e a importância não passa por herança.
