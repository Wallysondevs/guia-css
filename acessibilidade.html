CSS e Acessibilidade

Acessibilidade é o site funcionar para todo mundo: quem enxerga pouco, quem não enxerga e usa um leitor de tela, quem navega só pelo teclado, quem tem a mão trêmula no celular, quem fica enjoado com animação. O HTML faz metade do trabalho (Guia HTML). A outra metade é do CSS, e o CSS consegue tanto ajudar quanto estragar: uma única linha, outline: none, deixa o site inutilizável para quem usa o teclado. Nesta aula você vai ver as cinco regras de CSS que mais pesam, com os números de verdade.

Você vai aprender
  • Contraste: a conta que diz se um texto é legível, e o mínimo de 4,5 para 1.
  • Foco visível: por que nunca apagar o outline, e como fazer um foco bonito com :focus-visible.
  • Tamanho de toque: o mínimo de 24 × 24 px, e o recomendado de 44 × 44 px.
  • As preferências do sistema: prefers-reduced-motion, prefers-color-scheme, prefers-contrast e forced-colors.
  • Texto só para leitores de tela: a classe .sr-only, linha por linha, e por que display: none não serve.

As regras e os números vêm das WCAG (Web Content Accessibility Guidelines, "diretrizes de acessibilidade para conteúdo web"), a norma internacional, na versão 2.2. As contas de contraste foram feitas com a fórmula das WCAG; o que o leitor de tela "ouve" foi conferido na árvore de acessibilidade do Chromium (o que o navegador entrega aos leitores de tela).

A ideia: o prédio acessível

Um prédio acessível não é um prédio diferente: é o mesmo prédio, com rampa ao lado da escada, corrimão, placas com letra grande e em braile, botão do elevador na altura certa. Quem não precisa nem repara; quem precisa, entra. No CSS é igual: contraste bom, foco visível e botões grandes deixam o site melhor para todos (no sol forte, com pressa, com o celular numa mão só).

1. Contraste: o texto precisa se destacar do fundo

Contraste é a diferença de luminosidade entre a cor do texto e a do fundo, medida numa escala de 1:1 (nenhuma diferença, como branco no branco) a 21:1 (preto no branco). As WCAG pedem, no nível AA (o nível que as leis costumam exigir):

O quêContraste mínimo (AA)
Texto comum4,5 : 1
Texto grande (a partir de 24 px, ou 18,66 px em negrito)3 : 1
Bordas de campos, ícones e o contorno do foco3 : 1 contra o que está em volta

Lado a lado, com as contas feitas pela fórmula das WCAG:

<style>
  p {
    padding: 8px 12px;
    font-family: sans-serif;
  }
  .c1 { color: #cccccc; }
  .c2 { color: #999999; }
  .c3 { color: #767676; }
  .c4 { color: #595959; }
  .c5 { background-color: tomato; color: white; }
  .c6 { background-color: #b33a24; color: white; }
</style>
<p class="c1">#cccccc no branco: 1,61 : 1 (reprovado)</p>
<p class="c2">#999999 no branco: 2,85 : 1 (reprovado)</p>
<p class="c3">#767676 no branco: 4,54 : 1 (aprovado, por pouco)</p>
<p class="c4">#595959 no branco: 7 : 1 (aprovado com folga)</p>
<p class="c5">Branco no tomato: 2,95 : 1 (reprovado)</p>
<p class="c6">Branco no #b33a24: 5,92 : 1 (aprovado)</p>

Repare na quinta linha: branco sobre tomato, uma combinação muito comum em botões, tem só 2,95 : 1. Parece legível numa tela boa, dentro de casa; no celular, no sol, para quem enxerga pouco, não é. Um tom mais escuro do mesmo laranja-avermelhado (#b33a24) passa com 5,92 : 1. O #767676 é famoso: é o cinza mais claro que ainda passa no branco.

Como medir

  • No F12 do Chrome/Edge: clique no quadradinho de cor de uma propriedade color no painel de estilos. O seletor de cores mostra a razão de contraste e se ela passa no AA e no AAA.
  • Na web: verificadores de contraste (procure por "contrast checker"): você digita as duas cores e eles mostram a razão.
O validador não mede contraste

O vnu confere se o CSS está escrito certo, não se ele é legível. color: #ccc num fundo branco é CSS perfeitamente válido. Contraste é responsabilidade sua.

Duas regras que andam junto com o contraste:

  • Não use só a cor para dar uma informação. "Os campos em vermelho são obrigatórios" não funciona para quem não distingue vermelho. Acrescente um texto ou um símbolo (* e "obrigatório").
  • Deixe o texto crescer. Fontes em rem (aula Unidades) acompanham o tamanho de letra que a pessoa escolheu no navegador; caixas com altura fixa em px cortam o texto aumentado.

2. Foco visível: quem usa o teclado precisa ver onde está

Quem navega pelo teclado aperta Tab para ir de link em link, de botão em botão. O navegador desenha um contorno (o outline, aula Contorno) em volta do item que está com o foco. Sem esse contorno, é como usar um mouse com a setinha invisível.

O erro mais comum de toda a web é este:

/* "tira aquela borda feia" */
button:focus {
  outline: none;
}

Ele aparece em muito código copiado por aí, porque o contorno aparecia também no clique do mouse e "ficava feio". Hoje existe a solução certa: a pseudo-classe :focus-visible ("foco visível"), que o navegador liga só quando o foco precisa ser mostrado (no teclado, sim; no clique do mouse num botão, em geral não).

.botao:focus-visible {
  outline: 3px solid navy;
  outline-offset: 2px;
}
:focus-visible
Vale quando o elemento tem o foco e o navegador acha que ele deve aparecer (o foco veio do teclado, ou é um campo de texto). Funciona em todos os navegadores principais desde março de 2022 (Chrome 86, Firefox 85, Safari 15.4, pela tabela do MDN).
outline: 3px solid navy
Um contorno grosso, de cor com bom contraste com o fundo e com o botão. As WCAG pedem pelo menos 3 : 1 para o indicador de foco.
outline-offset: 2px
"Deslocamento do contorno": afasta o contorno 2 px do botão, para ele não se misturar com a borda.

Experimente: clique no texto acima dos botões e aperte Tab várias vezes. No primeiro botão, você vê o foco padrão do navegador; no segundo, nada (o outline: none); no terceiro, o contorno azul-marinho afastado. Agora clique com o mouse no terceiro: o contorno, em geral, não aparece.

<link rel="stylesheet" href="style.css">
<p>Clique aqui e aperte Tab:</p>
<button class="botao">Padrão</button>
<button class="botao sem-foco">outline: none</button>
<button class="botao foco-bom">:focus-visible</button>

.botao {
  padding: 12px 16px;
  border: none;
  background-color: #b33a24;
  color: white;
  font-size: 1rem;
}

/* Errado: o foco some */
.sem-foco:focus {
  outline: none;
}

/* Certo: um foco claro, só quando precisa */
.foco-bom:focus-visible {
  outline: 3px solid navy;
  outline-offset: 2px;
}

No Chromium, com o foco de teclado forçado em cada botão, a foto mostra: o primeiro com o contorno padrão do navegador, colado no botão; o segundo igual a um botão sem foco, impossível de distinguir dos outros; o terceiro com o contorno azul-marinho grosso, separado do botão por uma faixa branca.

Missão: o menu da Ana apagou o foco dos links. Apague a regra com outline: none e crie uma regra .menu a:focus-visible com outline: 3px solid e uma cor que contraste com o fundo (por exemplo, navy), com outline-offset: 2px. Teste com o Tab.

<link rel="stylesheet" href="style.css">
<nav class="menu">
  <a href="index.html">Início</a>
  <a href="receitas.html">Receitas</a>
  <a href="contato.html">Contato</a>
</nav>

.menu a {
  display: inline-block;
  padding: 12px;
  color: navy;
}

.menu a:focus {
  outline: none;
}

.menu a {
  display: inline-block;
  padding: 12px;
  color: navy;
}

.menu a:focus-visible {
  outline: 3px solid navy;
  outline-offset: 2px;
}

3. Tamanho de toque: dedos não são setinhas

A ponta do dedo é bem maior que a ponta da seta do mouse. Um link minúsculo, colado no vizinho, faz o leitor tocar no errado. As regras:

FonteTamanho
WCAG 2.2, critério 2.5.8 (nível AA, o mínimo)Pelo menos 24 × 24 px de área de toque (ou espaço livre suficiente em volta)
WCAG 2.2, critério 2.5.5 (nível AAA, o recomendado)44 × 44 px

Não é preciso aumentar a letra: basta aumentar a área clicável com padding (aula Espaço Interno), ou com min-height/min-width:

<style>
  nav a {
    font-family: sans-serif;
    color: navy;
  }
  .pequeno a {
    margin-right: 4px;
  }
  .grande a {
    display: inline-flex;
    align-items: center;
    justify-content: center;
    min-width: 44px;
    min-height: 44px;
    background-color: #eef;
  }
</style>
<p>Área de toque só do texto:</p>
<nav class="pequeno"><a href="#a">1</a><a href="#b">2</a><a href="#c">3</a></nav>
<p>Com min-width e min-height de 44px (o fundo mostra a área):</p>
<nav class="grande"><a href="#a">1</a> <a href="#b">2</a> <a href="#c">3</a></nav>

No Chromium, cada link da primeira linha tem só o tamanho do número: menos de 10 px de largura. Na segunda, cada um tem 44 × 44 px, com o fundo claro mostrando onde o toque vale.

4. As preferências do sistema: prefers-*

Os sistemas operacionais têm opções de acessibilidade, e o CSS consegue lê-las com media queries (aula Media Queries). Cada uma tem a sua aula ou exemplo:

ConsultaVerdade quando a pessoa…O que fazer
(prefers-reduced-motion: reduce)pediu menos movimentoDesligar animações grandes e a rolagem suave (aulas Menos Movimento e Rolagem Suave)
(prefers-color-scheme: dark)usa o tema escuroOferecer cores escuras, mantendo o contraste (aula Tema Escuro)
(prefers-contrast: more)pediu mais contrasteEscurecer os cinzas, engrossar bordas, tirar transparências
(forced-colors: active)usa um modo de cores forçadas (o "alto contraste" do Windows)Quase nada: o sistema troca as cores sozinho. Não esconda bordas e contornos, que viram as únicas divisas
.dica {
  color: #767676;
  border: 1px solid #ddd;
}

@media (prefers-contrast: more) {
  .dica {
    color: #333333;
    border-color: #333333;
  }
}

As quatro consultas funcionam nos navegadores principais. Pela tabela do MDN, a mais recente no Safari é a forced-colors (Safari 16), e no Firefox, a prefers-contrast (Firefox 101). Num navegador que não as conhece, o bloco é ignorado e a página fica com as regras normais.

5. Texto só para leitores de tela: .sr-only

Às vezes um botão tem só um ícone, como um "✕" para fechar. Quem enxerga entende; o leitor de tela anuncia só "botão", sem dizer o quê. A solução é pôr um texto de verdade no HTML e escondê-lo só dos olhos, deixando-o para o leitor de tela. É para isso que existe esta classe, conhecida como .sr-only (screen reader only, "só para leitor de tela") ou .visually-hidden ("escondido visualmente"):

.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
position: absolute
Tira o texto do fluxo da página: ele não empurra mais nada nem ocupa espaço (aula position: absolute).
width: 1px; height: 1px
Encolhe a caixa a um pontinho. Não usamos 0, porque alguns leitores de tela ignoram elementos de tamanho zero.
padding: 0; margin: -1px; border: 0
Nada de espaço interno nem borda que aumente a caixa; a margem negativa esconde o pontinho que sobra.
overflow: hidden
O texto, que não cabe em 1 px, fica cortado (aula overflow).
clip-path: inset(50%)
Recorta a caixa de fora para dentro até o meio: não sobra nada visível (aula Recortes).
white-space: nowrap
O texto não quebra em várias linhas dentro da caixa minúscula; alguns leitores de tela juntariam as palavras quebradas.

O resultado: o texto existe para o navegador, mas não aparece. Na árvore de acessibilidade do Chromium, o botão abaixo ficou com o nome "Fechar a janela". Com display: none no lugar do .sr-only, o botão ficou sem nome; com visibility: hidden, ficou com um nome feito só de espaços, o que dá no mesmo: essas duas formas escondem dos olhos e do leitor de tela (aula Escondendo).

Experimente: o botão mostra só o "✕", mas tem um texto escondido. Tire o class="sr-only" do <span> e veja o texto aparecer ao lado do ✕.

<link rel="stylesheet" href="style.css">
<button class="fechar">
  <span aria-hidden="true">✕</span>
  <span class="sr-only">Fechar a janela</span>
</button>

.fechar {
  min-width: 44px;
  min-height: 44px;
  font-size: 1.25rem;
}

.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

O aria-hidden="true" no "✕" é HTML: ele tira o símbolo da leitura, para o leitor de tela não anunciar "multiplicação, Fechar a janela". Outros usos comuns do .sr-only: um título para uma seção que visualmente não precisa de título, e o aviso "(abre em nova aba)" dentro de um link.

E o link "pular para o conteúdo"?

Uma variação útil é o texto que fica escondido e aparece quando recebe o foco: o link "Pular para o conteúdo", o primeiro do Tab, que leva direto ao <main>. Com .sr-only e uma regra :focus que desfaz o esconderijo (position: static, width: auto, height: auto, clip-path: none…), quem usa o teclado não precisa passar pelo menu inteiro em toda página.

6. Resumo das regras: o que fazer e o que evitar

FaçaEvite
Texto com contraste de pelo menos 4,5 : 1 (meça)Cinza-claro no branco; branco no tomato
:focus-visible com um contorno clarooutline: none sem colocar nada no lugar
Áreas de toque de 44 × 44 px (pelo menos 24 × 24)Links pequenos e colados
Respeitar prefers-reduced-motion e as outras preferênciasAnimações grandes sem como desligar
.sr-only para texto só para leitores de teladisplay: none no texto que o leitor de tela precisa ler
Fontes em rem, alturas flexíveisCaixas de altura fixa que cortam o texto aumentado

Quando dá errado

outline: none: o teclado fica cego, e ninguém avisa 
*:focus {
  outline: none;
}

O que o leitor vê: com o mouse, nada muda. Com o teclado, o Tab continua andando de link em link, mas não há nenhum sinal de onde está o foco: um Enter pode abrir qualquer coisa. Experimente o segundo botão da seção 2.

Por quê: é CSS válido, então o validador fica em silêncio e o F12 não risca nada. Mas fere o critério 2.4.7 das WCAG ("Foco visível").

Como consertar: apague a regra. Se o contorno padrão não combina com o site, troque por um seu, em :focus-visible, nunca por nada.

display: none no texto do botão: o leitor de tela anuncia só "botão" 
<button>
  <span aria-hidden="true">✕</span>
  <span style="display: none">Fechar a janela</span>
</button>

O que o leitor vê: na tela, o mesmo botão com o ✕. O que o leitor de tela anuncia: só "botão". Na árvore de acessibilidade do Chromium, o botão ficou sem nome.

Por quê: display: none (e visibility: hidden) tiram o elemento da página para todos, inclusive para o leitor de tela. Nenhum validador acusa.

Como consertar: a classe .sr-only no lugar do display: none.

Um espaço no valor: outline-offset: 2 px 
.botao:focus-visible {
  outline: 3px solid navy;
  outline-offset: 2 px;
}

$ vnu --css estilo.css
"file:/home/ana/site/estilo.css":3.21-3.22: error: CSS: “outline-offset”: Too many values or values are not recognized.

O que significa: "outline-offset: valores demais, ou valores não reconhecidos". Com o espaço, 2 px vira duas coisas: o número 2 sem unidade e uma palavra px solta (a coluna 21 a 22 da linha 3).

O que o leitor vê: o contorno aparece, mas colado no botão: o navegador ignorou só a declaração do outline-offset. O número e a unidade andam sempre juntos: 2px.

Resumo

  • Contraste: pelo menos 4,5 : 1 para texto comum, 3 : 1 para texto grande, bordas e foco. Meça (o F12 mostra); o validador não mede. Branco no tomato não passa.
  • Foco: nunca outline: none sem substituto. Use :focus-visible com um contorno grosso e outline-offset.
  • Toque: áreas de 44 × 44 px (mínimo de 24 × 24), com padding ou min-height.
  • Preferências: prefers-reduced-motion, prefers-color-scheme, prefers-contrast e forced-colors deixam o site seguir o que a pessoa escolheu no sistema.
  • Texto escondido: .sr-only esconde dos olhos e mantém para o leitor de tela; display: none e visibility: hidden escondem de todos.
