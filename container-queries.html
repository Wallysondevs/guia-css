CSS Container Queries

Com media queries, o CSS pergunta "qual é a largura da tela?". Mas um cartão de receita pode aparecer na coluna larga do meio da página e na coluna estreita do lado, na mesma tela. Para ele, a pergunta certa é outra: "quanto espaço eu tenho aqui?". É isso que as container queries ("consultas ao contêiner") fazem: o componente se adapta ao lugar onde foi posto.

Você vai aprender
  • Por que a media query não resolve o cartão que aparece em dois lugares.
  • container-type: inline-size: como transformar um elemento num contêiner.
  • @container (min-width: 400px) { … }: a regra que pergunta a largura do contêiner.
  • Dar nome ao contêiner (container-name e o atalho container).
  • As unidades do contêiner (cqi).
  • Os erros mais comuns, e por que o validador W3C do laboratório reclama de um CSS que funciona.
Suporte dos navegadores

As container queries de tamanho (as desta aula) funcionam no Chrome, Edge, Firefox e Safari desde fevereiro de 2023 (Chrome 105, Safari 16, Firefox 110). O MDN as marca como "Baseline: amplamente disponível". Navegadores mais antigos ignoram a regra @container inteira: escreva o CSS de fora dela de um jeito que funcione sozinho (o cartão em coluna, por exemplo).

A ideia: o móvel e o cômodo

Pense numa mesa dobrável. Quem decide se ela fica aberta ou fechada não é o tamanho da casa, é o tamanho do cômodo onde ela está. Na sala grande, ela abre; no corredor, fica dobrada. A mesma mesa, na mesma casa, de dois jeitos.

Na casaNo CSS
A casaA tela (a janela do navegador): é o que a media query mede
O cômodoO contêiner: o elemento onde o componente está (uma coluna, uma barra lateral)
A mesa dobrávelO componente (um cartão) que muda conforme o contêiner: a container query

1. O problema: o mesmo cartão em dois lugares

A página da Ana tem uma coluna principal larga e uma barra lateral de 200 pixels, lado a lado (com Flexbox). O mesmo cartão de receita aparece nas duas. O quadro está em 768 pixels, a largura de um tablet (os botões 375, 768 e cheia, na barra do quadro, mudam a largura da janela que a página enxerga). Primeiro, com uma media query:

Clique em 375: a tela fica estreita e o cartão principal também volta para uma coluna, mesmo tendo espaço. A media query não sabe onde cada cartão está.

2. A solução: container-type e @container

São dois passos: (1) dizer quem é o contêiner; (2) escrever a regra que pergunta a largura dele.

.principal,
.lateral {
  container-type: inline-size;
}

@container (min-width: 400px) {
  .cartao {
    display: flex;
    gap: 12px;
  }
}
container-type
"Tipo de contêiner". Transforma o elemento num contêiner que pode ser consultado.
inline-size
"Tamanho na linha": a largura (no português, que escreve da esquerda para a direita). É o valor de quase sempre: o contêiner passa a responder pela largura dele.
@container
A regra de consulta, como o @media. O que está dentro das chaves só vale quando a condição for verdadeira.
(min-width: 400px)
A condição: "o contêiner tem pelo menos 400 pixels de largura". Também pode ser max-width.
.cartao { … }
As regras de dentro valem para os elementos que estão dentro de um contêiner que cumpre a condição. Cada cartão olha o contêiner mais próximo dele.

3. Dando nome ao contêiner

Sem nome, cada elemento consulta o contêiner mais próximo acima dele. Quando há contêineres dentro de contêineres e você quer perguntar a um específico, dê um nome com container-name e use o nome na consulta:

.lateral {
  container-type: inline-size;
  container-name: lateral;
}

@container lateral (max-width: 250px) {
  .cartao h2 {
    font-size: 1rem;
  }
}

O atalho container junta os dois: primeiro o nome, depois uma barra, depois o tipo.

.lateral {
  container: lateral / inline-size;
}
lateral
O nome, inventado por você (letras, números e hífen). Não é uma classe: não tem ponto.
/
Separa o nome do tipo.
inline-size
O tipo, como em container-type.

Outras formas de escrever a condição

EscritaVerdade quando o contêiner…
(min-width: 400px)tem 400px ou mais
(max-width: 399px)tem até 399px
(width >= 400px)tem 400px ou mais (a escrita "de intervalo", com sinais de comparação)
(300px <= width <= 600px)tem entre 300 e 600px
(min-width: 25rem)tem 25rem ou mais (unidades relativas também valem)

4. As unidades do contêiner: cqi

Assim como vw é 1% da largura da janela, cqi (container query inline) é 1% da largura do contêiner. Com ela, um tamanho acompanha o espaço do componente. Junte com o clamp() para ter limites:

<link rel="stylesheet" href="style.css">
<div class="pagina">
  <main class="principal">
    <h2>Bolo de cenoura</h2>
  </main>
  <aside class="lateral">
    <h2>Bolo de cenoura</h2>
  </aside>
</div>

.pagina {
  display: flex;
  gap: 16px;
}

.principal {
  flex: 1;
  container-type: inline-size;
  background-color: oldlace;
}

.lateral {
  width: 200px;
  container-type: inline-size;
  background-color: lavender;
}

h2 {
  font-size: clamp(1rem, 5cqi, 2rem);
}

O mesmo título, com a mesma regra, fica com tamanhos diferentes: na coluna principal (536 pixels), 5cqi = 26.8px; na lateral (200 pixels), 5cqi = 10px, e o clamp() segura em 16px (valores conferidos no Chromium).

Unidade1 unidade é…
cqi1% da largura do contêiner (a mais usada)
cqw1% da largura do contêiner (igual a cqi em português)
cqb, cqh1% da altura do contêiner (só com container-type: size)

5. Media query ou container query?

Uma não substitui a outra. As duas convivem no mesmo CSS:

PerguntaUseExemplo
Como fica a página numa tela estreita?@mediaO layout geral (uma coluna no celular, duas no computador), o menu, o tamanho da letra base
Como fica este componente no espaço que ele ganhou?@containerCartões, listas de produtos, widgets que aparecem em vários lugares
A pessoa prefere tema escuro, menos movimento, vai imprimir?@mediaprefers-color-scheme, prefers-reduced-motion, print: a container query só mede tamanho
Existe também a consulta de estilo

Além do tamanho, o @container pode perguntar o valor de uma variável do contêiner: @container style(--tema: escuro) { … }. Ela é mais nova e o suporte ainda é parcial: em outubro de 2026, o caniuse marca o Chrome, o Edge (desde o 111) e o Safari (desde o 18) com suporte parcial, só para variáveis, e o Firefox com suporte completo desde o 151. Para começar, fique com as consultas de tamanho.

Quando dá errado

Esqueceu o container-type: a regra nunca vale 
.principal {
  flex: 1;
}

@container (min-width: 400px) {
  .cartao {
    display: flex;
  }
}

O que você vê: os dois cartões ficam em coluna, em qualquer largura do quadro (conferido no Chromium: display: block nos dois).

Por quê: ninguém foi declarado contêiner. Um @container sem contêiner acima do elemento simplesmente não se aplica, sem nenhum aviso. Diferente da media query, que sempre tem a tela para medir, a container query precisa que você diga quem é medido.

Como consertar: container-type: inline-size; no elemento pai (ou num ancestral) do cartão.

Estilizar o próprio contêiner dentro da consulta dele 
.principal {
  container-type: inline-size;
}

@container (min-width: 400px) {
  .principal {
    background-color: lightyellow;
  }
}

O que você vê: o fundo da .principal não muda, mesmo com 536 pixels (o fundo calculado continua transparente, rgba(0, 0, 0, 0)).

Por quê: a consulta só vale para o que está dentro do contêiner. Se o contêiner pudesse mudar a si mesmo pela própria largura, poderia entrar num ciclo sem fim (muda a largura, a regra deixa de valer, volta a largura…).

Como consertar: estilize os filhos, ou crie um elemento por dentro (um div que envolve o conteúdo) e mude o fundo dele.

container-type: size: o contêiner perde a altura 
.principal,
.lateral {
  container-type: size;
}

O que você vê: os cartões continuam no lugar, mas o rodapé que vem depois deles ("Lojinha da Ana · Rua das Flores, 12") sobe e fica em cima do primeiro cartão. A altura da .principal calculada é 0px.

Por quê: com size, o contêiner pode ser consultado pela largura e pela altura. Para isso, o navegador deixa de calcular a altura pelo conteúdo, e um contêiner sem height fica com altura zero; o conteúdo transborda.

Como consertar: use inline-size, que é o que você quer em quase todos os casos. size só com uma altura definida.

O validador do laboratório reclama de CSS correto

Digitou errado: o navegador ignora em silêncio 
.principal {
  container-type: inline;
}

@container (min-width: 400) {
  .cartao {
    display: flex;
  }
}

O que você vê: nada muda, os cartões ficam em coluna.

Por quê: inline não é um valor de container-type (é inline-size), então a declaração é ignorada e não há contêiner. E 400 sem unidade não é uma largura: a condição nunca é verdadeira. No F12, a declaração errada aparece riscada. Como o validador do laboratório não conhece @container, aqui ele não ajuda: confira os nomes com calma.

Resumo

  • Media query mede a tela; container query mede o contêiner, o espaço onde o componente está. O mesmo cartão pode ficar de dois jeitos na mesma tela.
  • Dois passos: container-type: inline-size no pai, e @container (min-width: 400px) { … } com as regras dos filhos.
  • Sem container-type num ancestral, o @container não vale, em silêncio. E a consulta não muda o próprio contêiner, só o que está dentro.
  • container-name (ou o atalho container: nome / inline-size) escolhe qual contêiner consultar: @container nome (…).
  • cqi é 1% da largura do contêiner; combina bem com clamp().
  • Use inline-size; size zera a altura de um contêiner sem height.
  • Funciona nos navegadores desde 2023, mas o validador vnu 26.10.12 ainda acusa @container e container-type como erro: é um erro falso.
