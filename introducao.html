CSS Introdução

Você já sabe escrever uma página em HTML: títulos, parágrafos, listas, links, imagens. Mas ela sai com cara de documento de 1995: letra preta de jornal, fundo branco, tudo encostado na esquerda. Quem dá cor, letra bonita, espaço e organização a essa página é o CSS. Nesta aula você vai ver o que é o CSS, o que ele faz (e o que não faz) e a mesma página da Ana antes e depois de ganhar uma folha de estilo.

Você vai aprender
  • O que é o CSS e por que ele existe separado do HTML.
  • A mesma página sem CSS e com CSS, desenhada ao vivo pelo seu navegador.
  • O que quer dizer Cascading Style Sheets, palavra por palavra.
  • A cara de uma regra de CSS (só uma olhada; os detalhes vêm nas próximas aulas).
  • O que o CSS faz, o que ele não faz e de onde ele veio.
  • O que acontece quando você erra: no CSS, quase nunca aparece mensagem de erro.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código. As mensagens de erro são do validador W3C (vnu), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a casa e a decoração

Pense numa casa. Primeiro vêm as paredes, as portas, os cômodos: aqui é a cozinha, ali o quarto. Depois vem a decoração: a cor da tinta, o piso, as cortinas, onde fica cada móvel. Você pode pintar a casa inteira de outra cor sem derrubar uma parede.

Uma página da web funciona igual:

Na casaNa páginaQuem cuida
Paredes e cômodos: "isto é a cozinha"A estrutura: "isto é um título", "isto é uma lista"HTML
Tinta, piso, cortinas, posição dos móveisA aparência: cores, letras, espaços, colunasCSS
A campainha, a luz que acende sozinhaO comportamento: o que acontece num cliqueJavaScript

O CSS é a linguagem da decoração. Ele não cria o título nem o parágrafo; ele diz como o título e o parágrafo que já existem no HTML devem aparecer. A próxima aula, HTML e CSS: Estrutura e Aparência, aprofunda essa divisão.

1. A mesma página, sem CSS

Esta é a página de receitas da Ana, só com HTML:

<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>
<h2>Bolo de cenoura</h2>
<p>Fofinho, com cobertura de chocolate. Fica pronto em 50 minutos.</p>
<h2>Pão de queijo</h2>
<p>Crocante por fora, macio por dentro. Rende 30 unidades.</p>

Repare no resultado: letra preta sobre fundo branco, com serifa (aqueles "pezinhos" nas pontas das letras, como em jornal impresso), tudo alinhado à esquerda. O título é grande e em negrito, os subtítulos um pouco menores.

Mesmo sem uma linha de CSS, a página já tem alguma aparência. Quem decidiu isso foi o navegador: ele traz uma folha de estilo própria, com o visual padrão de cada elemento (o <h1> grande e em negrito, o link azul e sublinhado). O seu CSS vem por cima dessa folha e muda o que você quiser.

2. A mesma página, com CSS

Agora o mesmo HTML, com uma linha a mais no começo (o <link>, que chama o arquivo de estilo) e um segundo arquivo, o style.css. Clique nas abas para ver cada arquivo:

Experimente: o resultado embaixo já tem o CSS aplicado. Na aba style.css, troque firebrick por navy e veja o título mudar de cor. Depois troque center por right.

<link rel="stylesheet" href="style.css">
<h1>Receitas da Ana</h1>
<p>Receitas simples, testadas na minha cozinha.</p>
<h2>Bolo de cenoura</h2>
<p>Fofinho, com cobertura de chocolate. Fica pronto em 50 minutos.</p>
<h2>Pão de queijo</h2>
<p>Crocante por fora, macio por dentro. Rende 30 unidades.</p>

body {
  font-family: sans-serif;
  background-color: linen;
}

h1 {
  color: firebrick;
  text-align: center;
}

h2 {
  color: darkgreen;
  border-bottom: 2px solid darkgreen;
}

O HTML é o mesmo, palavra por palavra. Só o CSS mudou a página:

  • o fundo ficou bege-claro (linen, "linho");
  • a letra perdeu os "pezinhos": virou uma letra sem serifa (sans-serif), mais limpa na tela;
  • o título ficou vermelho-escuro (firebrick, "tijolo refratário") e centralizado;
  • os subtítulos ficaram verdes, com uma linha verde embaixo.

Doze linhas de CSS e a página mudou de cara. Imagine agora um site com 50 páginas: todas chamam o mesmo style.css. Trocar a cor dos títulos do site inteiro é mudar uma palavra num arquivo. Essa é a grande vantagem do CSS.

3. O nome: Cascading Style Sheets

CSS é a sigla de Cascading Style Sheets, "folhas de estilo em cascata". Cada palavra tem um motivo:

Style
Estilo: a aparência. Cor, tamanho da letra, espaço, posição.
Sheets
Folhas: um arquivo de CSS é uma "folha de estilo", uma lista de regras, como a folha de instruções que um decorador recebe ("paredes da sala: bege; cortinas: verdes").
Cascading
Em cascata: várias regras podem falar do mesmo elemento ao mesmo tempo (a folha do navegador, a sua, uma regra geral e uma mais específica). A cascata é o jeito de decidir quem vence, como a água que desce de degrau em degrau. É uma das ideias mais importantes do CSS e tem aula própria: A Cascata: Quem Vence.

4. Uma olhada numa regra

Todo CSS é feito de regras. Esta é a regra que pintou o título:

h1 {
  color: firebrick;
}
h1
O seletor: quem recebe o estilo. Aqui, todo <h1> da página.
{ }
As chaves guardam as instruções para esse seletor.
color
A propriedade: o que mudar. color = "cor" (do texto).
firebrick
O valor: como fica. Um dos nomes de cor que o CSS conhece.
: e ;
Os dois-pontos separam a propriedade do valor; o ponto e vírgula fecha a instrução.

Em português: "todo h1, cor do texto: tijolo". Por enquanto basta reconhecer as partes. A aula Regras, Seletores e Declarações destrincha cada uma e mostra o que acontece quando falta um sinal.

Quase tudo o que você vê num site moderno, além do texto e das imagens, é CSS. Uma amostra do que você vai aprender neste guia:

E o que ele não faz

  • Não cria conteúdo de verdade. O texto, os links e as imagens importantes ficam no HTML. Se o CSS sumir, a página tem de continuar fazendo sentido (sem cor, mas com tudo lá).
  • Não reage como um programa. "Quando clicar, guarde o pedido e mostre o total" é JavaScript. O CSS reage a poucas coisas prontas, como o mouse em cima ou a largura da tela.
  • Não conserta HTML errado. Um título feito com <p> continua sendo um parágrafo para o leitor de tela e para o Google, mesmo que o CSS o deixe grande.

6. De onde veio o CSS

No começo da web, o HTML fazia tudo, inclusive a aparência, com elementos como <font color="red">. Cada página repetia a cor em cada linha, e mudar o visual de um site era refazer tudo. O CSS nasceu para separar as duas coisas.

QuandoO que aconteceu
1994Håkon Wium Lie propõe as "folhas de estilo em cascata"; Bert Bos se junta ao trabalho.
1996CSS 1 vira recomendação do W3C (o consórcio que cuida dos padrões da web): cores, fontes, margens.
1998CSS 2: posicionamento, tipos de mídia (tela, impressão). A revisão CSS 2.1 sai em 2011.
Depois de 2.1O CSS é dividido em módulos (cores, seletores, Flexbox, Grid…), cada um com o seu ritmo. O apelido "CSS3" vem daí; não existe um "CSS 4" único.
HojeOs navegadores ganham recursos novos todo ano: variáveis, aninhamento, :has(), container queries. Este guia ensina o CSS de hoje e avisa quando algo é recente.

7. Do que você precisa

De nada além do que você já usou no HTML:

  • um editor de texto (o arquivo .css é texto puro, como o .html);
  • um navegador, que lê o CSS e desenha a página.

Neste guia, você nem precisa sair da página: as caixas "Experimente" têm as abas index.html e style.css e desenham o resultado enquanto você digita. A aula O Editor do Guia mostra cada botão.

Quando dá errado

No HTML, o navegador conserta muito erro sozinho. No CSS é ainda mais silencioso: quando o navegador não entende uma instrução, ele simplesmente a ignora e segue para a próxima. Não aparece mensagem na tela. O sintoma é sempre o mesmo: nada muda.

Nome da propriedade errado: Property “colr” doesn't exist 
<style>
  h1 {
    colr: firebrick;
  }
</style>
<h1>Receitas da Ana</h1>

O que você vê: o título continua preto, como se não houvesse CSS nenhum. Faltou um o: a propriedade é color, não colr. O navegador não conhece colr, então pula essa linha sem avisar.

O <style> deste exemplo é um jeito de pôr o CSS dentro do próprio HTML; a aula Três Jeitos de Usar CSS explica quando usar cada jeito. Com o CSS num arquivo separado, o validador W3C aponta o erro:

$ vnu --css erro.css
"file:/home/ana/site/erro.css":2.9-2.14: error: CSS: “colr”: Property “colr” doesn't exist.

O que significa: "a propriedade colr não existe", na linha 2, colunas 9 a 14 do arquivo.

Como consertar: color: firebrick;. Na dúvida sobre o nome de uma propriedade, consulte a referência de propriedades.

Valor que não existe: “tomate” is not a “color” value 
<style>
  h1 {
    color: tomate;
  }
</style>
<h1>Receitas da Ana</h1>

O que você vê: de novo, o título preto. Os nomes de cor do CSS são em inglês: a cor é tomato, e tomate não quer dizer nada para o navegador.

$ vnu --css valor.css
"file:/home/ana/site/valor.css":2.10-2.15: error: CSS: “color”: “tomate” is not a “color” value.

O que significa: "tomate não é um valor de color". A propriedade está certa; o valor, não.

Como consertar: color: tomato;. A lista dos nomes está em Nomes de Cores.

Para achar esses erros sem o validador, o navegador tem uma ferramenta que mostra cada instrução ignorada: a aula Inspecionando com o F12 ensina a usá-la.

Resumo

  • O HTML diz o que cada coisa é (estrutura); o CSS diz como ela aparece (aparência).
  • CSS = Cascading Style Sheets, folhas de estilo em cascata: listas de regras, com um jeito de decidir quem vence quando duas falam do mesmo elemento.
  • Uma regra tem seletor (h1), propriedade (color) e valor (firebrick): h1 { color: firebrick; }.
  • Sem CSS, vale a folha de estilo do próprio navegador. O seu CSS vem por cima.
  • Um único style.css pode vestir o site inteiro: mudar uma palavra muda todas as páginas.
  • CSS errado não dá mensagem na tela: o navegador ignora a instrução e nada muda. O validador (vnu --css) e o F12 mostram onde está o erro.
