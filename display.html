CSS display

Por que um <p> sempre começa numa linha nova e um <strong> fica no meio da frase? Por que o width funciona numa <div> e não num <span>? A resposta é uma só propriedade: display ("exibição"), que diz como a caixa de um elemento se encaixa na página. Nesta aula você vai conhecer os três valores básicos, block, inline e inline-block, e trocar um pelo outro quando o padrão do HTML não serve.

Você vai aprender
  • O que é uma caixa de bloco (block) e uma caixa em linha (inline).
  • O que funciona e o que é ignorado em cada uma: width, height, margin, padding.
  • inline-block: no meio da linha, mas com tamanho.
  • Quais elementos são de cada tipo e quando vale mudar.
  • Os outros valores de display e as aulas de cada um.
  • Os erros: o width que não pega, a margem de cima ignorada, o espaço misterioso entre caixas e o validador.

Os resultados são desenhados pelo seu navegador. A diferença entre elementos de bloco e em linha já apareceu do lado do HTML, na aula Bloco × Em Linha do Guia HTML; aqui você vai controlá-la pelo CSS.

A ideia: tijolos e palavras

Pense numa página como uma parede de tijolos e, nos tijolos, frases escritas.

  • Um bloco é um tijolo inteiro: ocupa a fileira toda, de ponta a ponta, e o próximo tijolo vai para a fileira de baixo. Dá para escolher a largura e a altura dele.
  • Um elemento em linha é uma palavra dentro da frase: fica ao lado das outras e, se a linha acaba, continua na próxima. Uma palavra não tem "altura" própria: ela tem o tamanho do texto.
  • Um inline-block é um adesivo colado no meio da frase: anda junto com o texto, mas tem o seu próprio tamanho.

1. Os três lado a lado

As três caixas abaixo têm o mesmo CSS: largura de 120px, altura de 40px, margem de 10px, padding de 6px e borda. Só o display muda:

<style>
  .caixa {
    background-color: #fde8e1;
    border: 2px solid tomato;
    width: 120px;
    height: 40px;
    margin: 10px;
    padding: 6px;
  }
  .bloco  { display: block; }
  .linha  { display: inline; }
  .misto  { display: inline-block; }
</style>
<p>Texto antes <span class="caixa bloco">block</span> texto depois.</p>
<p>Texto antes <span class="caixa linha">inline</span> texto depois, numa frase comprida que continua na linha de baixo para você ver o padding.</p>
<p>Texto antes <span class="caixa misto">inline-block</span> texto depois.</p>

Repare em cada uma:

  • block: a caixa quebra a frase em três. "Texto antes" fica numa linha, a caixa em outra, "texto depois" em outra. A largura e a altura valem, e a margem afasta a caixa em todos os lados.
  • inline: a caixa fica no meio da frase, do tamanho do texto. O width e o height são ignorados. A margem dos lados afasta o texto vizinho, mas a de cima e a de baixo não. O padding de cima e de baixo aparece (o fundo e a borda crescem), mas não empurra as linhas vizinhas: a borda passa por cima da linha de baixo.
  • inline-block: a caixa fica no meio da frase, mas com 120×40 e com as margens em todos os lados. A linha fica mais alta para caber a caixa.

2. O padrão de cada elemento

Todo elemento já vem com um display, dado pelo navegador:

display padrãoElementos
blockdiv, p, h1…h6, ul, ol, header, nav, main, section, article, footer, form, blockquote
inlinespan, a, strong, em, code, label, img
inline-blockbutton, input, select, textarea
list-itemli (um bloco com marcador; aula Listas)
table, table-row, table-celltable, tr, td/th

O <img> é um caso especial: é inline, mas aceita width e height, porque o tamanho vem da própria imagem (é um elemento "substituído"). Em outras palavras, ele se comporta como um inline-block.

Para ver o display de qualquer elemento, abra o F12, escolha o elemento na aba Elements (Elementos) e procure display na aba Computed (aula Inspecionando com o F12).

CSS muda a aparência, não o HTML

Um <span> com display: block continua sendo um <span>: as regras do HTML continuam valendo. Um <div> dentro de um <span> continua inválido no validador, mesmo que o CSS transforme os dois em blocos. Escolha o elemento pelo significado e o display pela aparência.

3. Quando mudar: block num link

Num menu vertical, a Ana quer que a área clicável de cada link vá de ponta a ponta, não só em cima das letras. O <a> é inline: só a palavra é clicável, e o padding de cima e de baixo não empurra nada. Com display: block, o link vira um tijolo da largura toda:

Missão: passe o mouse nos links: o fundo só aparece atrás das letras, e o padding de cima e de baixo invade os links vizinhos. Faça os links ocuparem a largura toda do menu, cada um com o seu espaço.

<link rel="stylesheet" href="style.css">
<ul class="menu">
  <li><a href="index.html">Início</a></li>
  <li><a href="receitas.html">Receitas</a></li>
  <li><a href="sobre.html">Sobre</a></li>
</ul>

.menu {
  list-style: none;
  padding: 0;
  width: 200px;
  border: 1px solid navy;
}

.menu a {
  padding: 10px;
  background-color: #e8ecff;
}

.menu {
  list-style: none;
  padding: 0;
  width: 200px;
  border: 1px solid navy;
}

.menu a {
  display: block;
  padding: 10px;
  background-color: #e8ecff;
}

Com block, cada link ganha a largura dos 200px do menu, o padding empurra os vizinhos e o clique funciona em toda a faixa, o que ajuda no celular, onde o dedo é menos preciso que o mouse.

4. Quando mudar: inline-block num botão e num menu

O inline-block serve para coisas que ficam uma ao lado da outra, mas precisam de tamanho e espaço: um link com cara de botão, etiquetas, itens de um menu horizontal.

Experimente: troque o inline-block do .botao por inline e veja o fundo do botão encostar no parágrafo de cima: o padding continua desenhado, mas não empurra mais nada. Depois troque o dos li por block: o menu volta a ficar em pé.

<ul class="menu">

  <li><a href="receitas.html">Receitas</a></li>

</ul>

Menu na horizontal: o jeito moderno

Pôr os li em inline-block foi o jeito clássico de fazer menus horizontais, e ainda funciona. Hoje o mais usado é display: flex no <ul>, que alinha e distribui os itens com muito mais controle e sem o espaço extra da seção Quando dá errado. Ele tem um capítulo inteiro, a partir da aula Introdução ao Flexbox.

5. Os outros valores

O display tem mais valores. Cada um é assunto de outra aula:

ValorO que fazAula
noneSome com o elemento, como se ele não existisseEscondendo
flex / inline-flexArruma os filhos numa linha ou colunaFlexbox
grid / inline-gridArruma os filhos numa grade de linhas e colunasGrid
list-itemBloco com marcador de listaListas
table, table-cell…O comportamento das tabelasTabelas

Repare no par flex e inline-flex: o display decide duas coisas. Uma é como a caixa se encaixa lá fora, entre os vizinhos (bloco ou em linha). A outra é como ela arruma os filhos de dentro (texto normal, flex ou grid). O inline-flex é "em linha por fora, flex por dentro".

Quando dá errado

O width não funciona no <span> 
<style>
  .selo {
    width: 200px;
    height: 60px;
    background-color: gold;
  }
</style>
<p>Bolo de cenoura <span class="selo">Novo!</span></p>

O que você vê: o fundo dourado só cobre a palavra "Novo!". Nada de 200×60.

Por quê: o <span> é inline, e uma caixa em linha tem o tamanho do texto: width e height não se aplicam a ela. O validador não reclama: as declarações são válidas, só não valem para esse tipo de caixa. No F12, o Chrome costuma mostrar a declaração esmaecida no painel Styles, com um ícone de informação que explica que ela não tem efeito por causa do display.

Como consertar: display: inline-block (continua no meio da frase) ou display: block (vai para uma linha só dele).

A margem de cima não afasta o link 
<style>
  .voltar {
    margin-top: 40px;
  }
</style>
<p>Fim da receita.</p>
<a class="voltar" href="index.html">Voltar ao início</a>

O que você vê: o link fica logo abaixo do parágrafo, sem os 40px.

Por quê: o <a> é inline, e a margem de cima e de baixo de uma caixa em linha não empurra nada.

Como consertar: display: inline-block ou block no link; ou ponha a margem num bloco em volta dele (um <p>).

Duas caixas de 50% não cabem lado a lado 
<style>
  .metade {
    display: inline-block;
    width: 50%;
    background-color: #e8ecff;
  }
  .outra { background-color: #fde8e1; }
</style>
<div class="metade">Ingredientes</div>
<div class="metade outra">Modo de preparo</div>

O que você vê: a segunda caixa cai para a linha de baixo, mesmo que 50% + 50% dê 100%.

Por quê: caixas inline-block se comportam como palavras, e a quebra de linha entre as duas <div> no HTML vira um espaço entre elas, como o espaço entre duas palavras. 50% + um espaço + 50% passa de 100%.

Como consertar: para colunas lado a lado, use display: flex no pai (aula Flexbox): ele não tem esse espaço. Truques antigos, como colar as tags sem espaço no HTML, funcionam, mas deixam o código difícil de ler.

Dois valores que não combinam: inline block 
.botao {
  display: inline block;
}

O que você vê: nada muda; o link continua inline.

$ vnu --css style.css
"file:/home/ana/site/style.css":2.19-2.23: error: CSS: “display”: “block” is not a “display” value.

O que significa: "block não é um valor de display" ali, depois de inline. O nome do valor é uma palavra só, com hífen: inline-block. Sem o hífen, o navegador ignora a declaração inteira. O mesmo acontece com display: hidden, que não existe: o validador diz “hidden” is not a “display” value (para esconder, é none; aula Escondendo).

Resumo

  • display diz como a caixa se encaixa na página. Todo elemento já tem um padrão: div, p, h1 são block; span, a, strong são inline; button e input são inline-block.
  • block: linha própria, largura toda, aceita width, height e margens.
  • inline: no meio do texto, tamanho do conteúdo; ignora width, height e as margens de cima e de baixo.
  • inline-block: no meio do texto, mas com tamanho e espaço de verdade. Bom para botões e etiquetas.
  • O display muda a aparência, não o significado nem as regras do HTML.
  • Erros: width num span e margem de cima num a são ignorados em silêncio; caixas inline-block ganham o espaço do HTML entre elas; inline block sem hífen e hidden não são valores de display.
