CSS Comentários

Um comentário é uma nota que você deixa no código para as pessoas, e não para o navegador: ele pula tudo o que está dentro. No CSS, o comentário fica entre /* e */. Nesta aula você vai escrever comentários, usá-los para organizar a folha de estilo e para "desligar" uma declaração num teste, e conhecer os três erros que fazem um comentário engolir CSS que devia funcionar.

Você vai aprender
  • A forma do comentário: /* … */, numa linha ou em várias.
  • Para que servem: explicar o porquê, dividir o arquivo em seções, desligar uma declaração para testar.
  • A diferença entre os comentários do HTML, do CSS e do JavaScript.
  • Os erros reais: // (que não é comentário no CSS), comentário dentro de comentário e comentário sem */.

O que o navegador faz em cada erro foi conferido no Chromium. As mensagens são do validador W3C (vnu --css), rodado na máquina fictícia da Ana, na pasta ~/site.

A ideia: o post-it na receita

No caderno de receitas da Ana há post-its colados: "a vó usava manteiga, não margarina", "testar com menos açúcar". Quem faz o bolo segue a receita e ignora os post-its; quem vai mexer na receita lê os post-its e entende por que ela é assim.

O navegador é quem faz o bolo: segue as regras e pula os comentários. Você (e quem mexer no seu CSS daqui a seis meses) lê os comentários.

1. A forma do comentário

/* Cor da marca da Ana */
h1 {
  color: teal;
}
/*
Abre o comentário: uma barra seguida de um asterisco, sem espaço entre eles.
Cor da marca da Ana
O texto do comentário. Pode ter qualquer coisa: acentos, sinais, código.
*/
Fecha o comentário: o asterisco e depois a barra. Tudo entre o /* e o */ é ignorado pelo navegador.

O comentário pode ficar em qualquer lugar onde caberia um espaço: numa linha própria, no fim de uma declaração, entre duas regras. E pode ocupar várias linhas:

/*
  Folha de estilo do site Receitas da Ana
  Cores: teal (títulos), dimgray (textos), honeydew (fundo)
*/

h1 {
  color: teal; /* a mesma cor do logo */
}

Nada disso aparece na página. O comentário existe só no arquivo.

2. Para que servem

Explicar o porquê

Um bom comentário diz por que o código é assim, e não o que ele faz (isso o próprio código já diz):

Comentário que não ajudaComentário que ajuda
color: dimgray; /* cor cinza */color: dimgray; /* cinza mais claro deixaria pouco contraste */
font-size: 18px; /* tamanho 18 */font-size: 18px; /* as receitas são lidas de longe, na cozinha */

Dividir o arquivo em seções

Uma folha de estilo de verdade passa fácil de 300 linhas. Comentários de seção ajudam a achar as coisas (e o Ctrl+F do editor acha o título da seção):

/* ========== Base ========== */

body {
  font-family: sans-serif;
}

/* ========== Cabeçalho ========== */

h1 {
  color: teal;
}

/* ========== Receitas ========== */

h2 {
  color: darkgreen;
}

Os sinais de = são só enfeite, para a seção saltar aos olhos. Cada equipe tem o seu estilo; o importante é usar sempre o mesmo. Organizar o CSS em vários arquivos é outra opção, para projetos maiores (aula Organizando os Arquivos de CSS).

Muitos editores de código fazem isso com um atalho: Ctrl+/ põe ou tira o comentário da linha onde está o cursor (no VS Code, por exemplo). Dá para "desligar" uma regra inteira também, com o /* antes do seletor e o */ depois da }.

3. Cada linguagem, o seu comentário

HTML, CSS e JavaScript têm comentários diferentes, e cada um só funciona na sua linguagem:

LinguagemComentárioVale no CSS?
HTML<!-- nota -->Não
CSS/* nota */Sim
JavaScript// nota (até o fim da linha) e /* nota */Só o /* */

Dentro de um <style> no HTML, vale o comentário do CSS, porque ali dentro o navegador está lendo CSS.

Comentário não é segredo

Qualquer visitante pode abrir o seu style.css (é só digitar o endereço dele, ou usar o F12) e ler os comentários. Nunca escreva neles senhas, dados de clientes ou "este cliente é chato".

Quando dá errado

// não é comentário no CSS: a regra seguinte some

Quem já viu JavaScript (ou C, ou Java) tenta usar //:

// Títulos
h1 {
  color: teal;
}

p {
  // color: dimgray;
  font-size: 18px;
}

O que você vê: o título preto. O parágrafo fica com a letra de 18px, mas preto também.

Por quê: o CSS não conhece //. Na primeira linha, o navegador junta // Títulos com o h1 e lê um seletor só, // Títulos h1, que não faz sentido; a regra inteira do h1 é jogada fora. Dentro do p, o // color: dimgray; vira uma declaração inválida e é ignorada até o ;. Por acaso, ali o // "funcionou" como comentário, só porque a linha terminava em ;. É essa sorte que engana: um // cor da marca dentro do bloco, sem ; no fim, engole a declaração da linha de baixo, e fora de um bloco ele derruba a regra inteira.

$ vnu --css barras.css
"file:/home/ana/site/barras.css":4.2-5.1: error: CSS: Parse Error.
"file:/home/ana/site/barras.css":7.13-7.19: error: CSS: Parse Error.

O que significa: dois "erros de leitura": o primeiro, no fim da regra que foi descartada (linhas 4 e 5); o segundo, na linha 7, a do // color. As posições não apontam para o // da linha 1: o validador só percebe o problema quando a regra termina.

Como consertar: /* Títulos */ e /* color: dimgray; */.

Comentário dentro de comentário: o primeiro */ fecha tudo 
h1 {
  color: teal; /* cor /* da marca */ */
  text-align: center;
}

p {
  color: dimgray;
}

O que você vê: o título verde-azulado, mas à esquerda: o text-align sumiu. O parágrafo fica cinza, normal.

Por quê: comentários não se aninham. O /* abre; o segundo /* é só texto do comentário; o primeiro */ fecha. Sobra um */ solto, que gruda na linha de baixo: o navegador lê */ text-align: center; como uma declaração só, sem sentido, e a descarta.

$ vnu --css aninhado.css
"file:/home/ana/site/aninhado.css":3.15-3.20: error: CSS: Parse Error.

O que significa: "erro de leitura" na linha 3, a do text-align, que foi engolida.

Como consertar: um comentário só: /* cor da marca */. Ao desligar com comentário um trecho que já tem comentários dentro, tire os de dentro antes (ou desligue linha por linha).

Esqueceu o */: o resto do arquivo vira comentário, e o validador não avisa 
h1 {
  color: teal;
}

/* Rascunho: testar depois
p {
  color: dimgray;
}

h2 {
  color: navy;
}

O que você vê: o título verde-azulado, mas o parágrafo e o h2 pretos, como se as regras deles não existissem. E, para o navegador, não existem mesmo: o comentário abriu na linha 5 e nunca fechou, então tudo até o fim do arquivo é comentário.

$ vnu --css aberto.css; echo "saida: $?"
saida: 0

O que o validador diz: nada (código de saída 0). Um comentário que vai até o fim do arquivo é permitido.

Como achar: se "tudo daqui para baixo" parou de funcionar, procure um /* sem par logo acima. Muitos editores pintam o comentário de outra cor (em geral, cinza ou verde): se metade do arquivo ficou dessa cor, o comentário não fechou.

Como consertar: feche o comentário: /* Rascunho: testar depois */.

Resumo

  • Comentário no CSS: /* … */, numa linha ou em várias. O navegador ignora tudo o que está dentro.
  • Use para explicar o porquê, dividir o arquivo em seções e desligar declarações para testar.
  • // e <!-- --> não são comentários no CSS. O // numa linha antes de uma regra derruba a regra inteira.
  • Comentários não se aninham: o primeiro */ fecha, e o que sobra estraga a declaração seguinte.
  • Um /* sem */ apaga, em silêncio, tudo até o fim do arquivo; o validador não avisa.
  • Comentário é público: qualquer visitante pode ler o seu CSS.
